## 1. Три колонки (`/feed`)

Наследует **wide-режим шапки** ([projects.page.md §1](projects.page.md), [frame.md §2](frame.md)): часы/дата у левого края вьюпорта, капсула справа, центральная навигация `Дом · Новости · Принтеры · Проекты` сверху (пункт «Новости» уже в реестре `NAV_ITEMS`, `headerMode:'wide'`, маршрут `/feed` — данные реестра, шапку не трогаем). Контент — в увеличенном `--content-max-wide` ([projects.page.md §1.4](projects.page.md)).

Колонки **не равноправны** (эпик §2): центр — смысл, боковые — навигация/витрина. Это определяет и порядок деградации (§5).

### 1.1 Раскладка (десктоп ≥1280px)

```
        [ wide-шапка: часы·дата | Дом Новости Принтеры Проекты | капсула ]

┌ ЛЕВАЯ (280px, sticky) ┐ ┌ ЦЕНТР (680px, лента) ─────┐ ┌ ПРАВАЯ (320px, sticky) ┐
│ ┌ Написать пост    → ┐│ │ ┌─── карточка поста ─────┐│ │ Сейчас горячо           │
│ └──────────────────── │ │ │ …                      ││ │ ┌ мини-карточка ×5 ─────┐│
│                        │ │ └────────────────────────┘│ │ обновлено 4 мин назад  │
│   [Лента] [Подписки]   │ │ ┌─── карточка поста ─────┐│ │                        │
│                        │ │ │ …                      ││ │ Новинки принтеров      │
│ МОИ САБЫ               │ │ └────────────────────────┘│ │ ┌ релиз-карточка ×3 ────┐│
│ · Bambu Lab фанаты     │ │ …                          │ │                        │
│ · Creality K1          │ │ (бесконечный скролл)       │ │ Каталог фидов          │
│ · … (до 8)             │ │                            │ │ [поиск]                │
│ Все фиды →             │ │                            │ │ ┌ саб-строка ×8 ─────── │
└────────────────────────┘ └────────────────────────────┘ └────────────────────────┘
```

- **Ширины** (ориентир, точное — [metrics.md](metrics.md)): левая ~280px, правая ~320px, обе фикс; центр — гибкий остаток, но не растягивается без предела — карточка держит `max-width` ~680px даже на очень широких экранах (крупная колонка голосов должна стоять на одной вертикали по всей высоте скролла, эпик §3 — растянутая карточка это ломает).
- **Sticky-колонки.** Левая и правая — `position: sticky` под шапкой, **не скроллятся вместе с лентой** (эпик §2: «всегда одинаковой высоты»). Если содержимое колонки выше вьюпорта (длинный список «Моих сабов» и т.п.) — внутренний скролл колонки, не страницы; на практике при ≤8 сабах и 3 блоках справа это редкий случай.
- **Зазоры** — `clamp()` по [metrics.md](metrics.md), тот же принцип, что `.marketLayout`/сайдбар каталога ([marketplace.v2.md §1.1](marketplace.v2.md)) — тот же паттерн «узкая sticky-колонка + гибкий контент», разница только в том, что здесь их две.

### 1.2 Левая колонка — «где я»

Сверху вниз, `Card`-контейнер того же стекла, что сайдбар каталога:

1. **Переключатель потока** — отдельный от карточки публикации `SegmentToggle`
   **«Лента / Подписки»**, полная ширина колонки. Он стоит над карточкой с персонажем
   и CTA, а не внутри неё: сначала человек выбирает, что читать, затем видит
   приглашение показать свою работу. На узком экране
   переключатель остаётся над потоком, потому что левая колонка скрывается.
2. **«Написать пост»** — `PrimaryButton` (текст + круглая зелёная стрелка), полная ширина колонки. **Единственная зелёная CTA экрана.** Ведёт на `/feed/new` (спека — `feed.post.editor.md`). Гость — тот же паттерн, что «Предложить идею» ([ideas.md §1.6](ideas.md)): тап открывает overlay-промпт входа, не форму.
3. **«Мои сабы»** — `Eyebrow` «МОИ САБЫ» + реальные подписки из
   `GET /communities?member=me`, до 8 строк: круглая метка + название + подпись
   «Официальный канал» для `vendor|machine` или «Сообщество» для пользовательского саба.
   Тап целиком → скоуп конкретного саба. Строка тач-таргет ≥48px. Ниже —
   **«Найти сабы →»** на `/community`.
   - Активный саб (когда скоуп = конкретный саб) — в шапке ленты (§1.4 ниже) появляется его имя + кнопка «Отписаться» (вторичное стекло), а в списке слева этот саб получает лёгкую акцентную подложку (тот же язык, что активный таб bottom-tab, [touch.nav.md](touch.nav.md)) — «где я сейчас» читается с одного взгляда в обеих колонках сразу.

### 1.3 Правая колонка — «что ещё»

Три самостоятельных лёгких стеклянных модуля, а не одна большая карточка с карточками внутри.
Каждый модуль имеет свой `Eyebrow`, короткую поясняющую строку и плоский список с тонкими
разделителями. Так колонка читается как навигационная витрина и не спорит по весу с постами.

1. **«Сейчас обсуждают»** — 5 ранжированных строк: номер, заголовок поста (до 2 строк),
   `саб · N голосов · M ответов`, тап → пост. Под списком — приглушённая строка
   **«обновлено N мин назад»** (`--text-dim`, честность вместо иллюзии реалтайма — эпик §2).
   Превью-картинки нет: это быстрый вход в разговор, не вторая лента.
2. **«Календарь принтеров»** — 3 ближайших релиза из каталога (`PrinterReleaseCard`, визуал —
   [printers.md §1](printers.md), MF-33/MF-833) собраны в плоский timeline-список без ещё одного
   слоя карточного chrome. Под блоком — нейтральная ссылка **«Все новинки →»** на
   `/printers/releases`, мост между лентой и календарём новинок
   ([nav.sections.md §2](nav.sections.md), [printers.md §6](printers.md)).
3. **«Найти сообщество»** — строка поиска (компактный `Input`, debounce как везде) + до 8
   identity-строк сабов: круглая метка, название, тип/число участников и `Chip`-действие
   **«Подписаться»** справа. После тапа → «Отписаться» оптимистично, без перехода со страницы
   (тот же паттерн, что вступление в сообщество, [community.md §2.2](community.md)).

Правая колонка целиком — опциональна для сценария (тест эпика §2: «удаление не ломает поток»), поэтому это первое, что уезжает на узких экранах (§5).

### 1.4 Начало центральной колонки

Общий поток начинается сразу с первой карточки: отдельного заголовка «Лента мастерской» /
«Все посты» и дублирующего переключателя в центре нет. Это освобождает вертикальное место
и делает экран content-first, как Reddit.

Только у конкретного саба над потоком остаётся компактная контекстная строка:
`Eyebrow` «Сообщество» + `h1` `# Название саба`, одна приглушённая строка описания
и вторичная кнопка «Отписаться».

## 2. Карточка поста — один каркас, три тела

Решение зафиксировано эпиком ([feed.page.md §3](../epics/feed.page.md)): один тип карточки, различается только тело — колонка голосов стоит на одной вертикали по всему скроллу.

### 2.1 Общая анатомия

```
┌──────────────────────────────────────────────────────────────────┐
│ ┌────┐  bamboolab · @nick · 3 ч назад                             │  ← шапка: саб·автор·возраст
│ │ ▲  │                                                             │
│ │ 47 │  Напечатал вазу за 4 часа, PETG, полёт нормальный          │  ← заголовок (Unbounded medium)
│ │ ▼  │                                                             │
│ └────┘  ┌ тело: model_link / media / text (§2.2) ─────────────┐  │
│         └───────────────────────────────────────────────────────┘  │
│         ┌──────────┐ ┌──────────┐ ┌────────────────┐              │
│         │ 💬 12    │ │ Поделиться│ │        …        │              │  ← футер: ряд pill (§2.3)
│         └──────────┘ └──────────┘ └────────────────┘              │
└──────────────────────────────────────────────────────────────────┘
```

Карточка — `Card` (градиентная заливка, radius ~28, `1px solid var(--border)`), кликабельна **вся площадь кроме голосовалки и футер-пилюль** (тот же trade-off, что карточка идеи — [ideas.md §2](ideas.md)) → пост `/feed/p/:id`. Прочитанный пост (уже открывавшийся, есть в истории просмотра) — заголовок приглушён (`--text-dim` вместо `--text`, без изменения веса шрифта) при возврате в ленту — требование потока эпика §4, не вкусовщина: без этого бесконечный скролл превращается в бесконечный повтор.

- **Голосовалка** — левый край, `VoteArrows` вариант `compact` (§3).
- **Шапка** — компактный тип поста + `саб` (ссылка `/community/:slug`) `·` `@автор`
  (ссылка `/u/:username`) `·` относительный возраст. Каталожный `vendor|machine`-саб получает
  бейдж «✓ официальный». `source_type=agent|import` всегда получает отдельную provenance-метку
  «Опубликовано агентом» или «Проверено человеком» — AI не маскируется под бренд/человека.
- **Заголовок** — 1 строка, `Heading size="sm"`/Unbounded medium, обрезка `…`. Юзер-текст произвольный — без принудительного акцентного слова (тот же принцип, что заголовок идеи, [ideas.md §3.2](ideas.md)).
- **Тело** — по типу поста, §2.2.
- **Футер** — pill-ряд, §2.3.

### 2.2 Тело по типам

**`model_link` — публикация модели.** Встроенная плитка превью модели — **переиспользуем `ModelTile`/слоёный псевдо-3D-стек** ([model.preview.md](model.preview.md)), не рисуем новый превью-компонент: тот же silhouette+glow+shadow-стек, что каталог, но в компактной горизонтальной раскладке (превью слева ~120×120, справа format-eyebrow + название модели + `♥`/скачивания приглушённо). Плюс собственный текст автора поста ниже плитки, если есть (обычный текст, не md-рендер тела — это карточка ленты, не страница поста). Тап по превью-плитке → `/project/:id` модели напрямую (минуя пост); тап по остальному телу/карточке → пост (эпик §3).

**`media` — анонс принтера.** Обложка 16:9, `poster`-кадр видео, **автоплей выключен** (эпик §3: звук/трафик не тратим без спроса) — тонкая line-иконка ▶ по центру поверх постера сигнализирует «видео», не крупная play-кнопка на пол-карточки (это лента, не плеер). Тап по обложке/карточке → пост, там видео разворачивается целиком (спека `feed.post.editor.md`). Под обложкой — 2 строки текста автора, обрезка по высоте, без градиента (2 строки короче порога, где нужен градиент-fade — см. `text` ниже).

**`text` — пост в сабе.** Заголовок + первые ~3 строки тела (**plain-text сниппет** из markdown — заголовки/списки схлопнуты в текст, тот же приём, что сниппет идеи, [ideas.md §2.1](ideas.md)), `-webkit-line-clamp` с **градиентной обрезкой** (`mask-image: linear-gradient(to bottom, black 60%, transparent)` поверх clamp, не резкий обрез строки — читается как «текста больше», не как баг вёрстки). **Без плейсхолдера картинки** — карточка `text` просто ниже, чем `media`/`model_link` (эпик §3: «пост без картинки — норма, не пустое место», лента не рисует серый прямоугольник).

**`gitverse` — репозиторий/issue GitVerse** (MF-1051, дополняет [feed.page.md §3.1](../epics/feed.page.md)). Мини-превью в духе GitHub social-card, горизонтальная раскладка **тот же слот, что `model_link`** (превью слева, текст справа) — не рисуем третью геометрию тела ради одного нового типа:

```
┌──────────┐  owner/name                                    ┐
│  (ava)   │  первая строка описания репо                   │
│  owner   │  ⭐ 1.2k · TypeScript                            │
└──────────┘                                                 ┘
```

- **Превью-плитка** (~120×120, тот же радиус/стекло, что `ModelTile`-слот) — аватар владельца репо крупно, поверх — `owner/name` мелко приглушённым, если аватар не подтянулся (парсер не смог) — нейтральная заглушка-глиф GitVerse на стеклянной подложке, не пустой квадрат.
- **Текст справа** — `owner/name` (`--text`, medium), первая строка описания репо (`--text-dim`, 1 строка обрезка), ниже — бейдж-строка `⭐ звёзды · язык` (тот же `Chip`-примитив, нейтральное стекло, некликабельный — это метаданные, не действие). Плюс текст автора поста ниже плитки, если есть (тот же приём, что `model_link`).
- **Тап по превью-плитке** → внешняя ссылка на GitVerse, `target=_blank` (мы не хостим чужой код, эпик §3.1); тап по остальному телу/карточке → пост, как у остальных типов.
- **Деградация без превью** (парсер не смог — приватный/битый репо/rate-limit): карточка показывает голый `gitverse_url` текстом вместо плитки+бейджей — тот же заголовок и каркас карточки, просто тело схлопывается в одну строку-ссылку (`--text-dim`, line-иконка GitVerse слева), не блокирует публикацию (эпик §3.1: «то же правило, что видео без poster быть не может, а вот превью GitVerse может отсутствовать»).

**Неровные пропорции изображения — letterbox-blur, не серые поля** (референс оператора, вступление файла). Когда фактические пропорции обложки (`media`) или превью модели не совпадают с отведённой рамкой карточки — фон под кадром заполняется **блёрнутой копией того же изображения** (`filter: blur(24px) brightness(.55)`, `transform: scale(1.15)` чтобы скрыть блюр-край), а не залитым `--surface-2`. Тот же приём, что летбокс на полноэкранном просмотре поста в мобильных Reddit-клиентах — картинка «расширяется в себя», не обрамляется цветом фона темы. Деталь фиксируется как переиспользуемый паттерн — §6.

### 2.3 Футер — ряд отдельных pill, не плоская строка

**Решение по референсу оператора:** футер — **2–3 отдельные капсулы-`Chip`** в ряд, каждая — своя стеклянная пилюля (`border-radius:999`, тонкая обводка), не голый инлайн-ряд «иконка + пробел + текст». Тот же визуальный вес, что голосовалка-капсула сама по себе (`VoteArrows`), продолженный на остальные футер-действия — единый ряд из равнозначных по форме пилюль, премиальная деталь дёшево:

```
┌ 💬 12 ┐  ┌ Поделиться ┐
└───────┘  └────────────┘
```

- **Комментарии** — line-иконка чата + число (`comments_count`), нейтральное стекло, тап → пост, фокус на треде комментариев (`/feed/p/:id#comments`).
- **Поделиться** — line-иконка + текст «Поделиться» (не голая иконка — эпик-инвариант layout.md: действие дублируется текстом и иконкой), тап → `navigator.share()`/копия ссылки + тост (тот же паттерн, что «Поделиться» карточки модели, [marketplace.v2.md](marketplace.v2.md)).
- Обе пилюли — **вторичное нейтральное стекло**, не зелёные (зелёная CTA экрана — «Написать пост» в левой колонке, правило одного primary не нарушается). Тач-таргет каждой пилюли ≥48px по высоте, даже если визуально компактнее.
- Пилюли **перехватывают тап** — клик по ним не открывает пост (тот же trade-off, что голосовалка, §2.1).

### 2.4 «Раскрыть»/«Свернуть» — инлайн-расширение (MF-1051)

Третий уровень между карточкой и `/feed/p/:id`, сценарий — [feed.page.md §4.0](../epics/feed.page.md). **Не роут, не оверлей** — плоское визуальное состояние карточки внутри ленты (`Set<postId>` в сторе ленты, живёт пока `/feed` смонтирован).

```
         ┌──────────┐ ┌──────────┐ ┌────────────────┐ ┌──────────┐
         │ 💬 12    │ │ Поделиться│ │        …        │ │ Раскрыть ⌄│  ← новая pill, футер
         └──────────┘ └──────────┘ └────────────────┘ └──────────┘
```

- **Новая pill в футере** (§2.3, тот же `CardFooterActions`-ряд), крайняя справа: line-glyph шеврон + текст **«Раскрыть»**. Появляется, **только если есть что раскрывать** — таблица типов ниже; текстовый пост короче ~3 строк (уже весь виден в карточке) кнопку не получает вообще, не `disabled`-версию.
- **Тап** → карточка **растёт на месте** между телом и футером: контейнер расширенного контента анимируется по высоте (`max-height: 0 → auto`-эквивалент через измеренный `scrollHeight` + `opacity 0→1`), `--dur-slow` `--ease-out` — тот же примитив-масштаб, что схлопывание хрома в [motion.md §10.1](motion.md) (там `max-height`+`opacity` сворачивает, здесь тем же приёмом разворачивает). Соседние карточки ленты **не дёргаются рывком** — рост плавный, скролл-позиция под текущей карточкой не прыгает. Pill меняет текст/иконку на **«Свернуть»** (шеврон разворачивается на 180°, `--dur-toggle`).
- **Голосовалка и остальные футер-pill остаются на месте** под раскрытым блоком — раскрытие не переустраивает каркас карточки, только вставляет блок между телом и футером.
- **Содержимое раскрытого блока — по типу тела**, не один универсальный рендер (эпик §4.0):

  | Тип | Раскрыто (инлайн) | Не входит (только на странице поста) |
  |---|---|---|
  | `text` | весь `.md` тела поста, тот же рендер, что страница поста | комментарии, «Ещё из этого саба» |
  | `model_link` | превью модели крупнее + весь текст автора (не обрезан) | сама карточка модели (остаётся отдельной ссылкой), комментарии |
  | `media` | видео целиком, плеер, звук по тапу (не автоплей) | комментарии, «Ещё из этого саба» |
  | `gitverse` | полное описание репо (что отдал парсер) + весь текст автора | список issues/PR репо, комментарии |

- **«Перейти к посту →»** — если внутри раскрытого блока материала ещё больше (длинный текст автора, полное описание репо), внизу раскрытого блока — текстовая ссылка-строка (тот же тон, что «Все фиды →» левой колонки), тап → обычный `pushState` на `/feed/p/:id` (§4). Не второй CTA — просто выход в полноценный пост.
- **Звук** — нет (появление контента внутри страницы, не жест-подтверждение — тот же принцип, что `.stagger-reveal`, [sound.md §0](sound.md)). Тап по самой pill — обычный `.pressable` + `tick`, как у остальных футер-действий.
- **`prefers-reduced-motion`** — блок появляется/исчезает мгновенно (`display`/`opacity` без transition), высота не анимируется — тот же принцип, что [motion.md §10.1](motion.md).
- **`aria`** — pill получает `aria-expanded`, раскрытый блок — `aria-hidden="false"`/regionrole, фокус после тапа остаётся на pill (не прыгает в раскрытый текст) — раскрытие не должно ловушить клавиатурного пользователя.

## 3. Голосование

Контрол — **`VoteArrows`**, обобщённый примитив уже описанный в [components.md § Голосовалка](components.md) и [community.md §7.4](community.md) (тот же контракт, что `.modelVote` модели, `{value:1|-1|0}` → `{votes_up, votes_down, my_vote}`). **Расширение контракта этой спекой:** третий потребитель после `model`/`thread`/`post` — **`subjectType:'feed_post'`**, порог «повторилось трижды» пройден с запасом, это не новая копия JSX/CSS, а параметризация существующего.

- **Вариант `compact`** (§2.1 карточка ленты) — вертикальная капсула `[▲ счёт ▼]`, тач-таргет ≥48×48, у карточки поста — левый край. Тот же вид/цвет/тач/моушен, что везде: ▲ активная = `--accent`, ▼ активная = `--accent-danger`, повторный тап по активной = снятие (`value:0`), оптимистичный апдейт.
- **Счёт** — `votes_up − votes_down`, count-up на ±1/±2 при смене голоса ([motion.md §5/§8](motion.md)).
- **Ошибка сети** — откат счёта, тихий тост «Голос не сохранён» (severity `warn`, `overlay/sound.ts`).
- **Гость** — стрелки и счёт видны и кликабельны (чтение публично — эпик §5/[ux.md §1.2](../product/ux.md)); тап → overlay-промпт входа, **намерение запоминается** и голос применяется сам после логина (та же механика, что голос за идею гостя — задел, конкретный сторидж намерения решает Front/Fullstack).
- **«Размытый счёт» первые 10 минут жизни поста** (эпик §5, анти-абьюз) — счётчик рендерится как `~120` (тильда + округление до ближайшего порядка, не точное число) вместо точного `votes_up − votes_down`. Визуально — тот же `VoteArrows`, только текстовая маска на числе; после 10 минут следующий `GET` уже отдаёт точное значение, клиент не считает округление сам (доверяет API-флагу `score_approx`/аналогу, контракт — Fullstack).
- **Своя карточка не переставляется под голосованием** (эпик §5) — тап меняет только счётчик, порядок ленты не пересчитывается на клиенте.
- **Без звука** — как и везде для голосовалки ([sound.md §3](sound.md)): частый жест в ленте, звук на каждый апвоут — шум, не подтверждение.
- **`aria`** — `aria-pressed` на активной стрелке, `aria-label="Голосовать за/против поста, сейчас N голосов"`, счётчик `aria-live=polite`.

## 4. Состояния

| Состояние | Что видит |
|---|---|
| **Первый раз, подписок нет** | скоуп «Всё» + мягкая полоса над лентой: «Подпишитесь на свой принтер — лента станет вашей» + 3 предложенных саба (карточки-чипы с «Подписаться») по `printer_connections`/каталогу. Не блокирует чтение ленты под полосой. |
| **«Мои подписки» пуст** (подписан, постов нет) | не пустой экран: заголовок-плашка «В ваших сабах пока тихо» + первые 5 постов из «Всё», каждый с приглушённой меткой-eyebrow «Из общей ленты» поверх обычной шапки карточки. |
| **Загрузка (первая страница)** | 4–5 карточек-скелетов той же геометрии, что реальная карточка (голосовалка-капсула, шапка, тело, футер-пилюли — все области мерцают shimmer), лента не «прыгает» при подстановке реальных данных. |
| **Догрузка (бесконечный скролл)** | спиннер внизу ленты на подгрузке; **после 3 автодогрузок подряд** — вместо очередной автодогрузки кнопка **«Показать ещё»** (нейтральное стекло, ≥48px) — тач-fallback и уважение к трафику, тот же паттерн, что лента идей ([ideas.md §1.5](ideas.md)). |
| **Конец ленты** | строка-заглушка «Вы всё прочитали» (`--text-dim`, центр) + врезка **«Сейчас горячо»** вторым экраном (тот же список, что правая колонка §1.3, но развёрнутый в центр — на мобиле это и есть единственное место, где он виден, §5) — не тупик, а мягкий редирект внимания. |
| **Ошибка сети** | уже загруженные карточки остаются на месте (не мигают, не исчезают), внизу ленты — строка «Не удалось загрузить · Повторить» (`IconButton`/текстовая ссылка), тап повторяет последний курсорный запрос. |
| **Гость** | лента и голосовалка видны как есть (§3); действия, требующие входа (голос-эффект после клика, коммент, «Написать пост») → overlay-промпт входа. |
| **Закрытый саб** (скоуп = `unlisted`-саб, я не участник) | вместо ленты — центрированный блок: «Это закрытое сообщество» + кнопка «Запросить доступ» (вторичное стекло) — не 404, не пустая лента. |

Все загрузочные/пустые/ошибочные состояния используют существующий `EmptyState`/skeleton-паттерн `ui.tsx` — новых примитивов состояние не требует.

## 5. Мобильный и узкий экран (деградация)

Наследует тач-инварианты [layout.md](layout.md) (≥48px, `:active`, `touch-action:manipulation`). Три брейкпоинта, в порядке того, что уходит первым (эпик §7 — правая колонка не несёт того, без чего пользователь не может действовать):

- **< 1280px** — правая колонка (§1.3) уезжает из sticky-сайдбара и вставляется **внутрь ленты одним блоком после 5-го поста**: те же три подблока («Сейчас горячо» / «Новинки принтеров» / «Каталог фидов»), тот же контент, просто в потоке центральной колонки вместо сайдбара. Левая колонка пока остаётся sticky-сайдбаром (её функция — «где я» — важнее «что ещё», уходит она позже).
- **< 900px** — левая колонка (§1.2) сворачивается в **липкую полосу под шапкой**: `[Лента | Подписки]` сегмент (тот же компонент, просто горизонтальная лента вместо колонки) + `IconButton` «Фиды» справа от сегмента, тап открывает **`sheet()`** (слой всплывашек, [overlay.system.md](../epics/overlay.system.md)) со списком «Мои сабы» (тот же контент §1.2 п.3, просто в шите вместо колонки) — тот же паттерн, что шит фильтров каталога на мобиле ([marketplace.v2.md §1.4](marketplace.v2.md)). Скоуп остаётся на экране всегда (эпик §7: «это где я, его нельзя прятать»), «Написать пост» с этой ширины уже не в полосе — она переезжает в FAB следующего брейкпоинта, но полоса уже должна резервировать её место логически (кнопка просто не рисуется здесь на этой ширине, а не «исчезает без замены» — FAB подключается на ≤640px).
- **≤ 640px** — bottom-tab-режим ([touch.nav.md §1](touch.nav.md)): «Написать пост» становится **`FAB`** (круглая зелёная кнопка, `+`/стрелка-глиф, `position: fixed` над таббаром, тот же safe-area отступ, что таббар). Голосовалка `compact` укрупняется: стрелки/тап-зона до **48px** (было тач-минимум с запасом на десктопе, здесь — буквально визуально крупнее, эпик §7). **Свайп по карточке не голосует** — горизонтальный жест на карточке ленты игнорируется голосовалкой (только тап по стрелке), это явный анти-паттерн эпика §7 («случайный минус на скролле — худший баг такой ленты»); свайп-между-разделами навигации ([touch.nav.md §2](touch.nav.md)) по-прежнему работает вне карточек ленты.

Липкая полоса скоупа (< 900px) и bottom-tab-таббар (≤ 640px) — оба `position: fixed`/`sticky`, оба не перекрывают друг друга по вертикали (полоса — под шапкой сверху, таббар — снизу, контент между ними получает `padding-bottom` под таббар, как и везде — [touch.nav.md §1](touch.nav.md)).

## 6. Новые/расширенные компоненты → `components.md`

Паттерн ниже фиксирую как контракт для `components.md` (эволюция дизайн-системы, MF-40):

### 6.1 `VoteArrows`: `subjectType:'feed_post'`

Расширение уже обобщённого примитива ([components.md § Голосовалка](components.md), [community.md §7.4](community.md)) — третий/четвёртый потребитель (`model`/`thread`/`post` уже есть) добавляет `feed_post` к тому же union-типу параметра, без нового JSX/CSS. Единственная новая деталь контракта — **режим «размытого счёта»** (§3): опциональный проп `approx?: boolean` — при `true` число рендерится как `~{roundedValue}` вместо точного, без изменения формы/цвета/тач-поведения контрола. Первое применение этого флага — здесь; если понадобится в третьем месте, он уже общий.

### 6.2 Футер-pill-ряд (`CardFooterActions`)

Ряд из 2–3 нейтрально-стеклянных `Chip`-пилюль (иконка+текст/число), горизонтально, каждая — самостоятельная тач-цель с `pointer-events` только на себе, не на общем контейнере. Первое применение — футер карточки поста (§2.3: комментарии, поделиться). Отличается от обычного ряда `Chip`-фильтров тем, что это **действия карточки-контента**, не переключатели состояния — визуально тот же примитив (`Chip`), семантика другая (кнопка, не toggle), `aria-pressed` не ставим.

### 6.3 `ExpandableCardBody` — раскрытие карточки на месте (MF-1051)

Новый переиспользуемый композит (§2.4): футер-pill «Раскрыть»/«Свернуть» (вариант `CardFooterActions`, §6.2, с `aria-expanded`) + контейнер контента, растущий по высоте `max-height`+`opacity` (`--dur-slow`/`--ease-out`, тот же примитив, что схлопывание шапки [motion.md §10.1](motion.md)) + опциональная замыкающая ссылка «Перейти к посту →». Контент раскрытого блока — `children`, разный для каждого типа тела (§2.4 таблица); композит не знает про типы, только про анимацию раскрытия и структуру. Первое применение — карточка поста ленты; кандидат на переиспользование в других местах, где контент «читай больше не уходя со страницы» повторится в третий раз.

### 6.4 Letterbox-blur (рамка изображения неровных пропорций)

Новый переиспользуемый визуальный приём (§2.2): контейнер медиа/превью с фиксированными пропорциями, где фактическое изображение уже, чем рамка, получает фон — **само изображение, растянутое и блёрнутое** (`blur(24px) brightness(.55) scale(1.15)`), не заливку токеном темы. Первое применение — обложка `media`-поста и превью `model_link` в карточке ленты. Кандидат на переиспользование там, где уже сегодня плоская заливка используется как заглушка неровных пропорций (например `floating-veil` hero-карусели, [projects.page.md §2.2](projects.page.md)) — не трогаю существующие места этой спекой, просто фиксирую приём под новый кейс; миграция других мест — отдельное решение, если паттерн повторится в третий раз (эпик-принцип «повторилось дважды → фиксируем систему»).

## 7. Моушен и звук (сводка, ничего нового не вводим)

Все паттерны — уже существующие, применяем без изменений (полные хореографии — [motion.md](motion.md)/[sound.md](sound.md)):

- **Тап по карточке/пилюле футера/скоуп-сегменту/сабу в списке** — `.pressable` (`--dur-tap`/`--dur-press`) + звук `tick`.
- **Голосование** (§3) — count-up ±1/±2, микро-подскок стрелки (`--dur-pop`), **без звука** (осознанно, [sound.md §3](sound.md)).
- **Скоуп-переключатель «Лента» / «Подписки»** — `toggle`-тембр + морф заливки `--dur-toggle` ([motion.md §7](motion.md)), лента ниже перезагружается с `.stagger-reveal` первой страницы (без звука — появление контента, не жест, [sound.md §0](sound.md)).
- **Появление карточек ленты (первая загрузка/догрузка/pull-обновление)** — `.stagger-reveal`, без звука ([motion.md §5](motion.md)).
- **«Показать ещё» / «Повторить»** — обычный `.pressable` + `tick`, результат — та же `.stagger-reveal`-подгрузка.
- **`sheet()` «Мои сабы» на мобиле** — `.modal-in-out` (`--dur-slow`), тот же паттерн, что шит фильтров каталога.
- **Letterbox-blur фон** — статичный (блюр вычисляется один раз на загрузке кадра), без анимации самого блюра; сама карточка появляется обычным `.stagger-reveal`.
- **«Раскрыть»/«Свернуть»** (§2.4) — `max-height`+`opacity` рост/схлопывание блока `--dur-slow`/`--ease-out` (тот же примитив-масштаб, что [motion.md §10.1](motion.md)), шеврон pill разворачивается `--dur-toggle`, без звука; тап по самой pill — обычный `.pressable`+`tick`.

## 8. Инварианты приёмки (чек-лист ревью)

- [ ] **Три колонки:** левая/правая sticky, не скроллятся с лентой; центр держит `max-width` ~680px даже на широких экранах; wide-шапка с `Дом·Новости·Принтеры·Проекты` (§1).
- [ ] **Левая колонка:** «Написать пост» — единственная зелёная CTA экрана; отдельный скоуп «Лента»/«Подписки» синхронизирован с `?scope=`; «Мои сабы» ≤8 + «Все фиды →» на `/community`, не новая страница (§1.2).
- [ ] **Правая колонка:** «Сейчас горячо» с «обновлено N мин назад»; «Новинки принтеров»; «Каталог фидов» с подпиской прямо из блока (§1.3).
- [ ] **Карточка поста:** один каркас, четыре тела (`model_link`/`media`/`text`/`gitverse`); пост без картинки — карточка ниже, не серый плейсхолдер; letterbox-blur для неровных пропорций, не плоская заливка (§2.1–2.2).
- [ ] **`gitverse`-тело:** owner/аватар, описание-строка, ⭐+язык бейдж; деградация без превью — голая ссылка, не блок публикации (§2.2).
- [ ] **Футер:** ряд отдельных pill (комментарии, поделиться, «Раскрыть»/«Свернуть» когда есть что раскрывать), не инлайн-строка иконка+текст (§2.3–2.4).
- [ ] **Инлайн-раскрытие:** pill появляется только когда есть расширенный контент; рост на месте без прыжка соседей; правильный контент по типу тела (§2.4 таблица); «Перейти к посту →» когда материала больше, чем в раскрытии; НЕ роут/оверлей.
- [ ] **Прочитанный пост** — приглушённый заголовок при возврате в ленту (§2.1).
- [ ] **Голосование:** `VoteArrows` расширен `subjectType:'feed_post'`, не третья копия; гость видит и может тапнуть → промпт входа; «размытый» счёт первые 10 минут через `approx` (§3).
- [ ] **Все 8 состояний §4** спроектированы (первый раз/пусто-подписки/загрузка/догрузка/конец/ошибка/гость/закрытый саб), ни одно не оставляет пустого экрана без действия.
