# Публичный профиль v2: след мейкера

**Карточки:** MF-1947 (web/UX), MF-1948 (публичные агрегаты API).

Этот документ заменяет композицию «мини-профиля» из `marketplace.full.md §7` и визуальную
иерархию ранних `storefront.*` для общего `/u/:username`. Специфичные будущие поля коммерческой
витрины мастера остаются в `storefront.master.md`, но не создают вторую страницу.

## 1. Роль страницы

Профиль — не форма настроек и не длинный личный кабинет. Это публичное доказательство работы:
кто автор, что он сделал, о чём пишет и какой след оставил в сообществе. Проекты и посты
равноправны; персонаж — узнаваемое лицо автора. Репутация объясняется наблюдаемыми агрегатами.

Один маршрут работает в двух состояниях:

- **зритель** видит публичную личность, проекты, посты, репутацию и может подписаться;
- **владелец** видит ровно ту же витрину плюс вкладку «Мастерская» и компактное
  «Редактировать профиль». Настройки не меняют геометрию публичного слоя.

Публичный GET профиля доступен без сессии. Приватные списки оборудования, материалов,
покупок, уведомлений, идей и черновиков никогда не входят в публичный ответ.

## 2. Первый кадр

Сверху — один hero-блок:

1. большой 2D-снимок кастомного персонажа (через `AvatarBubble`, не фото и не WebGL);
2. имя, `@username`, бейджи, био и внешние ссылки;
3. четыре короткие метрики: проекты, посты, просмотры, подписчики;
4. одно контекстное действие: зрителю «Подписаться», владельцу вторичное «Редактировать».

Метрики «Проекты» и «Посты» переключают соответствующую вкладку. Персонаж остаётся крупным
на wide, но на телефоне переходит над именем и не отнимает горизонтальное место.

## 3. Вкладки

- **Обзор** — компактная полка проектов и три последних поста.
- **Проекты** — полная авторская полка; при 4+ карточках горизонтальная карусель со
  scroll-snap и кнопками для клавиатуры/пульта.
- **Посты** — авторская лента из канонического `FeedPostCard`, сортировка по новизне.
- **Мастерская** — только владельцу: идеи, печати, парк, материалы, уведомления, покупки.

Редактор публичных полей открывается общей `overlay.modal`; инлайн-форма между hero и
контентом запрещена.

## 4. Статистика и честность

Показываются только реально посчитанные агрегаты:

- проекты и суммарные скачивания — публичные `models`;
- просмотры проектов — события `model_view` публичных проектов;
- посты, рейтинг и комментарии — публичные `feed_posts`;
- просмотры постов — `feed_events(event_type='view')`;
- репутация/TL — существующее репутационное ядро.

Нули означают нули. Не показываем выдуманную карму, рейтинг без источника или персональные
данные зрителей. На API это один агрегирующий запрос без N+1.

## 5. Адаптив

- **≥1680px:** hero в три колонки, контент + sticky-сводка справа.
- **821–1679px:** персонаж и имя в две колонки, четыре метрики отдельным рядом.
- **561–820px:** основная колонка, сводка ниже в две карточки.
- **≤560px:** персонаж над именем, метрики 2×2, вкладки скроллятся, проектная карточка
  занимает ~84vw.
- **≤360px:** внешние поля не создают горизонтальный скролл; минимальная ширина не
  предполагается.

Все интерактивные цели — из UI-kit, минимум 48px. Скелетоны сохраняют геометрию, shimmer
отключается при `prefers-reduced-motion`.
