# Анонсы версий в Telegram (release-announcer)

> С 2026-07-17. Оператор следит за разработкой из Telegram — каждая новая
> версия портала автоматически превращается в пост. Агент для этого НЕ нужен
> и не тратится.

## Как это работает

1. CI бампает `version.json` и вешает тег `vX.Y.Z` (как и раньше).
2. Вотчер `/usr/local/bin/release-announcer` на dev-vm (systemd-таймер, 5 мин)
   ловит новые теги в `origin` и шлёт пост оператору через `tg-say`:
   `🚀 vX.Y.Z — заголовок · 🖼 dev.3mf.tech · дайджест · 🔗 гит · 🗂 MF-refs`.
3. Содержимое поста:
   - **Аннотированный тег с телом** (лучший вариант) — тело идёт в пост как есть.
     Формат тела: 1-я строка subject = заголовок поста; далее — что изменилось
     по-русски, живым языком; в конце `Role: Front` (станет `#Front`).
   - **Авто-тег CI без тела** — вотчер сам собирает дайджест из subject
     коммитов между тегами (ещё одна причина писать честные conventional
     commits с MF-refs).

## Правило для агентов

Завершил ЗАМЕТНУЮ фичу/фикс (виден пользователю на dev.3mf.tech) — оформи
версию сочно: `git tag -a v<version.json> -m "<заголовок>" -m "<что изменилось>" -m "Role: <твоя роль>"`
и `git push origin refs/tags/v<...>`. Мелочь — просто хороший commit subject,
дайджест соберётся сам. Слать в TG руками ЗАПРЕЩЕНО — этим занимается вотчер.
