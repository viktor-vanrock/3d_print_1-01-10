# Install-баннер (Android) + iOS-шторка «На экран Домой»

← [docs/design/readme.md](readme.md) · моушен-токены — [motion.md](motion.md) · звук — [sound.md](sound.md) ·
паттерн fixed-баннера снизу — [consent.md](consent.md) · сосед-текст — [push.notifications.md §3](push.notifications.md)
(iOS-деградация пушей переиспользует копию этого файла) · логика без UI — `pwa/install.ts`

Спека для **MF-753** (эпик MF-42 «Мобильный клиент/PWA», Фаза 1, MF-432). Логика уже готова и не меняется —
`usePwaInstall()` (`apps/web/src/pwa/install.ts`) отдаёт `canInstall`/`showIosInstructions`/`isStandalone`/`promptInstall()`.
Здесь — ровно то, чего не хватает: визуал, копирайт, показ/дедупликация.

## 0. Один компонент на два сценария, не два баннера

Android (Chrome/Edge, `canInstall`) и iOS Safari (`showIosInstructions`) — **не два разных виджета**, один
`InstallBanner`: одна оболочка, один копирайт-каркас, одна логика показа/cooldown (§5). Ветвится только CTA:

- **Android** — кнопка «Установить» напрямую дёргает `promptInstall()` (программная установка есть).
- **iOS Safari** — кнопка «Как установить» открывает шторку-инструкцию через `useOverlay().sheet()` (программной
  установки нет — см. `install.ts`, комментарий у `isIosSafariInstallable()`).

`canInstall` и `showIosInstructions` взаимоисключающие по построению хука (либо Android-ветка перехватила
`beforeinstallprompt`, либо детект UA признал iOS Safari) — ветвление `if/else`, без гонки состояний.

## 1. Когда показывается — порядок проверок

Один баннер, рендерится максимум один инстанс, проверки по порядку:

1. `isStandalone === true` (уже установлено/уже в PWA-режиме) → баннер не рендерится никогда, нечего предлагать.
2. **Согласие на аналитику ещё не дано** (`hasCurrentConsent() === false`, [consent.md](consent.md)) → install-баннер
   не рендерится, пока не показан и не закрыт консент-баннер. Это применение существующего принципа «не больше одного
   обучающего/алерт-элемента одновременно» ([readme.md §Философия п.4](readme.md)) — два fixed-баннера снизу
   одновременно теснятся и спорят за внимание; юридическое уведомление весомее промо-предложения установить приложение.
3. **Cooldown активен** (`dismissedAt` моложе 14 дней, §5) → не рендерится.
4. `canInstall === true` → **Android-вариант**.
5. `showIosInstructions === true` → **iOS-вариант**.
6. Иначе → ничего.

Реактивность: те же источники, что уже есть (`usePwaInstall()` — событийный, `subscribeConsent()` — уже
`useSyncExternalStore`-совместимый, [consent.ts](../../apps/web/src/consent/consent.ts)) — баннер появляется сам,
как только консент дан, без перезагрузки страницы (тот же приём, что консент-баннер уже даёт для профиля, §3
consent.md).

## 2. Где монтируется

`InstallBanner` монтируется **рядом с `<BottomTabBar/>`** в `app.tsx` (тот же условный блок, что уже рендерит
таббар на основных экранах IA — `apps/web/src/app.tsx` внутри `AuthGate`, после `screen`), а не на уровне
`ConsentBanner` (та монтируется до `AuthGate`, видна и на `LoginPage`/мастере/kitchen-sink). Осознанное отличие:

- Предложение установить приложение уместно, когда человек уже пользуется порталом (главная/маркет/лента), а не на
  экране входа или в служебном мастере «добавить принтер» — там оно отвлекает от однозадачной формы
  (`printer.wizard.md §1` тот же принцип «сфокусированный экран без хрома»).
- Побочный эффект, который и нужен: баннер существует ровно там же, где существует `BottomTabBar`, поэтому его
  оффсет над таббаром (§3) не требует отдельной координации между компонентами — они всегда монтируются и
  размонтируются вместе.

## 3. Форма и место

Переиспользуем паттерн `consent.md §1` почти 1:1 (тот же fixed-bottom, то же стекло) — не изобретаем новый слой:

- `position: fixed; bottom: 0; left: 0; right: 0;`, контент центрирован по `--content-max`, паддинг
  `max(16px, env(safe-area-inset-*))` по бокам — как `.consentBannerHost`.
- Фон — тот же стеклянный градиент, что `.consentBanner` (`color-mix(surface, accent 7%)` + `backdrop-filter: blur(20px)`),
  верхние углы `--card-radius-sm`, нижние — 0, верхняя граница `1px solid var(--border)`.
- **Новый z-токен `--z-install: 61`** (`theme/tokens.css`, между `--z-toast: 60` и `--z-consent: 62`) — промо-баннер
  весомее эфемерного тоста (не гаснет сам), но легче юридического уведомления. §1 гарантирует, что оба bottom-баннера
  не показываются одновременно логикой показа — z-порядок здесь подстраховка на случай гонки при рендере
  (первый кадр до того, как консент-стейт прочитан): если оба на миг оказались в DOM, консент физически перекрывает.
- **Оффсет над bottom-tab на `≤640px`**: `bottom: calc(56px + env(safe-area-inset-bottom))` вместо `bottom: 0`
  (`--z-bottomnav` бар — 56px + safe-area, `touch.nav.md §1`). Это то, чего у консент-баннера сегодня **нет**
  (он и таббар — оба `bottom: 0`, `--z-consent` выше `--z-bottomnav`, консент физически закрывает таббар на мобиле —
  наблюдаемо на `webcheck https://dev.3mf.tech/ --mobile`). Не чиню консент этой карточкой (не его скоуп), но
  install-баннер сразу проектируется правильно, раз монтируется в паре с таббаром (§2) — оффсет не костыль,
  а прямое следствие того, что оба компонента всегда рядом.
- **Раскладка (десктоп/планшет, >640px)** — одна строка: иконка-плашка слева (§6) · заголовок+подпись (`flex: 1`) ·
  кнопка CTA · кнопка-крестик закрытия справа.
- **Раскладка (≤640px)** — колонкой, как консент: иконка+текст в первой строке, кнопка CTA на всю ширину под
  текстом, крестик закрытия — абсолютно в правом верхнем углу баннера (тот же приём, что `.ovlModalClose`).
- Появление/уход — reveal снизу, `--dur-reveal`/`--ease-out`, тот же `setTimeout(10ms)`-триггер, что
  `ConsentBanner`/`OverlaySheetHost` (не `requestAnimationFrame` — motion.md, застревает в фоновой вкладке).

## 4. Копирайт

Один и тот же заголовок для обеих платформ, разная подпись и CTA (платформа определяет действие, не смысл):

> **Установите 3mf.tech**
> Android: Быстрый доступ с домашнего экрана и офлайн-режим. **[Установить]**
> iOS: Добавьте на экран «Домой» — как обычное приложение. **[Как установить]**

- Тон — тёплое приглашение, не императив/не тревога (это не консент — можно закрыть и забыть, обычная промо-строка,
  `--surface`, не `--accent-warn`).
- Кнопка-крестик закрытия без подписи, `aria-label="Закрыть"` (§7).

## 5. iOS-шторка (`useOverlay().sheet()`)

Открывается тапом по «Как установить». Использует готовый примитив (`overlay/sheet.tsx`) как есть, без
модификаций самого примитива:

```ts
useOverlay().sheet({
  title: "Установка на экран «Домой»",
  content: <IosInstallSteps />,
});
```

Содержимое — три шага текст+иконка (не скриншот — процесс, не картинка, легче поддерживать при смене iOS UI):

1. Нажмите иконку **«Поделиться»** (квадрат со стрелкой вверх) внизу экрана Safari.
2. Прокрутите список вниз и выберите **«На экран Домой»**.
3. Нажмите **«Добавить»** в правом верхнем углу.

Формулировка шага 2 — тот же текст, что уже зафиксирован в [push.notifications.md §3](push.notifications.md)
(«Поделиться → «На экран Домой»»): единственный источник этой копии теперь здесь, `push.notifications.md §3`
уже обновлён ссылкой на этот файл вместо дублирования строки.

- Иконки шагов — переиспользуем узнаваемые системные глифы iOS (квадрат-со-стрелкой-вверх для «Поделиться»,
  квадрат-с-плюсом для «На экран Домой»), но в нашей line-манере (2px stroke, без заливки) — это документирует
  чужой OS-жест, не наш собственный контрол, упрощение до нашего языка линий не искажает узнаваемость.
- Никакого CTA-кнопки в конце шторки — это инструкция, не форма; закрывается стандартно (крестик/`Esc`/тап по
  фону, уже есть в `sheet.tsx`).
- **Открытие шторки засчитывается как дедуп-жест** (§6 ниже) — увидел инструкцию, банер не должен предлагать её
  снова в этом же cooldown-окне, даже если юзер не поставил приложение сразу.

## 6. Иконка баннера — переиспользуем, не рисуем новую

`PrinterIcon` (`ui/ui.tsx`, уже поднят из двух копий в общий модуль, `components.md §Иконки`) на плашке
40×40px, `border-radius: var(--card-radius-sm)`, фон `color-mix(in srgb, var(--accent) 14%, transparent)` —
тот же приём тонированной подложки под иконку, что уже описан в `touch.nav.md §1` для активного таба
(«24×24 circle, `--accent` 12% opacity»), просто крупнее и под другой глиф. Не заводим отдельный
«лого-бейдж» лишь под этот баннер — принтер уже читается как символ приложения на нескольких экранах
(шапка/пуш-настройки), берём его.

## 7. Дедуп/повторный показ (cooldown)

Новый ключ `localStorage`: **`portal.pwa.installDismissedAt`** (ISO-таймстамп строкой) — тот же неймспейс-паттерн,
что `portal.consent.version`/`portal.sound.*`/`portal.theme` (`sound.md §0`).

Ставится (баннер скрывается на cooldown):
- тап по крестику закрытия;
- Android: `promptInstall()` вернул `"dismissed"` (юзер отклонил системный диалог) — то же самое намерение,
  что явный крестик, обрабатывается одинаково;
- iOS: открытие шторки-инструкции (§5) — юзер увидел, что делать, дальше это его решение вне баннера.

НЕ ставится:
- Android `"accepted"` — баннер и так не появится снова: `isStandalone` станет `true` после `appinstalled`
  (§1 п.1 навсегда подавляет баннер), отдельный cooldown избыточен;
- Android `"unavailable"` (гоночная реюза `deferred=null`) — тихо скрыть баннер без записи cooldown, тот же
  подход к редкой гонке, что `push.notifications.md §2.2` («трактовать как error, тихо, без отдельной ветки UI»).

**Срок — 14 дней.** Короче консента (тот вообще не таймаутится — юридическое обязательство), длиннее, чем
разовая коачмарка: установка приложения — решение, к которому люди возвращаются не с первого предложения, но
показывать его на каждой сессии — усталость от баннера сильнее, чем польза лишнего показа. Проверка — на
монтировании компонента (`Date.now() - Number(new Date(dismissedAt)) > 14 * 86400_000`), реактивность между
вкладками не нужна (это не юридический стейт, где расхождение критично, как у консента).

## 8. Токены

- `--z-install: 61` — новый (§3).
- Остальное — существующее без изменений: `--card-radius-sm`, `--border`, `--surface`, `--accent`,
  `--content-max`, `--dur-reveal`/`--ease-out` (мотив), `Button variant="primary"` как есть (тот же прецедент,
  что кнопка «Согласен» в `consent.md §4` — второй primary-стиль на экране одновременно с hero-CTA уже принят
  этим прецедентом, не новое решение).

## 9. Motion

Ничего нового сверх `motion.md`/консент-прецедента:

| Что | Токен |
|---|---|
| Появление/уход баннера | `--dur-reveal`/`--ease-out`, `opacity`+`translateY(16px→0)` — 1:1 `.consentBanner` |
| Тап по CTA/крестику (`:active`) | `.pressable`, `--dur-tap`/`--dur-press` |
| Шторка iOS (открытие/закрытие) | `.modal-in-out`/`--dur-slow` — уже даёт `sheet.tsx`, ничего не трогаем |

`prefers-reduced-motion` — бесплатно через токены (`tokens.css` единый источник, motion.md).

## 10. Sound

Без нового тембра, по существующей палитре (`sound.md §2`):

- Тап по CTA («Установить»/«Как установить», `Button variant="primary"`) — тон **`cta`** (та же строка таблицы
  `sound.md §2`, что «тап по PrimaryButton» — это и есть PrimaryButton экрана в моменте показа баннера).
- Тап по крестику закрытия — обычный **`tick`** (рядовая icon-кнопка, не первичное действие).
- Появление баннера само по себе — **без звука** (не жест пользователя, `sound.md §0`/`§3` — тот же принцип,
  что появление подсказки `permission_denied` в `push.notifications.md §2.4`).
- Открытие/закрытие шторки iOS — без отдельного звука сверх `cta`, которым уже отработал тап, открывший её
  (`sound.md §0` «один жест — один звук»).

## 11. a11y

- Хост баннера — `role="region" aria-label="Установка приложения"` (тот же паттерн, что `ConsentBanner`'s
  `role="region" aria-label="Согласие на обработку данных"`).
- Крестик закрытия — `IconButton`/кнопка с `aria-label="Закрыть"`, тач-таргет ≥48×48px (паддинг вокруг
  визуальной иконки, как везде — `push.notifications.md §2.1`).
- CTA-кнопка — обычная `Button`, доступный текст = видимый текст, без доп. `aria-label`.
- Шторка — уже `role="dialog" aria-modal="true"` из `sheet.tsx`, ничего добавлять не нужно.

## 12. Готово когда (проверяемо)

- Установлено/standalone → баннера нет никогда.
- Согласие на аналитику не дано → install-баннер не показывается, даже если `canInstall`/`showIosInstructions`
  уже `true`; появляется сам сразу после «Согласен», без перезагрузки.
- Крестик/отклонённый системный диалог/открытая iOS-шторка → баннер не появляется повторно 14 дней.
- Установка принята (Android `"accepted"`) → баннер скрыт навсегда (через `isStandalone`), без записи cooldown.
- На `≤640px` баннер сидит НАД bottom-tab баром, не перекрывает и не перекрыт им.
- Android: тап «Установить» вызывает системный `promptInstall()` напрямую, без промежуточных экранов.
- iOS: тап «Как установить» открывает шторку с 3 шагами, копия шага 2 совпадает с `push.notifications.md §3`.
- Тап по CTA звучит `cta`, крестик — `tick`, появление баннера — без звука.
- Крестик и CTA ≥48px по тач-таргету.
