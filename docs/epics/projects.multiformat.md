## 3. Решения (с вариантами)

### Р1. Терминология: «Проекты» — сейчас, одна витрина

Открытые вопросы §6.1/§6.2 projects.foundation.md **закрыты решением Валерия**: публичный раздел называется «Проекты» с этого эпика, витрина одна (не два раздела).

- Механика — строго по плану `docs/design/projects.md` §1.3: мини-словарь форм, замена по таблице строк (таб, заголовок каталога, плейсхолдер поиска, «Добавить проект», пустые состояния, страница сущности, профиль автора). Дизайн-фаза (§5) даёт финальные формулировки заголовков — это и есть «продумать заголовки» из запроса.
- **БД и API не переименовываем.** Таблица `models` и пути `/models` остаются — план миграции `models`→`projects` (`apps/api/src/db/migration-plan.models-to-projects.md`) живёт по своим триггерам. UI-словарь отвязан от схемы (ради этого его и строили) — смена термина не трогает данные.
- Отклонённые варианты: (а) *ждать второго живого ремесла* (рекомендация дизайна §1.1) — снято решением владельца; риск «проект = обещание мульти-артефактности» гасим Р2 (мультиформат реально открывается этим же эпиком, обещание перестаёт быть пустым); (б) *переименовать заодно БД/маршруты* — цена и риск без пользы, публичные пути не переименовываем (migration-plan §4).

### Р2. Мультиформат: два класса приёма — «конвейерные» и «артефакты как есть»

Принимаем не-печатные форматы **сейчас**, не дожидаясь конвертеров, честно разделив два класса:

1. **Конвейерные** (3D-печать): STL/OBJ/3MF — как описано в [матрице статуса конвертера](converter.status.md) (канонический 3MF, превью).
2. **Артефакты «хранить и скачивать как есть»** (новый класс): STEP (`.step`/`.stp`), чертежи/раскрой DXF/SVG, программы ЧПУ (G-code/NC), Gerber-наборы, архивы кода. Загружаются в соответствующие роли `model_files` (реестр MF-482: `cnc_program`, `drawing`, `gerber`, `code_archive`; STEP — роль `source` без конвейера либо `aux` — точную роль фиксирует Data/Mesh в фазе 1), хранятся и отдаются как есть. В UI — честная маркировка «скачать как есть», без «Открыть во вьюере» и без обещаний конвертации ([marketplace.md](marketplace.md) §1.6, честный UI).

Следствия:

- Правило «наличие роли в check ≠ пункт в UI загрузки» (projects.foundation.md §2 п.4) **дополняется**: пункт в UI загрузки появляется, но с классом «артефакт как есть». Обещания конвейера по-прежнему нет.
- Whitelist и magic-байты [formats.policy.md](formats.policy.md) **расширяются** (владелец — Mesh): сигнатуры STEP (`ISO-10303-21;`), DXF/SVG, эвристики G-code/NC, Gerber; запрет «gcode отклоняем всегда» снимается для роли `cnc_program`. Upload-валидатор `apps/api` одновременно закрывает долг §7 (детект по байтам, таксономия ошибок §6, лимит decompression) — принимать новые форматы поверх валидатора «по расширению» нельзя.
- **STEP-конвейер (BREP-тесселяция, превью) — НЕ в этом эпике.** STEP принимается и скачивается как есть; конвертация отложена в MF-337 (`cascadio`/FreeCAD-headless), см. [матрицу статуса](converter.status.md).
- Появление не-печатных артефактов «зажигает» уже спроектированный спящий UI: craft-бейджи, craft-фильтр, блок «Файлы проекта» по ролям (`docs/design/projects.md` §2–3, реализация — MF-483 + фаза 3 этого эпика).
- Отклонённые варианты: (а) *подождать конвертеров и открывать формат только с вьюером* — противоречит прямому запросу и откладывает «Проекты» на квартал+; (б) *принимать всё без валидации сигнатур* — небезопасно (formats.policy §1.1, §7) и уже признано долгом.

### Р3. Описание — markdown (сырец в БД, безопасный рендер на клиенте)

- **Хранение:** сырой markdown в `models.description` (колонка уже text). Никакого HTML в БД.
- **Рендер:** на клиенте, безопасное GFM-подмножество (заголовки, списки, таблицы, код, ссылки, картинки), **raw HTML вырезается санитайзером всегда**. Выбор библиотеки — за Front по дизайн-спеке; требование безопасности (XSS через описание невозможен) — приёмочное.
- **Картинки описания** — существующая роль `description_image` (MF-9): загрузка через редактор, в markdown — ссылка на файл роли. Внешние картинки-хотлинки — запрещены (приватность/протухание), только свои.
- **Редактор:** textarea + вкладка/панель предпросмотра (не WYSIWYG). Дизайн редактора и типографика рендера — Design, фаза 1.
- **Лимиты** (дефолт, решаем по ходу): описание ≤ 50 КБ, картинок описания ≤ 20.
- Отклонённые варианты: (а) *server-side рендер с кэшем HTML* — лишняя поверхность (санитизация на сервере + кэш-инвалидация) без выигрыша на нашем масштабе; (б) *rich-text/WYSIWYG-редактор* — дорого и против «строго по спекам» MVP; markdown — родной формат аудитории (те же люди пишут README).
- AI-слой: нейропоиск индексирует описание с очисткой от разметки (не эмбеддить синтаксис) — карточка AI в фазе 3.

### Р4. GitVerse: поле-ссылка `repo_url` — фундамент, не интеграция

«Заложить интеграцию» трактую как фундамент без глубокой связки (договорённость с GitVerse не закрыта — domain.model.md § Решённые, п.3):

- **Схема:** `models.repo_url text nullable` (валидация: https-URL). Нейтральное имя — принимает любой git-хостинг; GitVerse — первый класс на уровне UI (иконка/подпись), не схемы. Это **обновляет** прежнее «в схему не тянуть»: разрешено одно поле-ссылка, по-прежнему никаких OAuth-таблиц/токенов/синка.
- **UI:** строка-источник «репозиторий» в блоке «Код» — ровно в зарезервированное место `docs/design/projects.md` §4.2 (глиф + имя репо + «Открыть»). Задаётся в редакторе проекта.
- **Вне эпика:** OAuth-связка аккаунтов, пуш конфигов на GitVerse юзера, импорт репо, автосинк описания из README. Это отдельный эпик, когда договорённость закрыта.
- Отклонённые варианты: (а) *ничего не добавлять, ждать договорённости* — не отвечает «заложить»; (б) *полная интеграция сейчас* — нет договорённости, нет API-контракта, риск переделки.
- Docs при закрытии эпика сверяет `domain.model.md` § Решённые п.3 и `docs/design/projects.md` §4 с этим решением.

### Р5. Схема карточки — вердикт MF-9 обязателен, конфликтные постановки привести

Никаких `projects`/`project_files`/`project_models` — вердикт [model.card.editor.md](model.card.editor.md) (вариант B) в силе и обязателен для всех фаз этого эпика. **Постановки MF-342 и MF-495 противоречат вердикту** (написаны через `project_*`-таблицы) — Lead приводит их к варианту B (переписать или отменить как дубли) **до** старта Data-работ, чтобы не уехала параллельная схема.
