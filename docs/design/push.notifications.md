# Тумблеры пуш-уведомлений в ЛК + iOS-деградация

← [docs/design/readme.md](readme.md) · моушен-токены — [motion.md](motion.md) · звук — [sound.md](sound.md) · прецедент того же принципа (логика без UI) — `pwa/install.ts`

Спека для **[MF-434](https://tasks.3mf.tech) Фаза 3, шаг 2** (эпик MF-42 «Мобильный клиент/PWA»). Бэкенд-контракт и фронт-клиент готовы (`apps/web/src/push/push.ts`, коммит `b35ad5b`): подписка/отписка/preferences/молчаливая реподписка — вся логика уже есть, юзеру просто нечем её включить. Эта спека закрывает ровно то, чего не хватает: видимые тумблеры в ЛК и три деградационных состояния.

## 0. Где это живёт

Экран — свой профиль (`market/profile.tsx`, `ProfileScreen` с `own === true`). Новый блок **`PushSettingsSection`** — четвёртая секция страницы, **последняя**, под «Мои идеи» (`.ideasSection`): карточка автора → «Добавить проект» → галерея → «Мои идеи» → **«Уведомления»**. Не выше — это настройки, не контент, они не должны спорить за внимание с primary-CTA «Добавить проект» (readme.md §Философия п.2, «одна главная мысль на экран») и с галереей (то, ради чего юзер обычно открывает свой профиль). Отдельная вкладка/роут не нужна — `router.ts` не знает отдельного экрана настроек ЛК (тот же вывод, что уже сделан для отзыва cookie-согласия, [consent.md §3](consent.md)), заводить его ради одного блока — избыточно для этой карточки.

Секция гейтится по тому же `own`, что «Мои идеи», — уведомления только свои, у чужого профиля блока нет вообще.

## 1. Какое состояние показывается — порядок проверок

Четыре ветки, проверяются по порядку, рендерится ровно одна (или ничего):

1. **VAPID ещё не загружен** (`fetchVapidPublicKey()` не ответил) — секция не рендерится вообще (не скелетон: это нижний необязательный блок страницы, не первичный контент, скелетон здесь — лишний шум при каждом заходе в профиль).
2. **VAPID `null`** (окружение не сконфигурировано, `apps/api/src/push/vapid.ts` no-op) — секция **не рендерится**, без сообщения об ошибке. Это подтверждение из тела карточки: нет ключей на этом окружении — юзеру нечего чинить, показывать «ошибку» за то, что Ops ещё не завёл ключи, вводит в заблуждение сильнее, чем тихое отсутствие блока.
3. **`isPushSupported() === false`**:
   - если `usePwaInstall().showIosInstructions === true` (iOS Safari, не установлено на «Домой») → показать **§3 iOS-деградация** ниже;
   - иначе (любой другой браузер без Push API, либо iOS уже установлен, но версия ОС всё равно не поддерживает push) → секция **не рендерится**, по той же логике, что п.2: нет действия, которое юзер может предпринять из этого экрана, значит нет и блока. Это тот же принцип «не пустой экран с ошибкой» — просто ничего.
4. **`isPushSupported() === true`** → **§2 обычный блок** с master-тумблером и списком типов.

`usePwaInstall()` уже экспортирован (`pwa/install.ts`) и даёт `showIosInstructions`/`isStandalone` без новой UA-детекции — переиспользуем, не дублируем ветку iOS ещё раз.

## 2. Обычный блок (push поддержан браузером)

Структура — тот же язык, что «Мои идеи»: `Eyebrow` заголовок + список строк, без обёртки в один большой `Card` (components.md, `EmptyState`/`ideaRow` — стеклянные строки сами по себе несут форму).

```
Eyebrow: «Уведомления»

┌─ master-строка ────────────────────────────┐
│ 🔔  Пуш-уведомления                    ⏻   │
│     Ремиксы, лайки, продажи и заказы —      │
│     прямо в браузере                        │
└──────────────────────────────────────────────┘

(если включено) список из 6 строк типов:
┌────────────────────────────────────────────┐
│ 🔀  Ремиксы моих проектов              ⏻   │
│ ❤  Лайки                               ⏻   │
│ 💰  Продажи моделей                    ⏻   │
│ 💬  Комментарии                        ⏻   │
│ 🖨  Статус принтера                    ⏻   │
│ 📦  Новые заказы                       ⏻   │
└────────────────────────────────────────────┘
```

(эмодзи здесь — только чтобы обозначить место иконки в разметке; в реализации — line-иконки 2px stroke без заливки, components.md §Иконки, «эмодзи в интерфейсных иконках — нет»)

### 2.1 Новый примитив — `Switch`

В библиотеке (`ui/ui.tsx`) сегодня нет простого on/off-тумблера общего назначения — только `Chip`/`SelectionTile` (сегмент-выбор, не бинарный переключатель) и висп (`wisp.toggle.md`, явно «не банальный свитч» — собственный виджет только для темы). Здесь нужен именно банальный свитч, и он пригодится ещё раз почти сразу: мьют-тумблер «Звук» в капсуле шапки ([sound.md §0](sound.md)) — тот же примитив. Заводим один раз, не копируем разметку под каждый список настроек (components.md § «Компоненты» — не давать паттерну расползаться в вариации).

- **Форма:** трек 46×28px, `border-radius: 999`, бегунок-кружок 22px с отступом 3px от края трека (ход бегунка ≈18px).
- **Off:** трек `color-mix(in srgb, var(--border) 140%, transparent)` / приглушённая заливка `--surface`, бегунок `--text-dim`.
- **On:** трек — заливка `--accent` (мятная/зелёная, как везде), бегунок белый/светлый с лёгкой тенью.
- **Тап-таргет:** визуальный трек меньше 48px — оборачивается в кликабельный элемент с невидимым паддингом до 48×48px (тот же приём, что `IconButton`).
- **a11y:** `role="switch"`, `aria-checked`, `aria-label` = заголовок строки («Пуш-уведомления», «Лайки», …) — не полагаться на визуальный текст рядом, читалка должна понимать состояние без контекста DOM-порядка.
- **Disabled/pending:** во время ожидания ответа — трек приглушается (`opacity .5`) и не кликабелен, без спиннера поверх (маленький контрол, спиннер визуально шумит сильнее пользы) — конкретика по master/type-строкам ниже, т.к. семантика pending разная.

### 2.2 Master-строка

- Заголовок «Пуш-уведомления» + подпись «Ремиксы, лайки, продажи и заказы — прямо в браузере» (`--text-dim`, 13px, как `.profileCount`/`.ideaRowMeta`).
- Слева — иконка колокольчика (line, 2px stroke), справа — `Switch`.
- **Вся строка кликабельна** (тач-первый принцип, тот же приём, что `.ideaRow`/`ActionCard`) — тап где угодно в строке переключает master, не только по самому свитчу.
- Высота строки ≥48px, паддинг `14px 16px`, `border-radius: var(--ref-radius-lg, 16px)`, `border: 1px solid var(--border)`, фон `color-mix(in srgb, var(--surface) 55%, transparent)` — 1:1 токены `.ideaRow` (`profile.css`), не изобретаем новую подложку для того же визуального веса.

**Инициализация состояния** (при монтировании секции, уже внутри ветки «push поддержан»): быстрый путь — `Notification.permission === "granted"` как первое приближение синхронно; точнее — дождаться `registration.pushManager.getSubscription()` (уже есть внутри `push.ts`, нужно на разрешение экспортнуть тонкий `isSubscribed(): Promise<boolean>`, чтобы секция не дублировала эту логику) и считать состояние по факту существующей подписки — расхождение permission↔подписка возможно (юзер чистил данные сайта), а без этого master после релоада может лгать о состоянии.

**Тап по master, когда выключен:**
1. Строка уходит в pending (см. §2.1) — **без оптимистичного включения**: `subscribeToPush()` может открыть системный permission-prompt браузера, это модальное прерывание, обманывать глаз мгновенным «вкл» перед ним нельзя (в отличие от типов ниже — там нет системного диалога, там оптимизм уместен).
2. Результат `subscribeToPush()`:
   - `"subscribed"` → master → on, сразу подгружается `fetchPushPreferences()` и появляется список 6 строк (stagger не нужен, это settings-список, не лента карточек — motion.md §5 про появление контента здесь неприменим, это единичное открытие блока).
   - `"permission_denied"` → master остаётся off, под строкой появляется **предупреждающая подсказка** (см. §2.4) — не toast, это персистентное состояние браузера, не транзиентная ошибка.
   - `"error"` → master возвращается off, `overlay.toast({title: "Не удалось включить уведомления", sub: "Попробуйте ещё раз"})` — транзиентно, retry тем же тапом.
   - `"unsupported"`/`"no_vapid"` — по спеке §1 эти ветки сюда попасть не должны (гейт секции их уже исключает); если случилась гонка (VAPID пропал между монтированием и тапом) — трактовать как `"error"`, тихо, без отдельной ветки UI.

**Тап по master, когда включён:** оптимистично сразу → off (без системного диалога на отписку — `unsubscribeFromPush()` просто DELETE), список типов схлопывается/скрывается сразу же (не оставляем 6 неактивных серых строк висеть — «меньше слов», readme.md §Философия п.4), `unsubscribeFromPush()` уходит в фон; если вернула `false` — откат master обратно на on + список возвращается + `overlay.toast({title: "Не удалось отключить уведомления"})`.

### 2.3 Строки типов (6 штук, только когда master on)

Список появляется/пропадает вместе с master (см. выше), без отдельного скелетона на первый `fetchPushPreferences()` — та же логика, что список короткий и это не первичный контент экрана.

| `PushType` | Заголовок строки | Иконка (метафора, line 2px) |
|---|---|---|
| `remix` | Ремиксы моих проектов | развилка/два расходящихся штриха (переиспользовать, если такая иконка уже где-то рисуется под «ремикс»; если нет — первая, кто её вводит, дальше переиспользуют) |
| `like` | Лайки | контурное сердце |
| `sale` | Продажи моделей | монета/кошелёк |
| `comment` | Комментарии | «пузырь» речи |
| `printer_status` | Статус принтера | тот же принтер-глиф, что уже нарисован в `market/model.tsx`/`home/firstrun.tsx` (`PrinterIcon`) — не рисуем новую иконку под тот же смысл, components.md §Иконки. **Внимание:** сегодня `PrinterIcon` не экспортирован ни из одного модуля — это две локальные копии в обоих файлах. «Переиспользовать» = поднять глиф в общий `ui/` и переключить на него оба существующих места, а не завести третью копию в `profile.tsx` |
| `new_order` | Новые заказы | контур коробки/пакета (print-on-demand заказ на печать — физический, отличается от `sale`, это цифровая покупка модели) |

- Каждая строка — тот же `.ideaRow`-паттерн, что master (48px, border-radius 16, `--border`, `color-mix(surface 55%)`), без подписи под заголовком (в отличие от master, здесь не нужно — самого заголовка достаточно, шесть строк с подзаголовками растянули бы список).
- **Вся строка кликабельна**, как master.
- **Оптимистичный тап** (голосовалка-паттерн, components.md §Голосовалка): мгновенный визуальный флип `Switch`, затем `setPushPreference(type, enabled)`; ответ не совпал с ожидаемым (`data?.enabled !== enabled`) → откат строки + тихий `overlay.toast({title: "Не сохранилось, попробуйте снова"})`. Никакого pending-приглушения на эту строку — оптимизм именно ради того, чтобы не ждать сетевой round-trip визуально (нет системного диалога, откатить дёшево).
- Начальные значения — из `fetchPushPreferences()` (уже возвращает все `enabled: true` по умолчанию, если бэк ещё не хранил преференс, — не изобретаем свой дефолт на фронте).

### 2.4 Подсказка при `permission_denied`

Тонкая строка под master (не карточка, не toast — простой инлайн-текст с иконкой), тон **warn**, не danger/коралл (это не деструктив пользователя, это заблокированная браузером фича — «требует внимания, не ошибка», [palette.typography.md](palette.typography.md)):

> ⚠ Уведомления заблокированы в браузере. Разрешите их для сайта (иконка замка/ⓘ рядом с адресной строкой) и включите тумблер снова.

- Иконка — предупреждающий треугольник/восклицательный знак, `--accent-warn` (янтарь).
- Текст `--accent-warn` приглушённой яркости (не пульсирует, не критичный алерт — [status.alerts.md](status.alerts.md) «яркость=важность»: это не поломка принтера, тише).
- Показывается, пока `Notification.permission === "denied"` при следующей проверке (не только сразу после тапа — если юзер уже когда-то отклонил разрешение до этой сессии, подсказка видна с первого рендера блока вместо списка типов, вместо пустого off-состояния без объяснения).

## 3. iOS-деградация (Push API недоступен вне home-screen-install)

Вместо master+списка — один текстовый блок, без тумблеров вообще (нечего переключать, показывать disabled-тумблеры, которые никогда не станут кликабельными на этой платформе, — вредный сигнал, «почему не работает»):

> 🔔 **Уведомления в браузере**
> На iPhone/iPad пуши доступны только в приложении, установленном на экран «Домой». Добавьте 3mf.tech: **Поделиться → «На экран Домой»**.

- Та же строчная форма, что §2 (48px+ высота, `--border`/`color-mix(surface 55%)`), но без `Switch` — это информационная строка, не контрол.
- Текст инструкции («Поделиться → На экран Домой») — теперь единственный источник этой формулировки — сама шторка-инструкция установки PWA специфицирована в [pwa.install.md §5](pwa.install.md) (MF-753), тот же шаг 2 копии, не второй текст под тот же жест «добавь на экран Домой».
- Иконка слева — та же, что у master-строки в §2.2 (колокольчик) — визуальная непрерывность, юзер должен узнать «это про то же самое, просто по-другому».
- Никакого CTA-кнопки «Установить» здесь — на iOS программной установки нет (`usePwaInstall().canInstall` всегда `false` на iOS, см. `install.ts`), кнопка бы ничего не делала.

## 4. Motion

Ничего нового не заводим — укладывается в существующую шкалу ([motion.md](motion.md)):

| Что | Токен | Примечание |
|---|---|---|
| Тап по строке (`:active`) | `--dur-tap`/`--dur-press`, `.pressable` | тот же примитив, что везде |
| `Switch` включение/выключение (заливка трека + сдвиг бегунка) | `--dur-toggle`/`--ease-spring` | тот же морф, что [motion.md §7](motion.md) «Тумблер/сегмент-выбор» — `Switch` не новый мотив, он использует существующий |
| Появление/скрытие списка 6 строк при master on/off | `--dur-toggle`/`--ease-spring` (высота+opacity) | короткое, это не `stagger-reveal` ленты (motion.md §5 не подходит — это settings-список, не подгружаемый контент) |
| Pending-приглушение master во время ожидания permission-prompt | `opacity` переход `--dur-tap` | не пульсирует — это не алерт |

`prefers-reduced-motion`: заливка/появление схлопываются как везде (единый источник — motion.md «Reduced-motion»).

## 5. Sound

Переиспользуем палитру тембров ([sound.md §2](sound.md)), новых семейств не заводим:

- **Тап по любой строке/свитчу** (master и типы) — тембр `toggle` (не `tick`) на смену состояния, синхронно с морфом заливки трека — та же формулировка, что уже зафиксирована в [sound.md §3](sound.md) «Тумблер/сегмент-выбор».
- **Появление/скрытие списка типов** при вкл/выкл master — без звука (это следствие тапа по master, который уже прозвучал `toggle`; второй звук на раскрытие списка — дублирование одного действия, sound.md §0 принцип «один жест — один звук»).
- **`permission_denied`-подсказка** появляется — без звука (не жест пользователя в моменте, а асинхронный ответ на permission-prompt, тот же принцип, что «появление контента без звука», motion.md §5/sound.md §0).
- **Успешная подписка/отписка/сохранение преференса** — намеренно без отдельного success-звука сверх `toggle`: это не критичное событие уровня заказа/поломки принтера ([overlay/sound.ts](sound.md#0-разграничение-с-mf-443-важно-не-дублировать-движок), severity-каталог), обычный toggle-тон уже подтверждает действие.

## 6. a11y

- `Switch` — `role="switch"` + `aria-checked` + `aria-label` конкретного заголовка строки (§2.1).
- Список типов — обёрнут в `<fieldset>`/группу с `aria-label="Типы уведомлений"`, чтобы читалка объявляла контекст перед перечислением 6 переключателей.
- Тач-таргет всей строки ≥48px по высоте, `Switch` — минимум 48×48px кликабельной зоны за счёт паддинга (§2.1), даже если визуальный трек компактнее.
- Подсказка `permission_denied` (§2.4) — обычный текст в потоке, не требует отдельной `aria-live` (это не динамически прилетающая ошибка после сабмита формы, состояние стабильно на момент рендера).

## 7. Готово когда (проверяемо)

- В своём профиле (`own === true`) под «Мои идеи» — блок «Уведомления», у чужого профиля блока нет вообще.
- VAPID не сконфигурирован ИЛИ push не поддержан браузером (не-iOS) → блока нет вообще, без сообщения об ошибке.
- iOS Safari вне home-screen-install → вместо тумблеров — инструкция «Поделиться → На экран Домой», без CTA-кнопки.
- Push поддержан, юзер не подписан → master off, тап включает: либо весь список типов появляется (subscribed), либо warn-подсказка про заблокированный браузером пуш (permission_denied), либо тихий retry-toast (error) — без ложного мгновенного «вкл» до ответа браузера.
- Push поддержан, юзер подписан → master on + список из 6 типов, каждый тумблер переключается оптимистично и откатывается при ошибке сохранения.
- Тап по свитчу/строке звучит `toggle`-тембром, отличимым на слух от обычного `tick` (sound.md §2).
- Ни одна строка/тумблер не уже 48px по тач-таргету; `Switch` заведён как переиспользуемый примитив `ui/ui.tsx`, не скопирован inline в `profile.tsx`.
