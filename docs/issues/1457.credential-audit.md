# MF-1457 — аудит утечек credential

Дата: 2026-07-13. Контур: `apps/api` relay credential, только dev-код и тесты.

## Методика

- Проверены ответы `POST /internal/relay/session/open` для неверного/просроченного/отозванного credential.
- Проверены response headers и структурированные application logs; поиск выполнялся по синтетическим маркерам credential и internal token.
- Проверены обработчики исключений и диагностические вызовы `request.log` в `apps/api/src/devices`.
- Production, физический reset, печать и прошивка не выполнялись.

## Результат

Найденные тесты `apps/api/src/devices/relayInternal.test.ts` подтверждают `401` и машинный ответ без credential (`{"error":"invalid_token"}`) для неверного, истёкшего и отозванного значения. Redaction-тест дополнительно проверяет отсутствие синтетических значений в headers и logs; в логах остаются только безопасные поля события (`relay.auth_failed`, `error_code`). Полные credential и производные в проверенных каналах не обнаружены.

Команда:

```text
pnpm --filter @portal/api exec vitest run src/devices/relayInternal.test.ts --reporter=dot
```

Фактический результат: 7 тестов пройдено; 9 DB-зависимых тестов не стартуют из-за окружения — `SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string`. Это блокер воспроизводимого DB evidence, не обнаруженная утечка. Полный SHA отчёта фиксируется в комментарии карточки.
