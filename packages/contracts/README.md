# @portal/contracts — реестр ШВОВ между сервисами

Единственная точка синхронизации распределённой команды. Здесь живут ТОЛЬКО контракты (типы/схемы)
на границах сервисов — **никакой бизнес-логики, никаких зависимостей на `apps/*`**. Полная карта —
[docs/architecture/service.map.md](../../docs/architecture/service.map.md).

## Правило изменения (важно)
Меняешь форму данных на границе → **один PR только в этот пакет**, апрув CTO. После мержа обе стороны
шва (например web и api-домен) адаптируются каждая в своём темпе, не блокируя друг друга. Пока
контракт не тронут — пишешь свой сервис параллельно, ни с кем не синхронизируясь.
Изменения — **аддитивные** (новые опциональные поля), ломающие — только через версию контракта.

## Пять швов
| Папка | Шов | Стороны (продюсер → консюмер) |
|---|---|---|
| `http/` | web ↔ api | владелец api-домена → web |
| `device-protocol/` | relay ↔ device-agent | Relay + Bridge (обе) |
| `jobs/` | api ↔ воркеры (mesh/scout/giga/search) | api-домен → воркер |
| `printer-driver/` | контракт драйвера принтера | Bridge → адаптеры (moonraker/…) |
| `db-rows/` | кросс-доменное ЧТЕНИЕ строк БД | владелец таблицы → читатели |

Каждая папка — свой README с текущим состоянием и владельцами обеих сторон.
