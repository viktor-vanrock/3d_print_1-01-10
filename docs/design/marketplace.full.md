## 1. Навигация и маршруты (эволюция GAP-NAV)

Скелет ввёл переключатель `Дом ⇄ Маркетплейс` состоянием на уровне `App` (`section: "home" | "market"`, без URL-роутера — [marketplace.md](marketplace.md) §1). Полный маркет добавляет **два новых экрана**, у которых должен быть свой адрес (шаринг ссылки на модель — базовое ожидание маркетплейса):

- **Каталог** — `#/market` (текущий экран, эволюционирует, §2–3).
- **Страница модели** — `#/market/model/:id` (§5, новый).
- **Профиль автора** — `#/u/:username` (§7, новый).

**Решение (GAP-NAV-2):** скелетного `useState<Section>` уже не хватает — нужны параметризованные маршруты и кнопка «назад»/deep-link. **Предложение:** ввести лёгкий хэш-роутер (парсинг `location.hash` → `{screen, params}` + `hashchange`-listener; ~30 строк, без react-router — соответствует «полноценный роутер — отдельная задача, не блокирует» из скелета). Переходы между экранами — по [motion.md](motion.md) (section-fade), карточка модели открывается «reveal» из плитки каталога. Табы `Дом · Маркетплейс` у капсулы остаются как есть; на странице модели/профиля слева от часов появляется круглая `IconButton` «←» (паттерн шапки, [header.capsule.md](header.capsule.md) § «слева»).

Правило «один primary-CTA на экран» сохраняется на каждом маршруте (каталог → «Добавить»; страница модели → «Скачать 3MF»; профиль → «Добавить модель», если это свой профиль).

## 2. Каталог моделей (эволюция галереи)

Текущий экран `MarketplaceScreen` рендерит `.homeGallery` из плиток `ModelTile`. Достраиваем **панель управления** (сортировка + фильтр тегов) над сеткой и **обогащаем карточку**.

### 2.1 Раскладка экрана (сверху вниз)

1. **Шапка** (`HomeHeader`, табы + капсула) — без изменений.
2. **Интро-блок** `.marketIntro`: `Eyebrow` «Маркетплейс» + `StatusPill tone="warn"` «ЭКСПЕРИМЕНТАЛЬНО» (уже есть). Одноразовая плашка-объяснение (`marketplace_experimental` в `home_dismissed_prompts`) — уже есть, остаётся.
3. **Заголовок** — двухтоновый `Heading`: «**Маркетплейс** моделей» (акцентное слово мятным). `size="hero"` на десктопе, схлопывается по `clamp` на мобиле (уже в `.uiHeading`).
4. **Панель управления** (`.marketControls`, НОВОЕ — §2.2): ряд из сортировки + фильтра тегов + primary «Добавить».
5. **Сетка** `.homeGallery` (4→3→2 колонки — уже адаптивна) из обогащённых карточек (§2.3).
6. **Хвост пагинации** (§2.5): кнопка «Показать ещё» / скелетоны / «это все модели».

### 2.2 Панель управления (сортировка + фильтр)

Один горизонтальный ряд (`flex`, `wrap` на мобиле), собран из `Chip`:

- **Сортировка** — сегмент из 2 `Chip` (`data-selected` = активная): **«Новые»** (default, `created_at desc` — уже так в API) · **«Популярные»** (по числу голосов/скачиваний — GAP-API §9; до появления метрик кнопка присутствует, но помечена «скоро» и не активна, `disabled`-состояние `Chip`). Это выбор, не действие → не считается primary-CTA.
- **Фильтр по тегам** — ряд `Chip` с тегами (мульти-выбор, выбранный = зелёный). Источник тегов — популярные теги из `GET /tags` (GAP-API). Пока тегов в БД нет — весь блок фильтра **скрыт** (не показываем пустой ряд), появляется, когда `tags` заведены и у моделей есть теги. При активных фильтрах — маленькая `IconButton` «×» «сбросить фильтры» в конце ряда.
- **Primary «Добавить модель»** — `ActionCard variant="primary"` (уже есть в `.marketAddAction`). На широком экране — правый край панели; на узком — отдельной строкой под фильтрами (полная ширина). Единственный зелёный CTA каталога.

**Правило анти-перегруза:** сортировка + фильтр — приглушённые (нейтральное стекло), primary — единственный зелёный. Порядок чтения: заголовок → «чем управляю» (тускло) → «что делаю» (ярко) → контент.

### 2.3 Анатомия карточки каталога (обогащённая `ModelTile`)

Текущая плитка = превью-стек + название + `@username` + статус-пилюля. Достраиваем мету скачиваний/голосов/даты. Сверху вниз внутри `.homeModelTile`:

1. **Превью** — `.homeModelThumb` (слоёный псевдо-3D, [model.preview.md](model.preview.md)). **Хук под будущий рендер:** сейчас — line-глиф куба (`CubeIcon`) в том же стеке; когда появятся webp-превью (Фаза 3, MF-8) — вставляются в `.homeModelLayerFront`/`Back` **без изменения вёрстки** (стек уже готов принять `<img>`). Для `pending/processing/failed` рендера нет → плейсхолдер-глиф + статусная наложка.
2. **Название** — `.homeModelName` (Unbounded medium), `title` модели, обрезка в 1–2 строки (`line-clamp`, GAP-CSS — мелкая, §9).
3. **Автор** — `.homeModelSub`, `@username`, **кликабелен → профиль автора** (§7). На карточке — просто подчёркнутая ссылка-текст (тап уводит в `#/u/:username`, не открывая модель).
4. **Строка меты** (`.marketTileMeta`, НОВОЕ) — приглушённо, мелким, в один ряд: **голоса** (▲ N, если есть; при 0 — не показываем), **скачивания** (↓ N, семантика «сколько взяли», не лайк), **дата** (относительная: «3 дня назад»). Метрики — только `ready`-модели; иконки — line-глифы (не эмодзи, [components.md](components.md)). Числа — приглушённые (`--text-dim`), «яркость=важность»: это фон, не действие.
5. **Статус обработки** — `StatusPill` (уже есть, §6). Для `ready` пилюля скрыта (норма приглушена); для своих `pending/processing/failed` — видна (владельцу важно).
6. **Свой значок** (владельцу) — если `owner.id === me`, в углу превью маленькая `StatusPill tone="dim"` «Ваша» ИЛИ (лучше) убираем визуальный шум и полагаемся на видимый не-`ready` статус; для `ready`-своих — тонкая мятная обводка плитки (`data-mine`). Точное решение — на реализацию, главное чтобы владелец находил свои модели в общей ленте.

Клик по карточке (не по автору) → **страница модели** `#/market/model/:id` (§5).

### 2.4 Пустое состояние и скелетоны

- **Пусто** (`models.length === 0`) — `EmptyState` (уже есть): куб-глиф, «Здесь появятся ваши модели», подпись про STL/STEP/3MF, action = та же primary «Добавить». Это пассивный обучающий слой №1.
- **Загрузка** (`models === null`, первый фетч) — **скелетоны плиток** (GAP-CSS §9): N штук `.homeModelTile` с shimmer-заглушкой вместо контента (мягкое «дыхание» градиента, `prefers-reduced-motion` → статичный приглушённый блок). Сейчас код рендерит `null` при загрузке — заменить на скелетон-сетку, чтобы не было «прыжка» раскладки.
- **Ошибка загрузки** — `.marketLoadError` «Не удалось загрузить галерею. Проверьте связь.» (уже есть), тон danger.

### 2.5 Пагинация / бесконечная лента (решение)

API уже отдаёт `has_more` + `limit`/`offset` — инфраструктура готова. **Решение: «Показать ещё» (кнопка-догрузка), НЕ авто-infinite-scroll.**

Обоснование: (а) тач-киоск/мобайл — авто-подгрузка при скролле конфликтует с «контент по центру, фикс-хром — overlay» и мешает дотянуться до футера; (б) явная кнопка = явный тап-таргет ≥48px, предсказуемо; (в) реализуется поверх текущего `listModels({limit, offset})` без нового API. Паттерн:

- Первый экран — `limit` 24 (дефолт API). При `has_more` — под сеткой кнопка **«Показать ещё»** (`ActionCard variant="secondary"` или широкий `Chip`, ≥48px), тап → фетч следующего `offset`, аппенд к списку, каскад-появление новых плиток (stagger уже в CSS).
- Пока летит догрузка — на кнопке индетерминантный `ProgressBar` (GAP-PROGRESS) или строка «Загружаем…».
- Когда `has_more === false` — кнопку скрыть, показать приглушённую строку «Это все модели» (не алерт, просто конец).

*(Опционально позже — автоподгрузка по `IntersectionObserver` как прогрессивное улучшение поверх той же кнопки; не в этой итерации.)*

## 3. Флоу «Добавить» и «Редактировать» (эволюция модалки)

Скелетный `AddModelFlow` (дропзона → название/описание → прогресс) **остаётся как есть** для загрузки. Полный маркет добавляет **теги** при загрузке и **редактирование/удаление** после.

### 3.1 Добавление — что достраиваем к текущей модалке

Текущие поля: файл (дропзона), «Название» (обяз.), «Описание» (необяз.). Добавляем:

- **«Теги»** (необязательное, НОВОЕ) — под описанием. Ввод тегов: поле + чип-список выбранных (`Chip` с «×»), автодополнение из существующих тегов (`GET /tags?q=`, GAP-API). Каждый тег ≥48px, добавление по Enter/тапу подсказки. Лимит (напр. 8 тегов) — на реализацию. Пока сущности `tags` нет — блок скрыт (как фильтр §2.2), появляется вместе с тегами в БД.

Кнопки «Отмена»/«Загрузить», прогресс-бар, тексты ошибок §3.4 [marketplace.md](marketplace.md) — без изменений.

### 3.2 Редактирование своей модели (НОВОЕ)

Точка входа — только у владельца: на **странице модели** (§5) кнопка «Редактировать» (secondary), и/или в карточке каталога через `⋯`-меню (`IconButton` → `sheet` с «Редактировать»/«Удалить»). Открывается **той же модалкой**, что «Добавить», но:

- Заголовок модалки — «Редактировать модель».
- Файл **не меняется** (замена исходника = перезагрузка/новая модель — вне итерации): зона файла скрыта или показывает read-only имя исходника + формат.
- Поля «Название»/«Описание»/«Теги» — **предзаполнены** текущими значениями, редактируемы.
- Кнопка primary — «Сохранить» вместо «Загрузить». Отправка — `PATCH /models/:id` (GAP-API §9), без загрузки файла → без прогресс-бара.
- Успех — `toast({ severity: "success", title: "Изменения сохранены" })`, модалка закрывается, карточка/страница обновляются оптимистично.

### 3.3 Удаление своей модели (НОВОЕ, деструктив)

- Точка входа — кнопка «Удалить» в `⋯`-меню карточки и на странице модели (владельцу). **Всегда коралловая** (деструктив никогда не зелёный, [palette.typography.md](palette.typography.md)).
- **Подтверждение — обязательно, через `confirm`** слоя всплывашек: `overlay.confirm({ severity: "critical", destructive: true, title: "Удалить модель?", message: "«{название}» и её файлы будут удалены безвозвратно. Это действие нельзя отменить.", confirmLabel: "Удалить", cancelLabel: "Отмена" })`. `destructive: true` → красная кнопка подтверждения (уже поддержано в `ConfirmOptions`).
- При подтверждении — `DELETE /models/:id` (GAP-API §9), оптимистично убрать карточку из списка, `toast({ severity: "info", title: "Модель удалена" })`. Ошибка → `toast` critical «Не удалось удалить. Попробуйте снова.» с «Повторить».
- На странице модели после удаления — редирект в каталог (`#/market`).

## 5. Страница модели (НОВЫЙ маршрут `#/market/model/:id`)

Полноэкранный экран одной модели. Композиция — по [layout.md](layout.md) (контент по центру, `max-width`, симметричные поля ~80px десктоп / `clamp` мобайл; фикс-хром сверху). Двухколоночная на широком экране, одноколоночная на мобиле (§8).

### 5.1 Раскладка (десктоп: две колонки)

**Шапка:** `HomeHeader` + круглая `IconButton` «←» слева (назад в каталог/профиль).

**Левая колонка — зона превью (герой):**
- Крупный псевдо-3D стек `.homeModelThumb` (тот же слоёный, увеличенный; float/shadow-анимации, `prefers-reduced-motion` off). Хук под webp-рендер Фазы 3 — тот же, что в каталоге. Для `pending/processing/failed` — плейсхолдер-глиф + крупная статусная наложка (§6).
- Под превью (позже, вне итерации) — лента `makes` (фото готовых изделий, `docs/epics/domain.model.md`); сейчас — не показываем, место зарезервировано.

**Правая колонка — мета и действия:**
1. `Eyebrow` — формат исходника (напр. «STL → 3MF») + статус-пилюля, если не `ready`.
2. **Название** — `Heading size="md"` (Unbounded), `title`.
3. **Автор** — строка «by @username» с мини-аватаром (персонаж, [avatar.md](avatar.md), 36px, без кольца) → ссылка в профиль (§7).
4. **Голосование up/down** (НОВОЕ, §5.2).
5. **Кнопка «Скачать 3MF»** (§5.3) — единственный зелёный primary страницы.
6. **Полное описание** — `description` (многострочный, сохраняем переводы строк; пусто → «Автор не добавил описание» приглушённо).
7. **Теги** — ряд `Chip` (не-выбранные, приглушённые), тап по тегу → каталог с этим фильтром (`#/market?tag=…`). Пусто → блок скрыт.
8. **Тех.метаданные** (`.marketModelSpecs`, НОВОЕ) — таблица «ключ · значение», приглушённо:

   | Поле | Источник | Пример |
   |---|---|---|
   | Формат исходника | `source_format` | STL |
   | Габариты (bbox) | `models.bbox` jsonb | 82 × 40 × 15 мм |
   | Размер файла | `model_files.size_bytes` (source) | 4.2 МБ |
   | Загружено | `created_at` | 5 июля 2026 |

   bbox/размер сейчас не в контракте `GET /models` — приходят через `GET /models/:id` (GAP-API §9); пока поле пусто — строку скрываем (не «—»).
9. **Действия владельца** — если это моя модель: «Редактировать» (secondary) + «Удалить» (коралловая) — §3.2/3.3. Не-владельцу не показываются.

### 5.2 Голосование up/down (НОВОЕ)

Решение Валерия — Reddit-стрелки вверх/вниз (`docs/epics/domain.model.md` § votes: `value ±1`, `unique(user_id, subject)`).

- **Форма:** пара круглых `IconButton` (▲ / ▼) + число между ними (сумма голосов). Активный мой голос — акцентная заливка соответствующей стрелки (▲ зелёная при up; ▼ коралловая при down — деструктивная семантика цвета уместна, но БЕЗ пульса, это не срочность). Тап по активной стрелке — снятие голоса (toggle).
- **Оптимистично:** число меняется сразу, откат при ошибке API (`POST /models/:id/vote {value: 1|-1|0}`, GAP-API §9).
- **Гость/не-залогинен (MF-831/MF-850 — публичное чтение, `AuthGate` снят с публичных роутов):** стрелки и число голосов видны как есть, тап доступен. Тап по стрелке гостем не шлёт `POST /models/:id/vote` — открывает overlay-промпт входа (тот же паттерн — [feed.md §3](feed.md)), голос применяется сам после логина, повторный тап не нужен. Правило «один primary на экран» не нарушается: голоса — не primary-CTA, primary остаётся «Скачать» (гостю — тоже промпт входа, §5.3).
- До появления `votes` в БД — блок голосов скрыт (появляется вместе с сущностью).

### 5.3 Кнопка «Скачать 3MF» и её состояния (НОВОЕ)

Единственный зелёный primary страницы модели. Форма — `ActionCard variant="primary"` или крупная кнопка (текст «Скачать 3MF» + круглая иконка-стрелка-вниз аффорданс, [components.md](components.md)). Сама отдача файла — Фаза 3 (MF-338), но кнопка и её состояния проектируются сейчас:

| Состояние модели | Вид кнопки | Поведение |
|---|---|---|
| `ready` | активная зелёная «Скачать 3MF» | тап → запрос presigned-ссылки (`GET /models/:id/download`, Фаза 3) → скачивание `canonical_3mf` |
| `uploaded`/`pending` | приглушённая, disabled, «В очереди» | не кликается; подпись «Файл готовится» |
| `processing` | приглушённая, disabled, «Конвертация…» | лёгкий шиммер/индетерминантный бар; «Скоро будет готово» |
| `failed` | скрыта (для не-владельца) / у владельца — «Повторить обработку» | владельцу — действие ретрая (Фаза 3); чужую сломанную модель в ленте `ready`-фильтр и так не покажет |

- **До Фазы 3** (нет отдачи файла): кнопка присутствует в `ready`-состоянии, но при тапе — `toast({ severity: "info", title: "Скачивание скоро появится", message: "Отдача 3MF-файлов включится в ближайшем обновлении." })`. Это честное «спроектировано, ещё не подключено» без обмана.
- **Гость (MF-831/MF-850):** кнопка видна в том же виде, что залогиненному (не скрываем, не блёкаем — «Скачать» остаётся primary витрины). Тап гостем не шлёт запрос — открывает overlay-промпт входа; после входа скачивание продолжается само (не «войдите и начните заново»).
- Число скачиваний (§2.3) инкрементится при реальной отдаче (Фаза 3).

### 5.4 Состояния экрана (загрузка / не найдено)

- **Загрузка** (`GET /models/:id` летит) — скелетон страницы (превью-заглушка + серые полосы меты), тот же shimmer-паттерн, что каталог.
- **404 / модель удалена / нет доступа** — `EmptyState`: глиф, «Модель не найдена», подпись «Возможно, её удалили или ссылка устарела.», action = «В каталог» (secondary). Приватности в итерации нет → «нет доступа» = только «чужая не-`ready`» (API её и не отдаст) → трактуем как «не найдено».

## 8. Мобильная версия (обязательна для каталога и страницы модели)

Приложение тач-первое ([layout.md](layout.md) § тач/киоск); большая часть адаптива уже в токенах/CSS. Явные требования:

- «Показать ещё» — кнопка на всю ширину, ≥48px.

**Страница модели:**
- Две колонки → **одна колонка** (стек): превью сверху (полная ширина, тот же псевдо-3D), под ним — название, автор, голоса, **«Скачать 3MF» на всю ширину**, описание, теги, спеки, действия владельца. Порядок = приоритету: герой → что за модель → главное действие → детали.

**Профиль:** блок автора по центру, сетка моделей — та же адаптивная `.homeGallery`.

**Общие тач-правила** (уже в `tokens.css`/`.pressable`): `:active` вместо `:hover`, ≥48px, `touch-action: manipulation`, `-webkit-tap-highlight-color: transparent`. Все новые интерактивы обязаны им следовать. `prefers-reduced-motion` уважается везде (float/shimmer/каскад off).

## 11. Пост-аплоад сценарий владельца (критично, MF-461 п.6)

**Проблема, которую чиним (со слов Валерия, живой прогон):** сейчас `AddModelFlow` по успеху делает `toast` «Модель загружена» + `onUploaded(model)` и **закрывает модалку** (`apps/web/src/market/addmodel.tsx:83`), возвращая пользователя в общую ленту каталога. Ощущение — «добавил модель, а потом просто экран без всего»: нет ни подтверждения «вот твоя модель», ни следующего шага. Загрузка не должна заканчиваться высадкой в чужую ленту.

**Целевой флоу: загрузка → раскрытие → утверждение → готовая страница модели.** Модалка не просто закрывается — она **прорастает** в персональную страницу только что созданной модели.

### 11.1 Момент завершения загрузки («раскрытие карточки»)

Когда `uploadModel` вернул созданную `MarketModel` (сейчас — точка `onUploaded`), вместо мгновенного закрытия:

1. **Финиш прогресса.** Прогресс-бар доезжает до 100% и на ~`240ms` замирает зелёным (доводка индетерминантного в детерминантный `1.0` — тот же `.uiChecklistBarFill`, GAP-PROGRESS §9).
2. **Раскрытие (reveal).** Содержимое модалки заменяется на **компактную карточку новой модели** тем же slide/scale-паттерном, что `homeRise`/`homePop` (`home.css`, `cubic-bezier(0.2,0.7,0.3,1)`, ~`0.4s`): псевдо-3D превью-стек (пока плейсхолдер-глиф, §5) появляется float-ом, под ним — название, статус-пилюля. Это визуальное «вот она, твоя модель» — контент опережать анимацию не должен ([motion.md](motion.md): триггер — `setTimeout`, не rAF).
3. `prefers-reduced-motion` — без reveal-анимации: карточка просто заменяет форму загрузки (кросс-фейд ≤`120ms` или мгновенно).

Экран остаётся **той же всплывашкой** (`overlay.modal`), не уводит в отдельный маршрут до явного действия — владелец в контексте, лента под ним не тронута.

### 11.2 Шаг утверждения (проверить/дозаполнить → «Опубликовать»)

Под раскрытой карточкой — **шаг подтверждения публикации**, а не сразу «готово». Это второй кадр той же модалки:

- **Заголовок кадра:** `Eyebrow` «ШАГ 2 · ПУБЛИКАЦИЯ» + `Heading size="md"` «Проверьте перед публикацией».
- **Поля** — те же `.marketField*`, что при загрузке, **предзаполнены** тем, что ввёл пользователь: «Название» (обяз., уже валидно), «Описание» (необяз.), «Теги» (§3.1, когда сущность есть). Правится тут же — это последний шанс перед публичной лентой.
- **Единственный зелёный primary — «Опубликовать»** (`PrimaryButton` с иконкой-аффордансом). Правило «один зелёный CTA» соблюдено: на кадре утверждения publish — единственный акцент.
- **Вторичное — «Сохранить черновиком»/«Позже»** (secondary, приглушённо): закрыть модалку, модель остаётся в статусе `pending`/непубличная, попадёт в «мои модели» на профиле. (Флаг публичности — GAP-API §9 п.14; до него «Опубликовать» = просто закрыть с переходом на страницу, модель уже видна.)

**Почему отдельный шаг утверждения, а не автопубликация:** файл ушёл на конвертацию, но метаданные (название/описание/теги) — «лицо» модели в ленте; дать владельцу осознанно их подтвердить дешевле, чем потом чинить «я не то написал». Это тот же принцип «одна главная мысль на кадр» ([readme.md](readme.md) §2).

### 11.3 Поведение при `pending`/`processing` на пути публикации

Ключевой нюанс: к моменту, когда владелец жмёт «Опубликовать», **файл почти наверняка ещё `pending`/`processing`** (конвертация в 3MF — асинхронная, Фаза 3 MF-8). Публикация метаданных НЕ ждёт готовности файла:

| Что происходит | Что видит владелец |
|---|---|
| Нажал «Опубликовать», файл ещё `pending` | Модалка закрывается → переход (reveal-переходом §12/motion) на **страницу своей модели** `#/market/model/:id` (§5), где превью — плейсхолдер + статус-пилюля `dim` «В очереди», кнопка «Скачать» disabled «В очереди». Модель уже в его профиле и (после publish) в ленте. |
| Файл перешёл в `processing` | Пилюля `ok`+pulse «Конвертация», лёгкий шиммер превью — **обновляется поллингом** (`/models/:id`, 4с, §6), без перезагрузки страницы. Владелец видит прогресс на своей странице. |
| Файл стал `ready` | Пилюля скрывается, превью-стек «оживает» (webp — Фаза 3), «Скачать 3MF» становится активной зелёной — плавно (fade превью, [motion.md](motion.md) image-fade), без «прыжка». |
| Файл `failed` | Пилюля `danger` «Ошибка» + уже реализованный critical-тост «Не удалось конвертировать» (§6); владельцу — действие «Повторить обработку» (Фаза 3). Публичная видимость сломанной модели — `ready`-фильтр её и так прячет от чужих. |

**Итог пути:** пользователь ни в одной точке не оказывается на «пустом экране» — от финиша загрузки он всегда на *чём-то своём* (карточка в модалке → его страница модели со статусом), а не в анонимной общей ленте. Возврат в каталог — только по явному «←» или «В каталог».

## 12. Интерактивное 3D-превью «покрутить» (MF-461 п.7)

Зона живого 3D на **странице модели** (§5.1, левая колонка-герой). Архитектура принята: рендер **three.js на фронте**, ассет вьюера генерирует mesh-воркер отдельным файлом (`model_files.role='preview'` уже в схеме). Здесь — **UX и состояния вьюера, не пайплайн генерации**.

### 12.1 Место и переход из статичного превью

Псевдо-3D слоёный стек (§5.1, [model.preview.md](model.preview.md)) — это **постер/заглушка** вьюера. Живой three.js-canvas **не грузится сразу** (тяжёлый; тач-киоск, Save-Data): на месте героя сперва статичный псевдо-3D + аффорданс «покрутить» (круглая `IconButton` с глифом-орбитой + подпись, поверх превью). Тап/появление в вьюпорте (`IntersectionObserver`) → инициализация canvas, постер кросс-фейдом уступает место живой сцене ([motion.md](motion.md) image-fade). Это соответствует «анимация/тяжесть — необязательна, не опережает контент» ([readme.md](readme.md) §7).

### 12.2 Взаимодействия

- **Вращение орбитой** — drag (мышь) / one-finger drag (тач). Инерция мягкая, `damping`.
- **Зум** — колесо (десктоп) / **pinch** (тач, two-finger). Пределы min/max, чтобы не потерять модель.
- **Сброс камеры** — круглая `IconButton` «⟲» в углу canvas (≥48px), возврат к дефолтному ракурсу плавным твином (~`0.4s`, та же `cubic-bezier(0.2,0.7,0.3,1)`).
- **Без панорамирования** в этой итерации (лишняя степень свободы на тач-киоске путает; орбита+зум достаточно).
- Тач-правила обязательны: `touch-action: none` **только на самом canvas** (чтобы жест не скроллил страницу), но страница вокруг скроллится нормально; `-webkit-tap-highlight` off.

### 12.3 Состояния вьюера

| Состояние | Что показываем |
|---|---|
| **Постер (до инициализации)** | статичный псевдо-3D стек (§5.1) + аффорданс «покрутить». Дёшево, всегда есть. |
| **Загрузка меша** (fetch `preview`-ассета + парс) | постер остаётся + поверх `.uiSkeleton`-шиммер/спиннер на зоне превью (GAP-CSS §9) + приглушённо «Загружаем 3D…». Индетерминантно (размер меша заранее не знаем). |
| **Готов** | интерактивная сцена; аффорданс «покрутить» скрыт, «⟲ сброс» доступен. Мягкий авто-спин до первого касания (медленный, как float постера) — подсказка «меня можно крутить»; off при `prefers-reduced-motion`. |
| **Модель не готова** (`pending`/`processing`) | вьюер НЕ инициализируем (нет `preview`-ассета) → постер-плейсхолдер + статус-наложка §6 («В очереди»/«Конвертация»+pulse). Когда поллинг (§6) увидит `ready` и появление `preview` в `model_files` — аффорданс «покрутить» становится активным. |
| **Ошибка загрузки меша** (сеть/битый ассет/WebGL упал) | постер остаётся (не пустой экран!) + приглушённая строка «Не удалось загрузить 3D-превью» + `IconButton` «Повторить». Статичное превью и вся мета страницы работают — деградация мягкая. |
| **Fallback слабого устройства** | нет WebGL / `Save-Data` / `prefers-reduced-motion` + слабый GPU-хинт → живой вьюер не предлагаем вовсе: только статичный псевдо-3D постер (он и так «псевдо-3D»). Никакой ошибки — это осознанный fallback, а не сбой. |

### 12.4 Мобильные жесты (сводка)

one-finger drag = орбита; two-finger pinch = зум; двойной тап = сброс камеры (дубль к «⟲»). Все тап-таргеты хрома вьюера ≥48px. На узком экране (§8, одна колонка) вьюер — сверху на всю ширину, фиксированной высоты (напр. `min(70vw, 60vh)`), не «съедает» весь экран так, чтобы мета ушла глубоко под сгиб.

### 12.5 Границы

Проектируем **UX вьюера**. НЕ проектируем: формат `preview`-ассета (glb/draco/размер полигонажа), пайплайн mesh-воркера, освещение сцены three.js — это отдельная карточка Python-агенту (Architect заведёт по фиксации требований). Отсюда — только **контракт к ассету со стороны UX** (GAP-API §9 п.15): один `preview`-файл на модель, самодостаточный для орбитального просмотра, разумный вес под тач-киоск/мобайл.

## 13. Сквозная карта сценария владельца (MF-461 п.8)

Единая карта жизненного цикла своей модели. Каждый переход — с анимацией в терминах системы, пустыми и ошибочными состояниями. Экраны и примитивы — из §1–12 выше (не новые).

```
[Каталог/Профиль]
    │  primary «Добавить модель»  →  modal (section-fade)
    ▼
① ЗАГРУЗКА (§3.1)  — дропзона → название/описание/теги → «Загрузить»
    │  прогресс-бар 0..1 (uiChecklistBar)
    │  ошибки: тип/размер/сеть (тексты §3.4 marketplace.md, RU)
    │  успех  →  reveal (homeRise, ~0.4s)
    ▼
② УТВЕРЖДЕНИЕ (§11.2)  — раскрытая карточка + проверка полей → «Опубликовать»
    │  primary зелёный «Опубликовать» · secondary «Позже/черновик»
    │  файл параллельно pending/processing (§11.3)
    │  publish  →  переход на страницу модели (reveal/section-fade)
    ▼
③ ПРОСМОТР — своя модель (§5 + §12)
    │  статусы pending→processing→ready обновляются поллингом (§6, 4с)
    │  3D-вьюер: постер → «покрутить» → орбита/зум/сброс (§12)
    │  действия владельца: «Редактировать» · «Удалить»
    │
    ├──「Редактировать」→ modal «Редактировать модель» (§3.2)
    │       │  предзаполнено · файл read-only · «Сохранить»
    │       │  успех → toast «Изменения сохранены» + оптимистичное обновление
    │       └──→ ④ ПОВТОРНЫЙ ПРОСМОТР (та же страница, обновлённая мета)
    │
    └──「Удалить」→ confirm (destructive, коралл, §3.3)
            │  «Удалить модель? …безвозвратно»
            │  подтверждено → DELETE → toast «Модель удалена»
            └──→ редирект в [Каталог]  (модель исчезла оптимистично)
```

### 13.1 Таблица переходов, анимаций и краевых состояний

| Переход | Анимация (токены/паттерн) | Пусто / ошибка |
|---|---|---|
| Каталог → модалка загрузки | `overlay.modal` появление (overlay.css) | — |
| Файл выбран → поля | мгновенно | невалидный тип/размер → inline-ошибка RU (§3.4 marketplace.md), primary заблокирован |
| «Загрузить» → прогресс | детерминантный бар 0..1 | сеть/сервер → тост critical + «Повторить», модалка держит введённое |
| Загрузка успешна → карточка | **reveal** `homeRise`/`homePop`, ~`0.4s`, `cubic-bezier(0.2,0.7,0.3,1)` (§11.1) | reduced-motion → кросс-фейд ≤120ms |
| Карточка → шаг «Опубликовать» | тот же кадр модалки, поля fade-in | название пустое (не должно, но) → primary disabled |
| «Опубликовать» → страница модели | закрытие модалки + section-fade на маршрут `#/market/model/:id` | publish-ошибка → тост critical, остаёмся в модалке |
| Страница: pending→processing→ready | поллинг 4с; превью image-fade при `ready`; pulse на `processing` (§6) | `failed` → пилюля danger + critical-тост (уже есть) |
| Постер → 3D-вьюер | кросс-фейд постер→canvas; авто-спин-подсказка (§12) | ошибка меша → постер + «Повторить»; слабое устройство → только постер (§12.3) |
| «Редактировать» → модалка | `overlay.modal`, поля предзаполнены | сохранение-ошибка → тост, модалка держит правки |
| Сохранено → страница | закрытие + оптимистичное обновление меты | — |
| «Удалить» → confirm | `overlay.confirm` (destructive) | отмена → ничего; ошибка → тост critical «Не удалось удалить» + «Повторить» |
| Удалено → каталог | карточка исчезает (fade-out), редирект `#/market` | если удалил с чужой вкладки — 404-состояние страницы (§5.4) для других |

### 13.2 Инварианты сценария (проверяются на приёмке)

1. **Ни одной «пустой высадки».** После загрузки — всегда карточка/своя страница, не анонимная лента (чинит жалобу Валерия).
2. **Один зелёный primary на кадр** на каждом шаге: загрузка→«Загрузить», утверждение→«Опубликовать», страница→«Скачать 3MF» (у чужой) или это не конфликтует с «Редактировать/Удалить» (secondary/коралл).
3. **Деструктив всегда через `confirm` и всегда коралловый**, никогда зелёный ([palette.typography.md](palette.typography.md)).
4. **Статус живёт поллингом**, экран не требует ручного refresh; переходы статусов — плавные (image-fade/pulse), не «прыжок».
5. **Все тексты — RU**; `prefers-reduced-motion` уважается на каждом переходе (reveal/спин/шиммер off).
