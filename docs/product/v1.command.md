## Рамка

**Релиз v1 — 30.09.2026.** Ограниченный пилот личного портала: каталог
принтеров и филаментов, проекты/модели, обсуждения, личный кабинет, CI/CD,
`managed-local` через Moonraker, enroll и агент/relay на пилотных Klipper-моделях,
а также облачный headless-слайсинг в `apps/mesh` с per-account `slice_cache`.
Это решение [MF-1075](mention://issue/7c29c98a-04f5-43c0-8f6d-adbad265dfa2).

В v1 также входят API принтера v0, ключи/скоупы/rate-limit и
`config_fingerprint` как задел доверия. UI принтера, мастера подключения и
пилотная морда следуют Design-спекам: [printer.wizard.md](../design/printer.wizard.md),
[printers.catalog.md](../design/printers.catalog.md), [printer.face.md](../design/printer.face.md),
[printer.page-types.md](../design/printer.page-types.md).

Сознательно deferred: деньги и тяжёлый AI; Bambu/Prusa managed-cloud и другие
мультипротокольные адаптеры; фермы/организации; глобальный слайс-кэш, дедуп и
P2P-обмен; масштаб data-plane на сотни тысяч соединений. Это v2/v3 согласно
[roadmap.md](roadmap.md). Поиск по форме и Кандинский — север V1, полноценная
поставка запланирована на шов v1→v2.

## Порядок исполнения

**data → connector → UI → slice → QA/release**:

1. Data: аддитивные `slice_cache`, `user_api_keys`, `config_fingerprint`, профили и провенанс.
2. Connector: enroll, relay/agent, Moonraker и безопасный `managed-local`.
3. UI: каталог, мастер, парк и страница живого принтера по Design-спекам.
4. Slice: очередь `apps/mesh`, headless Orca/Prusa, per-account артефакт в S3.
5. QA/release: модель→профиль→G-code→принтер на dev, затем ограниченный пилот.

Этапы могут идти параллельно после готовности их контрактов.

## DoD limited pilot

На dev подтверждены схема и контракты; слайсер выдаёт и сохраняет G-code для
модель+профиль; `managed-local` показывает live state через direct GET браузера к Moonraker по LAN
(сервер не proxy и не command/upload path); enroll+агент
дают двустороннюю связь хотя бы на одной пилотной модели; внешний клиент
управляет принтером по API-ключу. P2P не проверяется: в v1 фиксируется только
совместимый фундамент.

Правило доски: **один результат — одна активная карточка**. Декомпозиция и
статусы живут в детях MF-1075.
