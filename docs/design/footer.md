# Подвал сайта + юридические страницы

← [docs/design/readme.md](readme.md) · токены — [palette.typography.md](palette.typography.md) · компоненты — [components.md](components.md) · тач-нав/safe-area — [touch.nav.md](touch.nav.md) · композиция — [layout.md](layout.md)

Спека для [MF-638](https://tasks.3mf.tech), запрос оператора [MF-637](https://tasks.3mf.tech): у портала сегодня нет общего подвала — юр. ссылки (лицензия/приватность/условия), обратная связь и копирайт нигде не стоят. Ниже — минимальный, не декоративный подвал на всех страницах + три черновые юр. страницы под него.

## 1. Зачем и где

Подвал — служебный, не витринный: последний элемент документа, обычный поток (НЕ `position: fixed`, НЕ стекло-оверлей как шапка/bottom-tab — это единственный chrome-элемент, который специально раздвигает контент, а не лежит поверх него). Стоит **на всех страницах** — рендерится в корневом лейауте `app.tsx` один раз, под контентом текущего экрана, экраны сами по себе о нём не знают.

Существующие юр./информационные экраны (главная, каталог, форум, ЛК и т.д.) не меняются — подвал просто добавляется под их существующим контентом.

## 2. Контент подвала

Три блока, слева направо на десктопе (`≥900px`), друг под другом на мобиле:

**Блок А — Юр. ссылки** (обязательный минимум запроса):
- Публичная лицензия → `/legal/license`
- Политика приватности → `/legal/privacy`
- Политика использования → `/legal/terms`
- Обратная связь → `mailto:support@3mf.tech` (дефолт — прямой контакт для юр./приватности вопросов; НЕ ссылка на форум, там это не найдут и не должны искать среди тредов)

**Блок Б — Навигация** (не выдумываем новых разделов, 1:1 с существующей IA, `NAV_ITEMS`/каталог/форум/ЛК):
- Дом → `/`
- Новости → `/feed`
- Принтеры → `/printers`
- Проекты → `/project`
- Форум → `/communities`
- Личный кабинет → `/profile` (если гость — ссылка ведёт на логин, как и везде в проекте; подвал не решает авторизацию по-своему)

**Блок В — Общая информация**:
- Одна строка о портале (черновик): «3mf.tech — портал 3D-печати: модели, принтеры, филаменты, сообщество»
- `© 2026 3mf.tech`
- Версия приложения — читается из `version.json` (`YY.RELEASE.MINOR`, уже есть паттерн в `docs/process/versioning.md`), формат `v26.2.186`. Мелко, приглушённо — это диагностическая деталь для тех, кто её ищет (баг-репорт), не витрина.

## 3. Визуал

Подвал — не карточка и не стекло, а тихая нижняя зона, ниже по яркости всего, что выше (принцип «яркость=важность», readme.md §3: подвал — самое повседневное место на странице).

- Фон — `--surface` (не `--bg`), тонкая верхняя граница `1px solid var(--border)` — та же логика разделения зон, что верх капсулы-шапки, но это низ, а не верх.
- Паддинг — `32px` сверху/снизу на десктопе, `24px` на мобиле, боковые поля — те же, что общий контентный `max-width` (layout.md «контент по центру вьюпорта»).
- Три блока — `display: flex; justify-content: space-between; gap: 32px` на `≥900px`; `flex-direction: column; gap: 20px` ниже — блоки идут друг под другом, каждый занимает всю ширину.
- Типографика — весь текст `--text-dim`, `14px`, обычный (не Unbounded — подвал не бренд-момент, это служебная зона, дисплейный шрифт только у CTA/заголовков по palette.typography.md). Заголовок блока (если нужен, например «Юр. информация») — тем же Eyebrow-паттерном, что везде: uppercase, letter-spacing, ещё тише (`opacity: .66`).
- Ссылки — обычный текст `--text-dim`, `:active` — `opacity: .5` (тач-фидбек, не `:hover` по layout.md). Никакого подчёркивания по умолчанию — список ссылок и так читается списком (вертикальный стек, `8px` между строками на мобиле / `12px` на десктопе).
- Копирайт+версия — самая тихая строка, `12px`, `opacity: .5`, внизу блока В (или под тремя блоками единой строкой на всю ширину на десктопе, если так собраннее вёрстке — на усмотрение Front, это не решает суть спеки).
- Тач-таргет: каждая ссылка — блок минимум `44px` по высоте на мобиле (padding, не сжимать список в одну плотную колонку из-за тесноты — это тот же инвариант ≥48px readme.md §99, чуть смягчён до 44px только здесь, потому что это финальный служебный список, не основной CTA; если можно выдержать 48px без разрастания подвала — держать 48px).

## 4. Мобила / bottom-tab — критично

На `≤640px` внизу уже стоит `position: fixed` `BottomTabBar`, 56px + safe-area (touch.nav.md §1). Подвал — это документ-поток, он рендерится ВЫШЕ таббара в DOM-потоке (обычный конец страницы), но экран уже получает `padding-bottom: calc(56px + env(safe-area-inset-bottom) + 16px)` под таббар (touch.nav.md §1 «Контент под баром») — это правило уже покрывает подвал: он просто последний блок контента перед этим паддингом, ничего дополнительно решать не нужно, но **это надо проверить руками** (webcheck на `≤640px`): подвал не должен визуально «утыкаться» в таббар без зазора и не должен требовать отдельного скролла, чтобы стать видимым (это нормально — подвал внизу длинной страницы, до него скроллят, как обычно).

На PWA/standalone-режиме (без адресной строки браузера) — подвал ничего не перекрывает, потому что это не fixed-элемент; единственная зона конфликта — нижний safe-area таббара, уже решённая выше.

## 5. Юр. страницы `/legal/:slug`

Три страницы, один общий шаблон экрана — не три разных лейаута:

- **Маршрут** — `/legal/license`, `/legal/privacy`, `/legal/terms` (публичные path-роуты, тот же паттерн, что `/project`/`/printers`: nginx отдаёт `index.html`, SPA парсит `pathname` — см. `router.ts`).
- **Композиция** — обычный контентный столбец, `max-width` как у текстовых экранов (форум/страница поста — `feed.post.editor.md` уже решал markdown-типографику рендера, тот же приём здесь: заголовок `H1` + markdown-тело тем же рендерером/стилями, что пост ленты, не изобретаем вторую типографику для длинного текста).
- **Заголовок страницы** — «Публичная лицензия» / «Политика приватности» / «Политика использования», обычный `Heading`.
- **Плашка черновика** — сразу под заголовком, ДО текста: приглушённый, но заметный баннер (тот же характер, что `StatusPill`/`--accent-warn`-тон status.alerts.md — «требует внимания», не декоративная фраза мелким текстом): «Черновая редакция — документ готовится к утверждению оператором. Актуальная версия будет опубликована здесь». Это не alert-с-пульсом (не аварийная ситуация), а именно приглушённо-жёлтая info-плашка, статичная.
- **Тело** — черновой текст (см. §6), обычный markdown-рендер: заголовки разделов, абзацы, списки.
- **Навигация обратно** — как на любой глубокой странице портала: заголовок кликабелен на `/` или системная навигация браузера/таббара уже решает «назад»; подвал самой юр. страницы такой же, как везде (эти страницы не исключение, они тоже подписаны стандартным подвалом снизу — единственная разница у `/legal/*` это баннер-черновик над текстом, не отсутствие подвала).
- **Мобила** — тот же контентный столбец, ужимается по общему контентному max-width правилу, ничего специфичного для этих трёх страниц.

## 6. Черновой текст трёх страниц

Пометка «черновая редакция» уже показана баннером (§5) — сам текст пишем нормальным тоном, без внутренних disclaimer-повторов в каждом абзаце.

## 7. Готово когда

- Подвал виден внизу любой страницы (десктоп + мобила `≤640px`), не перекрыт и не перекрывает `BottomTabBar`.
- Три юр. ссылки + «Обратная связь» + короткое описание + копирайт + версия — все на месте, все живые (ведут на реальные страницы/`mailto:`, не заглушки).
- `/legal/license`, `/legal/privacy`, `/legal/terms` открываются напрямую (deep-link, F5), показывают плашку «черновая редакция», тело читаемо на десктопе и мобиле.
- Ничего не сломало bottom-tab-навигацию PWA (touch.nav.md §4 safe-area всё ещё соблюдён).
