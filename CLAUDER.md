# CLAUDE.md — portal.ru (3mf.tech)

Этот файл ИИ-агенты (Claude Code и др.) читают **автоматически при входе в репозиторий**. Начни отсюда.

## 🚨 ГЛАВНОЕ: вся работа ведётся на доске задач

**Задачи проекта живут на доске `https://tasks.3mf.tech`** (self-hosted Multica), воркспейс **`3mf`**, префикс задач **`MF`** (карточки `MF-1`, `MF-2`, …). Это НЕ GitVerse Issues и НЕ только `issues/*.md` — это отдельная живая доска.

**Работать мимо доски нельзя:**
1. Перед началом — открой доску, найди свою карточку (или заведи новую).
2. Взял в работу → статус `in_progress`; закончил → `done` (плюс `blocked` с причиной).
3. **Любое поручение оператора = карточка на доске со статусом**, а не «тихое» действие. Команда должна видеть, что и как делается.

**Как оперировать доской — читать обязательно:**
- **[docs/process/multica.md](docs/process/multica.md)** — гайд для агентов: режим API/CLI (вести задачи) и режим демона (исполнять задачи на машине). Команды, аутентификация.
- **[docs/process/tasks.multica.md](docs/process/tasks.multica.md)** — правила доски: как оформлять карточки (шаблон/пример), проекты-фазы, категории, добавление пользователей, подключение агентов.
- **[docs/process/squad.multica.md](docs/process/squad.multica.md)** — живой сквад агентов Autofab (CTO → Lead → {Design, Fullstack, Data, PM} → разрабы + пайплайн): иерархия, роли, правила ведения доски.

**Быстрая проверка, что ты подключён к доске:**
```bash
multica issue list --limit 10          # должен показать карточки MF-*
```
Если команды `multica` нет или не авторизован — см. `docs/process/multica.md` § «Аутентификация». Вход CLI — только `multica login --token <PAT>` (браузерный `setup self-host` за PlagID-гейтом не проходит), сервер `https://tasks.3mf.tech`.

**Структура доски:** карточки — крупные (эпики), не сотни мелких. Проекты-фазы: `MVP`(=v1) / `v2` / `v3+ горизонт` / `Платформа-R&D`. Цветные категории-labels. Приоритет = важность. Дорожная карта по фазам и стратегия — в описаниях карточек и в `docs/product/vision.md`/`docs/product/features.md`.

### Первый шаг новичка (агент или человек)

1. Прочитай этот файл и `readme.md`.
2. Получи доступ к доске (см. «Доступы» ниже).
3. Поставь `multica` CLI и войди: `multica login --token <PAT>` (сервер `https://tasks.3mf.tech`) — детали в `docs/process/multica.md` § «Аутентификация».
4. Проверь подключение: `multica issue list --limit 10` — видишь карточки `MF-*` → ты на доске.
5. Возьми карточку: `multica issue update <MF-N> --status in_progress`. Закончил → `--status done`.
6. Делай работу по правилам репо (нейминг, секреты, PR — `CONTRIBUTING.md`). Новое поручение оператора — сразу карточкой на доске.

### Доступы к доске — кто владеет и как получить

- Доступ двухслойный: **PlagID-гейт** (Telegram через `auth.plag.space` — кто вообще войдёт на `tasks.3mf.tech`) + **учётка Multica** в воркспейсе `3mf`.
- Доступами владеет **оператор/владелец проекта** (Валерий, `@plag` на gitverse) — у него админ; выдача и отзыв доступа — только через него.
- **Чтобы получить доступ:** напиши оператору свой Telegram и email. Он: (1) добавит твой Telegram-ID в гейт, (2) добавит email в разрешённые в Multica, (3) пришлёт инвайт в воркспейс `3mf`. Пошаговая механика — `docs/process/tasks.multica.md` § «Как добавить нового пользователя».
- **Для CLI/агента:** после первого входа создай токен в вебе (Settings → Tokens) и `multica login --token <PAT>`; либо оператор выдаёт PAT напрямую. Сам PAT — секрет, в git не коммитить (`SECURITY.md`).

## Как здесь принято работать (обязательные правила)

- **Вся документация — в [docs/](docs/readme.md)** тематическими папками (architecture / infra / design / product / process / epics / issues); `docs/readme.md` — индекс и карта владения. В корне — только community-файлы, которые инструменты ищут по точному пути.
- **Процесс** (ветки/коммиты/PR/задания, эпики vs issues) — **[CONTRIBUTING.md](CONTRIBUTING.md)**.
- **Нейминг:** файлы/папки — lowercase, слова через точку, **без `-` и `_`** (`release.process.md`, не `release-process.md`). Исключения (community-файлы, `CLAUDE.md`/`AGENTS.md`, конфиги инструментов) — в `CONTRIBUTING.md` § «Нейминг».
- **Секреты НЕ коммитятся** — только `.env` локально/на VDS или GitVerse Actions Secrets. См. **[SECURITY.md](SECURITY.md)**.
- **Архитектура** (монорепо web/api/mesh/giga, границы) — **[docs/architecture/readme.md](docs/architecture/readme.md)**. **Инфра** (VDS/деплой/облако) — **[docs/infra/readme.md](docs/infra/readme.md)**.
- **Email/SMTP** (общая инфра для всех сервисов проекта — креды, DNS, доставляемость, как подключить новый сервис) — **[docs/infra/email.md](docs/infra/email.md)**. Читать перед любой работой с отправкой писем.
- **Перед правками `apps/web`** — читать **[docs/design/readme.md](docs/design/readme.md)** (визуальный стиль, тач/киоск-паттерны; главный документ ссылается на мелкие тематические файлы — читать их ситуативно, под конкретную задачу).
- **Версии** `YY.RELEASE.MINOR` — **[docs/process/versioning.md](docs/process/versioning.md)**.

## Доска (Multica) vs `docs/epics/`/`docs/issues/` в git

Не путать, они дополняют друг друга:
- **`docs/epics/` + `docs/issues/`** (в git) — спеки крупных инициатив и их трек-файлы: версионируются, ревьюятся в PR.
- **Доска Multica** (`tasks.3mf.tech`) — операционный статус и повседневная работа; здесь ассистент ведёт то, что делает. Крупная карточка на доске ссылается на `docs/epics/`/`docs/issues/`.

Правила и разграничение — `CONTRIBUTING.md` § «Задания».
