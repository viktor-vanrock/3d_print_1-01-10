# Сервис сборки моделей из фотографий (ветка `scan`)

Живёт не на VDS, а на HYPERPC — плотный этап фотограмметрии это CUDA. Вызывается из
[`branches/scan.py`](../../src/giga/branches/scan.py) по HTTP поверх Tailscale, тем же
приёмом, что ComfyUI.

## Что где

| | |
|---|---|
| каталог | `C:\photogrammetry` |
| COLMAP | `C:\photogrammetry\c311\bin\colmap.exe` (3.11.1, CUDA) |
| окружение | `C:\photogrammetry\venv` (fastapi, uvicorn, python-multipart, trimesh, fast-simplification) |
| автозапуск | задача планировщика `LaunchScanService`, триггер AtLogOn |
| порт | 8190 (8188 — ComfyUI, 8189 — embed-сервис) |
| GPU | 0 (ComfyUI на 2, языковые модели на 1 и 2) |
| лог | `C:\photogrammetry\scan.log` |

`SCAN_SERVICE_URL` в `portal.giga-dev.env` — адрес этого сервиса.

## Грабли, на которые уже наступили (MF-2075)

- **COLMAP 4.1.1 не работает с этим драйвером.** Свежая сборка линкуется с CUDA новее, чем
  позволяет 553.35 (CUDA 12.4), и падает на создании контекста ещё до первого кадра — с
  пустым сообщением. Взята 3.11.1: она везёт `cudart64_12.dll`. Драйвер не поднимаем — на
  нём работают ComfyUI и языковые модели.
- **CUDA недоступна из SSH.** Сеанс SSH на Windows — сеанс 0, видеокарта в нём не видна
  (`nvidia-smi` при этом работает: он ходит через NVML, а не CUDA). Считать может только
  процесс в интерактивном сеансе — там же, где ComfyUI. Отсюда и запуск задачей планировщика,
  а не из SSH напрямую.
- **`--data_type object` не существует** — только `individual`, `video`, `internet`. Мы берём
  `individual`: это полное попарное сопоставление, а при обходе предмета кругом кадр с начала
  и кадр с конца обязаны связаться, иначе круг рвётся.
- **Никаких труб для вывода COLMAP.** С `capture_output=True` задание однажды зависло
  навсегда: сам `colmap.exe` уже исчез, а `subprocess.run` продолжал ждать закрытия трубы.

## Настоящий размер (`scanscale.py`)

Фотограмметрия знает форму с точностью до масштаба. Приложение шлёт вместе с кадрами
`manifest.json` — позиции камеры из ARKit в метрах по серверным именам кадров. После сборки
сервис конвертирует sparse-модель COLMAP в текст, берёт из неё восстановленные центры камер
и делит расстояния: медиана отношений по парам и есть метров-на-единицу-COLMAP. Меш
масштабируется в миллиметры, статус отвечает `"scale": "metric"` — и apps/giga НЕ приводит
такой меш к условным 80 мм.

Проверено синтетикой: позы, спрятанные в чужую систему координат (поворот + сдвиг + деление
на 0.0173), восстанавливаются с ошибкой 0.00%; два грубых выброса медиану не сдвигают; при
меньше чем 8 совпавших кадрах — честный отказ вместо выдуманного размера.

## Конвейер v2 (по следам Polycam и лучших практик COLMAP)

Первые живые съёмки с телефона показали три беды, и все три лечатся до реконструкции:

- **Смаз.** Авто-съёмка снимает в движении, движение в сумерках — это мыло. Отсев по
  дисперсии лапласиана, порог относительный (0.22 медианы). Калибровка на живых кадрах:
  резкие 670–1360, смазанный — 52. Минимум кадров неприкосновенен.
- **Фон.** Фотограмметрия собирает столешницу лучше, чем предмет. rembg (U2-Net, CPU — GPU
  остаётся реконструкции) строит маску предмета на каждый кадр; COLMAP не извлекает фичи по
  чёрному. Тот же приём, что «Object Masking» у Polycam. Маскам можно не доверять: при
  неправдоподобной медианной доле предмета (<4% или >60% кадра) работаем без них.
- **Сотня кадров.** Полное попарное сопоставление растёт квадратом. До 80 кадров — попарное
  (круг обязан замкнуться), больше — последовательное со словарём признаков
  (`vocab_tree_flickr100K_words32K.bin`): кадры идут в порядке обхода, словарь замыкает круг.

**Честный таймер.** `stats.json` копит длительности реальных прогонов; оценка — медиана
секунд-на-кадр плюс медиана накладных. `/jobs/{id}` отдаёт `elapsed`/`expected`, ветка scan
транслирует их в progress/eta — таймер в приложении показывает реальную скорость, а не
константу.
