# Properties доски v1

> Статус: действующий контракт. Введён 2026-07-15 с Multica 0.4.2.

Properties — короткие, типизированные сигналы маршрутизации. Они не заменяют
description, acceptance, labels, dependencies, stage и динамические metadata.
Если поле не может быть выбрано без догадки, его оставляют пустым.

## Единственный набор

| Property | Владелец | Значения | Для чего |
| --- | --- | --- | --- |
| `Тип результата` | профильный лид при создании или декомпозиции | `Код в dev`, `Код в UltraPrint dev`, `Дизайн-спека`, `Контракт или данные`, `Устройство / LAN evidence`, `Инфраструктура`, `Только документация` | заранее делает финал карточки однозначным |
| `Целевая среда` | профильный лид до назначения | `Dev VDS`, `Release Worker`, `Mac / LAN`, `Dev VDS + Mac / LAN`, `Среда не требуется` | не отправляет работу в неверный runtime |
| `Критический путь v1` | только Headquarters/CTO | checkbox | отмечает обязательную текущую зависимость v1; не равен `urgent` |

Labels уже выражают домен (`дизайн`, `устройства`, `платформа` и т.д.), поэтому
новый Property «направление» запрещён. URL, SHA, ожидание и состояние пайплайна
остаются соответственно в `deploy_url`, `pipeline_status`, `waiting_on` и
`decision` metadata; их не дублируют в Properties.

## Приёмка по типу результата

- `Код в dev`: непустой MF-коммит в `portal.ru:origin/dev`, нужные проверки и
  наблюдаемый результат на `https://dev.3mf.tech` (или честно отделённый
  server-side seam).
- `Код в UltraPrint dev`: непустой MF-коммит в `UltraPrint:origin/dev`,
  contract/simulator-проверки и hardware evidence только там, где заявлена
  поддержка; связанный server/UI seam живёт отдельной portal-карточкой.
- `Дизайн-спека`: обновлён reusable канон в `docs/design/`, states и
  acceptance, плюс переданная реализационная карточка Autofab.
- `Контракт или данные`: версия контракта, fixture/provenance и независимая
  проверка схемы/данных.
- `Устройство / LAN evidence`: санитизированное воспроизводимое наблюдение
  exact model/protocol/state/recovery; отсутствие доступа — `blocked`, а не
  выдуманный успех.
- `Инфраструктура`: health, rollback и доказательство безопасного изменения.
- `Только документация`: ссылка на ревизию и документы-основания; не выдаётся
  за web delivery.

## Поведение сквадов

Headquarters выставляет Properties у direction/эпика, когда решение уже
однозначно. Если эпик объединяет несколько результатов или сред, `Тип
результата` и `Целевая среда` на нём остаются пустыми: их уточняют у дочерних
карточек. Флаг `Критический путь v1` может жить на эпике как портфельный
ориентир, но должен быть также на текущем конкретном шве. Исполнитель читает
значения как маршрут, не пересказывает их и не меняет definitions. Менять
`Критический путь v1` может лишь CTO/Headquarters; его снимают после закрытия
реального разрыва.

Показывать в списках и на карточках стоит только `Тип результата` и
`Критический путь v1`; `Целевая среда` нужна в sidebar и фильтре планирования.
Рабочая доска остаётся сгруппированной по status. Временные views:

1. `Критический путь`: checkbox=true — CTO, Project и Lead.
2. `Mac / LAN`: целевая среда — для Polygon и задач с реальным принтером.
3. `По типу результата`: только для планирования/декомпозиции, не для
   ежедневного исполнения.
