# Визуал страницы поста `/feed/p/:id` и редактора `/feed/new`

← [docs/design/readme.md](readme.md) · лента `/feed` (три колонки, карточка в списке, голосование) —
отдельная спека [feed.md](feed.md) (MF-814) · сценарий/поток — **UX**, [docs/epics/feed.page.md](../epics/feed.page.md)
§4 (открытие поста), §5 (голосование), §8 (создание/редактирование), §9 (крайние случаи) ·
конвенция роут-vs-модалка — [overlay.system.md](../epics/overlay.system.md) · компонент голоса —
[community.md §7.4 `VoteArrows`](community.md) · редактор тела — блочный
`apps/web/src/feed/blockeditor.tsx` (`FeedBlockEditor`).

**Что это.** Одевает две страницы, которые UX (MF-807) закрепил как **отдельные роуты, не
модалки**: открытие поста во весь экран и создание/редактирование. Поток и развилки уже решены
в `feed.page.md` — эта спека не переизобретает их, только визуал. Ничего нового в палитре/
типографике не вводит — только компоновка, два новых переиспользуемых компонента (§7) и
расширение уже принятого `VoteArrows` на новый `subjectType`.

## 0. Маршруты и режим шапки

Обе страницы — `headerMode: 'light'` (та же логика, что страница модели `/project/:id`,
[projects.page.md §1.2](projects.page.md): «парящая»/детальная композиция со своей `←`, не
wide-листинг). Путь строится тем же приёмом, что `router.ts` уже делает для модели
(`modelPath`/`addModelPath`) — Front заводит `feedPostPath(id)` → `/feed/p/:id` и
`feedNewPath()` → `/feed/new` по образцу.

| Маршрут | `headerMode` | `onBack` |
|---|---|---|
| `/feed/p/:id` (из ленты) | `light` | `←` возвращает **в ленту на ту же карточку**, не грузит `/feed` заново (§1.1) |
| `/feed/p/:id` (cold start — пуш/прямая ссылка) | `light` | нет истории → кнопка читается **«← В ленту»**, ведёт на `/feed` (§1.1) |
| `/feed/new` | `light` | `←` = «Отмена»: черновик уже в `localStorage` (§3.8), потерять нечего — уходим без `confirm()` |

## 1. Страница поста `/feed/p/:id`

### 1.1 Два входа — одна вёрстка, разный `onBack`

Решение уже принято UX (`feed.page.md` §4) — здесь фиксируется **только визуальная разница**,
она в одном месте: подписи и поведении кнопки `←` в шапке.

- **Из ленты.** `navigate()` (не `navigateWithTransition` full reload — SPA push, лента остаётся
  смонтированной под постом). `IconButton` `←` без подписи (тот же паттерн, что везде в `light`).
  Тап → `window.history.back()`-эквивалент, лента не перезагружается, скролл/курсор на месте.
  Возврат в ленту метит прочитанный пост приглушённым заголовком (это лента красит, не эта
  страница — но геометрия заголовка карточки должна поддерживать `data-read` модификатор,
  координация с [feed.md](feed.md)).
- **Cold start (пуш/прямая ссылка/шаринг).** Ленты под постом нет. `IconButton` с текстом
  **«← В ленту»** (шире тап-таргета, есть подпись — редкий случай, когда `IconButton` носит
  текст, как «← Назад» на странице сообщества [community.md §2.1](community.md)). Ведёт на
  `/feed` с дефолтным скоупом (§6 `feed.page.md`), не имитирует историю, которой не было.
- Определение входа — чисто клиентское: `history.state`/маркер, что попал на `/feed/p/:id`
  через `navigate()` из ленты, а не через прямой заход/`popstate` от внешнего URL. Технический
  выбор (реализация), дизайн фиксирует только два визуальных состояния кнопки.

### 1.2 Вертикальная композиция (десктоп)

Одна колонка, `max-width` как читающий контент (~720px — чуть шире карточки ленты 680px,
markdown длинного чтения дышит), центрирована в контейнере страницы (не «парящая» вдвуколонка
модели — пост это текст+обсуждение, не 3D-герой).

```
  ←  (или «← В ленту»)

  BambuFan · @nick · 3 часа назад                              [Изменено]  ← eyebrow-строка (§1.3)
  Почему профиль PLA плывёт на второй пластине?                            ← Heading, юзер-текст
                                                                              (без принудительного
                                                                              акцентного слова)

  ┌ ▲ ─┐
  │ 12 │                                                                    ← VoteArrows large (§1.5)
  └ ▼ ─┘

  <тело поста по типу — §1.4>

  ─────────────────────────────────────────────────────────────
  3 комментария                                          [Ответить]        ← §1.6
  ┌ композер комментария ─────────────────────────────────────┐
  └───────────────────────────────────────────────────────────┘
  <дерево комментариев>

  ─────────────────────────────────────────────────────────────
  ЕЩЁ ИЗ BAMBUFAN                                                           ← §1.7, 3 карточки
  ┌──────┐ ┌──────┐ ┌──────┐
  └──────┘ └──────┘ └──────┘
```

### 1.3 Шапка поста (eyebrow + заголовок)

- **Eyebrow** — `саб` (ссылка на `/community/:slug`, скрыта если `community_id === null` —
  пост в профиле автора, тогда eyebrow = просто `@автор`) `·` `@автор` (ссылка на `/u/:username`,
  или «[удалённый пользователь]» без ссылки — §6.2) `·` относительный возраст. Тот же порядок,
  что карточка треда форума ([community.md §3.2](community.md)) — читатель уже выучил этот
  паттерн на форуме, повторяем, не изобретаем второй.
- **`[Изменено]`** — мелкая приглушённая пилюля справа от eyebrow, только если `body` правили
  после публикации (§4 `feed.page.md`: «тело всегда + метка "изменено"»). Не туллтип с датой в
  MVP — сам факт важнее точного времени правки.
- **Заголовок** — обычный `Heading size="lg"`, **без** принудительной акцентной покраски слова
  (юзер-текст произвольный — тот же принцип, что заголовок идеи/треда,
  [ideas.md §3.2](ideas.md)/[community.md §3.2](community.md)).
- **Owner-действия** («Изменить»/«Удалить») — не в шапке (перегруз первого экрана), а рядом с
  футером тела поста, secondary-стекло + коралл — см. §1.4 конец, §4.

### 1.4 Тело поста по типу (полная форма, не карточная свёртка)

Общий каркас разворачивает то же, что лента показывает свёрнуто (спека
[feed.md](feed.md) — карточка списка); здесь — **полная** версия каждого типа.

- **`model_link`** — встроенный блок модели: превью (тот же рендер, что `ModelTile`/карточка
  каталога, `apps/web/src/market/modeltile.tsx`/`market.tsx`), имя модели, формат-eyebrow,
  счётчик ♥/скачиваний **под** превью (те же агрегаты, что на карточке модели), кнопка
  **«Открыть модель»** (secondary-стекло, глиф-стрелка) → `/project/:id`. Ниже блока —
  собственный текст автора поста (markdown, `MarkdownBody`), если есть. Блок — карточка-
  подложка (это отдельная **единица контента**, не парящая мета, тот же довод, что плитка
  make в [marketplace.v2.md §5.1](marketplace.v2.md)): `radius` крупный, тонкая мятная обводка,
  кликабелен целиком по превью → модель; тап вне превью (по остальному блоку) никуда не ведёт
  — это не карточка-ссылка, а встроенный виджет внутри статьи.
- **`media`** — видео **целиком**, нативный `<video controls poster>` (не автоплей — тот же
  принцип, что карточка в ленте, `feed.page.md` §3), full width колонки, `radius` карточки.
  Текст поста (если есть) — под видео, markdown.
- **`text`** — просто `MarkdownBody` полным текстом, без обрезки (в отличие от ленты). Пост без
  картинки — норма (§6 крайние случаи), верстается как обычный текстовый блок, никакого
  плейсхолдера «фото нет».
- **Markdown-типографика** — типографика длинного чтения из
  [projects.multiformat.md §3](projects.multiformat.md) (тот же класс `.markdownBody`,
  `renderMarkdown`/`MarkdownBody` из `market/markdown.tsx`, ничего нового не рендерим): картинки
  внутри статьи — `max-width: 100%`, подпись `alt` не показываем визуально, заголовки статьи
  (`h1`-`h3`) на градус мельче Heading страницы, чтобы не спорить с заголовком поста.
- **Теги/спеки** — модель и медиа не несут отдельных тегов на странице поста (это атрибуты
  вложения, не поста); для `text`-постов в сабе тегов нет вообще (в отличие от `question`-тредов
  форума — у ленты их не завели, `feed.page.md` не вводит теги постов).
- **Действия под телом** (перед разделителем комментариев): «Поделиться» (нейтральное стекло,
  тот же паттерн Web Share/копия+тост, что модель — [marketplace.v2.md §3.3](marketplace.v2.md)),
  и **только владельцу** — «Изменить» (secondary-стекло, disabled после 15 мин, но кнопка не
  исчезает целиком — см. §4.2) + «Удалить» (коралл, `confirm({destructive:true})`).

### 1.5 Голосование за пост

**`VoteArrows`, вариант `large`** — прямой перенос уже принятого компонента
([community.md §7.4](community.md), `subjectType:'feed_post'` уже расширен спекой ленты
[feed.md §6.1](feed.md)) — здесь тот же `subjectType`, просто крупный вариант вместо `compact`
(`POST /feed/posts/:id/vote {value}` → тот же контракт `{votes_up, votes_down, my_vote}`, что
модель/тред). Ничего нового не рисуем: крупный счётчик Unbounded, ▲ активная = `--accent`, ▼
активная = `--accent-danger`, повторный тап по активной = снятие, оптимистичный апдейт, без
пульса/звука (голос — не срочность).

- **Размытый счёт первые 10 минут** (`feed.page.md` §5, анти-абьюз) — тот же проп `approx`, что
  уже введён спекой ленты ([feed.md §6.1](feed.md)): при `now - post.created_at < 10min` число
  рендерится как `~{округлённое}` вместо точного, форма/цвет/тач-поведение контрола не меняются.
  Никакой второй реализации — страница поста просто передаёт `approx` в тот же `VoteArrows`.
- **Гость** — стрелки кликабельны, счёт виден (публичное чтение — канон,
  [ux.md §1.2](../product/ux.md)); тап → промпт входа (`overlay` авторизации), намерение
  запоминается, после логина голос применяется сам.

### 1.6 Дерево комментариев

- **Заголовок секции** — «`N` комментариев» (склонение — на реализацию), не «ОБСУЖДЕНИЕ» как у
  модели (пост — это уже обсуждение по своей природе, заголовок секции проще).
- **Композер верхнего уровня** — сразу под заголовком (писать — первым делом, тот же принцип,
  что комментарии модели, [marketplace.v2.md §4.1](marketplace.v2.md)): `.marketTextarea`,
  авто-рост, плейсхолдер «Что скажете?», кнопка «Отправить» — **не зелёный primary страницы**
  (зелёная CTA поста и так одна — «Написать пост» живёт в ленте, здесь на странице поста вообще
  нет зелёной primary — это норм, не каждый экран обязан её иметь, голос уже акцентный).
- **Карточка комментария** — мини-аватар автора (24–28px, [avatar.md](avatar.md)) + `@username`
  + относительная дата + `VoteArrows compact` (`subjectType: 'feed_comment'`) в торце + тело
  (markdown, тот же `MarkdownBody`, комментарии тоже поддерживают markdown — `feed.page.md` не
  ограничивает их plain-text, а `comments` уже полиморфны и рендерятся тем же санитайзером) +
  «Ответить» (открывает вложенный композер с `parent_id`).
- **Вложенность** (`comments.parent_id` — в схеме, `feed.page.md` §4: «дерево комментариев»).
  Визуально — отступ ~24px на уровень + тонкая вертикальная направляющая слева (тот же приём,
  что вложенный `reply` форума, [community.md §3.5](community.md)), но **не рекурсивно
  бесконечно**: глубже 4 уровней — дальнейшие ответы не увеличивают отступ (плоская линия на
  максимальном отступе), иначе на телефоне текст схлопывается в колонку в один символ шириной.
  Это визуальный кап, не кап данных — сервер отдаёт дерево как есть.
  Ветка с ≥8 прямыми ответами на один комментарий — сворачивается за строку **«Показать ещё N
  ответов»** (не подгружает лишнее на старте, тот же довод, что «Показать ещё» ленты).
- **Своя реплика** — тонкая мятная обводка/метка «вы» (`data-mine`, тот же приём, что коммент
  модели §4.1 marketplace.v2.md). Удаление своей реплики — `IconButton «⋯»` → `confirm` →
  soft-delete (`comments` — общая полиморфная сущность, поведение единое по всему порталу).
- **Сортировка** — по голосам внутри уровня (не по времени) — единообразно с постами
  форума-Q&A (`community.md §3.5`), это то же дерево-примитив на будущее (см. §7 «повторилось
  дважды»); для discussion-постов ленты порядок «по голосам» тоже читаем лучше времени (лучшие
  ответы наверху — тот же Reddit-принцип, что и вся лента).
- **Состояния** — пусто → компактный `EmptyState`: «Пока нет комментариев», подпись «Будьте
  первым»; загрузка → скелетон 2–3 карточек; ошибка → «Не удалось загрузить обсуждение» +
  «Повторить».
- **Гость** — читает дерево, тап по «Ответить»/голосу комментария → тот же промпт входа, что §1.5.

### 1.7 «Ещё из этого саба»

Полноширинная секция под деревом комментариев — не тупик, выход обратно в поток
(`feed.page.md` §4). 3 карточки того же типа, что лента (карточка поста ленты (каркас+тело+футер, [feed.md §2](feed.md))),
`GET /communities/:id/feed?limit=3` (или `GET /feed?scope=all&limit=3` для постов без саба —
`community_id === null`, тогда заголовок секции — «ЕЩЁ ОТ @АВТОРА» вместо «ЕЩЁ ИЗ …», источник
`GET /feed?author=:id`). Заголовок `Eyebrow`, сетка/ряд 3 карточек (десктоп), тот же
`.stagger-reveal` что и лента.

### 1.8 Состояния страницы поста

| Состояние | Что видно |
|---|---|
| Загрузка | скелетон: eyebrow-полоса, заголовок-полоса, блок тела (высота под тип неизвестна — универсальная плашка), голос dim, 2 скелетона комментариев |
| **Пост удалён** (переход по валидной ссылке на `status='deleted'`) | **не 404.** Компактный `EmptyState` на месте тела: «Пост удалён автором», кнопка «В ленту» (`feedPath()`). Ссылка была валидной, человек не виноват (`feed.page.md` §4) |
| Пост не найден (`id` вообще не существует) | тот же паттерн, текст «Пост не найден» — отличаем от «удалён», если API различает коды (`404` vs `410`/`status`); если не различает на бэке — единый текст «Пост не найден или удалён», не гадаем |
| Ошибка сети при загрузке | «Не удалось загрузить пост» + «Повторить» |
| Закрытый саб, не участник (`unlisted`) | «Это закрытое сообщество» + «Запросить доступ» (тот же текст, что лента §6 `feed.page.md`) — тело поста скрыто, только шапка + этот блок |
| Гость проголосовал → залогинился → пост уже удалён | тихо: «Пост удалён» вместо страницы, без ошибки (§9 `feed.page.md`) |

## 2. Редактор `/feed/new`

### 2.1 Вход и назначение

Из §8 `feed.page.md`: «Написать пост» (лента, левая колонка) / FAB (мобайл) / «Рассказать в
ленте» (карточка модели, `?model=:id` — предзаполняет вложение модели, §2.5) / «Новый пост»
(страница саба, предзаполняет «Куда публикую»). Все — на `/feed/new`, свой роут (форма длинная,
черновик, аплоад — модалка тут была бы «кадром в кадре», тот же довод, что вынос флоу «Добавить
модель» в свою страницу, [marketplace.v2.md §9.5 п.1](marketplace.v2.md)).

### 2.2 Вертикальная композиция

```
  ← (Отмена)

  Создать пост                         Черновик сохраняется автоматически

  Куда публикую
  [ ▾ В мой профиль                                          ]  ← §2.3

  [ Текст ][ Фото и видео ][ 3D-модель ][ GitVerse ]             ← §2.6

  Заголовок                                              12/120  ← §2.4, счётчик с 100
  [ Почему профиль PLA плывёт на второй пластине?             ]

  ┌ Блочный редактор ─────────────────────────────────────────┐  ← §2.5
  │ +  Начните рассказ…                                      │
  │    Текст · Подзаголовок · Список · Изображение · Видео   │
  └───────────────────────────────────────────────────────────┘

                                    ┌ Отмена ─┐  ┌ Опубликовать →┐

  справа: честная памятка «Хороший пост о самоделке»                ← §2.7
```

На десктопе форма занимает основную колонку, справа sticky-памятка с тремя практическими
советами и персонажем. На узком экране памятка уезжает под форму; публикация остаётся главным
действием. Никакого мини-превью карточки во время набора нет: оно дублировало форму и отнимало
место у текста.

### 2.3 «Куда публикую»

- `<select>`-подобное поле в стиле `.marketField`/`.marketInput` (тот же класс формы маркета,
  не новый примитив), список: **«В мой профиль»** первым пунктом (`community_id = null`), затем
  сабы, где автор состоит (`community_members`), отсортированные по последней активности.
  Если пользователь нигде не состоит — только «В мой профиль» в списке, поле не скрываем (сам
  факт выбора — часть формы, не появляется/пропадает).
- **Предзаполнение** (§8 `feed.page.md`): со страницы саба — этим сабом; с карточки модели
  (`/feed/new?model=:id`) — последний использованный саб (или профиль, если использованных
  ещё нет); иначе — последний использованный (`localStorage`, тот же неймспейс, что черновик,
  §2.8).
- Поле **не выбор `enum`-типа поста** — тип выводится из вложения (§2.6), не отсюда.

### 2.4 Заголовок

`.marketInput`, обязателен, `maxLength=120`. Счётчик `n/120` появляется **у поля** только начиная
со 100 символов (тот же порог/приём, что заголовок идеи, [ideas.md §3.2](ideas.md)) — не мозолит
глаза заранее. Пустой заголовок — кнопка «Опубликовать» dim + причина у поля (паттерн
`ideas.md §4.5`), не отдельный алерт.

### 2.5 Тело — блочный редактор

`apps/web/src/feed/blockeditor.tsx#FeedBlockEditor` хранит структурированный документ, но
показывает человеку спокойный чистый холст вместо Markdown-разметки и переключателя
«Редактор/Предпросмотр». Кнопка `+` открывает типы блоков: текст, подзаголовок, список,
изображение и видео. Клавиатурный ввод остаётся главным сценарием; управление блоками появляется
только в контексте активного блока. Лимит сериализованного тела — те же **50 КБ**, а вывод всегда
проходит существующий безопасный рендерер блоков. В форме нет отдельного preview-режима: результат
виден непосредственно в холсте.

### 2.6 Тип публикации и вложение

Над заголовком постоянно виден один сегментированный ряд **«Текст / Фото и видео / 3D-модель /
GitVerse»**. Это понятные пользователю форматы публикации, а не технический `enum`. Активное
состояние меняет текст и контур, не заливает кнопку тяжёлым цветом. Вложения
**взаимоисключающие** (пост — один тип:
`model_link` | `media` | `gitverse` | `text`, домен не допускает несколько сразу). Выбор одной
**заменяет** другую (если уже прикреплена модель, а автор жмёт «Прикрепить GitVerse» — тихая
замена, без `confirm`, это черновик, ничего не потеряно необратимо; UI просто снимает прежнее
вложение и открывает новый пикер). Ничего не прикрепил → `text`. «3D-модель» соответствует
существующему `model_link` ([feed.page.md §3.1](../epics/feed.page.md)); отдельной кнопки
«Приложить 3mf» не заводим.

- **«Прикрепить модель»** (glyph — куб/принтер, line) → модалка (`overlay.modal`) с поиском:
  строка поиска + список **своих** моделей сверху (частый кейс — «расскажи о своей»), затем
  результаты по каталогу (`GET /models?q=`, тот же паттерн, что каталог маркета §1.2
  `marketplace.v2.md`). Строка результата — мини-превью + название + `owner`. Тап → закрывает
  модалку, превью модели появляется **инлайн** над кнопками вложения (замена самих кнопок на
  карточку-превью с `IconButton «×»` снять вложение) — так автор сразу видит, что прикрепил, не
  открывая модалку заново.
  - **Уникальность `(author, model)`** (§9 `feed.page.md`): если автор уже писал `model_link`
    про эту модель — модалка после выбора не закрывается тихо, а показывает inline-предупреждение
    под строкой результата: «Вы уже рассказывали об этой модели · Открыть пост» (ссылка на
    существующий), выбор этой модели заблокирован (тап по строке результата не срабатывает,
    строка `disabled`-визуально).
- **«Прикрепить медиа»** (glyph — камера/плёнка, line) → нативный file-picker
  (`accept="image/*,video/*"`), после выбора — превью инлайн (та же замена кнопок на карточку):
  для видео — миниатюра первого кадра как черновой `poster` (или явное поле «Обложка», если
  автогенерация постера — не в объёме Front без сервера; на реализацию, дизайн допускает оба).
  **`poster` обязателен** перед публикацией (§9 `feed.page.md`: «лимит размера и длительности на
  аплоаде, автоплей выключен, poster обязателен») — если не задан, кнопка «Опубликовать» dim с
  причиной «Добавьте обложку видео».
- **«Прикрепить GitVerse»** (glyph — line-иконка GitVerse) → **не модалка** — компактное поле
  ввода `Input` раскрывается инлайн под рядом кнопок: «Ссылка на репозиторий или issue»
  (`placeholder: https://gitverse.ru/owner/repo`). Автор вставляет ссылку → на blur/Enter клиент
  дёргает парсер метаданных (Data), поле показывает `Spinner` внутри себя (справа, тот же
  приём, что debounce-поиск каталога) на время запроса. Успех → поле схлопывается в инлайн-превью
  (та же замена кнопок на карточку, что у модели/медиа): мини-`gitverse`-тело карточки
  ([feed.md §2.2](feed.md)) целиком — тот же компонент, что рендерит лента, не отдельная вёрстка
  превью здесь. Неудача парсинга (приватный/битый репо/rate-limit) — **не блокирует**: поле
  остаётся с введённой ссылкой, под ним — приглушённая строка «Превью не загрузилось, ссылка
  сохранена» (эпик §3.1: деградация до голой ссылки — не ошибка формы, публикация разрешена).
  Снять — тот же `IconButton «×»`, что у модели/медиа, возвращает к трём кнопкам и очищает поле.
- **Снять вложение** — `IconButton «×»` на инлайн-превью, возвращает к активному «Текст»,
  пост становится `text` (если в теле есть текст) или невалиден (нужен текст или вложение —
  формулировка на реализацию).

### 2.7 Правая памятка

Вместо дублирующего мини-превью — sticky-модуль **«Хороший пост о самоделке»**: покажите
результат, расскажите процесс, выберите точный саб. Ниже персонаж напоминает, что достаточно
заголовка и одного наглядного блока. Это честная помощь, а не декоративная заглушка; советы не
обещают функций, которых нет. На ширине меньше 980px колонка становится обычным блоком под формой.

### 2.8 Черновик

- **Автосейв** в `localStorage` (неймспейс `portal.feed.draft.*`, тот же паттерн, что
  `portal.overlay.*`/`portal.theme` — [overlay.system.md §5](../epics/overlay.system.md)) каждые
  ~2 с, содержит `{community_id, title, body, attachment}`. Один черновик, не менеджер
  черновиков (§8 `feed.page.md`).
- **Восстановление** — при заходе на `/feed/new`, если в `localStorage` лежит непустой черновик:
  верхняя полоса-баннер (тот же визуальный приём, что «одноразовая плашка» маркета,
  [marketplace.md](marketplace.md)) — **«Восстановлен черновик · Начать заново»**, где «Начать
  заново» — текстовая кнопка-ссылка, очищает форму и `localStorage`. По умолчанию форма уже
  заполнена черновиком — «восстановление» тихое, баннер только информирует, что это не пустой
  старт.
- **Очистка** — черновик стирается после успешной публикации (§2.9) или явного «Начать заново».
  Уход со страницы без публикации **не** стирает черновик — вернулся, увидел баннер.

### 2.9 Публикация

- **Картинки внутри статьи до создания поста** (`feed.page.md` §8/§10): медиа-блок блочного
  редактора загружает файл через тот же безопасный upload-контракт, что вложение. Если серверу
  нужен родительский id, первая вставка создаёт скрытый серверный черновик (`status='hidden'`)
  до явного «Опубликовать». Автор не видит технический шаг; без медиа форма целиком живёт в
  `localStorage` до публикации.
- **«Опубликовать»** — единственная зелёная primary **этого экрана** (форма без вложения не
  спорит с лентой — на `/feed/new` нет других зелёных). Активна при: заголовок непустой ≤120,
  `body` непустой **или** есть вложение (одного текста не требуем, если прикреплена модель/медиа
  — надпись автора необязательна для `model_link`/`media`, `feed.page.md` §3), тело ≤50 КБ,
  видео-вложение — с `poster`.
- **Успех** — `POST /feed/posts` (публикует скрытый черновик, если был, либо создаёт сразу
  `visible`) → редирект на `/feed/p/:id`, `toast({severity:'success', title:'Опубликовано'})`,
  `localStorage`-черновик очищен. Никакой премодерации (§8 `feed.page.md`).
- **Ошибка сети/валидации** — `toast critical` «Не удалось опубликовать. Попробуйте ещё раз»,
  черновик **не** стирается (в `localStorage`, форма остаётся заполненной).

### 2.10 После публикации (переход в режим редактирования на странице поста)

Не отдельный экран — те же поля, что §2.2–2.6, но **инлайн на `/feed/p/:id`** по кнопке
«Изменить» (§1.4). Правила уже зафиксированы UX (`feed.page.md` §8), визуал:

- **Тело** — можно править всегда. Открывает тот же `FeedBlockEditor` **на месте** тела поста
  (не модалка, не переход на `/feed/new` — inline-редактирование, тот же приём, что
  редактирование описания модели). Сохранение → `PATCH /feed/posts/:id`, на странице поста
  появляется/остаётся `[Изменено]` (§1.3).
- **Заголовок** — редактируется **только первые 15 минут** после публикации. Кнопка «Изменить
  заголовок» рядом с заголовком, пока окно открыто; после истечения — кнопки физически нет (не
  disabled с тултипом — она просто исчезает, чтобы не провоцировать вопрос «почему нельзя»
  каждый раз). Если нужен визуальный обратный отсчёт — мелкая приглушённая подпись «доступно
  ещё 12 мин» рядом с кнопкой в последние ~2 минуты окна (не постоянно, чтобы не шуметь).
- **Саб** — поле «Куда публикую» не показывается вообще в режиме редактирования (саб не меняется
  никогда, `feed.page.md` §8).
- **Удаление** — `confirm({destructive:true, title:'Удалить пост?'})` → soft delete. Если есть
  комментарии — пост схлопывается на месте в «[удалено автором]» (карточка остаётся в дереве
  комментариев видна, ветка обсуждения жива, §8 `feed.page.md`); если комментариев нет — пост
  просто исчезает из ленты/профиля, прямая ссылка ведёт на состояние §1.8 «Пост удалён».

## 3. Мобайл/планшет/тач

Наследует общий тач-контракт без изменений ([layout.md](layout.md): ≥48px, `:active`,
`touch-action:manipulation`). Дельта:

- **Страница поста (§1):** одна колонка на всю ширину минус поля контента (как везде на мобиле).
  `VoteArrows large` — стрелки укрупняются до 48px (тот же кап, что лента, `feed.page.md` §7).
  «Ещё из этого саба» — 1 колонка (список, не сетка).
- **Редактор (§2):** блочный холст растёт по содержимому, меню типов блоков остаётся в пределах
  вьюпорта, кнопка «Опубликовать» прилипает **над**
  системной клавиатурой (`position: sticky`, не `fixed` — тот же приём, что композер форума,
  [community.md §4](community.md), избегаем прыжка на iOS). Правая памятка §2.7 становится
  обычным блоком под формой и не вклинивается между полями и CTA.

## 4. Моушен и звук (сводка — переиспользуем принятое, ничего нового)

- **Тап любой кнопки/карточки/чипа** — `.pressable` + звук `tick` ([motion.md §1](motion.md)/
  [sound.md §3](sound.md)).
- **Голос (пост/комментарий)** — count-up ± дельта, микро-подскок стрелки (`modelVoteBounce`,
  [motion.md §8](motion.md)), **без звука** (не срочность, как везде в проекте).
- **Открытие поста из ленты** — `pushState` без page-transition спецэффекта (лента остаётся
  под постом, никакого кросс-фейда всей страницы — иначе создаётся ложное ощущение полной
  перезагрузки, `feed.page.md` §4 явно требует «лента не перезагружается и не прыгает»).
  Cold-start заход — обычная загрузка страницы, `.stagger-reveal` на первый рендер блоков.
- **Публикация (успех)** — `cta`-тон на тап «Опубликовать» ([sound.md §3](sound.md)), редирект —
  `section-fade` (тот же переход, что пост-аплоад модели, [marketplace.v2.md §7](marketplace.v2.md)).
- **Восстановление черновика** — баннер появляется без анимации-сюрприза (`reveal` мягкий,
  `--dur-reveal`), никакого звука (загрузка контента — не жест пользователя).
- **Удаление поста (успех)** — модалка закрывается (`.modal-in-out`), карточка на месте поста
  схлопывается в «[удалено автором]» плавным `--dur-reveal` кросс-фейдом текста, не мгновенной
  подменой.
- **`prefers-reduced-motion`/Save-Data** — весь список выше деградирует по общим правилам
  ([motion.md](motion.md)): count-up → мгновенная смена числа, `stagger-reveal` → без сдвига.

## 6. Крайние случаи (§9 `feed.page.md` — визуальное решение по каждому)

| Случай | Решение UI |
|---|---|
| Пост без картинки | норма — `text`-тело просто короче, без плейсхолдера |
| Удалённый автор | eyebrow показывает «[удалённый пользователь]» без ссылки, пост/голоса/комментарии сохранены |
| Модель из `model_link` удалена | встроенный блок модели (§1.4) схлопывается в приглушённую строку «Модель удалена», текст автора и обсуждение остаются как есть |
| Повторный `model_link` про ту же модель | блокировка на шаге прикрепления, не на публикации (§2.6) |
| Видео 200 МБ | лимит размера/длительности на клиентской валидации файла (точные числа — GAP-API, координация с Fullstack/MF-811), `poster` обязателен |
| Гость проголосовал → залогинился → пост удалён | тихо: показываем состояние §1.8 «Пост удалён», без ошибки |
| Гость жмёт «Написать пост» | промпт входа перед `/feed/new` (роут за `AuthGate`, как весь `apps/web`) |
| Закрытый саб в «Куда публикую» | список источник — только сабы, где автор состоит (`community_members`), `unlisted`-сабы без членства туда не попадают — нечего блокировать отдельным текстом |

## 7. Новые переиспользуемые компоненты (→ components.md)

### 7.1 `VoteArrows` — расширение контракта, не новый компонент

`subjectType` уже растёт с `'model'|'thread'|'post'` (форум, [community.md §7.4](community.md))
до `+ 'feed_post'` спекой ленты ([feed.md §6.1](feed.md), вместе с пропом `approx` для
размытого счёта §1.5). Эта спека добавляет к тому же union ещё `'feed_comment'` (§1.6) —
компактный вариант, без `approx` (размытие счёта — только для свежих постов, не для
комментариев). Форма/цвет/тач/моушен/звук — без изменений, никакой новой JSX/CSS.

### 7.2 `CommentTree`

Рекурсивный рендерер дерева комментариев с капом визуальной глубины (§1.6) и сворачиванием
широких веток («Показать ещё N ответов»). Первое место, где вложенность **реально** рисуется
(форум §3.5 `community.md` сегодня плоский, `parent_id` не рендерит вложенность). Если тот же
паттерн понадобится в форуме позже — выносить общий хук/компонент тогда (тот же принцип
«повторилось дважды», не «про запас»); сейчас это первое применение, специфичное для ленты.

### 7.3 `PostAttachmentPicker`

Четыре постоянно видимых таба формата (текст/медиа/модель/GitVerse) + модалка поиска модели +
инлайн-`Input` для GitVerse-ссылки + инлайн-превью
выбранного вложения со снятием (§2.6). Новый композит редактора поста — переиспользует
`overlay.modal`, поиск моделей (`GET /models?q=`, уже есть), `ModelTile`-превью и
`gitverse`-тело карточки ([feed.md §2.2](feed.md)) для инлайн-превью GitVerse-вложения,
специфической новой визуальной формы у него немного (в основном оркестрация существующих
примитивов).

## 8. Инварианты приёмки (чек-лист ревью)

- [ ] `/feed/p/:id` — два поведения `←`: из ленты (без подписи, лента жива под постом) vs cold
      start («← В ленту», редирект на `/feed`) — §1.1.
- [ ] Тело поста разворачивает `model_link`/`media`/`text` полностью (не как в карточке ленты) —
      §1.4.
- [ ] `VoteArrows large` за пост, `compact` за комментарий, размытый счёт первые 10 минут — §1.5.
- [ ] Дерево комментариев — реальная вложенность с визуальным капом глубины и сворачиванием
      широких веток, не плоский список — §1.6, §7.2.
- [ ] «Ещё из этого саба» — 3 карточки того же каркаса, что карточка поста ленты (feed.md §2), не тупик — §1.7.
- [ ] Удалённый пост по ссылке — не 404, «Пост удалён автором» + «В ленту» — §1.8.
- [ ] `/feed/new` — «Куда публикую» (профиль первым), заголовок 120/счётчик с 100,
