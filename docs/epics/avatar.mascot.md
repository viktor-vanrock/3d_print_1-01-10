# Персонаж-аватар «мейкер-маскот»

**Issue:** [010](../issues/010.avatar.mascot.md) · **Доска:** MF-446 (`tasks.3mf.tech`, воркспейс `3mf`) → **MF-448** (Фаза 1, done) / **MF-449** (Фаза 2) / **MF-450** (Фаза 3)

## Задача

Идея Валерия (2026-07-04): «Делаем как у Reddit персонажей для авы. Заходя на портал, справа сверху — персонаж, которого можно кастомизировать». Вместо фото или буквы-инициала у каждого юзера — **кастомизируемый 3D-персонаж-маскот**, который живёт в шапке (капсуле), меню профиля и в перспективе — везде, где сейчас была бы аватарка (лента, комментарии, профиль, Make-галерея).

## Зачем (развитие идеи, не только копия Reddit)

- **Идентичность без фото.** РУ-аудитория неохотно светит лица; персонаж снимает барьер и делает профиль живым с первой секунды — у Reddit это сработало массово.
- **Мейкер-тематика = контент-мультипликатор.** Части персонажа — это буквально печатаемые вещи (шапка, инструмент в руке, катушка филамента за спиной). Дальше — персонажа можно **напечатать**: «скачай STL своего маскота» — уникальная фишка, которой нет ни у одной 3D-платформы (Reddit продаёт NFT-скины аватаров; мы продаём/дарим реальный STL).
- **Экономика гардероба.** Части как награды за ачивки (за первый Make — шапка, за 10 продаж — золотое сопло, сезонные ивенты, брендовые коллаборации с производителями принтеров). Паттерн уже отработан у Валерия на `create.plag.space` (система ачивок с гардеробом — см. память `project_codemine.md`/`ACHIEVEMENTS.md`), переносится сюда осознанно.
- **UGC-слой на будущее.** Авторы сообщества смогут предлагать свои элементы гардероба (по аналогии с Reddit collectibles) — модерируемый пайплайн, не в v1.

## Исследование и вдохновители

- **Reddit avatar builder** (референс-скрины Валерия, 2026-07-04): категории-табы сверху (Наряды/Верх/Низ/Волосы/Лицо/Глаза/Головные уборы/Правая рука/Левая рука/Фоны/Цвета), сетка карточек-опций, превью персонажа слева, одна кнопка «Сохранить» снизу, история/избранное иконками. Взяли: структуру редактора (превью + категории + сетка + один CTA), сам факт **случайного костюма при регистрации** (Snoo не рождается голым дефолтом — у него сразу случайный цвет/наряд).
- **Among Us** (скрины персонажей разных цветов и поз — палец у рта, машет, лежит без рук): взяли принцип **простого цельного силуэта** и крупные округлые детали, читаемые даже в иконке 36px. Ноги из ранних итераций осознанно убраны в v5 — это уже самостоятельный персонаж Portal.ru, а не копия референса.
- **SberAI guide** (передан оператором 2026-07-19): взяли матовость, рассеянный свет, мягкие градиенты, крупные архетипичные элементы и отсутствие микрошумов. Палитра, логотипы и фирменные композиции SberAI не копируются; функциональный мятный акцент Portal.ru остаётся каноном.
- **Итерации по обратной связи (2026-07-04→19):** v1 плоский рукописный SVG → v2 SVG с поворотами → **v3 настоящий three.js** → v4 форма-боб с ногами → v4.2 без фонового кольца, с корректными ракурсами и компактной тенью → **v5 (2026-07-19): ноги убраны, добавлены большая мягкая голова, цельный торс, бороды, варианты рук, новые позы/инструменты и отдельная мастерская с прогрессивной загрузкой**. Форма v5 — новый канон.

## Архитектура

### Форма (зафиксирована, см. `docs/design/avatar.md`)

Большая мягкая голова и цельный округлый торс без ног. Руки — отдельные простые формы; материал и положение определяются слоями `arms` и `pose`. **Правило на будущее: новые части добавляются как отдельная геометрия поверх/вокруг зафиксированного торса — базовый силуэт и пропорции не редактируются без отдельного решения оператора.**

### Движок и перф

- **three.js**, живая 3D-сцена — драг пальцем (pointer capture) вращает персонажа, idle-покачивание, посадка на невидимый пол с мягкой тенью (`ShadowMaterial` + `PCFSoftShadowMap`), окружение через `RoomEnvironment`/PMREM для реалистичных бликов на пластике, ACES-тонмаппинг.
- **Отдельная мастерская `/profile/avatar`.** Слева один большой персонаж, справа табы категорий и сетка вещей. Первый кадр всегда лёгкий SVG. Live-сцена грузится динамическим `import()` отдельным чанком после первого paint/в idle-время; карточки каталога остаются SVG и не создают WebGL-контексты. При «Сохранить»
  renderer фотографирует три канонических ракурса (`left`/`right`/`front`) в 320px; конфиг и
  полный render set одним PATCH сохраняются в профиль/S3.
- **Social UI — только 2D.** Лента, комментарии, профиль, Make, лидерборды и меню используют
  серверные PNG; ни одна строка списка не поднимает WebGL.
- **Единственное live-исключение — top-right.** `LiveHeaderMascot` после capability gate
  динамически загружает облегчённую сцену без PMREM/теней, DPR ≤1.25 и event-driven ≤30fps:
  следит за локальным курсором, кивает при открытии меню и замечает новое уведомление. На
  touch/TV, Save-Data, reduced-motion, слабом устройстве, скрытой вкладке/потере контекста —
  статичный портрет. При открытом конструкторе header scene освобождается.
- **Фолбэк без WebGL** — SVG-компонент `MakerAvatar` (упрощённая плоская отрисовка того же конфига).
- **Facing по контексту** — это не просто эстетика, это принцип встраивания: любое новое место интеграции выбирает, в какую сторону персонаж «смотрит» (обычно — в сторону контента/текста рядом), а не переизобретает позу.

### Конфиг (`AvatarConfig`, `home/avatar.tsx`)

```
color       — 9 цветов пластика
texture     — слои печати / глянец / матовый / шершавый / мрамор / карбон
pose        — спокойно / привет / победа / думает / показывает / идея
outfit      — без одежды / худи / комбинезон / фартук / лаборатория / тех-жилет
hat         — шапки, шлемы, корона, кошачьи/лисьи ушки
eyes        — 6 выражений, включая визор и звёзды
beard       — нет / щетина / усы / полная / коса
arms        — обычные / перчатки / рукава / робот
accessory   — нет / шпатель / ключ / сердце / штангенциркуль / паяльник
back        — нет / катушка филамента / джетпак
```

Каталог умеет помечать сезонные, статусные, редкие и achievement-locked вещи. Entitlement
приходит из `/me/wardrobe/unlocks`; закрытая вещь видна, но недоступна и показывает условие.
В будущем первичный конфиг станет persona-seeded: стабильный seed аккаунта плюс выбранное
направление деятельности зададут осмысленный стартовый образ, после чего пользователь свободно
его изменит.

Поля `bg` (фон-кружок) больше нет — категория убрана целиком 2026-07-05: аватар нигде не рисуется с фоном (ни в капсуле/меню, ни в самом редакторе), только персонаж на прозрачном/нейтральном фоне контейнера.

Источник истины — `user_avatar.config` в БД. Локальные ключи account-scoped и служат только
быстрым/offline-кэшем. Серверные render URL revisioned и content-addressed; новая конфигурация
не может получить старые PNG из browser cache.

### Контракт интеграции

- Пользователь: только `AvatarBubble({config, snapshots, size, facing})`; фото и инициалы
  запрещены. Для legacy без записи — `deterministicAvatarConfig(user.id || username)` + SVG.
- Текущий аккаунт: `useAvatar(user.id)` даёт config, async save и реактивные snapshots.
- Чужой аккаунт: `snapshots` всегда передаётся явно (manifest или `null`), чтобы случайно не
  показать локальный портрет текущего пользователя.
- Сообщество: отдельный знак (`CommunityAvatar`/brand logo/буквенный mark); его нельзя заменять
  пользовательским маскотом. GitVerse avatar в repo-card — metadata внешнего объекта, не user avatar.

## Фазы

**Фаза 1 — готово (2026-07-04→05, карточка MF-448, `done`).** Конфиг+типы, SVG-фолбэк, live-3D-редактор (three.js, форма-боб, 6 текстур, 4 позы, наряды/шапки/лица/предметы), рендер в капсуле и меню профиля через PNG-снапшоты, кастомизация полностью рабочая и проверенная (автопрокликаны все опции — 0 ошибок рендера). Плюс полировка 07-05: без кольца/фона вокруг аватара нигде, верный поворот `facing`, тень не обрезается, категория «Фон» убрана из конфига.

**Фаза 2 — готово (2026-07-18).** Персист конфига, серверные revisioned portraits, mascot-only
лента/комментарии/профиль/Make/лидерборды, единый компонент интеграции и live top-right scene.

persona-seeded onboarding, UGC-пайплайн,
печатопригодный STL-экспорт.

## Критерии приёмки v5

- «Редактировать персонажа» открывает отдельный маршрут `/profile/avatar`, а не модалку.
- На первом кадре есть SVG-портрет; единственная three.js-сцена догружается отдельно. Каталог
  не поднимает WebGL на каждую карточку.
- Слева большой персонаж, справа категории и сетка вещей; мобильный CTA остаётся доступен снизу.
- Есть категории головы, выражения, бороды, туловища, рук, предмета, позы, цвета и текстуры.
- Ног нет ни в SVG, ни в 3D; форма остаётся читаемой в портрете 36px.
- Achievement-locked вещь видна с условием и не выбирается без unlock.
- Сохранение создаёт три PNG-ракурса и обновляет конфиг; без WebGL сохраняется конфиг с 2D-фолбэком.

## Критерии приёмки (Фаза 1, уже выполнено — для истории)

- Редактор открывается из меню капсулы («Редактировать персонажа»), не ломает клики по остальным пунктам меню (был баг с перехватом кликов — исправлен поднятием z-index шапки).
- Персонаж крутится пальцем в редакторе, все категории опций переключаются без ошибок рендера (проверено автоматическим прокликом всех вариантов).
- Сохранение генерирует и кладёт в `localStorage` три PNG-снапшота; капсула/меню сразу их используют.
- Без WebGL (или пока не сохранено ни разу) — рендерится SVG-фолбэк, не пустой блок.
- `prefers-reduced-motion` останавливает idle-покачивание и вращение сцены.
- Аватар в капсуле/меню — без кольца-обводки и без заливки-фона (только сам персонаж на прозрачном PNG); проверено пиксельным тестом на checkerboard-подложке.
- `facing="left"` визуально разворачивает лицо персонажа влево, `facing="right"` — вправо (проверено пиксельным тестом положения глаз в кадре, не только на глаз).
- Тень и парящие руки не обрезаются краем кадра снапшота.
- Конфиг не содержит поля `bg`; редактор не показывает категорию «Фон»; сцена (и редактора, и снапшотов) не рисует фон — ни цветной, ни через разросшуюся тень-«ловец».
