**Что это.** Стадия 1 (Design) эпика MF-558 [MF-560]. Полная UX-спека публичного раздела «Идеи»: лента предложений с голосованием, страница идеи с обсуждением, форма подачи с живой подсказкой дубликатов. По этому файлу Front собирает web в стадии 2 (подзадачи Front нарежу с него сам, когда Lead откроет стадию 2). Схему БД параллельно даёт Data (MF-559), API — Fullstack/Back (стадия 2).

**Зона.** Только дизайн-спека: раскладка, RU-тексты UI, все состояния (загрузка/пусто/ошибка), поведение на таче, голосовалка, маппинг статусов на палитру. Реализуют Front/Fullstack. DDL, роуты и формулу тренда не проектирую — беру готовыми из вердиктов Data/Fullstack (см. §10 «Стыки/контракты»).

**Правило работы (наследуется от витрины).** Только существующие токены ([theme/tokens.css](../../apps/web/src/theme/tokens.css)) и примитивы UI-кита ([ui/ui.tsx](../../apps/web/src/ui/ui.tsx), MF-40) + слой всплывашек (`overlay/`, MF-440). Где системы не хватает — помечено **GAP** и вынесено в §10. Новые переиспользуемые паттерны фиксирую в [components.md](components.md). Все тексты — **RU**.

**Границы (наследуются от эпика §«Что НЕ делаем в v1»).** НЕ проектирую: деньги/баунти/баллы/награды; **даунвоуты и рейтинги пользователей** (их нет — ни одного красного акцента, кроме статуса «отклонена»); AI-кластеризацию и автодедуп (только текстовый `pg_trgm`-поиск похожих); публичный роадмап с датами (страница показывает статусы, не обещания); анонимную подачу. Модераторский UI смены статуса — **не** в этой спеке (это внутренний инструмент команды; здесь — только как статусы **выглядят** для читателя, §3.3, §6).

**Ключевой зафиксированный стык (эпик, CTO+Fullstack 08.07).** Комментарии к идее в v1 идут через **свою таблицу `idea_comments`** (плоский тред на идею), **не** через форумный движок — форум-движка в коде нет. Раздел §3.4 проектирует тред именно под `idea_comments`; инлайн-встраивание согласовано контрактом с Fullstack (§10).

## 1. Лента идей (`#/issue`)

> **Маршрут — канонический (директива оператора MF-564, `docs/epics/ideas.page.md` §Маршрут, в main).** Публичный URL — **`/issue`** (список) и **`/issue/:id`** (страница идеи); внешне `3mf.tech/issue`. **`/ideas` → 301** на `/issue` (`/ideas/:id` → `/issue/:id`) — редирект только для внешних/старых ссылок; **вся наша навигация/CTA/ссылки ведут сразу на `/issue`**. Внутреннее имя фичи остаётся «идеи» — `issue` только адрес. Все web-маршруты в этой спеке (`#/issue`, `#/issue/:id`, `#/issue/new`) — по этому правилу. **Не путать с API:** серверные роуты остаются `/ideas`, `/ideas/similar` и т.д. (наименование Fullstack, слой `apps/api`) — меняется только публичный **URL страницы**, не путь API (§10).

Листинговая страница — по IA сестра витрины «Проекты». Наследует **wide-режим шапки** ([projects.page.md](projects.page.md) §1): часы/дата у левого края вьюпорта, капсула-островок справа, центральная навигация сверху. В реестр маршрутов добавляется таб **«Идеи»** (`headerMode: 'wide'`, маршрут `#/issue`) — это чисто данные реестра, шапку не правим (критерий MF-508 §6.2). Порядок центральной навигации: `Дом · Проекты · Идеи` (финальный состав — за владельцем навигации; §10 GAP-1).

### 1.1 Вертикальный ритм экрана (сверху вниз)

```
        [ wide-шапка: часы·дата | Дом Проекты Идеи | капсула ]     ← overlay, не часть потока

        ИДЕИ СООБЩЕСТВА · ГОЛОСУЙ ЗА БУДУЩЕЕ ПОРТАЛА              ← eyebrow (uppercase, dim)
        Идеи                                                      ← двухтоновый Heading (акцент «Идеи»)

  ┌ сегмент-табы ─────────────┐            ┌ PrimaryButton ──────┐
  │ [Популярные][Новые][Тренд]│            │ Предложить идею   → │   ← одна зелёная CTA на экран
  └───────────────────────────┘            └─────────────────────┘

  Категория: [Все][Каталог][Проекты][Форум][ЛК][Другое]          ← чипы-фильтры (ряд 1)
  Статус:    [Все][На рассмотрении][Запланирована][В работе][Готово][Отклонена]   ← чипы-фильтры (ряд 2)

  ┌──────────────────────── карточка идеи ────────────────────────┐  │ 128 ▲
  ┌──────────────────────── карточка идеи ────────────────────────┐  │  47 ▲
  ┌──────────────────────── карточка идеи ────────────────────────┐  │   9 ▲
        …                                                            ← лента (§2), голосовалка вшита в правый край карточки
                                  [ Показать ещё ]                    ← тач-fallback догрузки
```

- **Заголовок** — двухтоновый `Heading` (Unbounded, [palette.typography.md](palette.typography.md)): акцентное слово «Идеи» мятным. Eyebrow сверху — uppercase + трекинг, `--text-dim`.
- **Ширина контента** — увеличенный wide-`max-width` (как витрина). Лента — **одна колонка** карточек на всю ширину контента (карточка-действие горизонтальная, голосовалка в правом торце), не сетка: идея — это текст+голос, а не превью-тайл, поэтому читаемая строка-карточка вместо галереи.

### 1.2 Единый store «табы + фильтры + выдача»

Переиспользую управляемый store с MF-508 ([projects.page.md](projects.page.md) §3): одно наблюдаемое состояние `{ tab, category, status, items, cursor, loading, error }`; любой контрол (таб/чип) — контролируемый вход в store, выдача — производное. Смена любого фильтра сбрасывает курсор и перезапрашивает `GET /ideas` (§10). Состояние отражается в URL-хэше (`#/issue?tab=trending&cat=catalog&status=planned`) — шаринг ссылки на срез ленты и живой back/forward. **Активный набор фильтров не прячем** — выбранные чипы остаются зелёными (`Chip selected`), «Все» = сброс группы.

### 1.3 Сегмент-табы сортировки (Популярные · Новые · Трендовые)

Ровно паттерн **тайлов выбора / сегмент** из [components.md](components.md) (тот же примитив, что S/M/L): выбранный таб — зелёная заливка+свечение, остальные — тёмное стекло. Три значения:

| Таб | Что показывает | Источник порядка (Data §10) |
|---|---|---|
| **Популярные** (дефолт) | голоса за всё время, ↓ | `vote_count desc, created_at desc` |
| **Новые** | свежие, ↓ | `created_at desc` |
| **Трендовые** | голоса с затуханием по возрасту | `votes/(age_hours+2)^1.5`, окно 30 дней, считает api |

- **Дефолт при входе** — «Популярные» (самый предсказуемый срез; «пусто» на нём почти невозможно).
- **Трендовые:** порядок карточек — весь сигнал тренда. Дополнительно на первых 3 карточках трендовой вкладки — компактный **ранг-акцент** в углу голосовалки (тонкая amber-обводка счётчика, [palette.typography.md](palette.typography.md): янтарь = «обрати внимание, не ошибка»). Не бейдж, не эмодзи, не пульс — трендовость это про порядок, а не тревога.

### 1.4 Чипы-фильтры (категория + статус)

Два ряда пилюль-`Chip` (высота ≥48px, radius 999, тач-дружелюбно):
- **Категория** (фикс-список из эпика): `Все · Каталог · Проекты · Форум · ЛК · Другое`. Строковые значения enum — за Data (§10 стык-1); подписи RU беру дословно отсюда.
- **Статус:** `Все · На рассмотрении · Запланирована · В работе · Готово · Отклонена`. В фильтре показываю **читательски-осмысленные** статусы; «Предложена» скрыта в фильтре (это дефолтная масса — фильтровать по ней смысла нет, она = «всё, что не тронуто»), «Дубликат» и «Архив» — тоже не в основном ряду (они уводят из активной ленты; доступны только по прямой ссылке/поиску). Полный маппинг цветов пилюль — §6.
- На узких экранах ряд чипов — **горизонтальный скролл** с обрезкой-fade по краю (не перенос в 3 строки), momentum-скролл, `scroll-snap` по чипам. Тач-паттерн §7.

### 1.5 Пагинация и догрузка

- **Бесконечная догрузка** по 20 карточек через `cursor` из store (курсор — за api, §10). Триггер — IntersectionObserver на сентинеле у низа ленты.
- **Тач-fallback** — явная кнопка **«Показать ещё»** (нейтральное стекло, ≥48px) под лентой: на киоске/таче автоскролл-догрузка ненадёжна, кнопка гарантирует управляемость. При активном IntersectionObserver кнопка всё равно есть — двойная страховка, это не дубль CTA (она нейтральная, зелёная CTA на экране одна — «Предложить идею»).
- **Грабля моушена** ([motion.md](motion.md)): reveal догруженных карточек — по `setTimeout`, не `requestAnimationFrame` (rAF на паузе в фоне застрянет `opacity:0`).

### 1.6 Единственная зелёная CTA — «Предложить идею»

`PrimaryButton` (текст + круглая зелёная стрелка/«+», [components.md](components.md)). Стоит в верхней зоне справа от табов (десктоп) и **фиксируется внизу экрана** на мобайле (§7). Ведёт на форму подачи `#/issue/new` (§4). Второй зелёной кнопки на экране нет — правило «одна главная мысль на экран» ([layout.md](layout.md)).

**Гость (не авторизован):** CTA видна, но по тапу — не форма, а компактный overlay-промпт «Войдите, чтобы предложить идею» + кнопка входа (переиспользуем существующий флоу логина). Портал в v1 закрыт a priori (`docs/product/access.policy.md`) — лента и чтение идей гостю **недоступны**: `GET /ideas`/`GET /ideas/:id` без сессии отвечают 401, страница показывает не ошибку, а тот же overlay-промпт входа. Подача и голос — тоже под auth.

## 2. Карточка идеи в ленте (gradient card-действие)

Горизонтальная карточка на всю ширину контента — паттерн **крупной карточки-действия** ([components.md](components.md)): градиентная заливка, radius ≈28, тонкая `1px solid var(--border)`, кликабельна целиком → страница идеи (§3). В правом торце — **голосовалка** (§5): она перехватывает тап (голос без перехода), остальная площадь карточки ведёт на страницу.

### 2.1 Анатомия

```
┌───────────────────────────────────────────────────────────────────────┐
│  КАТАЛОГ · 3 дня назад                                      ┌────────┐  │  ← eyebrow: категория-чип · возраст
│                                                             │  128   │  │
│  Фильтр каталога по цвету филамента                         │  ▲     │  │  ← голосовалка (§5): счётчик + upvote
│                                                             │Голос-ть│  │     тап-таргет ≥48px, свой :active
│  Хочу отбирать модели по доминирующему цвету — сейчас       └────────┘  │
│  приходится открывать каждую…                       [● На рассмотрении] │  ← обрезка описания (2 строки) + статус-пилюля
└───────────────────────────────────────────────────────────────────────┘
```

- **Eyebrow-строка:** категория (мелкий чип или uppercase-текст) `·` относительный возраст («3 дня назад», из `created_at`). Приглушённый серо-зелёный.
- **Заголовок** — 1 строка Unbounded medium, `--text`, обрезка `…` по ширине. Тап → страница.
- **Обрезка описания** — 1–2 строки из markdown-`body`, **срендеренные в plain-text** (сниппет без разметки: заголовки/списки схлопнуты в текст, ссылки → текст-подпись), `-webkit-line-clamp: 2`, `--text-dim`. Полный md — только на странице идеи (§3.2).
- **Статус-пилюля** — `StatusPill` с тоном по §6. Для дефолтного статуса «предложена» пилюлю **скрываем** (яркость=важность: «предложена» = обычное, не событие; не зашумляем ленту массой одинаковых серых пилюль). Пилюля появляется, когда команда что-то со статусом сделала (на рассмотрении и дальше) либо статус негативный (отклонена/дубликат).
- **Голосовалка** — правый торец, вертикальная (счётчик над стрелкой). Подробно §5.

### 2.2 Состояния карточки

- **Проголосовано** — стрелка залита `--accent`, счётчик чуть ярче; повторный тап = отзыв (§5).
- **Своя идея** — голосовалка показывает счётчик, но upvote **задизейблен** (за свою идею не голосуют; факт «автор» — из payload). Тап по стрелке — тихо ничего (без ошибки), тап по карточке работает.
- **Дубликат/архив** в общей ленте не появляются (§1.4 фильтр); если пришли по прямой ссылке-срезу — карточка приглушена (opacity как dim-пилюля), голосовалка активна только у не-архивных.

## 3. Страница идеи (`#/issue/:id`)

Отдельный маршрут, **light-режим шапки** (как страница проекта: своя «парящая» композиция + кнопка «← назад», не wide-хром — [projects.page.md](projects.page.md) §1.2). Композиция — «парящая», по центру, без тяжёлых подложек.

### 3.1 Вертикальный ритм

```
  ← Назад                                                          ← IconButton (light-шапка)

  КАТАЛОГ · предложил @nick · 3 дня назад            [● На рассмотрении]   ← eyebrow-мета + статус-пилюля (§6)
  Фильтр каталога по цвету                                                 ← двухтоновый Heading (акцент — часть строки)

  ┌────────────── блок публичной причины ──────────────┐                  ← ТОЛЬКО для отклонена/дубликат (§3.3)
  └─────────────────────────────────────────────────────┘

  <markdown-рендер описания>                                              ← типографика MF-497 (§3.2)

  ┌──────── крупная голосовалка ────────┐
  │        128        [ ▲ Голосовать ]  │                                 ← счётчик + широкая upvote (§5, крупный вариант)
  └─────────────────────────────────────┘

  ─────────────────────────────────────────                               ← разделитель
  Обсуждение · 12                                                         ← заголовок треда
  [ поле комментария (md) · Отправить ]                                   ← ввод (auth)

```

### 3.2 Заголовок и markdown-описание

- **Заголовок** — двухтоновый `Heading`. Т.к. текст произвольный (юзер-контент), акцент-слово автоматически не выделишь — правило: **вся строка `--text`, без принудительного мятного слова**, кроме случая, где заголовок совпал с категорией (тогда категорию можно не подсвечивать). Двухтоновость держим на eyebrow (категория мятным опционально) — не ломаем чужой текст ради приёма.
- **Мета-eyebrow:** `КАТЕГОРИЯ · предложил @автор · возраст`. Автор — ник (профиль-ссылка `#/u/:username`), возраст из `created_at`.
- **Markdown-рендер** — **переиспользуем рендер и типографику GFM-подмножества из MF-497** ([projects.multiformat.md](projects.multiformat.md) §3): те же стили заголовков/списков/кода/ссылок/цитат, тот же санитайзер (**raw HTML вырезается всегда — XSS через описание невозможен**). Ноль нового рендера — тот же компонент, что описание проекта.

### 3.3 Статус-пилюля + блок публичной причины (новое, §6)

- **Статус-пилюля** справа от заголовка — `StatusPill`, тон и текст по §6.
- **Блок публичной причины — обязателен для `отклонена` и `дубликат`** (эпик: «отклонение и дубликат — только с публичной причиной»; DDL гонит это check'ом — Data §10). Это **не** тост и не мелкая подпись, а заметный блок под заголовком:
  - **Отклонена** — панель со стеклянной обводкой, коралловая иконка-точка + заголовок «Отклонена», ниже — текст `decline_reason` (обычный текст, не md). Коралл — единственное место красного акцента на всей странице ([palette.typography.md](palette.typography.md): коралл = деструктив/финальность). Голосовалка при этом **остаётся** (голоса — исторический сигнал), но приглушена.
  - **Дубликат** — та же панель, тон **dim** (не коралл — дубликат не «плохо», просто уже есть): «Дубликат идеи» + `decline_reason` + **обязательная ссылка на каноническую идею** («→ Смотреть оригинал», ведёт на `#/issue/:canonical_id`). Ссылка — крупная тач-цель (≥48px), не мелкий линк. Счётчик голосов канонической идеи — distinct по кластеру (Data: двойного счёта нет by design; UI просто показывает число из payload каноники).
- Для всех остальных статусов блок причины **отсутствует** (нет причины — нет блока).

### 3.4 Крупная голосовалка

Тот же компонент §5, **крупный вариант**: большой счётчик (Unbounded, ~48px) + широкая кнопка «▲ Голосовать» / «✓ Вы голосовали» (toggle). Тап-таргет ≥48px с запасом. Оптимистичный апдейт (§5). Своя идея → кнопка заменена спокойной подписью «Ваша идея» (без интерактива).

### 3.5 Тред обсуждения (`idea_comments`, плоский, инлайн)

**Собственная таблица `idea_comments`** (не форум — CTO+Fullstack 08.07). Плоский тред на идею (без вложенности-деревьев в v1). Инлайн-встраивание согласовано с Fullstack (§10 стык-3).

```
  Обсуждение · 12                                              ← заголовок + счётчик
  ┌ [ Ваш комментарий… (markdown)              ] [Отправить] ┐  ← composer (auth), textarea+md
  └──────────────────────────────────────────────────────────┘
  ┌──────────────────────────────────────────────────────────┐
  │ @nick · 2 ч назад                                        │  ← автор + возраст
  │ <md-рендер тела комментария>                             │  ← тот же санитайзер MF-497
  └──────────────────────────────────────────────────────────┘
  … (лента комментариев, новые снизу или сверху — §3.5 порядок)
```

- **Composer** — компактный md-редактор (лёгкий вариант MF-497: textarea + необязательный предпросмотр; тяжёлый тулбар не тащим для короткого коммента). Плейсхолдер «Ваш комментарий…». Кнопка «Отправить» — нейтральная (не зелёная: зелёная CTA страницы — это голос/подача, не коммент; чтобы не спорить за «одну главную мысль»). Только auth; гостю — строка «Войдите, чтобы комментировать».
- **Порядок** — новые **снизу** (хронология обсуждения читается сверху вниз, как чат/форум-тред). Догрузка старых — «Показать более ранние» сверху при длинном треде.
- **Тело коммента** — markdown, тот же санитайзер/рендер MF-497 (raw HTML вырезан).
- **Soft-delete под модерацию** (Data/Fullstack: `deleted_at`): удалённый комментарий — плейсхолдер «Комментарий удалён» (dim), автор/тело скрыты. Своё авторство — кнопка «Удалить» (коралловая, с подтверждением, [status.alerts.md](status.alerts.md): деструктив всегда коралловый).
- **Пусто** — «Пока нет обсуждения. Будьте первым» (§8).

## 4. Форма подачи идеи (`#/issue/new`)

Отдельный экран, **light-режим** + «← Назад». Композиция — «студийный момент»: ghost-input заголовка как герой экрана (референс AI-поиска главной, [components.md](components.md) «блок AI-поиска — призрачный»), под ним живой дедуп, дальше — описание и категория, снизу — ряд действий.

### 4.1 Вертикальный ритм

```
  ← Назад                                                    Осталось идей сегодня: 2 из 3   ← лимит показан ДО отправки

  ПРЕДЛОЖИТЬ ИДЕЮ                                            ← eyebrow
  О чём ваша идея?                                           ← ghost-input плейсхолдер (Unbounded, полупрозрачный)
  ┃ <caret>                                                    поле = крупный заголовок, без рамок (§4.2)

  ┌ Похоже, это уже предлагали ──────────────────────────┐   ← живой дедуп, появляется при вводе (§4.2)
  │ Фильтр каталога по цвету          128 ▲  [Голосовать] │
  │ Цветовой поиск моделей             47 ▲  [Голосовать] │
  └───────────────────────────────────────────────────────┘

  Описание                                                  ← md-редактор (MF-497 §3)
  ┌──────────────────────────────────────────────────────┐
  │ [Ж К ‹› • 1. H 🔗]   ⟦Редактор⟧ ⟦Предпросмотр⟧        │
  │ textarea…                                             │
  └──────────────────────────────────────────────────────┘

  Категория                                                 ← тайлы выбора (§4.4)
  [Каталог] [Проекты] [Форум] [ЛК] [Другое]

  ┌ ← Отмена ──────┐   ┌ Опубликовать идею            → ┐   ← ряд действий (secondary + зелёная primary)
  └────────────────┘   └─────────────────────────────────┘
```

### 4.2 Ghost-input заголовка + живая подсказка дубликатов (новое, §5-смежное)

- **Поле заголовка = призрачный hero-инпут** (паттерн `home` AI-поиска, [components.md](components.md)): Unbounded, крупный полупрозрачный плейсхолдер «О чём ваша идея?», без рамок/фона, акцентный caret. Лимит **120 символов** (Data check) — счётчик `n/120` появляется у поля при приближении к лимиту (>90), не мозолит глаза заранее.
- **Живой дедуп:** на ввод (debounce **250 мс**) — `GET /ideas/similar?q=` (§10), возвращает **≤5** похожих `[{id, title, vote_count, status}]` (триграммы `pg_trgm`, без AI). Под полем — панель «Похоже, это уже предлагали»: строки-результаты, у каждой — заголовок, счётчик, и кнопка **«Проголосовать»** — это **вариант голосовалки «вместо создания»** (§5): тап голосует за существующую идею прямо здесь и ведёт на неё (или показывает hero-успех «Голос учтён» и возвращает в ленту). Так дедуп даёт немедленную альтернативу, а не просто предупреждение.
  - Пусто (нет похожих) — панель не рисуем (не «0 результатов», просто нет блока).
  - Загрузка — тонкая мерцающая строка-скелет под полем (не спиннер).
  - Тап по строке-заголовку (не по кнопке) — открыть ту идею (новая вкладка/подтверждение, чтобы не потерять черновик — §4.6).
- **Дедуп не блокирует подачу** — это подсказка, не запрет: юзер вправе создать даже при похожих (по кнопке «Опубликовать»). Мягкое анти-дубль, не жёсткий гейт (эпик: только текстовый поиск, без автодедупа).

### 4.3 Описание (markdown)

**Переиспользуем md-редактор MF-497** ([projects.multiformat.md](projects.multiformat.md) §3): textarea + предпросмотр (сегмент-вкладки «Редактор»/«Предпросмотр»), лёгкий тулбар (Ж/К/список/заголовок/ссылка), тот же санитайзер. Ноль нового редактора. Необязательно (идея может быть в одном заголовке) — но плейсхолдер зовёт «Опишите подробнее: что и зачем».

### 4.4 Категория — тайлы выбора

Ряд **тайлов выбора** ([components.md](components.md), тот же примитив, что S/M/L): `Каталог · Проекты · Форум · ЛК · Другое`. Выбранный — зелёная заливка+свечение, остальные — тёмное стекло. Один выбор обязателен (дефолт — без предвыбора, «Опубликовать» дизейблена пока не выбрана категория; §4.5). Строковые enum-значения — за Data.

### 4.5 Лимит 3/сутки и отправка

- **Лимит показан ДО отправки** (эпик): в правом верхнем углу экрана — «Осталось идей сегодня: N из 3» (из payload/сессии; счёт по `ideas(author_id, created_at)` за сутки — Data индекс). При **N=0** форма подачи **заблокирована** заранее: поля dim, вместо «Опубликовать» — спокойная подпись «Лимит на сегодня исчерпан — вернитесь завтра» (не ошибка постфактум; уважаем время юзера — не даём заполнить и получить отказ).
- **«Опубликовать идею»** — зелёная primary (`PrimaryButton`), активна когда: заголовок непустой (≤120) И категория выбрана И лимит не исчерпан. Иначе — dim/disabled с понятной причиной у кнопки.
- **«Отмена»** — вторичная (нейтральное стекло, ← ), возврат в ленту; при непустом черновике — подтверждение «Удалить черновик?» ([status.alerts.md](status.alerts.md)).
- Двойного зелёного нет: одна primary на экран.

### 4.6 Успех — hero-иконка-кружок

После `POST /ideas` — полноэкранный **момент успеха** ([components.md](components.md) «hero-иконка-кружок», [layout.md](layout.md) «полноэкранные состояния»): крупный мятный круг с галочкой, «Идея опубликована», кнопка «Открыть идею» → `#/issue/:new_id` (+ вторичная «В ленту»). Не мелкий тост — это позитивный якорь возврата автора (метрика удержания эпика).

### 4.7 Ошибки формы (тексты)

| Ситуация | Текст | Где |
|---|---|---|
| Заголовок пуст | «Введите заголовок идеи» | под ghost-input, при попытке отправить |
| Заголовок >120 | «Заголовок — до 120 символов» + счётчик красным | у поля |
| Категория не выбрана | «Выберите категорию» | у тайлов |
| Лимит исчерпан (гонка) | «Лимит 3 идеи в сутки исчерпан» | тост-ошибка, кнопка dim |
| Сеть/500 при отправке | «Не удалось опубликовать. Попробуйте ещё раз» + черновик сохранён | тост, поля не сброшены |
| Гость (сессия истекла) | «Войдите, чтобы предложить идею» | overlay-промпт входа |

## 5. Голосовалка (новый компонент → components.md)

Переиспользуемый примитив: **счётчик голосов + upvote-toggle**, оптимистичный апдейт. Существует в трёх местах — карточка ленты (§2), страница идеи крупно (§3.4), строка дедупа «вместо создания» (§4.2). **Даунвоута нет** — только «за» и «отозвать» (эпик).

### 5.1 Анатомия и варианты

| Вариант | Где | Вид |
|---|---|---|
| **compact** | торец карточки ленты | вертикальный: счётчик над стрелкой ▲, тап-таргет ≥48×48 |
| **large** | страница идеи | крупный счётчик (Unbounded ~48px) + широкая кнопка «▲ Голосовать» |
| **inline** | строка дедупа формы | счётчик + кнопка «Проголосовать» (текст+иконка), «вместо создания» |

- **Тап-таргет ≥48px** (инвариант тача [layout.md](layout.md)), свой `:active` (сжатие), `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation`.
- **Состояния:** `не голосовал` (стрелка контурная, `--text-dim`) → `голосовал` (стрелка залита `--accent`, счётчик ярче, aria-pressed). Toggle: повторный тап = отзыв (delete строки, Data).
- **Оптимистичный апдейт:** тап немедленно меняет счётчик и вид (±1), затем `POST /ideas/:id/vote` (§10) подтверждает; на ошибку — откат счётчика + тихий тост «Не удалось. Попробуйте ещё». Флаг «голосовал ли юзер» и новый счётчик берутся из ответа (Fullstack §10).
- **Disabled-кейсы:** своя идея (§2.2) — стрелка dim, тап без эффекта; гость — тап открывает overlay-промпт входа (не молчит и не голосует вслепую); архив/удалённая — счётчик показан, upvote скрыт.
- **Один голос на идею** — гарантирует `unique(idea_id, user_id)` (Data); UI не считает уникальность сам, доверяет флагу из payload.
- **`aria`**: кнопка `role=button`, `aria-pressed` = голосовал, `aria-label="Голосовать за идею, сейчас N голосов"`; счётчик `aria-live=polite` чтобы SR озвучил изменение.

### 5.2 Моушен

Тап → микро-«подскок» стрелки + count-up счётчика на ±1 ([motion.md](motion.md): count-up, уважает `prefers-reduced-motion` — тогда просто мгновенная смена числа). Никакого пульса/звука (это не алерт — [status.alerts.md](status.alerts.md) пульс только для «требует внимания»).

## 6. Маппинг 8 статусов на палитру (новое → components.md)

Принцип **«яркость = важность»** ([status.alerts.md](status.alerts.md), [palette.typography.md](palette.typography.md)) применён к жизненному циклу идеи. Прогресс к «готово» = нарастание мятной яркости; негатив = коралл (ровно один); нейтральное/спящее = приглушённое серо-зелёное. **Даунвоутов и красных акцентов, кроме «отклонена», нет.**

Строковые значения enum — финально за Data (`text`+check, MF-559); ниже — канонический список из эпика и RU-подписи пилюль (Front берёт дословно, тон — из таблицы):

| Статус (значение) | Подпись пилюли | Тон / яркость | `StatusPill` | Заметки |
|---|---|---|---|---|
| предложена | *(скрыта в ленте)* | dim, серо-зелёное | не рисуем на карточке; на странице — тихая «Предложена» | дефолтная масса, не событие (§2.1) |
| на рассмотрении | На рассмотрении | мятный, **уровень 1** (faint) | `tone=ok level=1` | команда увидела |
| запланирована | Запланирована | мятный, **уровень 2** | `tone=ok level=2` | попала в план |
| в работе | В работе | мятный, **уровень 3** | `tone=ok level=3` | делается |
| готово | Готово ✓ | мятный, **уровень 4** (ярче всех) + галочка | `tone=ok level=4 done` | пик яркости, иконка-успех |
| отклонена | Отклонена | **коралл** (danger) | `tone=danger` | + обязательный блок причины (§3.3); единственный красный акцент |
| дубликат | Дубликат | dim, серо-зелёное | `tone=dim` | + ссылка на каноническую (§3.3); не «плохо», просто уже есть |
| архив | В архиве | dim, приглушённее прочих | `tone=dim` | автоархив 90 дней без активности; в ленте не показывается |

**Нарастание яркости (на рассмотрении→готово)** — это ключевое расширение `StatusPill`: сегодня примитив знает только `ok|warn|danger|dim` (бинарно). Нужен **уровень интенсивности `level: 1..4`** внутри `tone=ok`: точка-индикатор и текст идут по рампе `opacity`/свечения (уровень 1 ≈ 0.55 → уровень 4 = полный `--accent` + мягкий glow + галочка). Это GAP-2 (§10), фиксирую контракт в components.md.

**Почему так:**
- Пользователь на ленте мгновенно читает «моё предложение движется» по нарастающей мятности — без легенды.
- «Готово» — самый яркий + галочка: это и есть двусторонняя ценность эпика (видимый отклик), поэтому пик яркости именно здесь, а не на «в работе».
- Коралл строго один (отклонена) — деструктив/финальность; дубликат/архив **не** красные (они не наказание), а приглушённые.
- warn/янтарь в статусах идей **не используется** — очередь/срочность это про печать ([status.alerts.md](status.alerts.md)), у идей нет дедлайна-таймера. Единственное касание янтаря — ранг-акцент трендовой вкладки (§1.3), и то опционально.

## 7. Мобайл / планшет / тач-адаптив

Наследует тач-инварианты [layout.md](layout.md) (≥48px, `:active` вместо `:hover`, `touch-action: manipulation`, `-webkit-tap-highlight-color: transparent`, `user-select:none` на некликабельном). Дельта под идеи:

- **Лента (§1):** wide-`max-width` схлопывается в одну колонку с боковыми полями ~16–20px (клавиша `clamp()` от ~80px десктопа). Карточка остаётся горизонтальной; голосовалка не уезжает — она в торце, тап-таргет держит ≥48px.
- **Чипы-фильтры (§1.4):** горизонтальный momentum-скролл с fade-обрезкой по краям и `scroll-snap`, не перенос. Сегмент-табы (Популярные/Новые/Трендовые) — тоже скролл, если не влезают.
- **CTA «Предложить идею»:** на мобайле **фиксируется внизу** экрана (floating, поверх контента overlay-слоем, не раздвигает ленту — [layout.md](layout.md) фикс-хром). Одна, зелёная.
- **Форма (§4):** ghost-input заголовка масштабируется `clamp()`; панель дедупа — на всю ширину; тайлы категории — 2–3 в ряд с переносом; ряд действий (Отмена/Опубликовать) — липкий низ.
- **Голосовалка large (§3.4):** на мобайле счётчик над кнопкой (вертикально), кнопка на всю ширину контента.
- **Тред (§3.5):** composer липкий снизу при фокусе (системная клавиатура), комментарии — полная ширина.

## 8. Состояния: загрузка / пусто / ошибка (сводка)

Каждый экран проектируется во всех трёх состояниях. Используем `EmptyState`-примитив ([ui/ui.tsx](../../apps/web/src/ui/ui.tsx)) и правило «полноэкранные состояния процесса — hero, не мелкий спиннер» ([layout.md](layout.md)).

| Экран | Загрузка | Пусто | Ошибка |
|---|---|---|---|
| **Лента (§1)** | 3–5 карточек-скелетов (мерцающий градиент, не спиннер); табы/чипы сразу интерактивны | по фильтру: «Ничего не нашлось по фильтру. Сбросить?» + кнопка сброса. По вкладке без фильтров (пустой раздел на старте): hero «Пока нет идей. Предложите первую» + зелёная CTA | «Не удалось загрузить идеи» + «Повторить» (нейтральная); частичная (догрузка упала) — строка «Не удалось догрузить · Повторить» под лентой, уже показанное остаётся |
| **Страница идеи (§3)** | скелет заголовка+тела; голосовалка dim до загрузки счётчика | idea 404 (удалена/нет): «Идея не найдена» + «В ленту» | «Не удалось открыть идею» + «Повторить» / «В ленту» |
| **Дедуп формы (§4.2)** | тонкий строка-скелет под полем | нет похожих → блок отсутствует (не «0») | тихо: панель не показываем, подача не блокируется (дедуп — подсказка, его падение не должно ломать форму) |
| **Отправка идеи (§4)** | кнопка → спиннер-в-кнопке, поля залочены | — | §4.7 таблица ошибок |
| **Тред (§3.5)** | скелет 2–3 строк | «Пока нет обсуждения. Будьте первым» | «Не удалось загрузить обсуждение» + «Повторить»; отправка коммента упала → тост, текст в поле сохранён |
| **Голос (§5)** | оптимистично мгновенно | — | откат счётчика + тихий тост |

**Инвариант:** ни одно состояние не оставляет пустого экрана без действия. Ошибка всегда даёт «Повторить» или выход. Загрузка — скелет по форме контента, не крутилка по центру (кроме момента отправки).

## 10. Стыки и контракты (что UI читает/пишет) + GAP-лист

UI — **читатель** схемы Data (MF-559) и API Fullstack (стадия 2). Что нужно, чтобы Front не гадал:

**От Data (MF-559):**
- **Финальные строковые значения enum** — 8 статусов и 5 категорий (`text`+check). Подписи RU и тона — §6/§1.4 этой спеки; Front мапит `значение → {подпись, tone, level}`.
- **Payload карточки/списка:** как минимум `id, title, body(md), category, status, vote_count, created_at, author{username}, canonical_id`; для голосовалки — `viewer_has_voted` (флаг) и `is_author`; для дубликата — данные каноники (title/vote_count каноники или её id для дочитки).

**От Fullstack (стадия 2) — контракты, зеркалит существующий `models/vote.ts`.** *(Пути API ниже — серверные, слой `apps/api`; публичный **URL страницы** — `/issue` (§1 «Маршрут»), это разные вещи, API не переименовываем.)*
- `GET /ideas` — список: `tab(popular|new|trending)`, `category`, `status`, `cursor`; ответ `{items[], next_cursor}`. Тренд считает api (окно 30 дней).
- `GET /ideas/:id` — карточка (+ первый экран комментариев).
- `POST /ideas/:id/vote` — upvote/отзыв (toggle); ответ **`{vote_count, viewer_has_voted}`** — под оптимистичный откат (§5).
- `GET /ideas/similar?q=` — **≤5** `[{id, title, vote_count, status}]`, триграммы; под живой дедуп (§4.2), debounce 250 мс на клиенте.
- `POST /ideas` — создание (auth, `title≤120`, категория, `body` md); ответ `{id}` + актуальный остаток суточного лимита; под hero-успех (§4.6) и индикатор лимита (§4.5).
- **`idea_comments`** (§3.5): `GET /ideas/:id/comments` (пагинация), `POST /ideas/:id/comments` (md body). **Инлайн-встраивание треда на странице идеи** — согласовано: тред грузится тем же экраном (в `GET /ideas/:id` или отдельным `GET .../comments` — на усмотрение Fullstack; UI поддержит оба, но предпочитает первый экран комментариев в ответе идеи, чтобы не было второй «дыры загрузки»).
- **Гость vs auth:** какие поля/действия доступны без сессии (чтение — да; голос/подача/коммент — нет) — Fullstack подтверждает 401-семантику, UI показывает overlay-промпт входа.

## 12. Что НЕ меняем (границы)

- **Модераторский UI смены статуса** — не здесь (внутренний инструмент; здесь только как статусы выглядят читателю).
- **Форумный движок** — не ждём и не строим; комментарии = своя `idea_comments` (CTO+Fullstack 08.07).
- **Терминология/навигация витрины** («Проекты» и т.д.) — берём готовой (MF-497/508), не переизобретаем.
- **Формула тренда, DDL, роуты, санитайзер** — Data/Fullstack; UI их читает, не проектирует.
- **Анти-абьюз-механика** (цензы возраста, rate-limit, verified-гейт) — серверная, невидимая в UI, кроме дружелюбных текстов отказа (§4.7).
