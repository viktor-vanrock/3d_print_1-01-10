# UX-контракт публичного каталога материалов

**Статус:** решение UX для MF-11; продуктовый код не входит в этот документ.
**Область v1:** каталог филаментов (`kind=filament`). «Материал» в домене — линейка
бренда; цвет, диаметр и навеска — варианты этой линейки. Поэтому карточка списка
не притворяется отдельной карточкой каждого SKU.

## 1. Цель и границы

Каталог отвечает на вопросы «какие филаменты есть», «какая это линейка и у
какого бренда» и «есть ли нужный цвет/диаметр в вариантах». Он не является:

- формой добавления личной катушки — это существующие `MaterialPicker` и «Мои
  филаменты»;
- магазином: цена, наличие, оферы и покупка не показываются;
- редактором данных или источником новой карточки;
- каталогом смол, дерева и металла: в v1 список фиксированно ограничен
  `kind=filament`, хотя доменная модель допускает другие формы.

Название пользовательского раздела — **«Филаменты»**. В тексте карточки и API
сохраняем термин `material`, чтобы не смешать UX-ярлык с доменной сущностью.

## 2. Точки входа и маршруты

| Точка | Действие | Результат |
| --- | --- | --- |
| Основная навигация «Каталог → Филаменты» | Открыть каталог. | `/materials` |
| Прямая, сохранённая или внешняя ссылка | Открыть тот же список с URL-state. | `/materials?...` |
| Пикер «Мои филаменты», онбординг и рекомендация материала в проекте | Ссылка «Открыть каталог филаментов». Не заменяет выбор в текущем диалоге. | `/materials`; возврат в пикер не обещается в v1. |
| Плитка списка | Открыть конкретную линейку. | `/materials/:id` |
| Ссылка из карточки проекта на рекомендованный материал | Открыть ту же карточку. | `/materials/:id` |

`/materials/:id` использует UUID, пока API принимает и возвращает только `id`.
Будущий читаемый путь `/{vendor.slug}/{materials.slug}` не вводится как UI-алиас
без серверного резолвера и 301-правила: два канонических адреса одному объекту
противоречат правилу одного URL.

## 3. Листинг `/materials`

### 3.1 Композиция

На desktop: `HomeHeader`, заголовок «Филаменты», затем строка поиска и двухколоночная
область — sticky-сайдбар фильтров слева (около 264 px), адаптивная сетка справа.
Сетка считается от своей колонки, не от окна. На телефоне фильтры открываются
по кнопке «Фильтры» в bottom sheet; активные фильтры показываются числом на
кнопке, поиск остаётся над выдачей. Контрол «Сбросить фильтры» видим только при
непустом фильтре.

В списке всегда применяется скрытый параметр `kind=filament`; пользователь не
видит контрол «форма материала», чтобы не получить недоступные v1-сущности.

### 3.2 Поиск

Поле с лупой, понятным `aria-label="Поиск филаментов"`, плейсхолдером
«Название или бренд» и кнопкой очистки только для непустого ввода.

- Ввод ожидает 300 мс, затем обновляет `q`; запрос не отправляется на каждый
  символ.
- Поиск в v1 соответствует факту API: ищет только по имени линейки. Подсказка
  «Название или бренд» допустима лишь после расширения API на бренд; до этого
  используется точный текст «Название филамента».
- При изменении поиска или фильтра листинг начинается с первой страницы; старый
  ответ не должен перетирать более новый.

### 3.3 Фильтры v1

Каждый контрол ниже имеет одно значение: это сознательная граница текущего API,
а не упрощение значения фильтра.

| Контрол | URL / API | Поведение |
| --- | --- | --- |
| Бренд | `vendor=<slug>` | Одно значение. Список брендов не должен рисовать счётчики, пока API их не отдаёт; подойдут поле/селект с доступными значениями из отдельного справочника. |
| Тип пластика | `type=<slug>` | Один `Chip`-выбор: PLA, PETG, ABS, TPU, PA и прочие значения справочника. Подпись «Тип пластика», не «материал». |
| Цвет варианта | `color=<name>` | Одно значение. Это фильтр «у линейки есть хотя бы один такой вариант», а не выбор SKU. В плитке не обещаем, что именно этот цвет — единственный. |
| Поиск | `q=<text>` | Независим от фасетов; пустой параметр в URL не пишется. |

Фасеты не удаляют строки без данных молча. Однако отдельный `GapRow` из каталога
принтеров появляется только когда API научится возвращать число исключённых
`null`-записей: сейчас этого числа нет, поэтому выдумывать его нельзя.

### 3.4 Плитка линейки

Плитка — одна интерактивная ссылка с заметным focus-visible-контуром; её задача —
ответить «это нужная линейка?».

```
Бренд
Название линейки
Тип: PLA
Варианты: открыть карточку →
```

- Бренд — приглушённая строка над названием; название — главный текст.
- Тип берётся из `material_type.name`; `kind` не дублируется, поскольку весь
  экран уже про филаменты.
- Число, цвета, диаметры и навески вариантов не выводятся из листингового
  ответа: их там нет. Нельзя делать N+1 запрос `GET /materials/:id` на сетку.
- У линейки нет медиа в листинговом контракте; пока его нет, плитка текстовая,
  без ложной фотозаглушки и без пустой зоны 16:9.
- Клик/Enter открывает `/materials/:id`; неинтерактивные подписи не конкурируют
  с одной крупной зоной нажатия.

### 3.5 Пагинация

Страница содержит 24 линейки (`limit=24`), `offset=(page-1)*24`. При
`has_more=true` под сеткой есть кнопка «Показать ещё»; во время запроса —
«Загрузка…» и `disabled`. Новые плитки добавляются после уже показанных без
скачка к началу. API возвращает `total` как метаданные отфильтрованной выдачи, но «страница N из
M» и счётчик результатов в UI v1 не выводятся.

При фильтре/поиске `page` сбрасывается в 1. После «Показать ещё» URL меняется
через `replaceState`, чтобы возврат не требовал проходить историю каждой страницы.

## 4. Карточка `/materials/:id`

Вверху — breadcrumb «Каталог → Филаменты», затем бренд, название линейки и
`material_type.name`. Ниже — блок **«Варианты»**: каждая строка/чип даёт цвет
(`color_name`, при наличии — цветовой swatch с текстовой подписью), диаметр и
навеску, если они переданы. Цвет никогда не различается только цветом.

Отсутствующее значение варианта не заменяется прочерком: строка просто не
содержит соответствующую мету. Если вариантов нет, показывается честный текст
«Варианты ещё не добавлены», а не пустая сетка.

Если API возвращает `make_stats`, можно показать нейтральный блок «Напечатано с
этим материалом» только с реально заполненными агрегатами; если список `makes`
пуст, блок не превращается в ошибку. Расширенные `specs` отображаются лишь после
отдельного правила маппинга ключ→русская подпись/единица: сырой JSON пользователю
не показывается.

Действие карточки — вторичная кнопка «Сообщить о неточности» через
`ContextFeedbackDoor` с `ref={type:"filament", id, title}`. Кнопка «Добавить в
мои филаменты» не входит в публичный каталог этим контрактом: существующий
авторизованный флоу пикера сохраняет единый путь добавления и выбор варианта.

## 5. Состояния и восстановление

| Состояние | Листинг | Карточка |
| --- | --- | --- |
| Загрузка | 24 нейтральных skeleton-плитки; фильтры остаются доступны. | Skeleton заголовка и блока вариантов. |
| Первый пустой каталог | `EmptyState`: «Каталог филаментов пока наполняется»; без «сбросить». | Неприменимо. |
| Пусто после поиска/фильтров | `EmptyState` с лупой: «Ничего не найдено», вторичная кнопка «Сбросить фильтры». Сбрасывает `q`, `vendor`, `type`, `color`, `page`. | Неприменимо. |
| Ошибка сети/5xx | Сообщение «Не удалось загрузить каталог» и кнопка «Повторить»; ранее загруженные плитки не очищаются до успешной замены. | «Не удалось загрузить материал» + «Повторить» и ссылка в каталог. |
| 401 | Единый входной экран/оверлей сайта, а не ложное «ничего не найдено». | То же. |
| 404 | Неприменимо. | «Материал не найден»: причина не раскрывается; CTA «В каталог филаментов». |

## 6. URL-state

Канонический порядок параметров: `q`, `vendor`, `type`, `color`, `page`.
Пустые и дефолтные значения не пишутся; `kind=filament` также не пишется, так как
это инвариант маршрута. Примеры:

```text
/materials
/materials?q=matte&type=pla
/materials?vendor=rec&color=black&page=3
/materials/4d1e2f5c-0000-4000-8000-123456789abc
```

Неизвестные параметры игнорируются при разборе и не переносятся после следующего
изменения состояния. Невалидный `page` нормализуется к 1; `page` транслируется в
API `offset`, но не становится частью публичного контракта API. Из URL нельзя
установить `limit` выше 24.

## 7. Конфликты и условия передачи

| Поле или ожидание | Факт сейчас | Решение / владелец |
| --- | --- | --- |
| «Публичный» каталог | `GET /materials` и `GET /materials/:id` отвечают 401 без сессии. | **Product/Back:** подтвердить, что «публичный» означает доступный любому вошедшему, либо снять auth-gate. До решения Front обрабатывает 401 как вход, а не как пустоту. |
| Поиск по бренду | API ищет `m.name`, не `vendor.name`. | **Back:** добавить поиск по бренду, прежде чем обещать его в placeholder/acceptance Front. |
| Набор брендов/типов/цветов и их counts | API принимает один фильтр, но не выдаёт справочник и counts. | **Back:** endpoint фасетов либо явно назначенный источник данных. **Design:** не рисовать нулевые/количественные фасеты без него. |
| Мультивыбор брендов/типов/цветов | Один query-параметр каждого вида; сервер реализует одиночное значение. | **UX v1:** одиночный выбор. **Back:** расширение повторяемых параметров — отдельная карточка и решение о AND/OR. |
| Диаметр, навеска, наполнитель, температура | В базе есть часть данных, но list API не фильтрует и не возвращает варианты. | **UX v1:** не выводить фасеты. Нужны отдельный API-контракт и правило «неизвестное не молчит». |
| Медиа, цена, наличие, сортировка | Их нет в list response/контракте. | Не проектировать визуальные поля и сортировку «на вырост». Это отдельные продуктовые решения. |
| Читаемый URL | Домен допускает `vendor.slug + materials.slug`, API-detail принимает UUID. | До резолвера каноничен UUID. Не добавлять второй UI-адрес. |
| Маршрутизация веба | `router.ts` ещё не разбирает `/materials` и `/materials/:id`. | **Front:** добавить оба маршрута и deep-link/F5 serving; не использовать hash-маршрут. |

## 8. Передача в Design и Front

### Acceptance для Design

- Есть desktop и mobile-состояния списка, сайдбара/bottom sheet, плитки и detail.
- Цвет варианта передан swatch+текстом и не является единственным носителем смысла.
- Отрисованы loading, первый empty, empty по фильтру, ошибка, 401 и 404; они не смешаны.
- Нет UI-полей, которые отсутствуют в list API: фото, цены, count вариантов, диаметры,
  сортировка и фасетные counts.
- Действия соответствуют иерархии: на листинге нет ложного primary; в detail есть
  нейтральное сообщение о неточности.

### Acceptance для Front

- Роуты `/materials` и `/materials/:id` работают при прямом входе, F5 и Back.
- Список вызывает `GET /materials?kind=filament&limit=24` и добавляет только
  поддержанные query-параметры; detail вызывает `GET /materials/:id`.
- Debounce поиска 300–400 мс, отмена/игнорирование устаревшего ответа и сброс
  `page` при смене фильтра покрыты тестами.
- URL-state сериализуется в заданном порядке без пустых параметров; `page` правильно
  преобразуется в `offset`.
- «Показать ещё» использует `has_more`, не дублирует уже показанные записи и имеет
  disabled-состояние запроса.
- Плитка не делает detail-запросов для сетки; карточка не выводит сырой `specs`.
- Проверены keyboard focus/Enter, понятные labels и все состояния из §5.

## 9. Вне объёма этой карточки

Реализация Front/Back/Design, API-фасеты и их расширение, публичный доступ без
сессии, импорт и полнота данных, коммерческие оферы, личный склад катушек и
изменения существующего пикера. Для каждого из них нужна отдельная атомарная
карточка после решения конфликта из §7.
