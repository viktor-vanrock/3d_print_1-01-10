# `/materials` — публичный каталог материалов: листинг и фильтры

[`apps/api/src/catalog/materials.ts`](../../apps/api/src/catalog/materials.ts) · детальная
карточка — [material.face.md](material.face.md).

**Статус.** Контракт дизайна для MF-11 / MF-1466. Экран помогает выбрать линейку материала и
перейти к её вариантам; это не витрина магазина, не склад пользователя и не мастер совместимости
с принтером. Ни цена, ни наличие, ни «совместимо с моим принтером» в API не приходят — их здесь
не имитируем.

**Граница ответственности.** Сценарий входа, смысл фильтров и URL принадлежат UX-контракту
MF-1465; эта страница фиксирует визуальную форму и не расширяет API. Если его договорённость
потребует иной route или текста, UX меняет её явно, а не реализация молча. Ниже зафиксирован
фактический `GET /materials` на 2026-07-13, поэтому Front может работать без догадок.

## 1. Данные, которые экран вправе показывать

### 1.1 Листинг

`GET /materials` возвращает `materials[]`, `total`, `limit`, `offset`, `has_more`; дефолтный
размер страницы — 24, API принимает максимум 100. `total` — число материалов после фильтрации,
до применения `limit`/`offset`. Каждая плитка получает только:

| Поле API | Отображение | Нельзя выводить из него |
|---|---|---|
| `name` | заголовок линейки | вес, температуру, конкретный цвет |
| `vendor.name` | бренд над заголовком | логотип: отдельного asset-поля нет |
| `material_type.name` | тип материала, тихая мета | состав/свойства типа, если их нет в ответе |
| `kind` | нейтральная метка класса: `filament` → «Филамент», `resin` → «Смола», `plywood` → «Фанера», `aluminum` → «Алюминий» | другой перевод или новый класс |
| `id` | ключ плитки и адрес детальной `/materials/<id>` | публичный slug-адрес: detail API принимает только UUID |

`specs` в списке — свободный JSON без стабильной публичной схемы. В листинге он не рендерится.
Также в списке нет вариантов, изображений, количества результатов, доступных значений фасетов и
сортировки. Поэтому у плитки нет выдуманной катушки, свотчей, цен, счётчиков «(12)» и сортировки
«популярные».

### 1.2 Фильтры и URL

Один источник правды — query string. Из неё собирается запрос и восстанавливается экран при
back/forward или прямой ссылке. Значения URL кодируются обычным URL encoding; пустое значение
параметра удаляется.

| Контрол | Параметр | Фактический контракт | Вид и поведение |
|---|---|---|---|
| Поиск | `q` | строка до 200 символов, поиск только по `materials.name` | поле с лупой и `×`; задержка 350 мс; Enter применяет сразу |
| Бренд | `vendor` | один UUID **или** slug | один select/search-list; выбранное значение — чип с удалением |
| Тип | `type` | один slug `material_types` | один select/search-list; не мультивыбор |
| Класс | `kind` | `filament`, `resin`, `plywood`, `aluminum` | один сегмент из четырёх; нет значения «все» в URL |
| Цвет | `color` | свободная строка, матчится по `material_variants.color_name` | текстовый поиск цвета, не палитра и не hex-picker |
| Страница | `limit`, `offset` | offset-пагинация, `has_more` из ответа | Front задаёт `limit=24`; «Показать ещё» увеличивает `offset` на размер реально полученной страницы |

Смена любого фильтра или `q` сбрасывает `offset` в 0. Параметров для сортировки, диапазона
температуры, диаметра, веса, производителя в множественном числе и подсчёта фасетов API не даёт;
не добавлять их в UI «на будущее».

## 2. Листинг: композиция и компоненты

### 2.1 Рабочая страница, не hero

`HomeHeader` остаётся видимым, активный раздел — «Материалы» (если итоговая IA MF-1465 назовёт
его иначе, сохраняем только это место в шапке). Под ним компактный eyebrow `КАТАЛОГ МАТЕРИАЛОВ`,
заголовок `Материалы для печати` (Unbounded) и одна строка-пояснение: «Найдите линейку по бренду,
типу или цвету». Это каталог, поэтому поиск — рабочее поле, а не домашний ghost-input.

На широком экране фильтры стоят слева, результаты — справа; композиция наследует
`printers.catalog.md`, но без ложной сложности его шести фасетов.

```
┌──────────────────────────────────────────────────────────────────────┐
│ HomeHeader                                                   [капсула]│
├──────────────────────────────────────────────────────────────────────┤
│ КАТАЛОГ МАТЕРИАЛОВ                                                   │
│ Материалы для печати                                                  │
│ Найдите линейку по бренду, типу или цвету                             │
├───────────────────┬──────────────────────────────────────────────────┤
│ ФИЛЬТРЫ           │  Результаты                         [Сбросить]   │
│ [🔍 Поиск      ×] │ ┌────────────────┐ ┌────────────────┐            │
│ БРЕНД             │ │ Бренд          │ │ Бренд          │            │
│ [Выбрать бренд ▾] │ │ Название       │ │ Название       │            │
│ ТИП               │ │ Тип · класс    │ │ Тип · класс    │            │
│ [Выбрать тип   ▾] │ └────────────────┘ └────────────────┘            │
│ КЛАСС             │ ┌────────────────┐ ┌────────────────┐            │
│ [Филамент][Смола] │ │ …              │ │ …              │            │
│ [Фанера][Алюминий]│ └────────────────┘ └────────────────┘            │
│ ЦВЕТ              │                 [ Показать ещё ]                 │
│ [Например, чёрный]│                                                  │
└───────────────────┴──────────────────────────────────────────────────┘
```

Сайдбар 264px, `position: sticky` ниже шапки; правая сетка использует container query и переходит
4 → 3 → 2 плитки по ширине **правой** колонки. Внешние поля и ритм — из `layout.md`; gap сетки
16–18px. У каталога нет единственной hero-метрики и нет primary-CTA: единственное зелёное
действие на нём не требуется.

### 2.2 `MaterialTile`

Плитка — интерактивная единица контента: тёмное стекло, `border: 1px solid var(--border)`,
радиус 22–24px, min-height 152px, целиком ссылка. Нет фальшивого product-photo: в верхней части
нейтральная графическая метка `MaterialMark` — круглая нить/слой, построенная CSS/SVG из
`--text-dim`; она не кодирует цвет и не обещает фото.

Порядок контента: `vendor.name` (eyebrow) → `name` (2 строки с ellipsis) →
`material_type.name · локализованный kind`. Если строка типа отсутствует вопреки контракту,
скрывается только она — не рисуется «—». Видимый keyboard focus — мятный outline с offset,
`aria-label="Открыть материал {brand} {name}"`; вся плитка имеет min-height 48px и
`touch-action: manipulation`.

При hover/focus плитка приподнимается на 2px и усиливает border; на touch только короткое
сжатие (`:active`). Переход opacity/transform 160–200ms, а `prefers-reduced-motion` отключает
перемещение. Никакого бесконечного свечения: выбор материала — обычная навигация.

### 2.3 Фильтры

`FilterSelect` — не нативный незаметный select: поле 48px, label через `Eyebrow`, понятный
placeholder «Выбрать бренд» / «Выбрать тип», chevron и отдельная строка выбранного значения.
Поскольку API не отдаёт справочник фасетов, реализация получает допустимые значения только из
согласованного UX data source; пока его нет, контрол не притворяется полноценным списком и может
принять точное значение/slug через поиск. Создавать отдельный запрос за фасетами в этой задаче
нельзя.

`kind` — сегментный контрол с четырьмя равными кнопками; выбранная — мятная заливка, остальные
нейтральное стекло. У кнопок `aria-pressed`, навигация стрелками внутри группы и минимум 48px.
`color` — обычное поле с подсказкой «Например, чёрный»; введённое значение показывается таким же
чипом активного фильтра над сеткой, но не пытается стать цветовым образцом.

Если есть хотя бы один параметр `q`, `vendor`, `type`, `kind` или `color`, над сеткой возникает
строка «Активные фильтры» с удаляемыми чипами и нейтральной текстовой кнопкой «Сбросить». Сброс
очищает только эти пять параметров и `offset`; `limit` остаётся 24. `total` доступен как API-
метаданные, но UI v1 не обязан выводить счётчик результатов.

### 2.4 Догрузка

После первой страницы кнопка «Показать ещё» существует только при `has_more=true`. Во время
запроса она становится `aria-busy`, текст — «Загружаем…», уже показанные плитки не исчезают.
Новая порция появляется без прыжка scroll; фокус остаётся на кнопке. Когда `has_more=false`,
кнопка и завершающая декоративная строка отсутствуют. Несмотря на наличие `total` в API,
текст «Вы посмотрели все N» в UI запрещён: состояние завершения определяется `has_more`.

## 3. Мобильный режим

До 900px двухколоночная форма распадается: заголовок остаётся сверху, а «Фильтры» — кнопка
вторичного стекла 48px рядом с полем поиска. Она открывает bottom sheet с теми же контролами,
не отдельную страницу. В sheet:

1. заголовок «Фильтры» и `IconButton` закрытия;
2. бренд, тип, класс, цвет в том же порядке;
3. закреплённая снизу единственная primary-кнопка «Показать результаты» — закрывает sheet,
   URL уже синхронизирован, нового запроса по второму источнику не создаёт.

Сетка 2 колонки сохраняется до минимальной ширины плитки 148px, затем одна колонка. Весь экран
прокручивается одной осью; sidebar не становится горизонтальной лентой. Sheet закрывается свайпом,
Escape и кнопкой `×`, удерживает фокус и возвращает его в «Фильтры»; overlay не закрывает текущие
результаты в DOM для screen reader. На маленьком экране плитка не теряет бренд и тип: лишь
`MaterialMark` уменьшается.

## 4. Переход в карточку

Вся `MaterialTile` — одна ссылка на `/materials/<id>`; отдельная иконка «открыть» и вложенные
интерактивные элементы запрещены. Адрес строится только из UUID `id`, не из `slug`: detail API
принимает UUID. Возврат из карточки сохраняет текущую строку запроса каталога. Анатомия detail,
варианты, печати и все её состояния — единственный источник [material.face.md](material.face.md).

## 5. Честные UI-состояния листинга

| Состояние | Листинг |
|---|---|
| Первичная загрузка | шапка и фильтры доступны; 8 skeleton-плиток геометрии `MaterialTile` |
| Догрузка | старые плитки остаются; skeleton только после сетки/на кнопке |
| Пусто без фильтров | `EmptyState`: «Каталог материалов пока пуст»; вторичная «Обновить» |
| Пусто с фильтрами | «По этим условиям материалов нет» + «Сбросить фильтры»; панель остаётся доступной |
| Ошибка сети/5xx | inline в месте сетки: «Каталог не отвечает. Обновить»; header и фильтры живы |
| 401 | глобальный prompt входа с сохранением текущего URL; не маскировать под пустой каталог |

Листинг API сейчас требует сессию. Это конфликт с определением «публичный» у соседнего каталога
в `nav.sections.md §4`; дизайн не скрывает его, но Front не должен выпускать страницу для гостя
как фальшивую открытую витрину. После решения API-вопроса состояние 401 можно заменить на
свободное чтение, не меняя анатомию экрана.

## 6. Передача Front и критерии готовности

- Использовать существующие токены `--bg`, `--surface`, `--border`, `--text`, `--text-dim`,
  `--accent`, `--accent-warn`, `--accent-danger`; новые цвета и шрифты не нужны.
- `MaterialTile`, `FilterSelect`, `MaterialMark`, active-filter chips и skeleton должны быть
  компонентами, а не уникальной разметкой маршрута. Переиспользовать существующие `IconButton`,
  `EmptyState`, overlay и header.
- Любое действие доступно с клавиатуры, focus виден, все интерактивные цели ≥48px; цвет никогда
  не единственный носитель значения. Проверить desktop, tablet и mobile, а также reduced motion.
- Проверить контрактом: `q`, `vendor`, `type`, `kind`, `color`, `limit`, `offset`, `total`, `has_more`,
  401 и 404. Ни один UI-элемент не должен требовать поля, которого `GET /materials` или detail
  реально не возвращает.

Открытый вопрос для UX/API, а не для Front: откуда берётся список допустимых брендов и типов для
`FilterSelect`. Текущий `/materials` даёт фильтрацию, но не фасеты; до появления явного источника
контрол обязан оставаться поисковым/вводным и не показывать придуманные варианты.
