## 1. Архитектурные решения (зафиксированы, фазы на них стоят)

1. **Роутинг** — лёгкий хэш-роутер из спеки §1 (`#/market`, `#/market/model/:id`, `#/u/:username`), без react-router. Шаринг ссылок и Web Share стоят на этих маршрутах.
2. **Поиск (MVP)** — `GET /models?q=` с `ILIKE` по `title`/`description` + индекс по необходимости. Это осознанно примитивно: семантический поиск — отдельный эпик [neural.search.md](neural.search.md) (pgvector, giga), UI поиска проектируется так, чтобы замена бэкенда ничего не ломала (тот же инпут, тот же параметр).
3. **Ассет 3D-вьюера** — mesh-воркер при конвертации дополнительно кладёт в S3 `model_files.role='preview'` в формате **GLB (binary glTF)**: децимация до ~150k треугольников, целевой вес ≤5 МБ. Фронт грузит его three.js `GLTFLoader`. Почему не canonical 3MF во вьюер: 3MF — ZIP/OPC-контейнер под слайсеры, парс в браузере тяжелее и тянет полный полигонаж; GLB — нативный веб-формат. Канонический 3MF остаётся единственным форматом хранения/выдачи ([3mf.storage.md](3mf.storage.md)) — preview лишь производный артефакт.
4. **Превью каталога** — тот же mesh-воркер рендерит **webp-миниатюру** (offscreen-рендер), кладёт как отдельный файл; карточка каталога вставляет её в готовый слоёный стек (`.homeModelLayer*` уже принимает `<img>` — спека §2.3).
5. **«Сжатый 3mf»** — 3MF уже ZIP-контейнер; в конвертере проверить/включить deflate у lib3mf, зафиксировать в тестах, что выход меньше сырого STL. Отдельного формата «сжатый 3mf» не существует — требование закрывается компрессией контейнера.
6. **«Любой формат» загрузки** — MVP честно: STL/OBJ/3MF (что реально конвертируем). STEP — открытый вопрос §4 (нужен OCC/FreeCAD-headless, отдельная итерация MF-337). UI не обещает форматов, которых нет.
7. **Комментарии** — по [domain.model.md](domain.model.md): полиморфная таблица `comments (subject_type, subject_id, user_id, body, created_at)`, чтобы та же сущность позже вешалась на makes/посты. MVP — плоский список, без веток/реакций/модерации. **Решение Architect (2026-07-05, из §11.5 ревизии v2):** схема заводит `parent_id uuid nullable references comments(id)` сразу — это примиряет domain.model.md §57 («древовидные») с плоским MVP: задел бесплатный, снимает будущую миграцию; UI стадии 4 `parent_id` игнорирует (рисует плоско).
8. **Makes («я напечатал»)** — таблица `makes` (model_id, user_id, фото в S3, подпись, created_at); machine_id — nullable-задел, не обязателен. Это первый шаг make-галереи из docs/product/features.md, не полная соцлента.
9. **«Отправить в печать»** — кнопка проектируется и ставится **заглушкой** (disabled + «скоро»): реальная отправка требует коннективности принтеров (линия MF-26), в этот эпик не входит.
10. **«Поделиться»** — Web Share API, фолбэк «копировать ссылку» (+тост). Никакого сервера — только deep-link маршрута.
11. **Статистика владельца (MVP)** — голоса, скачивания, дата, число комментариев/makes. Счётчик просмотров — открытый вопрос §4 (не заводим молча).
12. **Голоса** — up/down стрелки, уже решено и лежит в БД (MF-462); UI — Reddit-паттерн из спеки §5.

### 1.1. Решения итерации v3 (2026-07-05, по фидбэку Валерия на прод стадии 2)

Фидбэк дословно (комментарий в MF-463): превью модели не грузится («ошибка загрузки»); интерфейс «чутка скомканный» — использовать больше страниц; отработать алгоритм создания прозрачных картинок без фона; «представь, что мы ставим модельку, создаём тени и всё такое и фотками».

13. **Выдача preview-ассетов — API-прокси, НЕ presigned.** Диагноз бага вьюера: MinIO на VDS живёт на loopback (`S3_ENDPOINT=http://127.0.0.1:9000`), presigned URL подписываются этим хостом — браузер их физически не достаёт → `GLTFLoader` падает → «Не удалось загрузить превью». Решение: API стримит ассеты сам — `GET /models/:id/preview.glb`, `GET /models/:id/thumb.webp` через `GetObject`-stream за той же сессионной авторизацией, с `ETag`/`Cache-Control: private, max-age=…`. `preview_url` в `GET /models/:id` становится путём API. Отклонённая альтернатива — публичный поддомен/nginx-прокси до MinIO + `S3_PUBLIC_ENDPOINT`: лишняя публичная поверхность, presigned-подпись пришлось бы делать вторым клиентом; MinIO остаётся приватным. Пересмотреть, если трафик ассетов станет заметной нагрузкой на Node.

   **Контракт ассет-эндпоинтов (реализовано, MF-470):**

   | Эндпоинт | Content-Type | Cache-Control | Что отдаёт |
   |---|---|---|---|
   | `GET /models/:id/preview.glb` | `model/gltf-binary` | `private, max-age=…` | Бинарный glTF (GLB) модели, ~150k tri, ≤5 МБ, за сессионной авторизацией |
   | `GET /models/:id/thumb.webp` | `image/webp` | `private, max-age=…` | WebP-миниатюра, 512px, строго прозрачный фон (см. п.15) |

   Оба стримятся через `GetObject` с `ETag`; при отсутствии ассета — 404 (клиент падает в фолбэк-цепочку §1.13/п.15).
14. **`model_files.role`: добавить `'thumbnail'`** в check-констрейнт (запрос Python-агента из MF-466 — объект `thumb.webp` в S3 уже лежит, строка отбивается констрейнтом). Идемпотентная миграция, как MF-453/462.
15. **Студийные «фото» модели (прозрачные картинки, тени, постановка).** Контракт зафиксирован Systems designer (коммит `8860277`, [docs/design/model.preview.md](../design/model.preview.md) § «Разделение ответственности»): «студия» (mesh-воркер) отдаёт **один силуэт на строго прозрачном фоне** (RGBA, ракурс ¾, матовый нейтральный материал, квадрат с полем, диффузная светотень) — ни фона, ни тени в пикселях; **постановку** (амбиент-свечение, псевдо-объём, дышащую тень пола) собирает CSS-стек на клиенте — так одна webp переиспользуется в каталоге/постере/make-гриде и адаптируется к теме. Зона mesh: качество рендера в рамках контракта (сглаживание/разрешение/свет; headless/CPU — VDS без GPU), запись `role='thumbnail'` (после п.14) и **бэкфилл превью-ассетов для уже загруженных моделей** (у всего `ready`-каталога должны появиться GLB+webp — иначе старые модели так и будут падать в ошибку/мок). Мультиракурсные `photo.{n}` НЕ делаем: интерактив закрывает живой GLB-вьюер, второй набор кадров — усложнение без потребителя.
16. **Многостраничность.** Оценка Валерия: текущий UI скомкан — «по возможности используй больше страниц». IA-решение зафиксировано Systems designer ([docs/design/marketplace.v2.md](../design/marketplace.v2.md) §9.5, коммит `8860277`), принцип «страница = одна задача»: главный кандидат — **флоу «Добавить модель» → своя страница `#/market/add`** (вместо модалки над каталогом); соцблоки страницы модели — вкладки-подмаршруты (реализуются на стадии 4); поиск/фильтры остаются в каталоге (их лечит раскладка §1-v2, не роут). Реализация — TypeScript (стадия 6).
