## Проверенные сценарии

- `/park`, аккаунт с 14 принтерами: список карточек на `ActionCard`, шапка «Мой парк» + единственный зелёный CTA «+ Добавить принтер», сводка «14 принтеров · 0 печатает · 0 на связи» — соответствует §1.1/§1.2/§4.
- Список одинаково раскладывается в одну колонку на desktop/tablet/mobile, без clipping/overflow карточек; cookie-баннер — сквозной сайтовый компонент, не специфичен для `/park`.
- `list`-уровень (`Creality Ender-3 V3 KE`, бейдж «В каталоге»): тап открывает форму редактирования, URL остаётся на `/park` — не ломает диплинк, соответствует §1.1 («list-уровень... карточка просто открывает форму редактирования»).
- Управляемых/custom-принтеров (`managed`/`custom`) с деплинком на `/printer/:id` в этом тестовом аккаунте нет — переход `/park → /printer/:id` не переисследован живьём в этом прогоне; путь не тронут в рамках MF-1586-скоупа (переиспользует уже принятый `printerlivescreen.tsx`, MF-953) и был предметом отдельной QA-приёмки MF-1081.
- Пустое состояние (`EmptyState`, единственный CTA в `/park/add`) не воспроизведено живьём — в наличии нет dev-аккаунта с нулём принтеров; поведение подтверждено по коду (`parkscreen.tsx:267-277`) и юнит-тестом `parkscreen.test.tsx:80-85` («показывает в пустом парке один акцентный сценарий добавления»).
- Фактический статус пилота сверен с контрактом, не с предположением: `GET /printers/creality.ender-3-v3-ke` и `GET /printers/flsun.v400` на dev возвращают `pilot_status.status="reported"`, `stage="not_started"`, `freshness="stale"` для обеих моделей (2026-07-18, дедлайн свежести 24ч истёк ещё 2026-07-12/13) — совпадает с `packages/contracts/http/fixtures/firmware-pilot.v1.json`. Состояния `building`/`burn_in`/`ready`/`stopped` Fleet ещё не публиковал НИ на dev, ни во фикстурах контракта — живьём не воспроизводимы в этом прогоне; их текст/тон проверен по исходникам и юнит-тестам (см. MF-1868).
- `/printers/creality.ender-3-v3-ke` и `/printers/flsun.v400` (каталожная карточка модели, §3.4 «на карточке модели `/printers/<slug>`») на dev отдают «Такого принтера у нас пока нет» — экран сидит на статическом `listPrintersFixture()` (`apps/web/src/printers/printerdetailscreen.tsx:181`), а не на живом `GET /printers/:slug`, поэтому ни один реальный slug каталога сегодня не открывается. Это дочерний виджет пилота на карточке модели был помечен «если есть время» в MF-1081 и не входит в обязательный скоуп MF-1586/1589 — фиксирую как наблюдение, отдельную карточку не завожу (не new regression от pilot-виджета, а более широкий и явно pre-existing разрыв каталога с API, вне контура «Девайсы: коннектор»).

## Детали дефектов

### MF-1867 — виджет пилота показывается на всех карточках парка

`PilotRow` (`apps/web/src/park/parkscreen.tsx:88-99`) не проверяет `PilotInfo.visible` перед рендером — в отличие от `CatalogPilotRow` (`apps/web/src/printers/printerdetailscreen.tsx:420-422`), где `if (!info.visible) return null;` уже есть. Итог на dev: строка «Пилот прошивки: нет данных о пилоте» видна на всех 13 непилотных карточках теста (`Agent final-check-back`, `Creality Ender-3 V3 SE` ×3, `Agent MF-930 relay live-check`, `Agent printer`, `Klipper MF-1511...` ×2, `Klipper MF-1331...` ×3, `Klipper MF-1330...`), нарушая §3.1/§3.4/чеклист §4 («виджет пилота — только на карточках Ender-3 V3 KE и FLSun V400»). Воспроизведено одинаково на всех трёх viewport.

### MF-1868 — текст/тон виджета не по спеке §3.2–3.3

`pilotInfoFor()` (`apps/web/src/park/firmwarepilot.ts`) для «свежего» факта интерполирует сырое значение `status.stage` (`not_started`/`building`/`burn_in`/`stopped`/`ready`) вместо русского текста из §3.2 — подтверждено самим тестом `parkscreen.test.tsx:317` (`Пилот прошивки: ${stage}` заложен как ожидаемый результат). `stage="stopped"` не обособлен как отдельное состояние (нет текста «остановлено», нет `tone="warn"`). `PilotRow`/`CatalogPilotRow` всегда рендерят `StatusPill tone="dim"` — для `stale`/`stopped` спека требует `tone="warn"`; подтверждено вычисленным стилем реальной пилюли Ender-3 V3 KE на dev (`data-tone="dim"`, `opacity:0.66`, нет `--accent-warn`). Вторая строка «Последний факт: {стадия}, обновлено {дата}» отсутствует в разметке (есть только в непереведённом `title`-тултипе), доступное имя не содержит модель.
