# Пользовательский путь и URL-контракт каталога материалов

**Статус:** решение UX для MF-1474 / фазы MF-346. Документ задаёт
пользовательский поток и адресный контракт; визуальная композиция остаётся в
`docs/design/materials.catalog.md`, реализация — в отдельных карточках Front и
Back.

**Граница v1:** публичный пользовательский раздел называется «Филаменты» и
показывает только `kind=filament`. Доменная сущность `material` — линейка
бренда; цвет, диаметр, навеска и SKU являются её вариантами. Личный склад
пользователя, покупка и другие виды материалов в этот маршрут не входят.

## 1. Канонические адреса

| Назначение | Канонический URL | Идентификатор и правило |
| --- | --- | --- |
| Каталог филаментов | `/materials` | Единственная точка списка; серверный `kind=filament` добавляет клиент и не пишет в адресную строку. |
| Фильтрованный каталог | `/materials?q=...&vendor=...&type=...&color=...&page=...` | Состояние списка сериализуется в заданном порядке параметров. |
| Карточка линейки | `/materials/:id` | `:id` — UUID из поля `material.id`. `slug` не является маршрутом v1, пока Back не добавит резолвер и правило постоянного перенаправления. |
| Выдача проектов из глобального поиска | `/project?q=...` | Существующий маршрут проектов. Он не становится маршрутом материалов. |

Адрес без завершающего слеша является нормой. В v1 не вводятся `/material`,
`/filaments`, `/materials/:slug` или адрес вида `/:vendor/:slug`: это создало
бы несколько ссылок на один объект.

### 1.1 Неизвестный объект и адрес

- Невалидный UUID, неизвестный UUID и detail, который API вернул как `404`,
  показывают состояние «Материал не найден» с единственным действием «В каталог
  филаментов» → `/materials`.
- Невалидный или отсутствующий `page` нормализуется к первой странице; в
  каноническом адресе `page=1` отсутствует.
- Неизвестные параметры списка не влияют на выдачу и удаляются при первом
  изменении URL-state. Они не должны передаваться в API.
- `401` не подменяется `404` или пустой выдачей: пользователь видит общий
  входной сценарий приложения. `5xx` и сетевой сбой остаются состоянием
  «Повторить», а не меняют URL.

## 2. URL-state списка

Канонический порядок: `q`, `vendor`, `type`, `color`, `page`. Пустые значения,
`page=1` и скрытый `kind=filament` не сериализуются.

| Параметр | Значение | Влияние на API | Изменение и сброс |
| --- | --- | --- | --- |
| `q` | Обрезанная строка поиска до 200 символов | `q` | Ввод ждёт 300–400 мс; непустое изменение удаляет `page`. |
| `vendor` | Один slug бренда | `vendor` | Смена или очистка удаляет `page`. |
| `type` | Один slug типа пластика | `type` | Смена или очистка удаляет `page`. |
| `color` | Одно название цвета варианта | `color` | Смена или очистка удаляет `page`. |
| `page` | Целое число от 2 | `offset=(page-1)*24`, `limit=24` | Увеличивается только после успешного «Показать ещё». |

Примеры:

```text
/materials
/materials?q=matte&type=pla
/materials?vendor=rec&color=black&page=3
/materials/4d1e2f5c-0000-4000-8000-123456789abc
```

### 2.1 Сохранение и восстановление

1. При прямом входе или обновлении страницы Front разбирает URL до первого
   запроса, добавляет `kind=filament` и запрашивает список с заданными фильтрами.
2. Если есть `page=N`, экран последовательно восстанавливает страницы 1…N по
   24 записи, чтобы адрес `page=3` воспроизводил тот же накопленный список, а
   не только третью порцию. При ошибке загрузка останавливается на доступной
   части и показывает «Повторить».
3. Поиск и фильтры меняют адрес через `replaceState`: ввод и серия уточнений не
   засоряют историю. Открытие detail и переход в выдачу проектов — обычная
   навигация (`pushState`), поэтому системная кнопка «Назад» возвращает к
   точному исходному URL, включая фильтры, накопленную страницу и позицию
   прокрутки браузера.
4. «Сбросить фильтры» очищает `q`, `vendor`, `type`, `color` и `page`, оставляя
   `/materials`; на первом пустом каталоге эта кнопка не показывается.

## 3. Путь «каталог → карточка → каталог»

| Шаг | Действие пользователя | Ожидаемый результат | Возврат / критерий сброса |
| --- | --- | --- | --- |
| 1. Вход | Открывает «Каталог → Филаменты» или прямую ссылку. | Открывается `/materials` либо точно восстановленный URL-state. | Адрес является единственным источником фильтров и страницы после F5. |
| 2. Уточнение | Набирает запрос либо выбирает один фильтр. | Через debounce для `q` / сразу для фильтра выдача заменяется; новый ответ не может перезаписать более свежий. | Любое уточнение начинает список с первой страницы и убирает `page`. |
| 3. Продолжение | Нажимает «Показать ещё». | Следующие 24 линейки добавляются к уже видимым; кнопка заблокирована во время запроса. | После успеха URL получает следующую `page`; при неуспехе набор и URL не меняются. |
| 4. Detail | Нажимает плитку линейки. | Открывается `/materials/:id`; detail не получает параметры фильтрации и не объявляет их частью своей ссылки. | Browser Back возвращает исходный URL списка. Явная ссылка из 404 или прямого detail ведёт на чистый `/materials`. |
| 5. Сброс | Нажимает «Сбросить фильтры» в пустой выдаче или сайдбаре. | Возвращается полный каталог. | Очищаются все параметры из §2, в том числе `page`. |

Плитка использует `id`, полученный из list response; Front не строит ссылку из
`slug` и не делает N+1 detail-запросы ради неё. В detail отображаются варианты
из `GET /materials/:id`; отсутствие варианта — честное состояние, не повод
менять адрес или возвращать пользователя к списку.

## 4. Глобальный поиск проектов

Глобальный поиск проектов и каталог материалов — независимые вертикали. Ввод на
главной ищет проекты существующим текстовым API, а действие «Все результаты»
делает переход только в:

```text
/project?q=<encodeURIComponent(запрос)>
```

`/project` читает `q` при первом рендере, передаёт его в `GET /models?q=...` и
сохраняет при F5, шаринге и возврате. Существующий переключатель wide/legacy
не является отдельным URL-контрактом: обе реализации выдачи обязаны читать один
и тот же `q` из маршрута.

Не меняем смысл `/market` и не вводим на нём маршрут материалов. Для ранее
сохранённых hash-ссылок `#/market?...` текущая миграция уже сохраняет query,
перенаправляя в `/project?...`; её нельзя заменять редиректом без query. Новый
код и новые ссылки используют только `/project`.

### Точка расширения текстового поиска

v1 оставляет текстовый поиск в `GET /models?q=...` и единый потребительский
путь `catalogstore → listModels → grid`. В будущем отдельный поисковый сервис
или нейропоиск может расширить именно этот адаптер: вернуть тот же текстовый
`q` и, при необходимости, допустимые фильтры каталога. Он не должен менять
адрес назначения, переписывать `/market` или создавать второй экран результатов.
Пока такого сервиса нет, UI не обещает семантический/AI-поиск.

## 5. Передача исполнителям

### Front

- Добавить роуты `/materials` и `/materials/:id`, включая прямой вход и F5;
  не добавлять slug-алиас.
- Сериализовать и восстановить URL-state строго по §2, включая последовательное
  восстановление накопленной пагинации.
- Сохранить `marketPath({ q }) → /project?q=...` и передачу `q` в wide и legacy
  выдачи; не переназначать `/market`.
- Покрыть тестами прямую ссылку, нормализацию `page`, сброс, Back после detail,
  404 и переход «Все результаты» с закодированным запросом.

### Back

- Сохранить поддержку list-параметров из §2 и detail по UUID до отдельного
  согласованного решения о slug-resolver.
- Для несуществующего/невалидного detail вернуть единый `404 { error:
  "not_found" }`; не отдавать внутреннюю ошибку.
- Расширение текстового поиска по бренду, фасеты или несколько значений фильтра
  не включать неявно: это требует отдельного API-контракта и обновления этого
  документа.

## 6. Проверяемые критерии решения

- У каждой линейки один канонический URL `/materials/:id`; неизвестный id даёт
  согласованный 404-сценарий.
- `q`, `vendor`, `type`, `color` и `page` сохраняются в прямой ссылке, после F5
  и при Browser Back; изменение фильтра или поиска сбрасывает страницу.
- Переход из глобального поиска ведёт в `/project?q=...`, не теряет текст и не
  ломает миграцию прежнего `#/market?...`.
- Текстовый API-поиск проектов имеет явную точку расширения за `listModels`, без
  нового URL или второй выдачи.
