# Композиция, тир-адаптивность, тач/киоск

← [docs/design/readme.md](readme.md)

## Композиция и лейаут

- **Контент по центру вьюпорта**, симметричные отступы, `max-width`. Фикс-хром — overlay поверх, не раздвигает.
- **Крупные тап-карточки-действия внизу экрана** — обычно две: слева вторичное («Назад / …», круглая ←), справа primary («Отправить на печать / …», зелёная круглая иконка). Заголовок + подпись-пояснение в каждой.
- **Один primary-CTA на экран** (зелёный). Вторичные — нейтральное стекло.
- **Чипы-подсказки** — ряд пилюль (примеры запросов на AI-экране: «котик в космическом шлеме»…).
- **Полноэкранные состояния процесса** (генерация, «поставлено в очередь») — отдельный экран с крупной hero-иконкой-кружком, а не мелкий спиннер в углу.

Точные отступы/зазоры — [metrics.md](metrics.md).

## Тир-адаптивность

Экран подстраивается под пользователя (демо-режимы Lite⇄Pro, расширены до трёх), НЕ перегружая новичка. Реализуется **через токены темы и набор модулей, не хардкодом цветов** — любой новый экран обязан жить во всех тирах.

- **Дом** — новичок/простой акк (0–2 принтера): тёплый, фокус «что напечатать/создать», минимум операционки.
- **Ферма** — про/принт-ферма (3–30 принтеров): строже/технологичнее, операционная сводка, контроль/масштаб.
- **Бизнес** — десятки принтеров + заказы/выплаты: как ферма + бизнес-модули.

Тир — авто по данным аккаунта (число принтеров/роль/объём) + ручной тумблер (persist).

## Тач/киоск-специфика

Референс — буквально демо тач-киоска (кастомная экранная клавиатура, крупные кнопки на всю ширину, нет hover). Что применено в `apps/web`:

- Никаких `:hover`-эффектов (на тач не сработает или залипнет) — вместо этого `:active` (лёгкое сжатие/затемнение).
- Минимальная высота интерактивных элементов — **48px**.
- `touch-action: manipulation` — убирает 300мс задержку и double-tap-zoom.
- `-webkit-tap-highlight-color: transparent` — свой `:active`-фидбек.
- `user-select: none` на некликабельных элементах (лейблы, иконки).
