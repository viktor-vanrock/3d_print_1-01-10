# Генерация по тексту (MF-353 Фаза 3 · MF-659)

← [docs/design/readme.md](readme.md) · моушен send-кнопки — [motion.md](motion.md) §3 · звук — [sound.md](sound.md) §3 · превью моделей — [model.preview.md](model.preview.md) · паттерн флоу-загрузки для сверки — [marketplace.md](marketplace.md) §3

> **Обновление MF-1996 (2026-07-20).** Канонический новый вход описан в
> [search.assistant.workspace.md](search.assistant.workspace.md): главная сначала
> ищет, «Создать своё» открывает приватную 3D-мастерскую, а generation job
> запускается отдельным подтверждением после brief. Старый прямой
> `Дом → POST /generations → /generate` ниже сохранён как описание legacy-экрана и
> больше не определяет поведение главной.

Спека нового экрана «Генерация по тексту»: пользователь описывает модель текстом, выбирает ветку
генератора, видит прогресс job'а и предпросмотр результата, может вернуться к истории своих
генераций. Собирается из существующих примитивов UI-кита (`apps/web/src/ui/ui.tsx`) и слоя
всплывашек (`apps/web/src/overlay`) — новых компонентов вводим только там, где система не
покрывает нужное (см. §6 GAP).

**Контракт данных** (из Fullstack, `apps/api/src/generations/contract.ts`, ветка `dev`, коммит `24c7d68`):
`POST /generations {branch, prompt, params?}` → `201`; `GET /generations/:id` → `queued|running|done|error`
+ `preview_url`/`artifact_url` (API-прокси, fetch с credentials) + `error`; `GET /generations` → история,
новейшие первые, лимит 50. Ветки: `openscad` → STL, `kzd` → PNG-чертёж, `hueforge` → zip
(квантование+heightmap+layers.json).

## 1. Точка входа и место в навигации

Роутер уже не хэш-скелет ([marketplace.md](marketplace.md) GAP-NAV закрыт) — есть `router.ts`
(path-роуты) и реестр `NAV_ITEMS` (`home/navitems.ts`), который сам разводит fwd/back-направление
перехода ([motion.md](motion.md) §2). Новый раздел — одна запись в реестре, без хардкода:

- Добавить `{ section: "generate", label: "Генерация" }` в `NAV_ITEMS`, новый `Route` вариант
  `{ screen: "generate" }` в `router.ts` (`parseLocation`: путь `/generate`), рендер в `app.tsx`
  рядом с `market`/`home`. Таб встаёт третьим в капсуле («Дом · Проекты · Генерация») — тот же
  `Chip`-паттерн с `data-selected`, никакого нового нав-примитива.
- **Второй вход — hero-инпут «Что напечатаем?» на Доме** (`home.css` `.homeGhostInput`, уже
  специфицирован в [motion.md](motion.md) §3/[sound.md](sound.md) §3: тап send даёт `cta`-тон +
  бёрст-анимацию + **морф кнопки в круглый прогресс-индикатор**). Это не два разных флоу, а один:
  тап send на Доме = отправка `POST /generations` c веткой по умолчанию (`openscad`, самый общий
  случай — «просто напечатать что-то») и введённым текстом как `prompt`, затем переход
  (`navigateWithTransition`, направление fwd) на `/generate` уже в состоянии «идёт генерация» —
  see §3. Так уже отрисованная на Доме анимация кнопки перестаёт быть декорацией без функции.
  Чипы-подсказки Дома («кот в шлеме», «ваза с узором» — [motion.md](motion.md) §3) — это буквально
  затравки промпта; тап по чипу вставляет текст в ghost-инпут, не отправляет сам.
- Прямой заход на `/generate` (таб или ссылка) открывает экран в состоянии «пустая форма» (§2) —
  hero-инпут повторяется здесь один-в-один по разметке (общий класс, не копия), чтобы у пользователя
  не было ощущения двух разных экранов ввода промпта.

## 2. Форма — состояние «пусто»

Вертикальная композиция, по центру вьюпорта (принцип «контент по центру», anti-overload):

1. **Заголовок** — `Heading` двухтоновый: «Генерация **по тексту**».
2. **Тайлы веток** — три `SelectionTile` в ряд (тот же примитив, что S/M/L в components.md):
   - `openscad` — иконка «куб/шестерня» (параметрическая деталь), подпись «3D-модель».
   - `kzd` — иконка «чертёж/линии», подпись «Чертёж КЗД».
   - `hueforge` — иконка «слои/палитра», подпись «HueForge (много цветов)».
   Один тайл выбран всегда (дефолт `openscad`), выбранный — зелёная заливка+свечение
   (components.md «Тайлы выбора»). Смена тайла — `toggle`-звук + морф заливки
   ([motion.md](motion.md)/[sound.md](sound.md) §7), **не** сбрасывает уже введённый текст промпта.
3. **Промпт** — переиспользуем `.homeGhostInput`/`.homeSendButton` разметку 1:1 (hero-заголовок как
   инпут, Unbounded, ghost-плейсхолдер, ни рамок/фона; send-кнопка справа — круглая, зелёная,
   дышит при непустом вводе). Плейсхолдер меняется по ветке: `openscad` → «Что напечатаем?»,
   `kzd` → «Что начертить?», `hueforge` → «Какую многоцветную сцену собрать?». Голосовой ввод и
   фото-кнопки Дома здесь **не переносим** — это специфика домашнего hero-блока, не общая форма
   (фото-референс для генерации — за рамками MF-353, не изобретаем незаявленный API).
4. **Параметры (`params`, необязательно)** — сворачиваемый блок «Дополнительно» (текстовая
   ссылка-тоггл под инпутом, не давит на форму весом): раскрывается в 2–3 простых поля per branch
   (напр. `openscad` — целевые габариты мм; `kzd` — толщина линии; `hueforge` — число цветов/слоёв).
   **Design оставляет конкретный набор полей на реализацию** (Fullstack/Back не зафиксировали схему
   `params` в контракте) — здесь фиксируется только форма подачи: свёрнуто по умолчанию, `Input`
   примитив ([ui.tsx](../../apps/web/src/ui/ui.tsx) `Input`/`FieldGroup`), без файлового аплоада.
5. Ниже — **история** (§5), если у пользователя уже есть генерации; при пустой истории блок не
   рендерится (не пустое место, экран короче).

Ровно один primary-действие на экране — сама send-кнопка (принцип «один CTA»); тайлы веток и
раскрытие «Дополнительно» — это выбор/настройка, не конкурирующее действие.

## 3. Отправка и прогресс

Тап по send-кнопке (валидация на клиенте: промпт непустой, иначе инлайн `warn`-текст «Опишите, что
сгенерировать» под инпутом, без запроса) → `POST /generations`:

- **Немедленно** (до ответа сервера): send-кнопка проигрывает бёрст `scale(1→1.15→1)`
  ([motion.md](motion.md) §3) и **морфит в круглый прогресс-индикатор** — пунктирное кольцо-орбита,
  тот же круг меняет содержимое без скачка макета. `cta`-звук на тап ([sound.md](sound.md) §3).
- **`queued`** (сервер принял, воркер ещё не взял) — кольцо статично, приглушённое (`dim`,
  как «В очереди» у моделей, [marketplace.md](marketplace.md) §4), под ним `StatusPill tone="dim"`
  «В очереди» + служебная строка «ветка: 3D-модель» (или соответствующая).
- **`running`** — кольцо **вращается непрерывно** (indeterminate — job длительность непредсказуема,
  нет `%` от провайдера), `StatusPill tone="ok" pulse` «Идёт генерация». Форма (тайлы/инпут) —
  дизейблится на время job'а (заблокировать повторную отправку), но остаётся видимой не пропадает —
  пользователь видит, ЧТО он просил, пока ждёт.
- **Поллинг** — `GET /generations/:id` через простой `setInterval`-рефетч ([marketplace.md](marketplace.md)
  §4 прецедент того же паттерна для `models`), интервал на усмотрение реализации (ориентир 2–3s —
  генерация не секундная операция, чаще опрашивать незачем).
- **`done`** — hero-иконка-кружок успеха: `scale(0.7→1.05→1)` спринг + галочка dash-in
  ([motion.md](motion.md) §4), звук `success` из `overlay/sound.ts` ([sound.md](sound.md) §0/§3) —
  затем кольцо-прогресс сменяется предпросмотром (§4), форма сворачивается в компактную строку
  «промпт · ветка» над результатом (не исчезает — можно поменять и перегенерировать, см. ниже).
- **`error`** — приглушённый shake кнопки + цвет-пульс к `--accent-danger` ([motion.md](motion.md) §4),
  `StatusPill tone="danger"` «Не удалось» + текст `error` от провайдера (сервер уже отдаёт его в
  поле, см. контракт) под пилюлей — это единственное место, где текст ошибки не наш RU-текст из
  таблицы §6, а прокинутый провайдерский; если он технический/нечитаемый — фолбэк «Генератор не
  справился. Попробуйте изменить запрос.». Действие «Повторить» — вторичная кнопка (стекло, не
  зелёная), запускает новый `POST /generations` с теми же параметрами.
- Форма НЕ блокируется намертво при ошибке сети/сервера на самом `POST` (до получения `id`) —
  это тот же кейс, что «Ошибка загрузки» в [marketplace.md](marketplace.md) §3.4: toast sticky
  «Не удалось отправить. Проверьте связь и попробуйте снова.» с действием «Повторить», форма
  остаётся редактируемой.

## 4. Предпросмотр результата

Ветка определяет тип превью — три поколения UI:

- **`openscad` (STL)** — интерактивный 3D: переиспользовать `ModelViewer`
  (`apps/web/src/market/modelviewer.tsx`) 1:1, тот же постер→тап→орбита фолбэк
  ([marketplace.full.md](marketplace.full.md) §12). **GAP-STL (см. §6)** — сегодня вьюер грузит
  только GLB (`GLTFLoader`), а ветка отдаёт STL: нужен loader для STL или конвертация на бэке,
  решение — не дизайн-вопрос, см. GAP.
- **`kzd` (PNG-чертёж)** — статичное изображение в стеклянной рамке (`Card`, radius 22,
  как рамка вокруг превью в каталоге, но без слоёного псевдо-3D стека — чертёж плоский по
  смыслу, объём/тень были бы фальшью). Тап — полноэкранный просмотр (`useOverlay().modal`,
  без доп. хрома, только `IconButton` «×» закрыть).
- **`hueforge` (zip)** — превью тоже изображение (рендер/превьюшка результата — конкретный формат
  `preview_url` для этой ветки уточнить у Fullstack при реализации, GAP-PREVIEW-FORMAT §6), та же
  рамка, что `kzd`. Артефакт (`artifact_url`, сам zip) скачивается отдельным действием «Скачать
  архив» под превью (иконка-стрелка-вниз + текст) — это не «примерка» файла, показывать нечего
  кроме превью-картинки.
- Под превью — во всех трёх случаях: действие «Скачать» (иконка+текст, скачивает `artifact_url`) и
  вторичное «Сгенерировать ещё» (сбрасывает результат, оставляет форму заполненной тем же
  промптом/веткой — быстрый повтор с правкой). Действие «Создать карточку» — **не в этой карточке**,
  оно в MF-660 (`--stage 2`, отдельный флоу «сохранить в каталог»), здесь только точка, откуда
  MF-660 подключится (слот действия рядом с «Скачать»/«Сгенерировать ещё»).

## 5. История генераций

`GET /generations` (лимит 50, новейшие первые) — простой вертикальный список (не сетка каталога:
здесь превью вторично, важнее промпт+статус+время):

- Каждая строка — `Card` компактной высоты: маленький квадратный превью-thumb слева (та же логика
  §4 по типу, уменьшенная — статичный кадр, не интерактивный вьюер в списке), затем промпт
  (обрезан до ~2 строк, `…`), под ним `StatusPill` (тон по статусу, см. §3) + относительное время
  («2 мин назад», «вчера»). Тап по строке — открывает эту генерацию в состоянии превью (§4) как
  если бы она только что завершилась (для `error`/`running` — соответствующее состояние §3).
- Список без явного заголовка-конкурента с формой — `Eyebrow` «История» тонкой строкой, не более.
- Пустая история — блок не рендерится вовсе (§2 п.5), никакого `EmptyState` здесь: пустая история —
  норма для нового пользователя, не повод занимать экран текстом «здесь будет ваша история».

## 6. GAP-лист (не изобретать молча на реализации)

1. **GAP-STL** — `modelscene.ts` грузит только GLB (`GLTFLoader`). Ветка `openscad` отдаёт STL.
   Варианты решения — не дизайн-выбор: (a) добавить `STLLoader` (`three/addons/loaders/STLLoader.js`)
   как альтернативный путь в `ModelScene` по расширению/`content-type` ответа, (b) просить Back
   отдавать GLB-конвертацию `preview_url` отдельно от STL-`artifact_url` (тот же паттерн
   thumbnail/preview у моделей, [model.preview.md](model.preview.md) «Где фотка показывается, а
   где крутится живой GLB»). Визуально для пользователя разницы нет — интерактивная орбита в
   любом случае; уточнить с Fullstack, какой путь дешевле по факту готового API.
2. **GAP-PREVIEW-FORMAT** — контракт не фиксирует, что именно отдаёт `preview_url` для `hueforge`
   (рендер heightmap? первый слой?) — уточнить у Fullstack перед вёрсткой превью-рамки этой ветки;
   дизайн ожидает «одна репрезентативная картинка», не более.
3. **GAP-PARAMS-SCHEMA** — `params` в контракте — свободный `object`, конкретных полей per branch
   нет ни в API, ни здесь (см. §2 п.4). Front фиксирует минимальный набор на реализацию либо
   уточняет у Fullstack/Back перед вёрсткой блока «Дополнительно» — секция не блокирует остальной
   экран (можно смёржить с пустым «Дополнительно» → добавить поля отдельной карточкой).
4. **GAP-NAV-3** — добавление третьего таба «Генерация» в `NAV_ITEMS`/`router.ts` (§1) — механически
   простое расширение существующего реестра, но именно Front первым добавляет третий элемент после
   `home`/`market` — сверить, что капсула по ширине не переполняется на узких экранах (тач-таргет
   ≥48px на таб при трёх пилюлях в ряд), при тесноте — см. [header.capsule.md](header.capsule.md)
   на предмет уже решённого паттерна сжатия капсулы.

## 7. Чек-лист приёмки

- [ ] Раздел «Генерация» доступен табом в капсуле и по `/generate`; переход туда/обратно — с
      fwd/back анимацией пилюли ([motion.md](motion.md) §2), как у существующих разделов.
- [ ] Тап send на Доме (`.homeSendButton`) отправляет генерацию веткой `openscad` по умолчанию и
      переводит на `/generate` в состоянии прогресса (не открывает пустую форму поверх).
- [ ] Три тайла веток, ровно один выбран всегда, смена не теряет введённый текст.
- [ ] Send-кнопка морфит в кольцо-прогресс без скачка макета; `queued`/`running` различимы визуально
      (статично vs вращается) и по `StatusPill`.
- [ ] `done` — hero-успех (спринг+галочка+звук), предпросмотр соответствует ветке (3D/картинка/картинка+скачивание).
- [ ] `error` — shake+цвет-пульс, читаемый текст ошибки (провайдерский или RU-фолбэк), «Повторить» работает.
- [ ] История рендерит генерации по статусам, тап открывает превью/прогресс соответствующей записи;
      пустая история не занимает экран пустым блоком.
- [ ] Всё уважает `prefers-reduced-motion`/mute-звук, живёт во всех темах (токены, не хардкод).
- [ ] Все GAP-и §6 либо закрыты, либо явно вынесены отдельной задачей (не молча).
