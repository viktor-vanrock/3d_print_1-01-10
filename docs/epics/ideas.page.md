# EPIC: Страница «Идеи» — предложения пользователей для обновлений

**Статус:** в работе — совет закрыт 08.07.2026, стейдж 1 запущен (MF-559 схема, MF-560 UX-спека); 08.07 принята волна 2 по директиве оператора (MF-564, см. §Волна 2)
**Issue:** MF-558 · **Лейбл:** социальное · **Приоритет:** medium (v1)
**Сроки:** стейдж 1 — 11.07 · стейдж 2 — 17.07 · стейдж 3 (QA) — 18.07 · **v1-страница — 21.07.2026** (буфер на фикс-луп после QA и проверку прода) · волна 2 — ориентир 24.07, коммитменты собирает Lead (MF-564)

## Проблема и цель

Пользователям некуда приносить запросы «сделайте вот это» — они тонут в форумных ветках и личных каналах, команда не видит спроса, пользователи не видят реакции. Страница «Идеи» — публичный канал: предложил → сообщество проголосовало → команда ответила статусом → все видят движение.

Ценность двусторонняя: пользователи получают влияние на продукт и видимый отклик; мы — приоритизацию бэклога реальным спросом и удержание (автор принятой идеи возвращается смотреть её судьбу).

**Антицель, главный риск:** кладбище проигнорированных запросов. Страница идей, на которой команда молчит, хуже отсутствия страницы — она документирует неуважение к пользователям. Контрмеры зашиты в механику (SLA + автоархив, см. §Жизненный цикл) и в метрику PM.

## Маршрут (директива оператора, MF-564)

Канонический URL страницы — **`3mf.tech/issue`** (список) и `3mf.tech/issue/:id`
(идея). `/ideas` — 301-редирект на `/issue`. Внутреннее имя фичи остаётся
«идеи»; «issue» — только адрес. Требование входит в **стейдж 2** (MF-562),
не в волну 2 — Lead доносит до Design/Front до старта web-сборки.

## Механики

### Подача идеи

- Только авторизованный пользователь. Форма: заголовок (≤120, `check` в БД), описание (markdown, рендер как в MF-497), категория из фиксированного списка: `каталог | проекты | форум | лк | другое`.
- **Живая подсказка дубликатов:** при вводе заголовка — поиск похожих идей (pg_trgm GIN по `ideas.title`, debounce ~250мс), до 5 штук, у каждой кнопка **«Проголосовать вместо создания»**. Дедуп до создания дешевле модерации после. Без AI — v1.
- Лимит: **3 идеи в сутки** на пользователя (проверка по индексу `(author_id, created_at)`); лимит показывается в форме до отправки, не после.

### Голосование

- Один голос «за» на идею на пользователя. **Даунвоутов нет** — они растят токсичность и удваивают поверхность абьюза; непопулярность видна нулём голосов.
- Голос отзывается (toggle). UI — оптимистичный апдейт (контракт vote/unvote возвращает новый счётчик + флаг «голосовал ли я»).
- Источник правды уникальности — `idea_votes` c `unique(idea_id, user_id)`. Отзыв = удаление ряда состояния.
- Счётчик денормализован в `ideas.vote_count` (паттерн `models.votes_up`).

### Статусы

`предложена → на рассмотрении → запланирована → в работе → готово | отклонена | дубликат | архив`

- Меняет только команда/модератор. Пользователь статусами не управляет.
- **Отклонена и дубликат — только с публичной причиной** (`decline_reason`, обязательность гоняется check-ом). Отказ без объяснения = молчание, см. антицель.
- В схеме — **`text` + `check`-констрейнт, НЕ native pg enum** (вердикт Data, домашний стиль: native enum на проде дорого расширять, drop+add check — принятый паттерн репо).

### Слияние дубликатов (вердикт CTO 08.07 — принята модель Data)

- «Дубликат B → каноническая A» = `B.canonical_id = A.id`. **Голоса физически НЕ переливаются.**
- Отображаемый счётчик каноники = `count(distinct user_id)` по кластеру (A + все её дубликаты): двойного счёта нет by design, один юзер в distinct один раз.
- Модель **обратима** (un-merge = обнулить `canonical_id`) и сохраняет форензику; физическая переливка деструктивна и запрещена.
- Дешёвый денорм `vote_count` работает для не-слитых идей (99% случаев); distinct-агрегация — только на кластерах, их мало.

### Обсуждение

- Тред комментариев на идею. **Форумных таблиц в `schema.ts` нет** (факт Data, 08.07) — переиспользовать на уровне БД нечего.
- **Дефолт CTO: эпик идей форумный движок НЕ ждёт.** Если форум-схема не готова войти в стейдж 1 — своя таблица `idea_comments` (плоский тред на идею) в той же миграции. Унификация с форумом, когда тот приедет, — отдельный осознанный рефакторинг, не блокер v1. Финальное слово по стыку — Fullstack; молчание = согласие с дефолтом.

### Лента и сортировка

- Вкладки: **популярные** (голоса за всё время) · **новые** (`created_at desc`) · **трендовые**.
- Тренд: `votes / (age_hours + 2)^1.5` — формула зависит от `now()` и не индексируется; считается **в приложении на окне последних 30 дней** (индекс по `created_at` покрывает выборку). Материализованный ранкинг — только при росте объёма, в v1 не делаем.
- Фильтры: категория, статус (индекс `(category, status, vote_count desc)`).

### Жизненный цикл и деградация

- **SLA:** каждой идее с ≥10 голосами — статусный ответ команды за 14 дней. Метрику ведёт PM (регулярный обход + недельная сводка CTO: факт срока, не оценка качества ответа).
- **Автоархив:** идеи без голосов и активности 90 дней (`last_activity_at`, partial-индекс) уходят в `архив`. Не удаляются, остаются в поиске; из архива можно вернуть голосом/комментарием.

### Анти-абьюз

Главный вектор — накрутка голосов фейк-аккаунтами.

- v1 включено: лимит подачи 3/сутки; голос только с подтверждённого аккаунта (гейт `user_identities.verified_at`); **append-only лог** `idea_vote_log` (`event cast|revoke`, `user_id`, `idea_id`, `ts`, `ip_hash`) — отзыв удаляет ряд состояния, форензика остаётся; спам-идеи — модерация.
- Заготовлено, включается порогами в api по факту абьюза, **без правки схемы**: ценз возраста аккаунта (из `users.created_at`), rate-limit голосов (оконный счёт по `idea_vote_log`). «Спящих» колонок не заводим — меньше мёртвой схемы.

## Данные (владелец — Data, MF-559)

Три таблицы, одна аддитивная (expand) миграция:

1. **`ideas`** — `id`, `author_id → users`, `title ≤120`, `body`, `category`, `status` (text+check), `canonical_id → ideas(id)` (null у не-дубликатов), `vote_count` (денорм), `decline_reason` (check-обязателен при отклонена/дубликат), `created_at`, `last_activity_at`.
2. **`idea_votes`** — `idea_id`, `user_id`, `created_at`, `unique(idea_id, user_id)`.
3. **`idea_vote_log`** — append-only форензика (см. §Анти-абьюз).
4. `idea_comments` — условно, по стыку §Обсуждение.

Индексы — под реальные запросы api (популярные/новые/фильтры/лимит/лог/pg_trgm на title); точные EXPLAIN на прод-объёмах — цифрами в MF-559. Применение на прод — заявкой Ops после merge.

## Контракты стыков (зафиксированы советом)

- **Data → Design/Front:** финальные строковые значения 8 статусов; в payload карточки — `vote_count` + `created_at` (под тренд-сортировку).
- **Fullstack → Front:** эндпоинт похожих идей `query → [{id, title, vote_count, status}]` (≤5); vote/unvote возвращает `{vote_count, voted}` под оптимистичный toggle; способ встраивания треда комментариев на странице идеи.
- **Design → Front:** UX-спека `docs/design/ideas.md` (MF-560) — раскладка списка/карточки/формы, все состояния (загрузка/пусто/ошибка), голосовалка (тап ≥48px, toggle), маппинг статусов на палитру «яркость=важность» (единственный красный акцент — «отклонена»).

## Метрики успеха

- ≥80% идей с ≥10 голосами получают статусный ответ ≤14 дней (SLA, обход PM);
- конверсии «предложена → запланирована» и «запланирована → готово» видны на странице;
- идей в неделю, голосов на идею, возвраты авторов идей.

## Волна 2 (директива оператора, MF-564) — после v1-страницы

Оператор 08.07 расширил замысел: подачу дополняют нейронки, а агенты,
улучшающие портал, сверяются с топом предложений. Волна 2 стартует после
релиза v1-страницы (стейджи 1–3 её НЕ ждут и не меняются). Декомпозиция
и сроки — Lead (MF-564).

### 2.1 AI-обогащение подачи (giga)

- **Механика:** юзер пишет свободный текст «чего не хватает» → кнопка
  «Оформить с ИИ» → giga возвращает черновик: заголовок ≤120,
  структурированное описание (что / зачем / кому полезно), категория из
  фиксированного списка. Юзер видит черновик в форме, правит, отправляет
  сам. **ИИ никогда не публикует — только заполняет поля формы.**
- **Валидация выхода:** ответ giga валидируется как обычный ввод (длина
  заголовка, категория строго из списка); prompt-injection в тексте идеи
  упирается в те же поля формы — исполнять нечего.
- **Прозрачность:** идея, отправленная из ИИ-черновика, помечается флагом
  `ai_assisted` (аналитика; показывать ли публично — решает Design).
- **Лимиты:** 10 вызовов обогащения в сутки на пользователя (ретраи
  дороже подачи); лимит подачи 3/сутки не меняется.
- **Деградация (обязательна):** giga недоступен или >5с — кнопка
  дизейблится, форма работает как в v1. Обогащение не на критическом пути.
- **Метрики:** % подач через ИИ; % черновиков, принятых без правок;
  доля «отклонена: непонятно» до/после.

### 2.2 Топ идей для агентов

Агенты, разрабатывающие портал, обязаны видеть спрос — петля «юзер
предложил → команда учла при разработке» замыкается механикой, не памятью.

- **Эндпоинт:** `GET /api/ideas/top?category=&status=&limit=` — публичный
  read-only JSON: `id, title, category, status, vote_count, trend_score,
  url`. Кэш ~5 мин. Абьюз-поверхности нет: отдаёт то, что и так на странице.
- **Процесс (docs/process/ideas.agents.md, волна 2):** берёшь фичу в зоне
  X → смотри топ идей категории X; идеи, которые закрывает работа,
  ссылками в карточку; при релизе связанные идеи переводятся в «готово» —
  автор видит отклик. Это операционализирует SLA из §Жизненный цикл.
- **Деградация:** эндпоинт упал → агент смотрит страницу; правило в доке
  не зависит от транспорта.
- **Метрики:** доля фиче-карточек со ссылками на идеи; идей, переведённых
  в «готово» по релизам.

### Не волна 2 (горизонт v2+)

Семантический автодедуп и AI-кластеризация тем; авто-создание карточек
доски из «запланированных» идей. Вернёмся с фактами использования.

## Связующий слой: точки входа и петля отклика (UX, MF-683)

Дизайн-спека `docs/design/ideas.md` (MF-560) владеет **страницей** `/issue`
целиком. Но пользователь почти не приходит на неё со словами «пойду предложу
идею» — боль рождается в контексте. UX-слой, который эпик и дизайн-спека не
владеют (полный сценарий — [docs/product/ux.md](../product/ux.md) §1):

- **Развилка «идея ≠ проблема» (не единый баг-трекер):** «хочу лучше» →
  голосуемый `/issue`; проблема с **контентом** (модель/принтер) → репорт **на
  карточке объекта** с авто-контекстом, кормит контент-агентов; **баг продукта**
  → `/issue` с авто-контекстом, помечен «проблема», **исключён из голосуемой
  ленты** (баг — не конкурс популярности). Финальную границу «отдельный канал vs
  тип на /issue» закрывает CTO/оператор; UX предлагает минимальный
  переиспользующий вариант.
- **Точки входа — где родилась боль:** пустой результат нейропоиска/фильтра →
  черновик заголовка из запроса; карточка модели/каталога → репорт с id объекта;
  экран ошибки/404/упавшая генерация → «проблема» с контекстом; ветка форума →
  «вынести в идею». **Контекст едет в форму `/issue/new` пред-заполнением** —
  идея приходит с телом, а не с чистого листа. Гость → промпт входа, не молчание.
- **Петля отклика (антицель «кладбища»):** смена статуса идеи → **уведомление в
  центр** (колокол капсулы, [overlay.system.md](overlay.system.md) MF-443) с
  глубокой ссылкой на `/issue/:id`; **«Мои идеи» в профиле/ЛК**; «готово» при
  релизе → пуш автору. Отклик возвращается к автору, а не ждёт его визита.
- **Агенты глазами юзера:** идею взял агент → агентский бейдж «в работе»
  (прозрачность авторства, [agents.and.humans.md](../product/agents.and.humans.md)).

**Реализация (параллельно основной странице):**
- **Design** — визуал точек входа + пред-заполнение формы контекстом + поверхности
  отклика («Мои идеи», уведомление о статусе). Нарезает Front-подзадачи с себя.
- **Fullstack** — бэкенд контекста и отклика: `origin`/контекст-поле на идее
  (+ тип «проблема», исключение из голосуемой ленты — согласование с Data),
  эмит уведомления при смене статуса идеи, `GET /ideas/mine`.

## Границы — что НЕ делаем в v1

- Никаких денег, баунти, баллов, наград.
- Без даунвоутов и рейтингов пользователей.
- Без AI-кластеризации и автодедупа — только pg_trgm-поиск похожих
  (AI-обогащение подачи — волна 2, см. выше; это помощь при вводе,
  не кластеризация).
- Не публичный роадмап: роадмап живёт в `docs/product/roadmap.md`; страница показывает статусы идей, не обещания дат.
- Без анонимной подачи.
- Без материализованного тренд-ранкинга.
