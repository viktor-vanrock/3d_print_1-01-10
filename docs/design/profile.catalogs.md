# Каталоги ЛК: редактирование «Мои принтеры» / «Мои филаменты» (MF-939)

← [docs/design/readme.md](readme.md) · компоненты — [components.md](components.md) · прецедент строки-настройки — [push.notifications.md](push.notifications.md)

Спека для **MF-939** (продолжение MF-358/MF-359, эпик MF-15 Фаза 2 «Основной поток — мои каталоги»).

## 0. Что уже готово — не трогаем

Живая проверка на dev.3mf.tech (webcheck, 2026-07-11, профиль `autofab-agent`) и код подтверждают: все три каталога ЛК **уже существуют и в основном работают**, это НЕ стройка с нуля.

- **Мои проекты** — галерея на своей странице профиля (`market/profile.tsx`, `listModels`) + полный CRUD со страницы проекта: создание («Добавить проект» → `AddModelFlow`), редактирование (`updateModel`, тот же `AddModelFlow` с `model`-пропом) и удаление (`deleteModel`, `market/model.tsx`) — всё уже смержено и живёт на дев/проде. **В этой спеке не трогаем.**
- **Мои принтеры** / **Мои филаменты** (`market/profile.catalogs.tsx`, `MyCatalogsSection`) — секции-строки в стиле «Мои идеи» (`.ideaRow`/`.ideaList`/`EmptyState`), уже умеют **добавить** (модалка `PrinterPicker`/`MaterialPicker`) и **удалить** (иконка-корзина + `overlay.confirm`).

**Единственный реальный пробел** относительно «Готово когда» MF-939 («создаёт/правит/удаляет») — **нет «правит»** для принтеров и филаментов: строка показывает только название и корзину, нет пути к уже готовым `PATCH /me/printers/:id` / `PATCH /me/materials/:id`. Заодно нет способа сделать непервичный принтер основным после первого добавления. Эта спека закрывает ровно эти два разрыва.

## 1. Строка каталога: тап открывает редактирование

Сейчас строка (`ideaRow`) статична, кликабельна только `IconButton`-корзина. Меняем:

- **Тап по всей строке** (кроме корзины) → открывает модалку редактирования (`overlay.modal`), тот же паттерн, что «Добавить принтер»/«Добавить филамент» уже используют. Это основное, самое частое действие над существующей записью (поправить сопло, сменить цвет катушки) — заслуживает всей площади строки, не мелкой третьей иконки (readme.md §Философия, «тач-первый»).
- **Иконка-корзина остаётся** правым отдельным элементом со своим `stopPropagation` — тап по ней по-прежнему сразу ведёт к `overlay.confirm` на удаление, не открывает редактирование. Никакой новой «карандаш»-иконки не добавляем — она была бы третьим одинаково ярким действием на строке ровно за то, что уже даёт тап по строке.
- Визуально строка получает лёгкий сигнал интерактивности — тот же `:active`-отклик (`.pressable`), что у `.ideaRow` в других местах (например `feed`), плюс `cursor: pointer`. Новых токенов не заводим.
- `aria-label` контейнера строки — `"Изменить «<label>»"` (label = `printerLabel(printer)` / `materialLabel(filament)`), чтобы читалка не путала с обычной ссылкой-навигацией.

## 2. Редактирование принтера

Модалка `overlay.modal({ title: "Изменить принтер" })`, форма — **переиспользует поля `ManualPrinterForm`** (`home/printerpicker.tsx`): Бренд, Модель, X/Y/Z мм, Сопло мм, Кинематика — те же `Input`, тот же порядок, предзаполненные текущими значениями строки. Не изобретаем вторую форму принтера.

Два подрежима по происхождению записи (`printer.verified`):

- **Каталожный принтер** (`verified: true`, привязан из популярных/поиска, `printer_id` не пуст) — поля **Бренд/Модель показываются, но не редактируются** (приглушённый текст, как заполненное `SchemaField`-поле без правки, [components.md § SchemaField](components.md#schemafield--поле-схемы-с-провенансом-mf-917)): бренд/модель — это и есть привязка к каталогу, менять их вручную ломает смысл «из каталога». Редактируются только **X/Y/Z, Сопло, Кинематика** — это честные правки «мой конкретный экземпляр отличается» (перепрошитое сопло, кастомный стол).
- **Ручной принтер** (`verified: false`) — редактируются все поля, включая Бренд/Модель, как при вводе.

**«Сделать основным»** — отдельная кнопка в подвале модалки (`variant="secondary"`), видна только если `!printer.is_primary`. Не смешиваем с полями формы — это не правка атрибута записи, а эксклюзивное переключение состояния с побочным эффектом на другие записи (сброс `is_primary` у остальных, тот же инвариант, что уже держит API). Тап → `PATCH /me/printers/:id { is_primary: true }` сразу (без «Сохранить»), модалка закрывается, список переsort’ится сервером (уже отдаёт `order by is_primary desc`).

Кнопка «Сохранить» (primary) внизу — сабмитит только полевые изменения (X/Y/Z/Сопло/Кинематика, + Бренд/Модель если ручной) через новый `updatePrinter(id, patch)` в `useActivation()` (`home/activation.ts`) → `PATCH /me/printers/:id`, который **уже есть на бэкенде** (`apps/api/src/profile/activation.ts`) — фронту нужно только подключиться, нового API-эндпоинта не требуется.

## 3. Редактирование филамента

Модалка `overlay.modal({ title: "Изменить филамент" })`. Название материала (`materialLabel`) — статичный нередактируемый заголовок сверху (смена материала = другая запись, не правка; захочет другой тип пластика — удаляет и добавляет заново, как и сейчас).

Ниже — то же, что можно менять в `PATCH /me/materials/:id`:

- **Цвет/вариант** — чипы вариантов **того же `material_id`** (тот же `Chip`-паттерн, что `MaterialPicker` для выбора самого материала, но здесь список — не поиск по каталогу, а варианты конкретного материала: `GET /materials/:id` уже отдаёт `variants[]` с `color_name`/`color_hex`/`diameter_mm`, эндпоинт существует, `apps/api/src/catalog/materials.ts`, доп-бэкенда не нужно). Выбранный вариант — заливка `--accent`, как везде у `Chip`. Если у материала нет вариантов — блок чипов не рендерится вообще (не пустой ряд).
- **Заметка** (`note`) — короткое многострочное поле (как есть на бэкенде — до 500 символов), тот же визуальный язык, что текстовое поле `description` в `AddModelFlow` (`market/addmodel.tsx`), без markdown-редактора — это не контент, а личная пометка («партия от 03.2026», «немного отсырел»).

Кнопка «Сохранить» → новый `updateFilament(id, patch)` в `useActivation()`/материалы-клиенте → `PATCH /me/materials/:id` (уже есть, `apps/api/src/profile/materials.ts`).

## 4. Результат сохранения

Общее для обеих форм (тот же принцип, что уже держит «Убрать принтер/филамент» в этой секции — успех тихий, ошибка — `toast`):

- **Успех** → модалка закрывается, список каталога обновляется значением из ответа PATCH (не отдельный refetch).
- **Ошибка** → модалка остаётся открытой (даём повторить не теряя ввод), `overlay.toast({ severity: "warn", title: "Не удалось сохранить" })` — тот же текст-паттерн, что «Не удалось убрать принтер»/«Не удалось убрать филамент» рядом в этом же файле.
- «Сделать основным» — своя отдельная ошибка при неудаче: `overlay.toast({ severity: "warn", title: "Не удалось сделать основным" })`, модалка в этом случае тоже остаётся открытой (кнопка не «Сохранить», это самостоятельное действие).

## 5. Motion / Sound

Ничего нового не заводим, всё — существующая шкала:

- Тап по строке (открытие модалки) — тот же `:active`/`--dur-tap`, что уже везде на `.ideaRow`/`.pressable`, звук — тембр `tap`/`tick` как у обычной навигационной строки ([sound.md §2](sound.md)), не `toggle` (это не бинарный переключатель).
- Открытие/закрытие модалки — стандартный `overlay.modal`-переход, тот же, что «Добавить принтер»/«Добавить филамент» уже используют.
- Чип цвета/варианта — существующий чип-select мотив ([motion.md §7](motion.md), тот же токен, что у `SelectionTile`/`Chip`).
- «Сделать основным» по успеху — без отдельного звука/пульса поверх обычного закрытия модалки (не критичное событие уровня алертов принтера, [status.alerts.md](status.alerts.md)).

## 6. Готово когда (проверяемо)

- Тап по строке в «Мои принтеры»/«Мои филаменты» (кроме корзины) открывает модалку редактирования; тап по корзине по-прежнему открывает подтверждение удаления, не редактирование.
- Принтер: каталожный — Бренд/Модель нередактируемы (видны, приглушены), X/Y/Z/Сопло/Кинематика редактируемы; ручной — редактируемы все поля. Непервичный принтер имеет кнопку «Сделать основным», после успеха список показывает его первым.
- Филамент: название материала статично, цвет/вариант выбирается чипами того же материала, заметка редактируется; материал без вариантов — блока чипов нет.
- Сохранение идёт через уже существующие `PATCH /me/printers/:id` / `PATCH /me/materials/:id` — нового API не потребовалось.
- Ошибка сохранения — `toast`, форма/модалка не закрывается, данные не теряются.
- «Мои проекты» не менялись — уже полный CRUD, регресс не внесён.
