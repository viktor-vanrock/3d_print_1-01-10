# Поиск → ассистент → 3D-мастерская

Статус: фронтовый вертикальный срез — **MF-1996/MF-2043**; единый discovery и
постоянный кэш концептов — **MF-2067/MF-2068**; серверная декомпозиция —
**MF-1997—MF-2003, MF-2044—MF-2047**. Этот документ дополняет
[frame.md](frame.md), [home.scenario.md](home.scenario.md) и
[generation.md](generation.md). При конфликте рамка главной из `frame.md` старше.

## 1. Продуктовая логика

Одно поле на главной запускает единый discovery:

1. После debounce одновременно ищутся реальные проекты и `ready`-концепты
   постоянного глобального кэша, а локальная Gemma готовит содержательные варианты.
2. Проекты и концепты показываются вперемешку одной сеткой, без разделов
   «готовое»/«можно создать» и без отдельного CTA.
3. Ready cache hit появляется первым. Только недостающие варианты ставятся в
   Z-Image-очередь, строго по одному в порядке карточек; skeleton занимает их
   будущие места, PNG проявляется без модалки и перехода.
4. Клик по готовому концепту — единственное явное действие генерации: создаёт
   TRELLIS-job по сохранённому prompt. Для гостя этот write-контур начинается со входа.
5. Каждый PNG остаётся в `generated_concepts`; похожий повторный запрос использует
   ANN/lexical RAG и не создаёт уже найденные изображения повторно.

`/giga/:threadId` остаётся мастерской для диалога и сложных итераций, но простой
путь query → concept → TRELLIS целиком живёт на главной.

## 2. Состояния главной

| Состояние | Что видит человек | Действие |
|---|---|---|
| Пустой запрос | Плейсхолдер «Найти или создать модель» и примеры | Пример только заполняет поле |
| Discovery идёт | Скелеты в геометрии будущих плиток | Источники наполняют сетку независимо |
| Есть cache hit | Готовые PNG вперемешку с проектами | Клик запускает TRELLIS по сохранённому prompt |
| Не хватает концептов | Shimmer-плитки на постоянных местах | Z-Image заполняет их строго последовательно |
| Нет проектов | Концепты остаются той же выдачей | Отдельное пустое состояние/CTA не добавляется |
| Один источник недоступен | Остальные результаты остаются | RAG деградирует на lexical, без модалки |

Результат поиска должен появляться быстро. Structured LLM не стоит на горячем
пути каждого символа: нормализация запроса и RAG включаются на сервере после
дебаунса/минимальной длины, с кэшем и жёстким таймаутом. При деградации всегда
остаётся обычный каталожный поиск.

## 3. Центр чатов Giga

Giga имеет три масштаба одного и того же диалога:

1. **Строка в шапке** ищет в текущем разделе; Enter не создаёт чат.
2. **Большой оверлей** открывается кнопкой Giga в строке и позволяет начать
   разговор, не теряя контекст страницы.
3. **Полный `/giga`** показывает историю слева и активный разговор справа;
   `/giga/:threadId` — адресуемая рабочая задача.

Внутри смешиваются не
сообщества, а только приватные контексты пользователя:

- создание/ремикс 3D-модели;
- помощь с проектом;
- помощь с принтером;
- общий вопрос.

У карточки есть тема, тип, последняя активность и одно из состояний:
`waiting_user`, `ready`, `working`, `failed`.
Публичные community threads и feed comments используют другие сущности и
никогда не являются источником приватной истории по умолчанию.

Канонический адрес «Все чаты» — `/giga`; `/chats` остаётся алиасом. Пока
серверный API MF-1997 не готов, фронт использует адаптер
`apps/web/src/assistant/localassistant.ts`: данные разделены по `user.id` и
лежат в localStorage. Это fixture, не долговременное хранилище и не источник
для RAG.

### 3.1 Контекстный поиск

Одна и та же строка в шапке меняет подпись и намерение по маршруту:

| Маршрут | Scope | Что меняет Enter |
|---|---|---|
| `/` | На главной | домашнюю выдачу моделей |
| `/feed`, `/news` | В ленте | уже загруженную ленту; полный поиск требует серверного индекса |
| `/printers` | В принтерах | запрос каталога и его релевантность |
| `/project` | В проектах | запрос каталога проектов |
| прочие | На сайте | предлагает продолжить с Giga |

Поле не должно притворяться глобальным RAG до появления живого индекса. Scope
всегда виден рядом с запросом. Персонаж в шапке реагирует на набор: смотрит в
левый нижний сектор и достаёт компактную клавиатуру; при
`prefers-reduced-motion` остаётся статичная поза.

## 4. 3D-мастерская

Маршрут: `/giga/:threadId`.

Desktop:

- сцена занимает всё доступное пространство;
- чат плавает справа колонкой 360–410 px;
- сверху только назад, тема, показать/скрыть чат, fullscreen и история;
- текущая модель не исчезает во время новой версии.

Mobile:

- сцена остаётся основным экраном;
- чат становится нижним sheet до 70dvh;
- sheet можно свернуть, продолжая крутить модель;
- textarea отправляет Enter, Shift+Enter оставляет перенос.

Стадии: `brief → ready → queued/running → done|failed`. Ошибка сохраняет brief,
сообщения и предыдущий результат. Скачивание/печать/публикация появляются
только после готового артефакта и не являются одним действием.

### 4.1 Ожидание — тоже интерфейс

Ограниченные мощности нельзя прятать за бесконечным спиннером. После явного
запуска мастерская остаётся полезной и различает состояния:

| Состояние | Сообщение | Поведение |
|---|---|---|
| Восстановление | «Возвращаем статус задачи» | Deep-link проверяет уже созданный job, новый не создаёт |
| Очередь с оценкой | «Позиция N · примерно через M минут» | ETA приходит с сервера; при отсутствии данных показывается честный диапазон «обычно 2–4 минуты» |
| Подготовка | «Подготавливаем генератор» | Загружается workflow/модель, позиция в очереди уже не показывается |
| Работа | Черновая форма → геометрия → проверка → экспорт | Determinate progress только при серверном проценте, иначе спокойный indeterminate |
| Дольше обычного | «Нужно немного больше времени» | Job не дублируется; ETA помечается устаревшим и обновляется сервером |
| Потеря сети | «Связь прервалась — задача не потеряна» | Backoff-polling/SSE reconnect; можно закрыть страницу |
| Ошибка/таймаут | Причина понятным языком + «Повторить» | Brief, сообщения и предыдущая версия остаются |
| Готово в фоне | Уведомление + карточка в `/chats` | Открывает тот же thread/version, а не новую задачу |

Анимации объясняют процесс: орбиты — очередь/занятый генератор, этапы —
реальный pipeline, sweep — неизвестный прогресс. Они отключаются при
`prefers-reduced-motion`. Нельзя анимировать выдуманный процент.

Текст ассистента поступает дельтами и печатается потоком, но доступность не
жертвуется эффекту: live-region получает осмысленные законченные куски, после
`message.completed` сохраняется полное сообщение. При reconnect клиент
передаёт последний `event_id` и не дублирует уже показанные дельты.

## 5. Серверные контракты

Контракты создаются в `packages/contracts/http`, реализация — не импортом
чужого `src`, а через API.

### 5.1 Гибридный поиск — MF-1998/MF-2003

```http
GET /assistant/search?q=держатель%20камеры&limit=10
```

```json
{
  "query": {"raw": "держатель камеры", "normalized": "держатель камеры"},
  "results": [
    {
      "entity_type": "model",
      "entity_id": "uuid",
      "score": 0.91,
      "reasons": ["назначение", "визуальное сходство"]
    }
  ],
  "has_more": false,
  "generation_offer": {
    "show": true,
    "reason": "low_relevance"
  },
  "degraded": false
}
```

Pipeline: lexical candidates → versioned 2048-dim embedding candidates →
`/rerank` top-N. Текущая `models.embedding vector(1024)` не расширяется
молча: нужен новый versioned index, backfill с checkpoint и метрики покрытия.
Для STL/3MF/OBJ индексатор рендерит несколько ракурсов на сервере и отправляет
изображения в multimodal embed.

### 5.2 Приватные чаты — MF-1997

```http
POST /assistant/threads
GET  /assistant/threads?cursor=...
GET  /assistant/threads/:id
POST /assistant/threads/:id/messages
POST /assistant/threads/:id/runs
GET  /assistant/runs/:id
```

Создание thread принимает `mode`, `initial_message`, `source_context`.
Сообщения и run-команды требуют idempotency key. Каждый read/write проверяет
владельца на сервере. Список не содержит полное тело всех сообщений.

`POST .../runs` принимает только разрешённые типы (`clarify`, `generate_3d`,
`revise_3d`) и возвращает server-owned status. Provider URL, prompt,
`reasoning_content` и внутреннее имя модели не попадают в браузер.

Основной транспорт живого run — SSE; polling остаётся обязательным fallback.
`GET /assistant/runs/:id/events` поддерживает `Last-Event-ID`. Минимальный
набор идемпотентных событий:

```text
run.snapshot        полное состояние после подключения/reconnect
assistant.delta     {message_id, seq, text}
assistant.completed {message_id, body}
run.queue           {position, eta_seconds, estimate_updated_at}
run.phase           {phase, label}
run.progress        {phase, progress} // progress: 0..100 либо null
artifact.preview    {version_id, preview_url}
run.completed       {version_id, artifact_url}
run.failed          {code, retryable, safe_message}
```

`seq` монотонный внутри сообщения, `event_id` — внутри run. ETA является
оценкой, содержит время последнего пересчёта и может стать `null`, если очередь
нестабильна. Клиент не выводит точное время без серверного значения.
Терминальные состояния обязательны: `done`, `failed`, `cancelled`,
`timed_out`. Отдельный heartbeat не добавляет текст в историю.

## 6. HYPERPC и граница доверия

HYPERPC доступен только серверным воркерам по Tailscale. Браузер, service
worker и публичный API никогда не получают `100.74.48.83` или provider port.

- structured chat — отдельный конфигурируемый URL с health-discovery: в
  текущей документации указан `:1234`, в оперативной памятке встречается
  `:1236`; порт нельзя зашивать в фронт;
- fast text — `:1235`;
- embed/rerank — `:8189`, размерность 2048;
- TRELLIS/ComfyUI — `:8188`.

Обязательно: egress allowlist, короткие connect/read timeouts, bounded retry
с jitter, circuit breaker, ограничение размера prompt/файлов, trace-id без
текста личного запроса, метрики очереди и ручной kill switch. Сервисы без
авторизации не публикуются наружу.

## 7. Очередность поставки

1. MF-1999 — versioned contracts и error model.
2. MF-2002 — Tailscale/perimeter/health/observability.
3. MF-1997 + MF-2003 — хранилище чатов и versioned index.
4. MF-1998 + MF-2000 — hybrid search, RAG и clarification runner.
5. MF-2001 — TRELLIS job, артефакты и прогресс.
6. MF-1996 — переключить fixture-first фронт на API без смены компонентов.

Готовность всей истории проверяется не демонстрационным ответом LLM, а
сквозным сценарием: найти существующее → создать своё → уточнить → явно
запустить → увидеть прогресс → покрутить готовый артефакт → вернуться к нему
из `/chats`.
