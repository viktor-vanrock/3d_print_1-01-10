# `/research` — рабочее место ресёрчера (визуал)

← [docs/design/readme.md](readme.md) · сценарий/поток (не переизобретаем) —
[epics/printers.research.md §7–8](../epics/printers.research.md) (владелец UX) · переиспользуемые
принципы каталогов — [product/ux.md §5](../product/ux.md) · MF-861

**Что это.** Визуал двух экранов: `/research` (очередь работ ресёрчера) и `/research/<slug>`
(форма карточки принтера по [printer.schema.json](../research/printer.schema.json)). Оба за гейтом
роли `researcher`. Аудитория формы двойная — человек через веб и агент (`researcher-creality`)
через тот же API мимо UI (`printers.research.md §8`) — это не меняет визуал, но объясняет, почему
главная работа экрана не «ввод с нуля», а **обзор того, что уже написал агент, и починка дыр**.

**Границы.** Поток, порядок шагов, что делает каждый контрол и куда ведёт — зафиксировано UX
(`printers.research.md §7–8`), здесь не переизобретается. Разошёлся с потоком в реализации — карточка
назад на UX, не молча по-своему. Здесь: композиция, компоненты, палитра, типографика, моушен, звук.
Каталог `/printers` (публичная сторона, `printers.research.md §9`) — отдельная спека
[MF-862](mention://issue/2cff9989-1e8d-4cf7-8806-2d645b6e8078), шипится независимо.

## 0. Гейт роли (общий для обоих экранов)

Три состояния входа, `printers.research.md §8.5`:

| Кто | Что видит |
|---|---|
| Гость | промпт входа (`useOverlay()` логин-флоу, переиспользуем как везде) |
| Вошёл, роли `researcher` нет | **не 404, не «доступ запрещён»** — `EmptyState` по центру контента: line-глиф лупы/папки, заголовок «Это рабочее место команды Ресёрчеров», подпись «Здесь заполняют базу принтеров — характеристики, фото, источники», `PrimaryButton` «Хочу заполнять каталог →» (ведёт на форму заявки/контакт — контракт ручки за Fullstack, здесь только кнопка). Тот же паттерн, что закрытый саб (`feed.md`) и «нет роли» — гейт **вербует**, не отказывает. Меню/капсула остаются живыми — упавший гейт не забирает навигацию (`nav.sections.md §4`) |
| Роль есть | обычный рендер экрана |

Оба экрана — `wide`-режим шапки (тот же механизм включения, что `/projects`/`/printers`,
[projects.page.md](projects.page.md)), контент по центру, симметричные отступы.

## 1. `/research` — очередь работ

**Это очередь, не витрина** (`§8.2`): рамка ближе к списку задач, чем к галерее каталога. Сайдбар
фильтров каталога здесь не переиспользуем — сегменты решают ту же роль одним рядом сверху, список
ниже занимает всю ширину контента (одна колонка строк, не сетка тайлов — строка несёт много полей,
тайл их обрежет).

### 1.1 Композиция (десктоп)

```
┌────────────────────────────────────────────────────────────────────┐
│  Ресёрчеры                                          [Найти / создать 🔍]│  ← eyebrow + поиск-создание (§1.3)
│                                                                       │
│  ( Мои · Мой бренд · С пробелами · Низкая уверенность ·             │  ← сегмент-ряд (§1.2)
│    Помечено пользователями · Все )                                  │
│                                                                       │
│  Начните с пробелов вашего бренда →                                 │  ← строка-подсказка, первый визит (§1.5)
│                                                                       │
│  ┌ Creality · K1 Max · creality.k1-max ────────────────────────┐    │
│  │ shipping  ●●●●●○○ 5 из 7   confidence: high   🤖 researcher- │    │  ← строка очереди (§1.4)
│  │                                            creality · 2 дня назад│ │
│  └──────────────────────────────────────────────────────────────┘   │
│  ┌ Bambu Lab · A1 mini · bambu.a1-mini ────────────────────────┐    │
│  │ …                                                             │   │
│  └──────────────────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────────────────┘
```

### 1.2 Сегменты

Один орган управления (`ux.md §3`), состояние в URL (`?scope=`). Визуально — тот же
**сегмент-тумблер/тайлы выбора**, что сортировка ленты идей (`components.md`, морф заливки
`--dur-toggle`/`--ease-spring`, `motion.md §7`): ряд пилюль, активная — заливка мятным, остальные —
тёмное стекло. Шесть сегментов в ряд на десктопе; на планшете/мобиле — горизонтальный скролл того же
ряда (не второй уровень меню, не «Ещё» — `ux.md §4` про потолок разделов сюда не относится, это
контрол внутри экрана, но принцип «не сворачивается» тот же).

Порядок слева направо = порядок значимости работы: `Мои` (моё авторство/бренд агента, которым я
управляю, если ресёрчер привязан к бренду) → `Мой бренд` → `С пробелами` → `Низкая уверенность` →
`Помечено пользователями` → `Все`. Дефолт при первом входе — `Мой бренд`, если он есть у ресёрчера, иначе
`С пробелами` (работа, не витрина — `§8.2`).

### 1.3 Поиск = кнопка создания

**Голой кнопки «Создать карточку» на экране нет** — это прямое требование `§8.2` (главный источник
дублей). Композиция — full-width поисковая строка над сегментами, тот же паттерн, что живой поиск
проектов (`projects.page.md §3`, `🔍 Найти проект…`), не hero-ghost-input (это рабочий инструмент, не
момент открытия сайта — `home.scenario.md`-паттерн здесь избыточен).

- Ввод (debounce 250 мс, тот же интервал, что дедуп идей — `ideas.md §4.2`) → живая выдача-панель
  под полем: строки по `brand`/`model`/`aliases`/`slug`, каждая — бренд · модель · чип статуса · тап
  открывает форму карточки.
- **Последняя строка выдачи, всегда** — `+ Создать карточку "<текущий ввод>"`, визуально отделена
  тонкой линией-разделителем от результатов, нейтральная (не зелёная — primary-CTA на экране один,
  сохранение внутри формы) иконка `+`. Тап → `/research/new?draft=<ввод>` (заголовок/идентичность
  предзаполнены строкой поиска — то же «контекст едет с пользователем», `ux.md §1.2`).
- Пусто в поле → панель не рисуется вовсе (нет режима «пустой поиск»).
- Мягкая проверка дубля на blur `brand`+`model` внутри формы (§2.3) — тот же принцип, отдельная
  реализация (форма уже открыта, дедуп там локальный к полям, не к строке поиска).

### 1.4 Строка списка

Одна строка на карточку, тач-высота ≥56px (плотнее стандартного тач-таргета — это рабочий список для
частого использования, не первый контакт), `.pressable` на всю строку, тап → `/research/<slug>`.
Слева направо:

1. **Бренд · Модель** (основной текст, `--text`), под ними мельче `slug` (`--text-dim`, моно/технический
   вид — рабочий идентификатор, отличать от человекочитаемого заголовка).
2. **Чип статуса** — `StatusPill` тона по `announced`/`shipping`/`eol` (`dim` для `announced` и `eol`,
   обычная заливка для `shipping` — рампа `status.alerts.md`, не критичность, а фаза жизни).
3. **Полнота N из 7** — компактный индикатор из точек (●●●●●○○, 7 сегментов ровно по короткому набору
   `§8.2`: `build_volume`, `hotend.max_temp_c`, `bed.max_temp_c`, `kinematics`,
   `multimaterial.supported`, `price`, `media.hero`), заполненные — мятные, пустые — `--border`-тон
   контур. Не прогресс-бар (тот читается как «загрузка», это статичный факт).
4. **`confidence`** — текст-бейдж `высокая`/`средняя`/`низкая` (не иконка — редко сканируется глазом,
   когда уже нужно, читается словом).
5. **`filled_by`** справа — если агент, `AgentBadge` (`components.md`, серая пилюля line-искра) +
   имя (`researcher-creality`); если человек — обычный `@nick`. Агентское авторство прозрачно на
   каждой строке (`agents.and.humans.md`).
6. **`updated_at`** относительной строкой («2 дня назад») — крайняя правая колонка, `--text-dim`,
   не участвует в тап-зоне отдельно (строка кликабельна целиком).

Сегмент `Помечено пользователями` добавляет седьмую колонку — маленький коралловый флаг-иконку слева
от бренда (визуальный маркер «есть репорт неточности», не блокирует строку).

### 1.5 Состояния экрана

| Состояние | Что видит |
|---|---|
| Первый раз, роль есть | обычная очередь + строка-подсказка курсивом/приглушённо над списком: «Начните с пробелов вашего бренда» — не отдельный `EmptyState`, список уже содержит карточки |
| Очередь сегмента пуста | `EmptyState`: line-глиф галочки/чек-листа, «Пробелов по вашему бренду нет», `PrimaryButton`-вторичный «Проверить анонсы →» → `/printers/releases` |
| Грузится | 4–5 скелетон-строк той же высоты, что реальная строка (`§1.4`) — не спиннер по центру, список — основной контент экрана |
| Ошибка сети | компактная строка на месте списка: «Очередь не отвечает. Обновить» (тот же тон, что ошибка каталога `nav.sections.md §4`), меню/капсула живы |

## 2. `/research/<slug>` — форма

### 2.1 Рамка

Двухколоночная композиция на десктопе (≥1024px): форма слева (переменная ширина, читаемый максимум
~720px), закреплённая панель «Источники» справа (`§2.6`), `position: sticky` от верха контентной
области до конца формы. На планшете/мобиле — одна колонка, источники уходят в отдельный узел (`§4`).

```
┌───────────────────────────────────────────────┬──────────────────────┐
│  ← К очереди          заполнено 4 из 7          │  Источники            │
│                                                  │                       │
│  ▸ Идентичность                        2 из 4    │  [1] creality.com/k1max │
│  ▾ Фото                                3 фото     │  [2] 3dprintbeginner.ru│
│  ▾ Стол                                1 из 3  ✓  │  + добавить URL        │
│  ▸ Хотэнд                              0 из 4     │                       │
│  ▸ Скорость                            0 из 2     │                       │
│  ▸ AMS / мультиматериал                1 из 2  ✓  │                       │
│  …                                                │                       │
│  ▸ _meta (confidence)                             │                       │
│                                                    │                       │
├────────────────────────────────────────────────┤                       │
│  [ Сохранить ]                    sticky, низ формы│                       │
└────────────────────────────────────────────────┴──────────────────────┘
```

Заголовок страницы — не `slug`, а «{Бренд} {Модель}» (человекочитаемо), под ним eyebrow «заполнено 4
из 7» — тот же счётчик, что в очереди (`§1.4`), здесь — по всем секциям схемы, не по короткому набору
фасетов (в форме считаем полноту иначе, чем в списке: список кормит фасеты каталога и намеренно
короткий, форма показывает реальный охват работы над карточкой).

### 2.2 Секции — сворачиваемые, заголовок «N из M»

Порядок фиксирован UX (`§8.3`): **Идентичность → Фото → Спеки (по секциям схемы) → `_meta`**. Каждая
секция — `.pressable`-заголовок (тап разворачивает/схлопывает), справа число «N из M» тем же
точечным индикатором, что `§1.4`, но с подписью числом (форма — рабочий инструмент, точность важнее
компактности списка). Секция с ≥1 заполненным полем получает мелкую зелёную точку-галочку рядом со
счётчиком (беглый скан «где я уже поработал»). Первая посадка на форму — все секции, где `filled_by`
агента уже что-то оставил, **развёрнуты по умолчанию**; пустые — свёрнуты (человек видит агентскую
работу сразу, не должен раскрывать двадцать пустых аккордеонов).

### 2.3 Секция «Идентичность»

Обязательные `brand`, `model` — обычные текстовые поля (radius 22–28, `metrics.md`). `slug`
генерируется вживую под полями серым моно-текстом «→ creality.k1-max», с карандаш-иконкой
(`IconButton` компактный) — тап открывает его как редактируемое поле, по умолчанию свёрнут в
предпросмотр (ресёрчер не должен думать про slug, если авто-версия его устраивает). Ниже —
`aliases` (тег-инпут: чипы с `×`, ввод+Enter добавляет), `status` (тайлы выбора S-размера:
`анонсирован`/`выпускается`/`снят с производства` — тот же примитив, что уровни принтера в
`printer.wizard.md §3.1`), `released_at` (date-поле, плейсхолдер «если неизвестно — оставьте пустым»).

**Мягкий дедуп на blur `brand`+`model`** — узкая инлайн-плашка под полями, тон `dim`, не блокирует:
«Похоже на существующую: Creality K1 Max — открыть?» (тот же тон и necessity, что дубликат-панель
идей, `ideas.md §3.3`, но без голосовалки — здесь тап просто уводит на существующую карточку).

### 2.4 Секция «Фото»

Сразу после идентичности (`§8.3` п.2 — «принтера узнают по картинке»). Один поток загрузки, переиспользуем
drop-зону маркетплейса (`marketplace.md §3.2`, шаг A): пунктирная область на всю ширину, «Перетащите
фото сюда или нажмите, чтобы выбрать», подпись «JPG/PNG/WebP · до 8 фото». Загрузка каждого файла —
немедленно (presigned URL, `§8.3`), превью появляется сразу в галерее-сетке (3–4 в ряд, квадратные
тайлы radius 16–20), с тем же прогресс-баром переиспользованным из `.uiChecklistBarFill`
(`marketplace.md §3.3`) поверх тайла, пока летит конкретный файл — так параллельная загрузка
нескольких фото не блокирует друг друга визуально.

- **`hero`** — маленькая звезда (line-иконка, не залитая) в углу каждого тайла; тап переключает
  `hero` на этот тайл (только одна звезда залита зелёным одновременно — взаимоисключающий выбор, тот
  же морф заливки `--dur-toggle`, что тумблер). Первая успешно загруженная фотография получает `hero`
  автоматически — если ресёрчер загрузил только одно фото, звезду вообще не нужно трогать.
- Тайл `hero` дополнительно получает тонкую мятную обводку (2px) — отличим от остальных на
  беглый скан, не только звездой.
- Удаление — `×` в углу тайла (`IconButton` компактный, поверх превью на `:active`-подложке), тап по
  самому тайлу (не по `×` и не по звезде) открывает лайтбокс-просмотр в полный размер.
- Лимит 8 — по достижении зона загрузки визуально гасится (`opacity ~.5`, курсор/тач неактивен),
  подпись меняется на «Лимит 8 фото».
- Пусто (0 фото) — зона занимает больше места (первый экран без фото выглядит незаконченным,
  визуальный вес побуждает загрузить), подпись про источник: «Фото с офсайта вендора — не чужие
  водяные знаки» (`§8.3`).

### 2.5 Три состояния поля — `SchemaField` (новый примитив)

Ядро всего экрана (`§7.2`), нужен новый визуальный язык на **три** состояния, не два:

| Состояние | Визуал |
|---|---|
| **Заполнено** | обычное поле, значение видно; под полем мелкая строка-сноска `[2] 3dprintbeginner.ru` (`--text-dim`, тап открывает выбор источника — `§2.6`) — не подпись «источник:», а сам номер, компактно |
| **Искали, нет данных** | поле визуально «выключено» (плейсхолдер приглушён, фон чуть темнее `--surface`), **галка слева от поля** (не чекбокс общего вида — компактная line-галка ~20px) залита нейтральным серо-зелёным, когда отмечена; рядом текст плейсхолдера меняется на курсивное «не нашёл» вместо обычного плейсхолдера поля. Отметить галку и ввести значение одновременно нельзя — тап в поле снимает галку (взаимоисключающе, без модалки-подтверждения, это частое обратимое действие) |
| **Не трогали** | обычное поле, пустое, плейсхолдер стандартный (название поля), галка не отмечена, **без сноски снизу** — это дефолт, никакого визуального шума |

Ключевое отличие от «сетки прочерков» (`§7.2`, запрещено): состояния 2 и 3 никогда не превращаются
в ряд одинаковых «—» — состояние 2 несёт активную галку (осознанный факт), состояние 3 просто
выглядит как обычное пустое поле формы, ничем не привлекая внимание. Разница читается по галке, не по
самому полю.

Один инстанс `SchemaField` инкапсулирует: label, инпут (текст/число/select/toggle — тип зависит от
поля схемы), галку «не нашёл», сноску источника. Переиспользуется во всех секциях спек (`build_volume`,
`hotend`, `bed`, `speed`, `multimaterial`, `toolhead_extras`, `connectivity`, `materials_supported`,
`dimensions_mm`, `price`, `unique_features`) — единообразие важнее точечной кастомизации под секцию.

### 2.6 Панель «Источники»

Закреплена сбоку (десктоп), не поле в конце формы (`§8.3` п.4). Список URL с номерами `[1] [2] [3]`
(моно-нумерация, крупнее обычного текста — это координаты, на них ссылаются сноски полей), рядом с
каждым — домен как читаемый текст (не сырой URL), тап по строке открывает ссылку в новой вкладке
(иконка «↗»), `×` удаляет источник (снимает атрибуцию у полей, которые на него ссылались — те поля
визуально переходят в состояние «не трогали» по сноске, но значение остаётся, просто без источника).
Внизу — «+ добавить URL», текстовый инпут, Enter добавляет и присваивает следующий номер. Лимит 2–5
источников по `§8.3` мягкий (не жёсткий блок при 6-м, просто панель не поощряет больше).

**Автоцепление последнего использованного источника** (`§8.3`, ключевая эргономика): когда ресёрчер
вводит значение в любой `SchemaField`, сноска под полем автоматически получает номер **последнего
источника, у которого была любая активность** (клик по строке источника в панели, или последнее
вручную выбранное значение сноски у другого поля) — двадцать полей заполняются с одним источником
одним действием (выбрать источник один раз), а не двадцатью. Активный источник получает тихий
индикатор в панели — тонкая мятная точка слева от номера `[2]`, без подписи «активен» текстом
(ненавязчиво, не отдельный баннер). Тап по номеру сноски у поля открывает компактный `Select` из
текущих источников — сменить атрибуцию конкретного поля вручную, не трогая «последний активный».

### 2.7 Секция `_meta`

`confidence` — три радиокнопки текстом (не иконками — смысл нужен, не пиктограмма): «Сверил с
офсайтом» / «Одна вторичная статья» / «Слухи, ревизия неясна» — визуально те же тайлы выбора S,
горизонтальный ряд на десктопе, столбик на мобиле. `filled_by`/`gaps`/`updated_at` — не поля ввода,
служебная строка мелким текстом под радиокнопками: «Заполняет: вы · обновлено только что» (после
сохранения — «2 дня назад»).

### 2.8 Сохранение

Одна `PrimaryButton` «Сохранить», `position: sticky` к низу формы (не к низу вьюпорта — форма может
быть короче экрана на десктопе, кнопка не должна висеть посреди пустоты). Автосейв черновика в
`localStorage` с момента, когда есть `brand`+`model` (тот же паттерн частоты/баннера восстановления,
что редактор поста, `feed.post.editor.md §2.8`: тихий автосейв ~2с, при заходе на форму с непустым
локальным черновиком — узкая info-плашка сверху «Восстановлен черновик · Начать заново»).

Четыре исхода, `§8.4` — каждый как компактный **inline-callout** над кнопкой (не тост — тост исчезает,
а состояние формы должно остаться читаемым, пока ресёрчер решает следующий шаг), моушен callout —
`--dur-callout`/`--ease-spring` (`motion.md §4`):

| Исход | Визуал |
|---|---|
| Успех, опубликовано | зелёный callout, галочка-иконка (stroke-draw), «Сохранено · опубликовано» + вторичная ссылка «Открыть в каталоге →» |
| Успех, черновик (нет источника) | янтарный callout (`warn`, не ошибка — `status.alerts.md` семантика), «Сохранено. Чтобы опубликовать, добавьте хотя бы один источник» + тап по колауту скроллит и подсвечивает панель источников (мягкий `outline`-пульс 1 цикл, не бесконечный) |
| Ошибка валидации схемы | коралловый callout «3 поля не приняты» **над кнопкой**, но реальная ошибка — у самого поля (`SchemaField` получает состояние `error`: тонкая коралловая обводка + текст ошибки под полем, не над формой). Скролл к первому невалидному полю. Никогда не сырой JSON |
| Конфликт правок | отдельная секция вместо callout — раскрывается над кнопкой сохранения: «Пока вы редактировали, `researcher-creality` обновил 2 поля» (агент-бейдж, если конфликтующая сторона — агент), список конфликтных полей, у каждого — старое/новое значение бок о бок + сегмент-выбор «оставить моё / взять их» (тот же тайл-выбор S, два варианта). Непересекающиеся поля мержатся молча, в списке не показаны. Тон секции — нейтральное стекло, **не коралл** (`§8.4`: конфликт — норма, не ошибка; коралл здесь читался бы как «вы сделали что-то плохое») |

Ошибка сети при сохранении — отдельно от валидации: коралловый inline-текст под кнопкой «Не
сохранилось, черновик цел, повторить» + кнопка повтора рядом (черновик остаётся в `localStorage`,
`§8.5`).

## 3. Мобайл/тач

- **Очередь** — строка `§1.4` теряет колонку `updated_at` (уходит на вторую строку мелким текстом
  под slug), сегменты — горизонтальный скролл-ряд (снап на пилюлю), поиск-строка остаётся full-width
  сверху.
- **Форма** — одна колонка. Панель «Источники» **не модалка и не второй bottom-sheet** (конфликтовало
  бы с bottom-tab, тот же запрет «не две панели снизу», что сравнение принтеров,
  `printers.research.md §9.4`): сворачивается в компактную секцию-аккордеон **внутри потока формы**,
  сразу под заголовком страницы, по умолчанию свёрнута с меткой «Источники (2) ▾». Сноски полей
  работают идентично — тап открывает тот же `Select`, просто список источников не виден постоянно.
  Кнопка «Сохранить» — sticky над системной клавиатурой, тот же приём, что композер форума
  (`feed.post.editor.md §3`).
- Фото-сетка — 2 в ряд вместо 3–4.

## 4. Моушен и звук (хореография по элементам)

Переиспользуем словарь `motion.md`/`sound.md`, новых треков не заводим:

| Элемент | Motion | Sound |
|---|---|---|
| Тап строки очереди / секции-аккордеона | `.pressable` press/release (`motion.md §1`) | `tick` на `pointerdown` |
| Сегмент-тумблер (`§1.2`), тайлы `status`/`confidence` | морф заливки `--dur-toggle`/`--ease-spring` (`motion.md §7`) | `toggle`-тембр |
| Разворот/схлопывание секции спек | высота + fade содержимого, `--dur-nav`/`--ease-out` | без звука (навигационный жест внутри формы, не подтверждение) |
| Галка «не нашёл» | заливка галки — `--dur-toggle` морф (та же семья, что `Switch`) | `toggle`-тембр |
| Загрузка фото — превью появляется | `.reveal` (fade+rise) на каждый новый тайл | без звука (появление контента, `motion.md §5`/`sound.md §3`) |
| Тап звезды `hero` | микро-подскок `scale` (эталон голосовалки, `motion.md §8`) + морф заливки звезды | `tick` |
| Кнопка «Сохранить» (primary) | press-паттерн `§1` + после ответа сервера — callout `--dur-callout`/`--ease-spring` (`motion.md §4`) | `cta`-тон на тап (единственный primary экрана), успех/ошибка callout — тон из `overlay/sound.ts` по severity (`sound.md §0`, не новый слой) |
| Автоцепление активного источника (точка-индикатор) | тихая fade-смена точки между источниками, без анимации-скачка | без звука (фоновая индикация, не жест) |
| Восстановление черновика (баннер) | мягкий `.reveal`, без сюрприза (`feed.post.editor.md §4`) | без звука |
| Конфликт-секция раскрывается | `--dur-slow`/`--ease-out` (как `.modal-in-out`-семья — заметное, но не резкое появление) | без отдельного звука — открытие секции, не действие |

Всё уважает `prefers-reduced-motion`/mute-тумблер — токены и правила берём как есть, ничего не
переопределяем локально для этого экрана.

## 5. Новый переиспользуемый примитив → `components.md`

**`SchemaField`** (§2.5) — первое применение здесь, но контракт («поле схемы с тремя состояниями +
опциональная сноска-провенанс») переиспользуем в любой будущей форме над `_meta`-провенансом (следующий
кандидат — филаменты, тот же паттерн `printer.schema.json`-класса каталогов, `ux.md §5`). Зафиксировать
в `components.md` при реализации: label, инпут (полиморфный по типу поля), галка «не нашёл», сноска
источника, состояние `error`. Front выносит как отдельный компонент, не копипастит по секциям.

## 6. Готово когда (проверяемо)

- Гейт роли на обоих роутах — вербующий текст, не 404/403 (`§0`).
- Очередь: 6 сегментов в URL, поиск = единственный путь создания, последняя строка выдачи всегда
  «Создать карточку "…"» (`§1.3`).
- Строка очереди показывает все 6 полей `§1.4`, включая агент-бейдж у `filled_by`.
- Форма: порядок секций Идентичность→Фото→Спеки→`_meta` не нарушен; `SchemaField` различимо визуально
  в трёх состояниях без прочерков-сеток (`§2.5`).
- Панель источников — сноска на каждом заполненном поле, автоцепление последнего активного видно
  индикатором, не текстом (`§2.6`).
- Кнопка «Сохранить» никогда не задизейблена пустыми полями; 4 исхода `§8.4` визуально различимы
  между собой (успех/черновик/ошибка полей/конфликт), конфликт — нейтральный тон, не коралл.
- Мобайл: источники — аккордеон в потоке, не второй bottom-sheet поверх таббара.
