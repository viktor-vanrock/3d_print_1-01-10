## 0. Карта разделов

```
#/community                 — список сообществ (раздел витрины, wide-хром)
#/community/:slug           — страница сообщества: шапка + лента тредов (light-хром, своя «← Назад»)
#/thread/:id                — страница треда: тело + голос + посты, Q&A-пересортировка (light-хром)
```

**Точка входа в навигацию** — новый пункт капсулы-шапки/центральной wide-навигации (реестр `NAV_ROUTES`, тот же механизм, что «Дом»/«Проекты»/«Маркетплейс», [projects.page.md §1.2](projects.page.md)), подпись **«Форум»**. `headerMode: 'wide'` для `#/community` (листинговая страница — как витрина, сетка+поиск), `'light'` для `#/community/:slug` и `#/thread/:id` (детальные страницы со своей «← Назад», как `#/issue/:id`/`#/model/:id`).

Стиль наследует принятый визуальный язык без исключений: тёмный тил-фон, градиентные карточки, Unbounded для заголовков, одна зелёная CTA на экран, тач-таргеты ≥48px, `:active` вместо `:hover` ([layout.md](layout.md), [palette.typography.md](palette.typography.md)). Ничего нового в палитре/типографике этот файл не вводит — только компоновка и два новых переиспользуемых примитива (§7).

## 1. Список сообществ (`#/community`)

### 1.1 Раскладка

Тот же скелет, что каталог маркета v2 ([marketplace.v2.md §1](marketplace.v2.md)): поиск-строка сверху (`q` — `GET /communities?q=`, debounce 250ms, живой), слева узкий сайдбар-фильтр по `kind` (Принтер/Филамент/Ремесло/Своё — тайлы-чипы, множественный выбор не нужен, один активный `kind` или «Все»), справа сетка карточек сообществ 3–4 в ряд (десктоп). Мобайл — сайдбар схлопывается в горизонтальный скролл чипов над сеткой (тот же паттерн §1.4 marketplace.v2.md).

Единственная зелёная CTA экрана — **«Создать сообщество»**, зафиксирована в правом верхнем углу поисковой строки (десктоп) / плавающая внизу (мобайл, тот же приём, что «Предложить идею» — [ideas.md §7](ideas.md)). Открывает форму §1.3.

### 1.2 Карточка сообщества (сетка)

Крупная карточка-действие ([components.md](components.md)): градиентная заливка, radius ~28, кликабельна целиком → `#/community/:slug`.

```
┌──────────────────────────────────────┐
│ [Принтер]                             │  ← CommunityKindBadge (§7.1), только не-custom
│ Bambu Lab фанаты                      │  ← name, Unbounded medium, 1 строка
│ Обсуждаем профили печати, апгрейды…   │  ← description, line-clamp 2, --text-dim
│                                        │
│ 128 участников · 34 треда   [Владелец]│  ← мета-строка + RoleBadge (§7.2), только если viewer_role≠null
└──────────────────────────────────────┘
```

- **`CommunityKindBadge`** (§7.1) — верхний левый угол, только для `kind ∈ {machine, vendor, craft}` (системные, лениво созданные под каталожный саб). Для `kind='custom'` (пользовательские клубы) — бейдж скрыт (нет «типа» — это и есть тип, шуметь незачем; тот же принцип, что craft-бейдж скрыт при единственном ремесле, [projects.md §2.1](projects.md)).
- **Мета-строка** — `member_count` «участников» · `thread_count` «тредов», приглушённо. `RoleBadge` (§7.2) справа, рендерится только если `viewer_role !== null` (сообщество, где я состою) — так своя лента и чужая визуально различимы без отдельной вкладки «Мои сообщества» (она не в API-контракте этой фазы — открытый вопрос §8).
- **Тап по карточке** — переход. Кнопка вступить/выйти — **не** на карточке ленты (перегруз плитки вторым тап-таргетом на границе 48px в сетке 3-в-ряд); вступление — на странице сообщества (§2.2). Ровно тот же trade-off, что голосовалка идей не дублируется в двух местах одной карточки.
- **Пусто/загрузка/ошибка** — стандартная тройка (§8 сводка).

### 1.3 Форма создания сообщества (модалка/оверлей, не отдельный роут)

Компактный оверлей (`.modal-in-out`, [motion.md](motion.md)), не полноэкранная форма (в отличие от подачи идеи — сообщество создаётся реже и данных меньше, полноэкранный «студийный момент» тут избыточен).

```
┌ Создать сообщество ─────────────────────────────── ✕ ┐
│ Название                                              │
│ [ Bambu Lab фанаты                                  ] │  ← Input, лимит 120 (COMMUNITY_NAME_MAX_LENGTH)
│                                                        │
│ Описание (необязательно)                              │
│ [ textarea, лимит 4000                              ] │  ← COMMUNITY_DESCRIPTION_MAX_LENGTH, plain text не md
│                                                        │
│ Видимость                                             │
│ [● Публичное]  [○ По ссылке]                          │  ← SelectionTile-пара, публичное — дефолт
│                                                        │
│              ┌ Отмена ─┐  ┌ Создать сообщество   → ┐  │  ← secondary-стекло + зелёная primary
└────────────────────────────────────────────────────────┘
```

- Только `kind='custom'` доступен пользователю (API `POST /communities` всегда ставит `'custom'` — каталожные `machine`/`vendor` заводятся системой лениво, эту ручку UI не трогает и не показывает выбор `kind`).
- **Slug** — не спрашиваем у пользователя (API генерирует транслитерацией + суффикс при коллизии, `contract.ts:slugify`); поле slug в форме нет, это скрытая деталь адреса.
- **Валидация тех же лимитов, что бэкенд** (клиент дублирует правило для мгновенной обратной связи, сервер — источник истины): имя обязательно/≤120, описание ≤4000. Тексты ошибок — по образцу §4.7 [ideas.md](ideas.md) (та же формулировка «до N символов» + счётчик у поля при приближении).
- **Успех** (`201`) — оверлей закрывается, редирект на `#/community/:slug` новой (владелец уже видит себя `owner`, §2.2). Без hero-полноэкранного успеха — это не такое редкое/значимое событие, как первая идея; тихий редирект + тред пуст с призывом «Заведите первый тред» (§3.4 пусто).
- **`SLUG_TAKEN` (409, гонка на транслитерации)** — тост «Название уже занято похожим сообществом, уточните» (редкий кейс, ретраить не нужно — просто попросить другое имя).
- Кнопка «Создать сообщество» — активна когда имя непустое и ≤ лимита; иначе dim с причиной у поля (тот же паттерн §4.5 [ideas.md](ideas.md)).

### 1.4 Состояния списка

- **Пусто** (нет сообществ вообще / по фильтру) — `EmptyState`: line-глиф людей/чата, «Сообществ пока нет» (общий список) или «Ничего не нашлось» (активен `q`/`kind`), подпись «Создайте своё — будете первым», CTA = «Создать сообщество» (та же кнопка §1.1, не дублируем зелёную — если primary уже видна в шапке, EmptyState даёт вторичную ссылку-репит действия на неё, не вторую зелёную).
- **Загрузка** — skeleton-сетка 6 карточек (shimmer, тот же паттерн, что каталог маркета).
- **Ошибка** — приглушённая строка «Не удалось загрузить сообщества» + `IconButton` «Повторить».
- **Догрузка** — курсорная пагинация `next_cursor`, «Показать ещё» внизу сетки (тот же паттерн, что лента идей §1.5).

## 2. Страница сообщества (`#/community/:slug`)

### 2.1 Вертикальный ритм

```
  ← Назад                                                        ← IconButton (light-шапка)

  [Принтер]                                                      ← CommunityKindBadge (если не custom)
  Bambu Lab фанаты                                    [Владелец] ← Heading (Unbounded) + RoleBadge (если состою)
  Обсуждаем профили печати, апгрейды, самодельные апгрейды…      ← description, полный текст (не clamp — это не лента)
  128 участников · 34 треда              ┌ Вступить          → ┐ ← мета + primary CTA (или «Выйти», §2.2)

  ─────────────────────────────────────────
  [Все] [Обсуждения] [Вопросы]         ┌ + Новый тред        →┐ ← сегмент-фильтр type + вторая зелёная? см. §2.3
  ┌ карточка треда ─────────────────────────────────────────┐
  │ …                                                        │
  └───────────────────────────────────────────────────────────┘
  … (лента, §2.4)
```

### 2.2 Вступить/выйти + роль

- **Гость сообщества** (`viewer_role === null`) — кнопка **«Вступить»**, зелёная primary (единственная на экране — см. §2.3 про конфликт с «Новый тред»). Тап → `POST /communities/:id/join`, оптимистично меняет кнопку на «Выйти» + появляется `RoleBadge` «Участник»; на ошибку — откат + тихий тост.
- **Участник** (`role='member'`) — кнопка **«Выйти»**, вторичное стекло (выход — не деструктив уровня удаления, но и не primary; коралловая обводка не нужна, это обратимое действие). Тап → `confirm`-подтверждение не нужен (обратимо одним тапом «Вступить» назад) → `POST /communities/:id/leave`.
- **Владелец/модератор** (`role ∈ {owner, moderator}`) — кнопка «Выйти» видна, но у **последнего owner** API вернёт `409 LAST_OWNER_CANNOT_LEAVE` → тост «Вы последний владелец — назначьте другого перед выходом» (нет UI назначения роли в этой фазе — `POST /communities/:id/members/:userId/role` требует списка участников, которого API этой фазы не отдаёт; открытый вопрос §8, не блокер).
- **`RoleBadge`** (§7.2) рядом с именем сообщества — показывает **только свою** роль (`owner`/`moderator`/`member`), не список чужих (нет ручки).

### 2.3 Новый тред — вторая зелёная? Нет

Правило «одна primary-CTA на экран» ([layout.md](layout.md)) требует решения: на странице сообщества одновременно претендуют «Вступить» (§2.2) и «+ Новый тред». Разводим по состоянию, не по двум зелёным одновременно:

- **Не состою** (`viewer_role === null`) — primary зелёная = **«Вступить»**. «Новый тред» здесь тоже нужен (API не требует членства для создания треда — `threads.ts` проверяет только сессию и статус сообщества, не роль), но рисуется **вторичным стеклом** — присоединение важнее для новичка (растит `member_count`, метрика вовлечённости эпика метрик §MF-732).
- **Состою** (`viewer_role !== null`) — «Вступить» кнопки уже нет (заменена на «Выйти», вторичная), значит зелёная primary освобождается → **«+ Новый тред»** становится зелёной. Ровно один переход состояния кнопки, не две одновременные CTA.

### 2.4 Карточка треда в ленте

```
┌───────────────────────────────────────────────────────────────────┐
│ [Вопрос] закреплён                                    ▲ 12         │  ← type-badge (+«закреплён» если pinned) · compact-голос
│ Почему профиль PLA плывёт на второй пластине?                      │  ← title, 1 строка, Unbounded medium
│ Печатаю на A1, первая деталь ок, вторая уже подтекает…    3 ответа  │  ← content-сниппет (plain, clamp 2) · post_count
│ #профили #a1 #pla                          @nick · 2 часа назад    │  ← теги (question) · автор · возраст
└───────────────────────────────────────────────────────────────────┘
```

- **`ThreadTypeBadge`** (§7.3) — «Обсуждение»/«Вопрос», нейтральный чип (не статусная семантика — это тип контента, не срочность). Question-тред с `accepted_post_id !== null` получает мелкую зелёную галочку рядом с бейджем «Вопрос ✓ решён» — единственный акцентный сигнал в ленте, помогает быстро найти закрытые вопросы.
- **`pinned`** — текстовая метка «закреплён» приглушённо рядом с type-badge (не отдельная иконка-канцелярия — не тот референс). Закреплённые треды уже идут первыми по сортировке API (`order by pinned desc`) — визуальная метка просто объясняет порядок.
- **Голос компактный** (§7.4, вариант `compact`) — торец карточки, тот же паттерн-место, что голосовалка идей ([ideas.md §2](ideas.md)), но это **Reddit-пара ▲/▼** (см. §7.4 — API даёт `votes_up`/`votes_down` раздельно и допускает `value:-1`), не upvote-only как у идей. Число = `votes_up − votes_down`.
- **Теги** — только у `question` (`THREAD_MAX_TAGS=5`), чипы мелкие, тап → фильтр ленты сообщества по тегу (открытый вопрос реализации — API этой фазы не отдаёт `GET /threads?tag=`, фильтрация тегов на клиенте по уже загруженной странице — приемлемо для MVP-объёма).
- **Тап по карточке** (кроме голоса) → `#/thread/:id`.

### 2.5 Форма нового треда (модалка, тот же приём что §1.3)

```
┌ Новый тред ──────────────────────────────────────────── ✕ ┐
│ [● Обсуждение]   [○ Вопрос]                                │  ← TypeToggle (тот же паттерн, что идеи/проблема, feedback.entrypoints.md §4)
│                                                             │
│ Заголовок                                                  │
│ [ Почему профиль PLA плывёт на второй пластине?          ] │  ← THREAD_TITLE_MAX_LENGTH=200
│                                                             │
│ Текст                                                      │
│ ┌ md-редактор (MF-497, лёгкий тулбар) ──────────────────┐ │  ← THREAD_CONTENT_MAX_LENGTH=20000
│ └─────────────────────────────────────────────────────────┘ │
│                                                             │
│ Теги (до 5, только для вопроса)                            │  ← поле показывается ТОЛЬКО при type='question'
│ [ профили ] [ a1 ] [ pla ] [ + добавить ]                   │
│                                                             │
│              ┌ Отмена ─┐  ┌ Опубликовать          → ┐      │
└───────────────────────────────────────────────────────────┘
```

- **`TypeToggle`** — тот же компонент, что развилка идея/проблема ([feedback.entrypoints.md §4](feedback.entrypoints.md)), два состояния вместо N — переиспользуем визуал (тайл-пара), не изобретаем третий toggle-примитив.
- **Теги — только question.** Поле тегов монтируется/скрывается по выбору типа (не dim, а буквально нет в DOM — переключение toggle меняет форму целиком). Ввод — чипы через запятую/Enter, максимум 5 (`THREAD_MAX_TAGS`), клиент режет 6-й молча-с-тостом «До 5 тегов».
- **Markdown** — переиспользуем редактор MF-497 ([projects.multiformat.md §3](projects.multiformat.md)), тот же санитайзер (raw HTML вырезан) — нулевой новый рендер, как и в идеях/маркете.
- **Ошибки** — зеркалят коды API: `TITLE_REQUIRED`/`TITLE_TOO_LONG`/`CONTENT_REQUIRED`/`CONTENT_TOO_LONG`/`INVALID_TAGS` → те же формулировки-паттерна, что §4.7 [ideas.md](ideas.md) («Заголовок — до 200 символов» и т.п.).
- **Успех** — закрыть модалку, редирект `#/thread/:new_id`.

### 2.6 Состояния ленты тредов

Тройка пусто/загрузка/ошибка, как §1.4, тексты под контекст: пусто → «Тредов пока нет. Начните обсуждение» + CTA «Новый тред» (не создаём вторую зелёную — если «Новый тред» уже primary §2.3, EmptyState даёт вторичный повтор действия; если primary сейчас «Вступить» — сюда зелёную всё равно не ставим, вторичная кнопка ведёт в ту же форму).

## 3. Страница треда (`#/thread/:id`)

### 3.1 Вертикальный ритм

```
  ← Назад                                                              ← IconButton, ведёт в #/community/:slug

  Bambu Lab фанаты · @nick · 3 часа назад            [Вопрос] [✓ решён]  ← eyebrow: сообщество·автор·возраст + type/accepted
  Почему профиль PLA плывёт на второй пластине?                          ← Heading, двухтоновый как обычно НЕ форсим (юзер-текст, §3.2 ideas.md принцип)
  #профили  #a1  #pla                                                    ← теги (question)

  <markdown-рендер содержимого треда>                                   ← MF-497 типографика

  ┌ ▲ ─┐                                                                 ← голос за ТРЕД, крупный вариант (§7.4 large)
  │ 12 │
  └ ▼ ─┘

  ─────────────────────────────────────────
  3 ответа                                                              ← заголовок секции + post_count
  ┌ композер (kind по типу треда) ───────────────────────────────────┐
  └──────────────────────────────────────────────────────────────────┘

  ┌ [✓ Принято] @masha · 1 час назад                        ▲ 8  ▼ ┐   ← принятый ответ ЗАКРЕПЛЁН сверху (question)
  │ <md ответа>                                                     │      кнопка «Отметить принятым» видна только автору
  └──────────────────────────────────────────────────────────────────┘   вопроса, на posts.kind='answer'
  ┌ @petya · 40 мин назад                                    ▲ 3  ▼ ┐
  │ <md ответа>                              [ Отметить принятым ] │   ← видно только автору вопроса, ТОЛЬКО на answer
  └──────────────────────────────────────────────────────────────────┘
  … остальные посты по голосам (question) / по времени (discussion)
```

### 3.2 Заголовок и мета

- **Eyebrow** — `название сообщества` (ссылка на `#/community/:slug`) `·` `@автор` (ссылка `#/u/:username`) `·` относительный возраст. Правее — `ThreadTypeBadge` + «✓ решён» (только question с `accepted_post_id !== null`), тот же принцип, что в ленте (§2.4).
- **Заголовок** — обычный `Heading`, **без** принудительного акцентного слова (тот же принцип, что заголовок идеи, [ideas.md §3.2](ideas.md): юзер-текст произвольный, красить слово наугад нельзя).
- **Теги** — под заголовком, чипы, только question.
- **Содержимое** — markdown-рендер (MF-497, тот же санитайзер что везде).
- **Закрытый/заблокированный тред** (`status ∈ {closed, locked}`, статус ставится вне этого API-контракта — модерация вне охвата этой фазы) — форма ответа (§3.4) скрыта, вместо неё спокойная строка «Тред закрыт для новых ответов»; чтение и голосование остаются доступны. Отмечаю на случай, если статус появится в UI раньше модерационных инструментов — сама модерация (кто и как переводит статус) вне охвата этой карточки.

### 3.3 Голосование за тред

**Reddit-стрелки** (§7.4, вариант `large`) — прямой перенос уже принятого паттерна модели ([marketplace.v2.md §3.1](marketplace.v2.md)): вертикальная пара ▲/▼ на полупрозрачном стекле, число между ними = `votes_up − votes_down`, ▲ активная заливается `--accent`, ▼ активная — `--accent-danger`, повторный тап по активной = снятие (`value:0`), оптимистичный апдейт, **без пульса/звука** (голос — не срочность, тот же вывод, что уже зафиксирован в motion.md §8/sound.md §3 для upvote-идей — распространяем на downvote тоже: даунвоут это несогласие, не алерт).

### 3.4 Композер ответа

Форма зависит от `thread.type` (контракт `posts.ts`: `question → answer|comment`, `discussion → reply|comment`):

- **Question** — композер по умолчанию отправляет `kind='answer'` (основной ответ на вопрос, самый частый кейс). Под текстовым полем — мелкая ссылка-переключатель «Оставить комментарий вместо ответа» → `kind='comment'` (для «уточните формат вопроса», не претендует на «принято»). Плейсхолдер «Ваш ответ…» (или «Ваш комментарий…» при переключении).
- **Discussion** — композер по умолчанию `kind='reply'` (реплика в общей ветке), тот же переключатель на `comment` для короткой реакции. Плейсхолдер «Ваш ответ…»/«Комментарий…».
- **Reply/comment на конкретный пост** — кнопка «Ответить» на карточке поста (§3.5) открывает тот же композер с `parent_post_id` предзаполненным и визуальной меткой «Ответ для @nick» над полем (отмена — крестик у метки, возвращает композер к обычному виду без `parent_post_id`).
- Технически — тот же лёгкий md-редактор, что везде (MF-497), `POST_CONTENT_MAX_LENGTH=20000`. Кнопка отправки — **нейтральная**, не зелёная (тот же довод, что комментарии модели, [marketplace.v2.md §4.1](marketplace.v2.md): зелёная primary страницы уже занята голосом/вступлением, локальное действие блока не спорит за неё).
- Гость — сайт целиком за `AuthGate` ([marketplace.v2.md §4.2](marketplace.v2.md) — уже так для комментариев модели), отдельного «войдите, чтобы ответить» текста не нужно, композер всегда доступен залогиненному.

### 3.5 Карточка поста

```
┌ [✓ Принято]  @masha · 1 час назад                       ▲ 8 ▼  ┐
│ <md-рендер тела ответа>                                        │
│                                          [ Ответить ]           │  ← видно всем (кроме гостя — его нет)
│                              [ Отметить принятым ]              │  ← видно ТОЛЬКО автору вопроса, ТОЛЬКО kind='answer'
└─────────────────────────────────────────────────────────────────┘
```

- **Автор + возраст** — как везде (`@nick` ссылка на профиль, относительное время).
- **`is_accepted`** (флаг из `GET /threads/:id`, посчитан бэком) — рендерит бейдж **«✓ Принято»** слева от меты, зелёная точка+галочка (пик яркости «яркость=важность», аналог статуса «готово» у идей — [components.md «Статус-пилюля»](components.md)). Только один пост в треде может быть `is_accepted`.
- **Закрепление принятого сверху** — не клиентская сортировка: `GET /threads/:id` уже отдаёт `posts[]` в нужном порядке (accepted → по голосам → по времени, `thread-detail.ts`). UI просто рендерит массив как есть, **не пересортировывает сам** — источник истины сервер, повторный `GET` после голосования/accept возвращает уже пересортированный список.
- **Голос компактный** (§7.4, вариант `compact`) в правом торце карточки поста — тот же Reddit-контрол, что у треда (§3.3), только меньше.
- **«Ответить»** — открывает композер с `parent_post_id` (§3.4). Видно на всех постах (и answer, и reply, и comment) — вложенность один уровень, глубже API не поддерживает (`parent_post_id` не рекурсивен по контракту — плоская привязка к любому существующему посту в треде).
- **«Отметить принятым»** — рендерится **только если** `viewer.id === thread.author_id` (я — автор вопроса) **и** `post.kind === 'answer'` **и** `thread.type === 'question'` — тройное условие, не одно. На чужих ответах-`comment` кнопки нет вообще (не только dim — её физически нет, `NOT_AN_ANSWER` иначе вернёт 422). Тап → `POST /threads/:id/accept {post_id}`, оптимистично помечает пост, **вызывает пересортировку с анимацией** (§7.5), при ошибке — откат.
- **Уже принят другой пост** — на новом кандидате кнопка читается «Сделать принятым вместо текущего» (не «Отметить» с нуля) — снятие с прежнего происходит автоматически на бэке (`accept.ts`: новый accept просто перезаписывает `accepted_post_id`, старый эффект не отзывается явно, только визуально теряет бейдж на следующем `GET`).
- **Вложенный reply** (есть `parent_post_id`) — визуальный отступ ~24px + тонкая вертикальная направляющая линия слева (один уровень, не рекурсивная лесенка — контракт плоский).

### 3.6 Состояния

- **Пусто** (0 постов) — под композером `EmptyState` компактный: «Пока нет ответов. Будьте первым» (discussion) / «Пока нет ответов на вопрос» (question) — тот же тон, что пустое обсуждение модели ([marketplace.v2.md §4.2](marketplace.v2.md)).
- **Загрузка** — skeleton 2–3 карточек поста.
- **Ошибка загрузки треда** (404/500) — не пустой экран: «Тред не найден» / «Не удалось загрузить тред» + IconButton «Повторить»/ссылка назад в сообщество.

## 4. Мобайл/планшет/тач

Наследует общий тач-контракт без изменений ([layout.md](layout.md): ≥48px, `:active`, `touch-action:manipulation`, `-webkit-tap-highlight-color:transparent`). Дельта:

- **Композер (§3.4):** на мобиле — `textarea` авто-растёт, кнопка отправки прилипает над системной клавиатурой (`position: sticky`, не `fixed` — избегаем прыжка при открытии клавиатуры на iOS).

## 5. Моушен и звук (сводка, ничего нового не вводим)

Все паттерны — уже существующие, применяем без изменений:

- **Тап любой кнопки/карточки/чипа/тайла** — `.pressable` (`--dur-tap`/`--dur-press`) + звук `tick` ([motion.md §1](motion.md), [sound.md §3](sound.md)).
- **Голос (тред/пост, §3.3/§3.5)** — count-up ± дельта, микро-подскок стрелки (`--dur-pop`, тот же keyframe что `modelVoteBounce`, [motion.md §8](motion.md)), **без звука** (осознанно, components.md/sound.md §3 — распространяем на downvote).
- **«Вступить»/«Выйти», TypeToggle** — `toggle`-тембр + морф заливки `--dur-toggle` ([motion.md §7](motion.md), [sound.md §2](sound.md)).
- **Создание сообщества/треда (успех)** — `cta`-тон на тапе «Создать»/«Опубликовать» ([sound.md §3](sound.md)), закрытие модалки — `.modal-in-out` (`--dur-slow`).
- **Отметить принятым (успех)** — момент подтверждения: бейдж «✓ Принято» появляется с тем же приёмом, что галочка успеха ([motion.md §4](motion.md): stroke-dashoffset 0→100% 220ms) + мгновенный цвет на полную яркость. Пересортировка постов ниже — **не** резкий скачок позиций: список анимируется через FLIP-переход (элемент, получивший accepted, плавно едет на новую позицию, `--dur-reveal`/`--ease-out`, ~280ms), а не мгновенная перерисовка — иначе «куда делся мой пост» дезориентирует на самом ценном моменте Q&A. Синхронный звук — `cta`-тон на тап (действие автора вопроса), без отдельного тона на переезд постов (не жест пользователя).
- **Появление ленты (сообщества/треды/посты)** — `.stagger-reveal`, без звука ([motion.md §5](motion.md)/[sound.md §3](sound.md): загрузка контента — не жест).

## 7. Новые переиспользуемые компоненты (→ components.md)

Паттерн повторился ≥2 раза в этой же спеке (карточка сообщества/лента/детали, лента тредов/деталь треда, посты) — фиксирую здесь как контракт для `components.md` (эволюция дизайн-системы, MF-40).

### 7.1 `CommunityKindBadge`

Малый чип, семейство `Chip`/`StatusPill` (пилюля, line-глиф, без эмодзи) — тот же приём, что `CraftBadge` ([projects.md §2](projects.md)): реестр `kind → {метка, глиф}`, нейтральный тон (не статусный — это категория, не срочность).

| `kind` | Метка | Глиф |
|---|---|---|
| `machine` | Принтер | line-иконка принтера |
| `vendor` | Филамент | line-иконка катушки |
| `craft` | Ремесло | line-иконка инструмента |
| `custom` | *(скрыт)* | — |

### 7.2 `RoleBadge`

Мелкая нейтрально-серая пилюля (аналог `AgentBadge` по форме, [components.md](components.md) — не смешивать смысл, отдельная ось), показывает **только собственную** роль зрителя в сообществе (нет API-списка участников → нет UI для чужих ролей в этой фазе).

| `role` | Подпись |
|---|---|
| `owner` | Владелец |
| `moderator` | Модератор |
| `member` | Участник |

### 7.3 `ThreadTypeBadge`

Пилюля типа треда, нейтральный тон (тип контента, не статус/срочность): `discussion` → «Обсуждение», `question` → «Вопрос». Question с `accepted_post_id !== null` — рядом мелкая зелёная «✓ решён» (единственный акцентный сигнал у бейджа, пик «яркость=важность» для закрытых вопросов).

### 7.4 `VoteArrows` (Reddit-пара ▲/▼) — обобщение существующего `modelVote`

**Не новый компонент с нуля** — обобщение уже реализованного паттерна модели (`apps/web/src/market/model.tsx`, классы `.modelVote`/`.modelVoteBtn`/`.modelVoteCount`, спека [marketplace.v2.md §3.1](marketplace.v2.md)). Тот же контракт `{value: 1|-1|0}` → `{votes_up, votes_down, my_vote}` уже используют `POST /threads/:id/vote` и `/posts/:id/vote` (identичная форма ответа, что `/models/:id/vote`) — это третий и четвёртый вызывающий, порог «повторилось дважды» ([components.md](components.md) правило эволюции) пройден, стоит вынести в общий компонент, параметризованный `subjectType: 'model'|'thread'|'post'` и вариантом размера, вместо копирования JSX/CSS в третий раз.

- **Варианты:** `large` (страница треда, §3.3) — крупный счётчик + широкие стрелки; `compact` (карточка треда в ленте §2.4, карточка поста §3.5) — уменьшенная версия, тап-таргет держит ≥48px несмотря на меньший визуальный размер стрелки (паддинг компенсирует).
- **Форма/цвет/тач/моушен/звук** — без изменений от уже принятого: полупрозрачное стекло, ▲ активная = `--accent`, ▼ активная = `--accent-danger`, повторный тап = снятие, оптимистичный апдейт, `--dur-pop`/`--ease-spring`, без звука ([marketplace.v2.md §3.1](marketplace.v2.md), [motion.md §8](motion.md)).
- **`aria`** — `aria-pressed` на активной стрелке, `aria-label` «Голосовать за/против …, сейчас N голосов», счётчик `aria-live=polite`.

### 7.5 FLIP-пересортировка списка (Q&A accept)

Новый примитив анимации: элемент списка, сменивший позицию после серверного ответа (`accept`/`vote` в question-треде), переезжает на новое место плавным transform-переходом, а не мгновенной перестановкой DOM. Механика — стандартный FLIP (First-Last-Invert-Play) на клиенте: замерить позицию до перерисовки, применить обратную трансформацию, снять её анимацией `--dur-reveal`/`--ease-out`. Первое реальное применение — здесь; если паттерн понадобится в третьем месте (например, будущая пересортировка ленты идей по трендам), выносить в общий хук `useFlipReorder` тогда же, не раньше (тот же принцип «повторилось дважды → фиксируем», не «про запас»).

**Контракт API** (из `c534952`, роуты живут на dev.3mf.tech — см. плашку в начале файла):

| Метод | Путь | Использует |
|---|---|---|
| `POST` | `/communities` | §1.3 форма создания |
| `GET` | `/communities?kind&q&cursor&limit` | §1 список |

| `POST` | `/communities/:id/join` | §2.2 |
| `POST` | `/communities/:id/leave` | §2.2 |
| `POST` | `/communities/:id/members/:userId/role` | не используется в этой фазе UI (нет списка участников, §2.2 примечание) |
| `POST` | `/communities/:id/threads` | §2.5 форма треда |

| `POST` | `/threads/:id/vote`, `/posts/:id/vote` | §3.3/§3.5 (`{value:1|-1|0}` → `{votes_up,votes_down,my_vote}`) |
| `POST` | `/threads/:id/accept` | §3.5 «Отметить принятым» (`{post_id: uuid|null}`) |

**Открытые вопросы (следующий проход, не блокируют реализацию §1–7):**

1. **Нет `GET`-списка участников сообщества** — `RoleBadge` (§7.2) поэтому показывает только свою роль, не список «кто модератор»; управление ролями (`members/:userId/role`) не имеет UI в этой фазе. Если понадобится страница участников — отдельная карточка, не блокер.
2. **Нет вкладки «Мои сообщества»** в профиле (по аналогии с «Мои идеи», [feedback.entrypoints.md §6](feedback.entrypoints.md)) — API этой фазы не отдаёт `GET /me/communities`; `RoleBadge` в сетке (§1.2) — временная замена сигнала «я тут состою» без отдельного экрана.
3. **Фильтр ленты по тегу** (§2.4) — `GET /communities/:id/threads` не принимает `tag=`; для MVP-объёма фильтрация на уже загруженной странице клиентом приемлема, при росте объёма тредов — нужен серверный параметр (Back).
4. **Вложения/inline-превью моделей в постах** — отдельная карточка [MF-744](https://tasks.3mf.tech) (Back), эта спека их не ждёт: композер §3.4 и карточка поста §3.5 не резервируют место под них специально, но и не мешают — вложение по паттерну markdown-редактора MF-497 (кнопка на тулбаре) добавится вторым проходом без переверстки текстового блока.
5. **Гео-клубы** (MF-26, региональные сообщества) — вне охвата, `kind` не расширяется этой спекой.
6. **Модерация тредов** (`status='closed'/'locked'`, кто и как переводит) — UI §3.2 читает статус, но не даёт инструментов его менять; отдельная карточка при появлении модераторских действий.
