## 0. Принципы (унаследованы, не изобретаем новые)

- **Одна мысль на экран** (readme.md §2): в просмотрщике — один шаг, не список шагов сразу.
- **Тач-первый**: тап-таргеты ≥48px, `:active` вместо `:hover`, drag в редакторе — desktop-удобство, но не единственный способ переупорядочить (см. §1.2).
- **Не строим новый аплоадер** — редактор шага переиспользует существующий загрузчик фото/файлов проекта (MF-9, роль `description_image`-подобная — `assembly_step_photo`) и существующий превью-стек карточки (не заводим третий визуальный язык для одной фотографии).
- **Не токенизируем лишнее** — раскладки ниже используют существующие компоненты (`Card`, `Chip`, `SelectionTile`, `Checklist`-паттерн бара, `StatTile`, `IconButton`) и токены (`--dur-*`, метрики из `metrics.md`). Новых component-токенов вводим два: `--dur-step` (переход между шагами) уже покрыт `--dur-nav` — **не заводим**, используем существующий.

## 1. Редактор гайда (карточка автора, MF-9, вкладка «Сборка»)

Вкладка живёт в табах редактора проекта рядом с «Файлы»/«Описание» (существующая вкладочная навигация MF-9 — `SegmentToggle`-паттерн, components.md). Контент вкладки — список шагов + панель редактирования выбранного.

### 1.1 Раскладка

**Desktop/tablet (≥900px):** двухколоночный сплит внутри вкладки.
- **Левая колонка (~320px, sticky)** — список шагов: карточка-строка на шаг (drag-хендл слева · номер · превью-миниатюра 40×40 если есть фото, иначе плейсхолдер-глиф · заголовок шага, обрезан в одну строку · кнопка удаления справа, `IconButton` тон `danger`, появляется по `:active`/фокусу строки, не висит всегда — не захламляем список). Внизу списка — `Button` вторичный «+ Добавить шаг» на всю ширину колонки.
- **Правая колонка** — форма редактирования шага, выбранного в списке слева (клик по строке = выбор, `data-selected`, подсветка `--accent` тонкой левой полосой 3px как выбранный пункт меню). Пустое состояние (ни одного шага) — `EmptyState` по центру правой колонки: «Добавьте первый шаг» + та же кнопка «+ Добавить шаг».

**Mobile (<900px):** список и форма — не сплит, а последовательность. Список шагов — вертикальная лента карточек-строк (та же раскладка строки, но без sticky). Тап по строке **не показывает форму рядом** (нет места) — открывает `Sheet`/полноэкранный оверлей редактирования шага (тот же паттерн, что модалка «Добавить» в маркете — `marketplace.full.md`), с кнопкой «Готово» вверху закрывающей обратно к списку. Drag-переупорядочивание на тач — см. §1.2.

### 1.2 Переупорядочивание шагов

Два равнозначных способа, не один:

- **Drag (desktop, мышь/перо + тач через long-press)** — хендл-«шесть точек» (`⠿`, line-icon 2px stroke, тот же язык, что весь набор иконок) слева строки, `cursor: grab`/`grabbing`. Во время перетаскивания: перетаскиваемая строка — `opacity: .85` + лёгкая тень приподнятости (`box-shadow` увеличенный blur), остальные строки уступают место плавным сдвигом (`--dur-toggle`/`--ease-spring`, тот же морф, что везде для перекомпоновки). Дроп — строка садится на место с лёгким `--dur-pop` оседанием. Номера шагов (1, 2, 3…) пересчитываются сразу после дропа, не после сохранения.
- **Кнопки ↑/↓ (всегда доступны, тач-надёжный фолбэк)** — по краю строки, каждая ≥48×48px тап-зона (даже если визуальная иконка компактнее — components.md инвариант), меняют шаг местами с соседним, тот же плавный сдвиг-морф что и drag. Первая строка — кнопка ↑ дизейблена (`opacity .4`, не скрыта — предсказуемая раскладка), последняя — ↓ дизейблена. Это не дублирование drag «на всякий случай» — это единственный надёжный путь на тач-скринридере/клавиатуре (`aria-label="Переместить шаг вверх/вниз"`), drag непригоден для a11y как единственный механизм.

Сохранение порядка — оптимистичное (номера обновляются на клиенте сразу), фактический `PATCH`/`PUT` порядка шагов уходит на бэк с debounce, как обычные автосейвы редактора проекта (не блокируем UI ожиданием ответа на каждый свап).

### 1.3 Форма шага (правая колонка / sheet)

Сверху вниз, одна карточка-форма:

1. **Фото шага** — тот же аплоадер+превью, что MF-9 использует для `description_image`/файлов проекта: дропзона-плейсхолдер (пунктирная обводка `--border`, line-icon камеры + подпись «Загрузить фото»), после загрузки — превью 16:9 с кнопкой замены/удаления (`IconButton ×` в углу превью). Необязательное поле — шаг без фото допустим (не все шаги фотогеничны), но пустая дропзона не блокирует сохранение.
2. **Текст шага** — многострочный `Input`/textarea, авто-рост высоты, плейсхолдер «Что делаем на этом шаге?». Markdown не нужен (короткая инструкция, не пост ленты) — обычный текст с переносами строк.
3. **Модели/детали проекта** — `SelectionTile`-сетка (тот же паттерн, что выбор S/M/L, components.md), по одной плитке на файл/деталь проекта (превью-миниатюра + имя файла), мульти-выбор (тап переключает `data-selected`, не radio). Список деталей — уже загруженные файлы проекта (MF-9 «Файлы»), не новый источник данных.
4. **Крепёж/инструменты** — `Chip`-мульти-выбор (пилюли, тот же тон, что фильтры каталога): готовый набор чипов из справочника крепежа/инструментов (винт M3×10, шестигранник 2.5мм и т.п. — источник справочника вне скоупа дизайна, у Back), выбранные — залиты `--accent` 12% + текст `--accent`, невыбранные — обычное `dim`-стекло. Если справочника ещё нет на дату верстки — свободный текстовый `Chip`-ввод («добавить вручную» plus-чип в конце ряда) как временный фолбэк, не блокировать верстку.

### 1.4 Motion/Sound редактора

| Событие | Токен | Звук |
|---|---|---|
| Добавление шага (кнопка «+») | новая строка въезжает `--dur-pop`/`--ease-spring` снизу списка + `.stagger-reveal` если несколько сразу | `tick` |
| Удаление шага | строка сжимается по высоте и растворяется `--dur-nav`/`--ease-out`, соседи занимают место тем же сдвигом-морфом | `toggle`-тембр (деструктивное, но обратимое действие — не critical-алерт, без коралловой пульсации) |
| Drag/свап шага | сдвиг соседей `--dur-toggle`/`--ease-spring`, дроп-оседание `--dur-pop` | `tick` на дроп (не на каждый промежуточный сдвиг во время протяжки — иначе трещотка) |
| Выбор шага в списке (desktop) | подсветка левой полосы `--dur-tap` | без звука (это фокус, не действие) |
| Открытие/закрытие sheet (mobile) | тот же паттерн, что модалка маркета — `--dur-nav`/`--ease-out` slide-up/down | `nav`-свуш |
| Тап по `SelectionTile`/`Chip` | `.pressable` стандарт | `tick` |

## 2. Просмотрщик гайда (карточка проекта, MF-10)

Отдельная вкладка/секция на странице проекта (рядом с «Файлы», «Обсуждение» — существующая IA `projects.page.md`), заголовок «Сборка» + счётчик «Шаг 3 из 8».

### 2.1 Раскладка шага

**Desktop/tablet:** двухколоночный сплит внутри вьюпорта секции (не всей страницы — шапка/нав проекта остаются).
- **Левая колонка** — 3D-превью детали текущего шага (тот же слоёный псевдо-3D стек, что каталог — [model.preview.md](model.preview.md): амбиент-свечение + объём + резкий силуэт + тень пола, парение выключено в статике превью детали, чтобы не отвлекать от инструкции — **без** float-анимации здесь, только появление). Если у шага несколько деталей — плитки-миниатюры под главным превью, тап переключает главное (тот же принцип, что галерея карточки модели).
- **Правая колонка** — текст шага (крупно, `--font-sans`, не Unbounded — это инструкция для чтения, не hero-заголовок), под ним компактный список «Понадобится на этом шаге»: крепёж/инструменты шага как `Chip`-ряд некликабельный (информационный, не фильтр).

**Mobile (<900px, в духе MF-42 — без горизонтального скролла §0):** вертикальный стек, не сплит — 3D-превью сверху (квадрат, во всю ширину минус отступы), текст шага под ним, список крепежа/инструментов под текстом. Никакого горизонтального свайпа карточек — весь горизонтальный скролл на этом экране запрещён инвариантом touch.nav.md §0 духа MF-42.

### 2.2 Навигация между шагами

- **Кнопки «← Назад» / «Далее →`»** внизу секции, полноширинные на mobile (две кнопки в ряд, `flex: 1` каждая — тот же принцип, что таббар touch.nav.md), на desktop — по краям под контентом. Последний шаг — «Далее» меняется на «Готово ✓» (`--accent` заливка, завершающее действие, тот же приём «терминальный шаг ярче», что чек-лист `level:4` из components.md §«Статус-пилюля»). Первый шаг — «Назад» дизейблена (`opacity .4`, не скрыта).
- **Свайп влево/вправо по контенту шага (mobile, ≤640px)** — второй вход к тем же «Назад»/«Далее», **тот же паттерн, что touch.nav.md §2** (rubber-band, порог 25%/флик, axis-lock от вертикального скролла инструкции). Не новая механика — переиспользуем `hero.tsx` rubber-band разбор, как это уже сделано для навигации по разделам.
- **Переход между шагами** — та же View Transition, что переход разделов (motion.md §2, `--dur-nav`/`--ease-out`), направление анимации соответствует «Далее»→слева-направо / «Назад»→справа-налево (тот же `data-nav-dir`, что везде).

### 2.3 Чек-лист прогресса

Компактная строка-индикатор над контентом шага (не отдельная развёрнутая карточка типа `Checklist` из ui.tsx — там она для онбординга со списком заголовков, здесь список шагов может быть длинным и не нуждается в тексте каждого):
- **Прогресс-бар** — та же полоска-заливка, что `.uiChecklistBar`/`.uiChecklistBarFill` (components.md/`ui.tsx`), заполнение = `текущий_шаг / всего_шагов`, подпись рядом «Шаг 3 из 8».
- **Точки-маркеры** под баром (по одной на шаг, ≤12 шагов показываем все точки; больше — бар без точек, только текст, точки на такой плотности превращаются в шум): пройденный шаг — залитая точка `--accent`, текущий — залитая точка чуть крупнее + кольцо-акцент, будущий — контурная `--text-dim`. Тап по точке (desktop/tablet, не занимает мобильный тач-таргет плотной строки) — прыжок на соответствующий шаг, та же переходная анимация §2.2.

**Синхронизация прогресса:**
- Залогиненный с активной build session — состояние шага пишется в эту
  session (см. контракт Back), при повторном визите она открывается на первом
  готовом/непройденном действии. В проект и авторский шаблон прогресс не
  записывается.
- Гость — в `localStorage` можно хранить только позицию чтения (ключ по id
  проекта/гайда), чтобы продолжить с места. Это не build session, не
  `done`-evidence и не основание добавить проект в «Собрано». Баннер логина
  посреди инструкции не нужен; авторизация предлагается на действии
  «Начать сборку».

В публичном просмотрщике переход «Далее» меняет только позицию чтения.
В build session действие становится `done` только после явного
подтверждения/валидного результата соответствующего шага: «прочитал» не
равно «сделал». Повторный просмотр инструкции состояние не снимает.

### 2.4 Motion/Sound просмотрщика

| Событие | Токен | Звук |
|---|---|---|
| Переход «Далее»/«Назад» (кнопка) | `--dur-nav`/`--ease-out`, направленный View Transition | `nav`-свуш, pitch по направлению (тот же принцип, что touch.nav.md §6) |
| Довершённый свайп (mobile) | тот же переход, что кнопка | тот же `nav`, звук идентичен тапу по кнопке |
| Недотянутый свайп/откат | rubber-band возврат, без токена (следует за пальцем) | без звука (жест не завершился — touch.nav.md §6 принцип) |
| Точка-маркер заполняется (шаг пройден) | `--dur-toggle`/`--ease-spring`, тот же морф что заливка тумблера | `tick`, тише обычного — фоновое подтверждение, не отдельное событие |
| Последний шаг → «Готово ✓» | кнопка доливается в `--accent`, короткая вспышка `--dur-callout` | `success` (severity), это терминальное событие гайда — заслуживает полноценного, не приглушённого как pull-to-refresh (там фоновая подгрузка списка, здесь — завершение целого сценария пользователя) |
| Переключение детали в 3D-превью (плитка-миниатюра) | кросс-фейд главного превью `--dur-nav`/`--ease-out`, без float (см. §2.1) | `tick` |

## 3. BOM-сводка

Блок в начале секции «Сборка» (до первого шага просмотрщика), сворачиваемый (`Card` с `Eyebrow` «Понадобится для сборки» + шеврон, открыт по умолчанию на desktop, свёрнут по умолчанию на mobile — экономим первый экран под сам гайд).

### 3.1 Раскладка

Три подсписка одна под другой (не табы — все три обычно короткие, табы были бы лишним кликом ради экономии места, которого и так хватает):

1. **Детали для печати** — сетка `SelectionTile`-подобных плиток (переиспользуем визуальный язык §1.3, но здесь некликабельны для выбора — кликабельны для перехода): миниатюра детали (тот же слоёный псевдо-3D превью, компактный вариант — как плитка каталога) + имя + агрегированное количество («×2» бейдж поверх миниатюры, сумма по всем шагам, где деталь встречается). **Клик по плитке → переход на модель** (маршрут карточки модели/файла проекта) — единственный кликабельный подсписок BOM, печатная деталь всегда ведёт к своему 3D-объекту.
2. **Крепёж** — `Chip`-ряд, агрегированные количества в подписи чипа («Винт M3×10 ×12»), некликабельно (крепёж не ведёт никуда — это не модель).
3. **Инструменты** — тот же `Chip`-ряд, без количеств (инструмент либо нужен, либо нет — считать «×3 отвёртки» бессмысленно), некликабельно.

Пустой подсписок (гайд без крепежа, например) — подзаголовок подсписка не рендерится вовсе, не показываем «Крепёж: —» — не подсвечиваем отсутствие незначимой секции.

### 3.2 Motion/Sound

- Раскрытие/сворачивание блока — стандартный аккордеон-паттерн: высота `--dur-nav`/`--ease-out`, шеврон поворот на 180° тем же таймингом. Звук — `toggle`-тембр (смена состояния раскрыт/свёрнут).
- Клик по детали → переход — обычная навигация, тот же `nav`-свуш, что везде.
- Появление плиток при первом раскрытии — `.stagger-reveal`, тот же примитив, что подгрузка карточек (motion.md §5), ~40–60ms между плитками.

## 4. Что переиспользуем, что не заводим заново

- Аплоадер/превью фото шага — существующий из MF-9 (`description_image`-подобная роль), НЕ новый компонент.
- Псевдо-3D превью детали (BOM-плитка, превью шага) — существующий слоёный стек [model.preview.md](model.preview.md), НЕ новый визуальный язык для детали.
- Прогресс-бар/точки — расширение существующего `.uiChecklistBar` паттерна (`ui.tsx`), НЕ копия `Checklist` целиком (там текстовый список шагов с заголовками — здесь плотные точки, разные плотности данных).
- Свайп между шагами — переиспользует rubber-band разбор `hero.tsx`/паттерн touch.nav.md §2, НЕ вторая реализация жеста.
- `SelectionTile`/`Chip`/`Card`/`IconButton`/`EmptyState` — существующий словарь `ui/ui.tsx`, без вариаций разметки по месту.

## 5. Готово когда (сверка с критериями MF-1012/MF-9)

- Редактор: список шагов drag- и кнопками-переупорядочиваемый (оба пути работают, кнопки — a11y-фолбэк, не декоративный дубль), форма шага сохраняет фото/текст/детали/крепёж-инструменты, ≥5 шагов переживают reload в том же порядке.
- Просмотрщик: один шаг на экране, кнопки и свайп (mobile) листают вперёд/назад, точки-маркеры и бар синхронно отражают позицию, прогресс переживает reload у залогиненного (бэк) и гостя (`localStorage`), мобильный шаг читается без горизонтального скролла.
- BOM: агрегированные количества деталей/крепежа совпадают с суммой по шагам, клик по печатной детали ведёт на модель, крепёж/инструменты — некликабельные списки с количествами/без.
- Каждый интерактивный элемент ≥48px тап-зоны, фокус видим (`:focus-visible`), звук на завершённых действиях (тап/переход/готово), тишина на незавершённых (недотянутый свайп/откат) — инвариант из touch.nav.md переносится сюда без изменений.
