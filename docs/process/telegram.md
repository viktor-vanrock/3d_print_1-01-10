# Телеграм-мост «Autofab» — вопросы агентов оператору

Канал для вопросов, которые может решить только оператор (Валерий): сроки, деньги, доступы, продуктовые развилки. Агент задаёт вопрос командой — вопрос прилетает в телеграм-чат, ответ оператора возвращается комментом в карточку.

## Как пользоваться (агентам)

Два канала, оба пишут вопрос в очередь моста; ответ оператора в любом виде возвращается комментом в карточку `MF-N`.

```bash
# открытый вопрос — кнопки [✅ Да] [❌ Нет] [⏳ Отложить] + ответ reply'ем
ask-operator MF-123 "Вопрос одной-двумя фразами"

# вопрос-выбор — опрос, оператор тапает вариант
ask-operator-choice MF-123 "Какой вариант?" "Вариант A" "Вариант B" "не нужно"
```

- Обе команды в PATH обоих раннеров (VDS: `/usr/local/bin/`, Мак: `/opt/homebrew/bin/` — проксирует на VDS по ssh).
- Имя спрашивающего — из `MULTICA_AGENT_NAME`/`ASK_AGENT`; сообщение подписано первой строкой: `🤖 Lead · MF-N`. Схема с отдельными саб-ботами на направленца **свёрнута 2026-07-08** (не оправдала себя) — работает один @AutofabBot с подписью.
- Оператор отвечает **одним из трёх способов**: тап инлайн-кнопки, выбор в опросе, или reply на сообщение-вопрос. Любой из них → коммент в карточку.
- Сам вопрос продублируй комментом в карточку (след). Оператор — последняя инстанция после направленца/CTO.

## Устройство

- **Главный бот** `@AutofabBot` (менеджер, `can_manage_bots`). Чат — супергруппа «Valery & Autofab» (`-1004375876872`), оператор `269949384`.
- **Подпись агента** — первой строкой сообщения (`🤖 <Агент> · MF-N`); отдельные саб-боты свёрнуты (managed-bots механика описана в git-истории этого файла, если понадобится вернуть).
- **Мост** — `~/tg-bridge/tg-bridge.mjs` на VDS (Node 22, systemd `tg-bridge.service`, v3). Интегрированы фичи Bot API 2026 (9.4–10.1):
  - **инлайн-кнопки** быстрого ответа на открытом вопросе (callback → коммент в карточку, кнопки гаснут после ответа);
  - **опросы-выбор** (`sendPoll`, `is_anonymous:false`) — тап варианта → `poll_answer` → коммент;
  - **реакция 👍** на reply-ответ оператора вместо лишнего сообщения (`setMessageReaction`);
  - **форум-топики на направление**: если группа переведена в форум (`is_forum`), мост сам создаёт топик «Autofab <Label>» и шлёт туда вопросы направления (`createForumTopic` + `message_thread_id`); иначе плоский чат;
  - **команды** `/help` `/status` (setMyCommands + меню-кнопка);
  - **managed sub-bots** (9.6): токен саб-бота берётся `getManagedBotToken` (параметр `user_id`).
  - Очередь: CLI кладёт JSON в `~/tg-bridge/queue/`, отдельный таймер (2с) шлёт; поллинг всех ботов параллельный (`Promise.all`).
- **Секреты**: токен главного бота — `~/tg-bridge/.env` (chmod 600, не в git); токены саб-ботов — `~/tg-bridge/state.json` (там же offsets getUpdates).

## Эксплуатация (Ops)

```bash
systemctl status tg-bridge          # жив ли
sudo journalctl -u tg-bridge -f     # лог
ls ~/tg-bridge/queue/               # зависшие вопросы (норма — пусто)
```

- Мост не отвечает → `sudo systemctl restart tg-bridge`; очередь не теряется (файлы).
- Новый саб-бот: оператор тапает диплинк → мост сам подхватит и отчитается в чат; затем оператор добавляет саб-бота в чат участником.
- Смена токена главного бота: BotFather → обновить `~/tg-bridge/.env` → рестарт юнита.
- Сеть: исходящие к `api.telegram.org` идут через Tailscale exit-node (см. `../infra/readme.md` § «Исходящий трафик»).

## Известные ограничения

- Формат ответа — только reply на сообщение-вопрос; сообщение без reply мост игнорирует.
- Форум-топики на направление включаются, только если оператор переведёт группу в режим «Темы» (настройка группы в приложении, не через Bot API). Код уже готов — включит автоматически при `is_forum:true`.
- Не интегрированы (неприменимо к Q&A-релею): Rich Messages/AI-стриминг (`sendRichMessageDraft` — для генеративных ответов самого бота, не наш кейс), live photos, paid media, подарки, guest/business mode, кастом-эмодзи на кнопках (нужен Premium у владельца).
- Не-текстовый ответ (фото/голос) в карточку не переносится — придёт пометка «смотри телеграм».
