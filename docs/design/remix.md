## 1. Контракт с API (требование к Фазе 1 / MF-369)

Спека собрана вокруг self-referential связи проекта, как описано в MF-369. Поля, которые нужны экрану — если бэкенд назовёт иначе, это переименование, не редизайн:

| Поле | На модели | Зачем |
|---|---|---|
| `remix_of_project_id` | ремикс | признак «это ремикс», ссылка на оригинал |
| `remix_of` (объект: `id`, `title`, `owner.username`, `owner.display_name`, `thumb_url`, `status`) | ремикс, денормализовано | блок «Ремикс из ‹оригинал›» рисуется без второго запроса |
| `remixes_count` | оригинал (и цепочка) | счётчик во вкладке, бейдж на плитке (§4.4) |
| `GET /models/:id/remixes?limit&offset` | оригинал | пагинированная выдача прямых ремиксов (только прямых — цепочки не разворачиваем, §3.3) |
| `POST /models/:id/remix` | оригинал | создание ремикса; сервер сам пишет атрибуцию, клиент её не отправляет (§2.3) |

**Ошибочные случаи, которые обязан различать API** (и которые обязан по-разному показать экран, §2.5, §5.4):
- нет прав (оригинал приватный/удалён у другого) → 403/404 → «Ремикс недоступен»;
- цикл (ремикс собственного потомка) → 409 → «Нельзя сделать ремикс из своего же ремикса этого проекта» (см. §2.5, редкий кейс, но обязателен по MF-369 «запрет циклов»);
- сеть/сервер → generic `toast critical`.

## 2. Поток «Сделать ремикс»

### 2.1 Точка входа

На карточке оригинала, в ряду действий рядом со «Скачать 3MF»/«Поделиться» (`model.card.v3.md` §0, вьюер-чром не трогаем) — вторая по значимости кнопка **«Сделать ремикс»**: secondary-стекло (не зелёный — зелёный уже занят «Скачать», правило «один primary на кадр» держим), иконка — ветвление/fork-глиф (`components.md` § «Иконки», тот же язык, что «Форк» дерева гита — namesake не случаен, это тот же ментальный жест «беру и продолжаю от этой точки»).

Кнопка видна **всегда**, когда модель `ready` (нечего ремиксовать из ещё конвертирующегося исходника — источник должен быть валиден и скачиваем). У модели в `pending`/`processing` кнопки нет вовсе (как «На весь экран» у вьюера, `model.card.v3.md` §3 — тот же принцип: не предлагать действие над тем, чего фактически ещё нет).

**У своей же модели** кнопки «Сделать ремикс» нет — ремикс собственного проекта не имеет смысла (это уже редактирование, кнопка «Редактировать» рядом решает эту задачу).

**Гость** (не залогинен) — кнопка видна, тап открывает overlay-промпт входа (тот же паттерн, что композер комментариев, `model.card.v3.md` §4.4), после логина продолжает поток на этой же карточке.

### 2.2 Что происходит: переиспользуем аплоад-модалку, не рисуем новую

Тап открывает **тот же `AddModelFlow`**, что «Добавить» из каталога (`marketplace.full.md` §11.1), с двумя отличиями:

1. **Заголовок модалки** — «Ремикс: {название оригинала}» вместо «Добавить модель» — пользователь должен видеть контекст, из чего он делает ремикс, весь путь до самой публикации.
2. **Блок атрибуции оригинала** — новая секция **над** дропзоной, `.marketField`-паттерном, но **не поле ввода** — плашка: миниатюра-превью оригинала (thumb, 40–48px, скруглённая) + название + `@username` автора, всё **не редактируется** (без инпута, без «×» — это факт, не черновик). Тап по плашке — переход на карточку оригинала в новой вкладке (не теряем черновик загрузки при уходе со страницы, `target="_blank"`).

Дропзона → «Название»/«Описание»/«Теги» → «Загрузить» дальше идёт **как есть** (§0). «Название» **не** предзаполняется названием оригинала (это была бы ловушка: два проекта с одинаковым именем в ленте, автор ремикса обязан дать своё) — пустое поле, как при обычной загрузке.

### 2.3 Публикация: сервер, не клиент, пишет атрибуцию

Клиент не отправляет ничего про оригинал в теле формы, кроме контекста запуска (`remix_of` берётся из URL, которым открыта модалка, `POST /models/:id/remix` — `:id` оригинала уже в пути). Это обязательное решение: атрибуция «нередактируема» именно потому, что клиент физически не может её подделать/стереть — не UI-запрет, а отсутствие поля.

Дальше — шаг «Опубликовать» (`marketplace.full.md` §11.2) **без изменений**: reveal → проверка полей → «Опубликовать» → переход на страницу **новой** карточки (`#/market/model/:id` ремикса).

### 2.4 Первое, что видно на новой карточке

На только что созданной странице ремикса **сразу виден** блок «Ремикс из ‹оригинал›» (§3) — это и есть подтверждение «получилось», обещанное в готовности карточки MF-1038 («после публикации виден блок…»). Не отложенный рендер — блок в том же первом кадре, что статус-пилюля `pending`/«В очереди» файла (`model.card.v3.md` §11.3): атрибуция не ждёт готовности файла, она есть с первой секунды.

### 2.5 Крайние случаи потока

| Ситуация | Поведение |
|---|---|
| Оригинал стал приватным/удалён между открытием карточки и тапом «Сделать ремикс» | Кнопка недоступна: тап → `toast critical` «Оригинал недоступен для ремикса» (без открытия модалки) |
| Циклическая ссылка (ремикс из своего же потомка) — редкий кейс, но API обязан гасить (MF-369) | Модалка не позволяет дойти до публикации из такого контекста: API вернёт 409 на попытку — `toast critical` «Нельзя сделать ремикс из своего же ремикса», модалка закрывается, остаёмся на карточке |
| Пользователь закрыл модалку/ушёл до «Опубликовать» | Как обычная загрузка — модель остаётся у себя в профиле непубликованной черновиком (`marketplace.full.md` §11.2, «Сохранить черновиком»), атрибуция уже привязана (создана на сервере при старте потока) — при повторном открытии «моих моделей» видно, что это черновик-ремикс |
| Гость | overlay-промпт входа при тапе (§2.1) |
| Сеть/сервер при `POST /models/:id/remix` | `toast critical` «Не удалось создать ремикс. Попробуйте снова», модалка остаётся открытой на дропзоне |

## 3. Блок «Ремикс из ‹оригинал›» на карточке ремикса

**Место.** Сразу под названием/автором/голосами модели, **над** описанием (`model.card.v3.md` героя не трогаем структурно — это вставка одной строки-плашки в существующий вертикальный поток, не новая секция героя).

**Вид.** Приглушённая узкая плашка на всю ширину колонки (не карточка-в-карточке — не конкурирует вниманием с самой моделью, «яркость = важность», `model.card.v3.md` §5): fork-глиф (тот же, что кнопка §2.1) + текст «Ремикс из **{название оригинала}**» (жирностью выделено название, не вся строка) + маленький круглый аватар/thumb оригинала слева от текста. Вся плашка кликабельна → `/project/:remixOfId`.

**Оригинал стал недоступен** (удалён/приватный после того, как ремикс уже опубликован) — плашка **остаётся**, но название теряет ссылку и получает приглушённый суффикс «(недоступен)»: связь — исторический факт, скрывать её нечестно, но вести на 404 тоже нельзя.

**Цепочки (ремикс ремикса).** Плашка показывает только **прямого** родителя, не всю цепочку до корня — «одна мысль на кадр» (§3.3 ниже поясняет то же решение для выдачи).

## 4. Блок/вкладка «Ремиксы» на карточке оригинала

### 4.1 Место и заголовок

Новая вкладка в существующем ряду вкладок карточки (`model.card.v3.md` §1: `Обсуждение · Напечатали · Статистика`), добавляется **четвёртой**: **«Ремиксы (N)»** — счётчик в заголовке вкладки, как «Обсуждение (N)» (§4.1 того же файла). Свой маршрут `/project/:id/remixes` (тот же паттерн под-маршрутов).

**Вкладка видна всегда**, даже при `N=0` — «Ремиксы» это витрина возможности «из этой модели можно сделать своё», а не только текущий счётчик; скрытая при нуле вкладка прячет саму опцию remix от тех, кто зашёл в первый раз (сигнал важнее пустоты, тот же аргумент, что у вкладки «Статистика» §5 в `model.card.v3.md`).

### 4.2 Выдача

Сетка плиток, переиспользуем `ModelTile` из каталога (`marketplace.full.md` §2.3) без нового компонента — превью, название, автор, голоса уже там есть. Сортировка одна — «сначала новые» (тот же аргумент, что у комментариев §4.3 `model.card.v3.md`: десятки ремиксов, не тысячи, лишний переключатель не нужен).

**Пагинация** — «Показать ещё» (не бесконечный скролл), тот же паттерн, что лента комментариев (`model.card.v3.md` §4.2).

### 4.3 Только прямые дети, не вся цепочка

Вкладка «Ремиксы» показывает **только прямых потомков** этого проекта (по `remix_of_project_id = :id`), не рекурсивный список внуков. Если у ремикса, в свою очередь, есть свои ремиксы — они видны на **его** вкладке «Ремиксы», не здесь. Это соответствует MF-369 («учесть цепочки») без визуального разворачивания дерева — дерево ремиксов исследуется переходами карточка→карточка (как дерево гита, `model.card.v3.md` §0, «форк» — уже принятый паттерн для той же формы навигации), а не отдельным деревовидным виджетом, которого нет ни у одной другой сущности портала.

### 4.4 Бейдж на плитке каталога

Плитка `ModelTile` с `remixes_count > 0` получает мелкую приглушённую пилюлю в углу превью — «↳ N» (тот же fork-глиф, минимально, без текста «ремиксы»): в каталоге это должно читаться с одного взгляда, не отвлекая от самого превью модели. `remixes_count = 0` — пилюли нет вовсе (не «0»).

### 4.5 Состояния

- **Пусто (N=0):** заглушка в теле вкладки — приглушённый fork-глиф + «Пока ни одного ремикса» + подпись «Кто-то возьмёт эту модель за основу — и она появится здесь» (тон обещания, не пустоты — тот же приём, что «Статистика появится, когда…» `model.card.v3.md` §5). Кнопки нет — сделать ремикс может любой посетитель кнопкой на самой карточке (§2.1), дублировать CTA во вкладке не нужно.
- **Грузится:** сетка скелетон-плиток (2–4 в зависимости от ширины), не спиннер — тот же язык, что скелетон обсуждения.
- **Ошибка загрузки:** строка «Не удалось загрузить ремиксы» + «Повторить».
- **Догрузка следующей страницы:** кнопка «Показать ещё» уходит в состояние ожидания, не исчезает и не дублируется.

## 6. Крайние случаи и где заабьюзят (сводка)

| Риск | Как гасит поток |
|---|---|
| Клиент подделывает/редактирует атрибуцию оригинала | Атрибуция не поле формы — пишется сервером из `:id` в пути `POST /models/:id/remix`, клиент физически её не отправляет (§2.3) |
| Цикл: ремикс собственного потомка | API 409 (MF-369 «запрет циклов»), клиент показывает `toast critical`, не даёт зайти в тупиковый флоу (§2.5) |
| Оригинал исчез после того, как ремикс уже существует | Плашка §3 остаётся как исторический факт, ссылка гасится, суффикс «(недоступен)» — не 404 и не тихое исчезновение атрибуции |
| Вкладка «Ремиксы» превращается в развёрнутое дерево на 5 уровней | Показываем только прямых детей; глубже — переходом на карточку ребёнка (§4.3) |
| Пустая вкладка «Ремиксы» читается как «фичи нет» | Вкладка видна всегда (не прячется при N=0), пустое состояние — приглашение, не тупик (§4.5) |
| Ремикс из ещё конвертирующегося (`pending`) оригинала | Кнопки «Сделать ремикс» нет, пока источник не `ready` (§2.1) |
| Два проекта с одинаковым названием (ремикс скопировал имя оригинала) | «Название» ремикса не предзаполняется — пустое поле, автор обязан дать своё (§2.2) |

## 7. Приёмка сценария

- [ ] Кнопка «Сделать ремикс» на карточке оригинала: видна только у чужой `ready`-модели, гостю — overlay-промпт входа, недоступному оригиналу — `toast critical` без открытия модалки.
- [ ] Модалка ремикса — переиспользует `AddModelFlow` (не новый флоу), заголовок с названием оригинала, плашка атрибуции над дропзоной нередактируема, тап по плашке ведёт на карточку оригинала.
- [ ] «Название» ремикса не предзаполнено. Атрибуция создаётся сервером, не отправляется клиентом.
- [ ] После «Опубликовать» — блок «Ремикс из ‹оригинал›» виден на новой карточке сразу, синхронно с первым кадром, не отложенно.
- [ ] Блок «Ремикс из ‹оригинал›»: клик ведёт на оригинал; при недоступном оригинале — ссылка гасится, текст «(недоступен)», плашка не исчезает.
- [ ] Вкладка «Ремиксы (N)» видна всегда, включая N=0; пустое состояние — приглашение, не тупик; сетка `ModelTile`, «Показать ещё», только прямые дети.
- [ ] Бейдж «↳ N» на плитке каталога появляется только при `remixes_count > 0`.
- [ ] Цикл (ремикс своего потомка) гасится на уровне API 409 + `toast critical`, UI не даёт зайти в тупик молча.
