# Маркетплейс: галерея моделей + флоу «Добавить» (скелет)

← [docs/design/readme.md](readme.md) · **Полный маркет** (каталог, страница модели, редактирование, профиль автора, мобайл) — [marketplace.full.md](marketplace.full.md) (MF-461). Этот файл описывает скелет (MF-458/459), который уже в проде; полная спека достраивает его.

Дизайн-план вкладки «Маркетплейс» (MF-457 / [MF-458]). **Скелет**: приоритет — целостность флоу, не полировка. Раздел помечается «экспериментальный». Всё собирается из **готовых примитивов** UI-кита (`apps/web/src/ui/ui.tsx`, эпик MF-40) и слоя всплывашек (`apps/web/src/overlay`, эпик MF-440); новые сущности вводим только там, где текущая система не покрывает нужное — такие места явно помечены как **GAP**.

Скелет НЕ включает (границы MF-457): покупку/продажу и цены, форки, «отправить в печать», поиск/фильтры, рейтинги/комментарии, скачивание готового 3MF (Фаза 3, MF-338 — но галерея готовится к нему структурно).

## 1. Вкладка «Маркетплейс» — место в навигации

**Проблема (GAP-NAV, важно):** в приложении **нет навигации между разделами** — `app.tsx` рендерит единственный `HomeScreen`, роутера/табов не существует. «Отдельная вкладка» физически некуда повесить. Это первый архитектурный вопрос реализации.

**Решение для скелета — минимальная навигация, не полноценный роутер:**

- Ввести лёгкий переключатель раздела на уровне `App` (например, `useState<"home" | "market">` или хэш-роут `#/market`) — достаточно для скелета, полноценный роутер (react-router / file-based) — отдельная задача, не блокирует.
- **Где живёт переключатель визуально:** капсула-«островок» уже «едет по всем страницам» и по [header.capsule.md](header.capsule.md) её **левый край принимает контекст страницы**. Табы разделов ставим как ряд из 2 сегментов **слева от капсулы** (или под часами на узких экранах): `Дом · Маркетплейс`, стиль — те же `Chip`-пилюли с `data-selected` (выбранный = зелёная заливка). Это переиспользует существующий сегмент-примитив, не вводит новый нав-компонент.
- Правило «один primary-CTA на экран» соблюдено: таб-пилюли — это выбор, не действие; единственный зелёный primary на экране Маркетплейса — кнопка «Добавить» (§3).

**Метка «экспериментальный раздел»:**

- В шапке раздела (под табами, над галереей) — `Eyebrow` + `StatusPill tone="warn"`: `ЭКСПЕРИМЕНТАЛЬНО · Маркетплейс`. Янтарь = «требует внимания, не ошибка» ([palette.typography.md](palette.typography.md)) — семантически верно для «раздел в разработке», без пульса (это статус, не срочность).
- Одноразовая пояснительная плашка (`Card`, приглушённая): «Маркетплейс — экспериментальный раздел. Пока это скелет: загрузка моделей работает, но покупка, печать и поиск появятся позже.» С кнопкой «Понятно» (сохранение через тот же механизм `home_dismissed_prompts`, что и онбординг-чек-лист — см. `activation.ts`). Не более одного обучающего элемента на экране (принцип анти-перегруза).

**Заголовок раздела:** двухтоновый `Heading` — «Маркетплейс» белым + акцентное слово мятным (напр. «Ваши **модели**» на экране своей библиотеки; для общего каталога — «**Маркетплейс** моделей»). Точная копирайт-строка — на реализацию.

## 2. Галерея моделей

### 2.1 Раскладка

- **Переиспользуем сетку `.homeGallery`**: `grid-template-columns: repeat(4,1fr)`, gap 18px; ступени 3 (≤1000px) → 2 (≤720px) колонки уже заданы. Никакой новой сетки.
- **Карточка модели = плитка `.homeModelTile`** (radius 24, стекло, каскадное появление `homeRise` со stagger по `--i`).
- Появление галереи — каскад (stagger ~60ms/плитку, уже в CSS); всё off при `prefers-reduced-motion` ([motion.md](motion.md)).

### 2.2 Анатомия карточки

Сверху вниз, внутри плитки:

1. **Превью** — `.homeModelThumb` (слоёный псевдо-3D стек: glow → back-blur → front → тень-пол, [model.preview.md](model.preview.md)).
   - **Заглушка (скелет):** реальные превью-рендеры появятся в Фазе 3 эпика MF-8. До тех пор — **тот же слоёный стек с нейтральным line-глифом** (как мок-глифы на главной), заглушка НЕ ломает раскладку: webp-рендер вставится в тот же стек без изменения вёрстки. Для `pending/processing/failed` превью-рендера ещё/уже нет — показываем плейсхолдер-глиф + статусную наложку (§4).
2. **Название** (`.homeModelName`, Unbounded/medium) — `title` модели.
3. **Автор** (`.homeModelSub`, приглушённо) — `@username` владельца. (♥-лайки с главной НЕ переносим — рейтингов в скелете нет.)
4. **Статус обработки** — `StatusPill` в углу превью и/или строкой меты (см. §4). Для `ready` пилюлю можно скрывать (готовое — норма, «яркость=важность»: спокойное состояние приглушено).

### 2.3 Пустое состояние (обязательно)

Моделей ещё нет → **`EmptyState`** (`.uiEmptyState`), по центру места галереи:

- Иконка — простой line-глиф куба/коробки в мятном кружке (`.uiEmptyStateIcon`).
- Заголовок: «Здесь появятся ваши модели».
- Подпись: «Загрузите первую — STL, STEP или 3MF до 100 МБ. Мы приведём её к чистому 3MF.»
- Action-слот `EmptyState` — та же primary-кнопка «Добавить», что и в §3 (единственный зелёный CTA). Пустое состояние — это пассивный обучающий слой №1, не алерт.

## 3. Флоу «Добавить»

### 3.1 Точка входа

- **Кнопка «Добавить»** — единственный зелёный primary на экране Маркетплейса. Форма: `ActionCard variant="primary"` (заголовок «Добавить модель» + подпись «STL · STEP · 3MF, до 100 МБ» + круглая иконка-аффорданс «+»). Размещение — над галереей справа или в правом-верхнем слоте контента; в пустом состоянии — как action `EmptyState`.
- На узких экранах допустима круглая `IconButton` с «+», но текст+иконка предпочтительнее (тач-правило «действие дублируется текстом И иконкой»).

### 3.2 Модалка «Добавить модель»

Открывается через **`useOverlay().modal({ title: "Добавить модель", content: … })`** — НЕ локальный `useState('open')` (граница слоя всплывашек). Стекло `--bg-raised`, radius 22, pop-анимация — всё уже в overlay-слое. Внутри — вертикальный флоу:

**Шаг A. Выбор файла**
- Зона drop/тап: крупная пунктирная область (тач-таргет на всю ширину, ≥48px по высоте, `:active` вместо `:hover`). Копирайт: «Перетащите файл сюда или нажмите, чтобы выбрать». Подпись мелким: «STL, STEP или 3MF · до 100 МБ».
- Нативный `<input type="file" accept=".stl,.step,.stp,.3mf">` под зоной (системный пикер — свой не рисуем, [layout.md](layout.md) § тач-киоск).
- После выбора — строка выбранного файла: имя + размер + круглая `×` (`IconButton`) сбросить.

**Шаг B. Поля**
- **«Название»** (обязательное) — текстовое поле, radius 22–28 ([metrics.md](metrics.md)), плейсхолдер «Например: Органайзер для стола». Предзаполняется именем файла без расширения, редактируемо. Валидация: непусто.
- **«Описание»** (необязательное) — многострочное поле. **UI закладывает его как есть**, хотя колонки `description` в `models` нет — добавление колонки на этапе реализации (§5, GAP-DESC).

**Шаг C. Отправка**
- Кнопка «Загрузить» — primary (зелёная), внизу модалки. Вторичная «Отмена» — нейтральное стекло (закрывает модалку). Ровно один primary в модалке.
- При тапе: клиентская валидация (формат/размер/непустое название) → если ок, старт загрузки.

### 3.3 Индикатор загрузки файла

- Пока файл летит на сервер — **прогресс-бар** поверх/под зоной файла. **Переиспользуем `.uiChecklistBar` + `.uiChecklistBarFill`** (мятный градиент, `transition: width`) — не заводим новый бар для скелета.
- **GAP-PROGRESS:** `.uiChecklistBarFill` сейчас управляется дискретными шагами чек-листа, а не непрерывным `%` загрузки. Для реального прогресса аплоада (`XMLHttpRequest.upload.onprogress` / fetch stream) нужен **вынесенный примитив `ProgressBar`** (детерминированный `value 0..1` + опциональный indeterminate-режим для «ждём сервер»). **Предложение:** извлечь бар из `Checklist` в отдельный `ProgressBar` в UI-ките (MF-40) — переиспользуется здесь, в конвертации (§4) и в будущих загрузках. До извлечения — временно инлайн те же CSS-классы.
- Крупная модалка загрузки/процесса — по [motion.md](motion.md) это «отдельный момент процесса», не мелкий спиннер в углу: под баром — служебная строка `имя.stl · 62% · загрузка`.
- После 100% загрузки: модалка закрывается (или переходит в состояние «принято»), в галерее **сразу появляется карточка** новой модели со статусом `pending`/`processing` (§4). `toast({ severity: "info", title: "Модель загружена", message: "Идёт конвертация в 3MF" })` — краткое подтверждение.

### 3.4 Ошибки (тексты на русском)

Все — через слой всплывашек (toast/модалка), тон = семантика ([status.alerts.md](status.alerts.md)):

| Причина | Где | Текст (RU) | Тон |
|---|---|---|---|
| Неверный формат | инлайн под зоной файла + блок «Загрузить» | «Формат не поддерживается. Нужен STL, STEP или 3MF.» | danger (коралл) |
| Файл больше 100 МБ | инлайн под зоной файла | «Файл больше 100 МБ. Уменьшите модель или сожмите.» | danger |
| Пустое название | инлайн под полем | «Введите название модели.» | warn |
| Ошибка загрузки (сеть/сервер) | toast, sticky, с действием «Повторить» | «Не удалось загрузить. Проверьте связь и попробуйте снова.» | danger |
| Ошибка конвертации | статус карточки `failed` (§4) + toast | «Не удалось конвертировать модель. Попробуйте другой файл.» | danger |

Формат/размер валидируем **на клиенте до отправки** (быстрый фидбек), но сервер — источник истины (4xx с кодом причины, MF-455) → серверную ошибку тоже маппим на эти же тексты.

## 4. Статусные состояния карточки модели

Пять состояний из схемы `models`. Визуальный язык — `StatusPill` + наложка на превью; «яркость = важность» ([status.alerts.md](status.alerts.md)): спокойное приглушено, требующее внимания — ярче.

| Статус БД | Пилюля (тон) | Текст RU | Превью | Поведение |
|---|---|---|---|---|
| `uploaded` / `pending` | `dim` (серо-зелёный, приглушённо) | «В очереди» | плейсхолдер-глиф, лёгкий димминг | ждёт конвертера; без пульса |
| `processing` | `ok`-мятный, **лёгкий pulse** | «Конвертация» | плейсхолдер + мягкое «дыхание»/шиммер | активная работа; pulse допустим (не срочность, а «идёт процесс») |
| `ready` | пилюля **скрыта** или `dim` «Готово» | — / «Готово» | полноценное псевдо-3D превью (когда появится рендер MF-8) | норма → приглушено; карточка кликабельна |
| `failed` | `danger` (коралл), без пульса | «Ошибка» | плейсхолдер + коралловая обводка/димминг | доступно действие «Повторить»/«Удалить» (см. ниже) |

Детали:
- **`processing`** — если хочется «живого» ощущения без превью-рендера: мягкий шиммер по плитке ИЛИ переиспользовать индетерминантный `ProgressBar` (GAP-PROGRESS) полоской по низу превью. `prefers-reduced-motion` → статичная пилюля.
- **`failed`** — деструктив/повтор через `confirm`/`toast`-действия; удаление — всегда коралловое (деструктив никогда не зелёный, [palette.typography.md](palette.typography.md)).
- Пилюля живёт в углу превью (overlay) и/или в строке меты под названием — на реализацию; главное, чтобы статус читался с одного взгляда по цвету точки.
- Обновление статуса `pending→processing→ready` в скелете — polling списка моделей (простой `setInterval` рефетч) достаточно; realtime (SSE/WS) — не в скелете.

## 5. GAP-лист (что дизайн-система/бэкенд НЕ покрывают)

Фиксируем явно, чтобы этап 2 (реализация) не спотыкался и не изобретал молча:

1. **GAP-NAV — навигации между разделами нет.** `app.tsx` = единственный `HomeScreen`, роутера нет. Нужен минимум: переключатель `Дом ⇄ Маркетплейс` (хэш-роут или `useState` на уровне `App`) + таб-пилюли слева от капсулы. Полноценный роутер — отдельная задача, скелет не блокирует.
2. **GAP-PROGRESS — нет отдельного `ProgressBar`.** Есть только `.uiChecklistBar`, вшитый в `Checklist` и управляемый дискретными шагами. Нужен вынос в примитив `ProgressBar` (детерминированный `value` + indeterminate) в UI-ките MF-40 — для аплоада и для `processing`. До выноса — временно те же CSS-классы инлайном.
3. **GAP-DESC — колонки `description` в `models` нет.** UI-поле «описание» закладываем сейчас; ALTER TABLE (`description text`) — решаем на этапе реализации (ожидаемо по MF-458).
4. **GAP-DROPZONE — нет примитива зоны загрузки файла** (drag-and-drop + тап + список выбранного). Для скелета — локальная реализация в модалке Маркетплейса; если паттерн повторится, кандидат в MF-40.
5. **Экспериментальная плашка/дисмисс** — переиспользуем механизм `home_dismissed_prompts` из `activation.ts`; ключ для Маркетплейса добавить в тот же объект.

Всё остальное (карточки, пилюли, чипы, модалки, тосты, пустое состояние, превью-стек) — закрыто существующими примитивами. Реализация должна **компоновать их**, а не плодить копии.

## 6. Чек-лист приёмки скелета (для этапа 2)

- [ ] Из «Дома» можно перейти в «Маркетплейс» и обратно (переключатель + метка «экспериментально»).
- [ ] Галерея рендерит карточки моделей из `models` (сетка `.homeGallery`, плитка `.homeModelTile`, превью-заглушка).
- [ ] Пустое состояние показывается, когда моделей нет, и ведёт в флоу «Добавить».
- [ ] Флоу «Добавить»: выбор файла → название(обяз.)+описание → индикатор загрузки → карточка со статусом.
- [ ] Все 5 статусов (`uploaded/pending/processing/ready/failed`) визуально различимы по `StatusPill`.
- [ ] Ошибки формата / >100 МБ / пустого названия / сети / конвертации показывают тексты на русском.
- [ ] Всё живёт во всех темах (токены, не хардкод) и уважает `prefers-reduced-motion`.
- [ ] Все GAP-и §5 либо закрыты, либо явно вынесены в отдельные задачи (не молча).
