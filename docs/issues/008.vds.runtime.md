# 008 · Поднять рантайм на VDS (Node/Postgres) + секреты для авторизации

**Статус:** done — `3mf.tech`/`api.3mf.tech` живут по HTTPS, e2e проверено (PlagID-редирект + email OTP → сессия).
**Тип:** infra
**Создано:** 2026-07-03, закрыто 2026-07-03

## Суть

`apps/api`/`apps/web` с авторизацией (PlagID + email-домен-гейт) реализованы в коде. VDS был голый Ubuntu 24.04 — поднят полностью, задеплоено, снаружи работает.

## Сделано 2026-07-03

1. **Node.js 22 LTS + pnpm** (corepack), **PostgreSQL 16** (роль/база `portal`, миграция применилась — `users`/`user_identities`/`email_otp` на месте).
2. **Секреты** сгенерированы (`openssl rand`), только на VDS в `~/portal.api.env` (chmod 600, не в git): `DATABASE_URL`, `JWT_SECRET`, `AUTH_HMAC_KEY`, `AUTH_ENCRYPTION_KEY`, `PLAGID_EXTERNAL_TOKEN_SECRET`, `WEB_APP_URL`, `PLAGID_CALLBACK_URL`, `COOKIE_DOMAIN`.
3. **`apps/api`** — systemd-сервис `portal.api.service` (`EnvironmentFile=~/portal.api.env`, слушает `127.0.0.1:3000`, автостарт+автоперезапуск).
4. **`apps/web`** — статическая сборка (`VITE_API_URL=https://api.3mf.tech`), отдаётся nginx.
5. **nginx** — vhost'ы `3mf.tech` (статика) + `api.3mf.tech` (proxy → `127.0.0.1:3000`). Грабля: `/home/plag` был `750`, `www-data` не мог зайти → 500-ки — исправлено `chmod o+x /home/plag`.
6. **UFW**: разрешены только 22/80/443.
7. **`garage/auth`** — задеплоен с `EXTERNAL_TOKEN_SECRET` (тот же секрет, что `PLAGID_EXTERNAL_TOKEN_SECRET`).
8. **TLS — выпущен** `certbot --nginx` (Let's Encrypt, HTTP-01), сертификат на `3mf.tech`+`api.3mf.tech`, автопродление настроено certbot'ом. Подробности задержки 80/443 (не certbot-специфичные) — `docs/issues/009.dns.cloudru.md`.
9. **Проверено снаружи (не с самой VDS):**
   - `https://3mf.tech` → 200, `https://api.3mf.tech/health` → 200.
   - PlagID: `GET /auth/plagid/start` → корректный 302 на `auth.plag.space/login?redirect=...`.
   - Email: полный цикл `start` → код из `journalctl` → `verify` → `Set-Cookie` (`Secure`, `Domain=.3mf.tech`) → `/auth/session` узнаёт пользователя.
   - Тестовые пользователи после проверки удалены из `users`/`user_identities`.
