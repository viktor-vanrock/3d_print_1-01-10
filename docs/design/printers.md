# `/printers/releases` — календарь новинок (визуал)

← [docs/design/readme.md](readme.md) · сценарий/поток (не переизобретаем) —
[nav.sections.md §3.4](nav.sections.md) (UX, MF-801) · раздел «Принтеры» целиком, каталог и
карточка принтера — [printers.catalog.md](printers.catalog.md) (MF-862, уже сдано, здесь не
повторяется) · переключатель «Каталог · Новинки» — [printers.catalog.md §1.1](printers.catalog.md)
· мост из ленты — [feed.md §1.3](feed.md) (дельта ниже) · MF-833.

**Что это.** `printers.catalog.md` закрыл каталог, карточку принтера и `/printers/compare` —
все три уже реализованы (`apps/web/src/printers/{printersscreen,printerdetailscreen,
comparescreen}.tsx`). Единственный экран раздела «Принтеры» без визуальной спеки —
**`/printers/releases`**: сегодня переключатель шапки просто пересортировывает тот же
каталог по свежести (`?view=new`), а не показывает ленту событий по датам, которую описал
UX (`nav.sections.md §3.4`: `announced → preorder → shipping`, группировка по месяцам,
действие «Уведомить о выходе»). Этот файл — визуал недостающего экрана + карточка релиза,
которую переиспользует правый рельс `/feed`.

**Решение ревью 16.07.2026.** Отдельный маршрут сохраняем: бейдж `NEW` и сортировка в
каталоге отвечают на поиск новой модели, но не заменяют календарь событий, группировку по
месяцам и подписку «Уведомить о выходе». `Рекомендуемые` в каталоге — не персональная
реклама: первыми идут записи с верифицированными данными, при поиске дефолт меняется на
«Релевантные». Правило реализовано в `sortPrinters` и описано в `printers.catalog.md §5`.

**Границы.** Поток и состав данных (`GET /releases`) — за UX, здесь не переизобретается.
Здесь: композиция, карточка релиза, состояния, моушен, звук, тач/ТВ.

## 1. `PrinterReleaseCard` — новый примитив

Одна карточка = одно событие каталога, не пресс-релиз (§0 п.«Календарь как рекламная
площадка», `nav.sections.md §7`): без баннеров, без цены «от», без кнопки «купить».

Анатомия (горизонтальная строка, та же стеклянная поверхность, что `PrinterTile`):

- **Дата** — слева, приглушённый моноширинный столбец (день · месяц сокращённо), тот же
  ритм, что временные метки в `feed.md §2`.
- **Статус-пилюля** — `announced` (dim), `preorder` (обычная заливка, акцентный тон, короче
  жить), `shipping` (сплошная заливка бренд-зелёным — единственный полностью «горячий» тон
  на карточке). Один и тот же токен пилюли, что `printers.catalog.md §1.1`/`§4.1` для
  жизненного статуса модели — не заводим второй словарь цветов для того же смысла.
- **Вендор · модель** — обычный текст, тап по всей строке (не только по названию) ведёт на
  `/printers/:id`, **если запись в `machines` уже есть**; если каталожной карточки ещё нет
  (чисто анонс без спек) — тап неактивен, вместо ссылки нейтральная подпись «пока без
  карточки» (частный случай §0 п.1 из `printers.catalog.md`: не рисуем мёртвую ссылку).
- **Действие справа** — `Chip`-кнопка **«Уведомить о выходе»** → подписка на саб вендора
  (переиспользуем существующий паттерн подписки, `community.md §2.2`: тап → оптимistично
  «Уведомления включены», без диалога). Гость → промпт входа по тапу, карточка событий
  читается свободно.

Три композиции одного и того же каркаса:
1. **Рельс `/feed` (§1.3 фида)** — 3 карточки, компактная ширина колонки (~320px), дата и
   пилюля в одной строке над названием (вертикальный стек, не горизонтальный — колонка
   узкая).
2. **Лента `/printers/releases`** — полноширинная строка внутри `wide`-контейнера
   (`printers.catalog.md §1.2`), горизонтальная анатомия как описано выше.
3. **Ссылка на карточку принтера** (§3.3 `printers.catalog.md`, «Что выходит») — не новая
   композиция, тот же рельсовый вид сбоку у карточки модели-предшественника, если она уже
   продаётся, а новая версия анонсирована; вне охвата MF-833, зафиксировано на будущее.

Реализация — новый файл `apps/web/src/printers/releasecard.tsx`, экспортируется в
`components.md` рядом с `PrinterTile`.

## 2. `/printers/releases` — рамка страницы

Тот же `wide`-контейнер и шапка раздела, что `/printers` (`printers.catalog.md §1`,
переключатель «Каталог · Новинки» тот же орган, просто второе положение вместо
query-сортировки). Сайдбар фильтров **не переносится** — календарь не фильтруется по
фасетам каталога (`nav.sections.md §3.4` не упоминает фильтры), поэтому вместо
сайдбар+сетка здесь одна колонка: центр той же ширины, что карточка принтера
(`printers.catalog.md §4`, `max-width` контента), без правой пустоты — календарь читается
сверху вниз, не сканируется взглядом по сетке.

Группировка по месяцам, ближайшее сверху:

```
┌ Сентябрь 2026 ──────────────────────────────┐
│ [PrinterReleaseCard] × N                     │
├ Октябрь 2026 ─────────────────────────────── ┤
│ [PrinterReleaseCard] × N                     │
└───────────────────────────────────────────── ┘
```

- Заголовок месяца — `Eyebrow`-строка (тот же токен, что `feed.md §1.4`), не отдельная
  `Card`: месяц — это разделитель ритма, не контейнер.
- Внутри месяца карточки идут по дате по возрастанию, без дополнительной сортировки —
  календарь, не лента приоритетов.
- **Прошедшие месяцы** (`shipping`, событие позади) сворачиваются после первого будущего
  месяца под кнопкой **«Показать остальные (N)»** с шевроном вниз. Она раскрывает и снова
  сворачивает список («Скрыть остальные (N)»), отражает состояние через `aria-expanded`, имеет
  hover/focus-отклик и тач-таргет не меньше 48px. Календарь открывается на «сейчас», не
  пролистывается с начала года.

## 3. Состояния

Наследуют словарь `printers.catalog.md §7` / `nav.sections.md §4`, специфика календаря:

| Состояние | Что видит | Почему |
|---|---|---|
| **Месяц пуст** | Не пустая секция — месяц просто не рисуется; если пуст **весь ближайший диапазон**, одна строка «Ближайшее — в {месяц}» + карточка следующего события | пустая сетка месяца ничего не сообщает (`nav.sections.md §4`); мы не рисуем воздух там, где нет данных |
| **Календарь пуст целиком** | Та же честная строка каталога: «В календаре пока нет анонсов» — без хиро, без иллюстрации | второй пустой чек-лист запрещён рамкой (`frame.md §2`) |
| **Грузится** | 3 скелетон-строки текущего месяца, заголовок месяца уже на месте | шапка раздела не мигает |
| **Ошибка** | «Календарь не отвечает. Обновить» в теле, меню и переключатель «Каталог · Новинки» живы | упавшая секция не забирает навигацию |
| **Гость** | читает ленту свободно; тап «Уведомить о выходе» → промпт входа | чтение публично — сквозное правило |
| **Уже подписан** | `Chip` в состоянии «Уведомления включены» (та же залитая форма, что «Отписаться» в `community.md §2.2`) | подписка — не одноразовое действие, состояние должно быть видно при повторном визите |

## 4. Мобайл/тач

- `< 900px`: одна колонка на всю ширину контента (см. `printers.catalog.md §6`), карточка
  релиза складывает горизонтальную анатомию в две строки: дата+пилюля сверху, вендор/модель
  + `Chip` снизу — тот же паттерн сжатия, что `PrinterTile` в узкой сетке.
- Тап-зона всей строки карточки ≥ 44px по высоте (стандарт портала), `Chip` подписки — своя
  тап-зона внутри строки (не дублирует тап по карточке, как `+`-кнопка сравнения у
  `PrinterTile`, `components.md §«Фасетный каталог»`).
- Свайп между разделами (`touch.nav.md §2`) работает как обычно — лента календаря
  вертикальная, горизонтальных рельсов внутри неё нет, коллизии жестов (`nav.sections.md
  §1.4`) здесь не возникает.

## ТВ / пульт

Список карточек — вертикальный D-pad-навигируемый список (`tv.10foot.md §3`), фокус-ринг
на всей строке карточки, `ОК` на карточке со ссылкой уводит на `/printers/:id`, на карточке
без ссылки — активирует `Chip` подписки напрямую (нет второго интерактивного элемента
внутри строки, значит незачем заходить «внутрь» карточки отдельным нажатием).

## 5. Моушен и звук

Переиспользуем словарь `motion.md §5` (появление контента) и `sound.md §3`, ничего нового
не заводим:

- **Появление ленты** — карточки месяца проявляются тем же лёгким stagger, что карточки
  каталога (`motion.md §5`), задержка между карточками короче (список плотнее сетки).
- **Переключатель «Каталог · Новинки»** — тот же моушен и звук, что любой `SegmentToggle`
  портала (`motion.md §7`, `tick` на тап + смена контента cross-fade, не полный переход
  раздела — это подвкладка, не роут-переход `motion.md §2`).
- **Тап «Уведомить о выходе»** — микро-подскок кнопки + звук `confirm` (семейство
  «подтверждение», `sound.md §2`) в момент, когда `Chip` меняет состояние на «включено» —
  тот же тайминг, что подписка на саб (`community.md §2.2`).
- **`prefers-reduced-motion`** — stagger схлопывается, `Chip` меняет состояние мгновенно без
  подскока, звук остаётся (звук не моушен, [motion.md — Reduced-motion](motion.md)).

## 6. Дельта к `feed.md` §1.3 — мост в обе стороны

Под блоком «Новинки принтеров» правого рельса `/feed` (`feed.md §1.3` п.2, три карточки
релиза — уже используют `PrinterReleaseCard` в компоновке §1 «рельс» этого файла) —
добавляется нейтральная строка-ссылка:

```
Новинки принтеров
[PrinterReleaseCard] × 3
Все новинки →
```

- Та же типографика и тон, что «Все фиды →» соседнего блока левой колонки (`feed.md §1.2`) —
  не новый паттерн ссылки-подвала, переиспользуем существующий.
- Ведёт на `/printers/releases`. Это единственная правка `feed.md` — поток и обоснование
  моста уже решены UX (`nav.sections.md §2` п.3), `feed.md §1.3` не переоткрывается сверх
  этой строки.

## 7. Готово когда

- [ ] `PrinterReleaseCard` реализована как переиспользуемый примитив (рельс `/feed` и лента
      `/printers/releases` рендерят один компонент, не два похожих).
- [ ] `/printers/releases` группирует по месяцам, открывается на ближайшем будущем месяце,
      прошедшее сворачивается под «Раньше».
- [ ] Все состояния §3 покрыты, включая «календарь пуст» и «месяц пуст».
- [ ] «Уведомить о выходе» — оптимистичная подписка, видимое состояние «включено» при
      повторном визите, гость получает промпт входа.
- [ ] Мобайл/ТВ-поведение §4 работает без переизобретения — те же примитивы фокуса/тач, что
      остальной каталог.
- [ ] `feed.md` получил строку «Все новинки →» под блоком «Новинки принтеров».
- [ ] Раздел не выкатывается, пока `GET /releases` отвечает `401` гостю (тот же блокер, что
      `nav.sections.md §4`, снимает карточка Fullstack — не эта).
