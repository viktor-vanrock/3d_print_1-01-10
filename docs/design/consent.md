# Баннер согласия на поведенческую аналитику (152-ФЗ, MF-610)

← [docs/design/readme.md](readme.md)

Спека под контракт `POST /consent` ([MF-609](../epics/analytics.events.md) §«Согласие»): `{ action: "granted"|"revoked", version: string }`. Один чекбокс/согласие покрывает и поведенческую аналитику, и cookie (эпик решил не разносить на два типа) — баннер НЕ предлагает выбор «аналитика да, cookie нет».

## 1. Форма и место

**Fixed-полоса снизу**, не sticky (в отличие от `DevBanner` — тот резервирует место в потоке; консент-баннер не должен двигать раскладку экрана при появлении/исчезновении, философия «фикс-хром не раздвигает контент», [readme.md](readme.md) §Философия п.4).

- `position: fixed; bottom: 0; left: 0; right: 0;` — полноширинный фон-подложка (`--surface` + `backdrop-filter: blur(20px)`, тот же паттерн стекла, что `.ovlToast`/`.ovlSheet` — `overlay.css`), контент внутри центрирован по `--content-max` (1280px), как весь остальной контент сайта.
- Верхние углы скруглены `--card-radius-sm` (22px), нижние — 0 (полоса «встаёт» от края вьюпорта, тот же приём, что нижний sheet). Верхняя граница `1px solid var(--border)`.
- Не модальна — не блокирует контент под собой, `pointer-events` только на самой полосе. Это НЕ нарушает fail-closed: fail-closed гарантируется на бэке (событие не пишется без свежего `granted`), баннер лишь не должен молча скрываться сам.
- **Новый z-токен `--z-consent: 62`** (`theme/tokens.css`, рядом с `--z-toast: 60`/`--z-sheet: 65`) — юридическое уведомление весомее эфемерного тоста (остаётся видимым, пока тост показывается и гаснет), но уступает функциональным оверлеям, которые пользователь открыл сам, и критичным алертам печати (`--z-sheet`/`--z-modal`/`--z-alert` перекрывают его, когда открыты). Не переиспользуем `--z-toast`/`--z-alert` — это разные по природе слои (транзиент/критично-прерывающий vs персистентно-фоновый).
- Раскладка полосы: текст согласия слева (или сверху на мобильном — колонкой), кнопка «Согласен» справа, на мобильном — на всю ширину под текстом (тач-таргет ≥48px по всей ширине, легко попасть большим пальцем снизу экрана).
- Появление/уход — по мотиву `motion.md` (reveal снизу, не резкий), уважает `prefers-reduced-motion`.

## 2. Текст

Заголовок не нужен — одна строка + кнопка, лаконично (принцип «одна мысль на экран»):

> Мы используем cookie и анализируем ваши действия на сайте, чтобы улучшать сервис. Продолжая пользоваться сайтом, вы соглашаетесь с обработкой поведенческих данных. [Подробнее](/privacy) · **[Согласен]**

- Одна кнопка **«Согласен»** (`Button variant="primary"`, `ui.tsx`) — по клику `POST /consent {action:"granted", version: CONSENT_VERSION}`, баннер скрывается (локальный стейт + запись согласия локально, чтобы не мигать на каждом рендере/навигации до ответа сервера).
- **Кнопки «Отклонить»/«Настроить» нет** — fail-closed на UX-уровне: пока нет клика «Согласен», баннер просто остаётся видимым при каждом визите/навигации (не одноразовый дизмисс без действия). Ссылка «Подробнее» ведёт на текстовую страницу политики (если её ещё нет — обычная ссылка, не блокирует эту карточку; заведите отдельной карточкой, если политики конфиденциальности не существует).
- Тон — нейтральный, не «юридическая простыня»: одна фраза, без канцелярита длиннее необходимого.

## 3. Место отзыва согласия

Минимально — пункт **внутри модалки редактирования профиля** (`ProfileEditForm`, `home/profileedit.tsx`, открывается из капсулы шапки → «Профиль»): отдельного экрана настроек в роутере ещё нет ([router.ts](../../apps/web/src/router.ts) знает только публичный `profile{username}`), заводить его ради одной ссылки — избыточно для этой карточки.

- Внизу формы, после кнопки «Сохранить», разделитель + строка: **«Отозвать согласие на аналитику»** — текстовая ссылка-кнопка (`variant="secondary"`, не primary — это не основное действие формы, второй по яркости акцент).
- По клику: `POST /consent {action:"revoked", version: CONSENT_VERSION}` → `overlay.toast({title:"Согласие отозвано"})`, форма не закрывается. Если баннер уже был скрыт (согласие было дано раньше) — после отзыва он должен снова появиться при следующей навигации (стейт согласия читается из того же места, что источник для эмиттера на фронте).
- Когда появится отдельный экран настроек/приватности — переносим сюда как один из пунктов, это временное, не архитектурное решение.

## 4. Токены

По умолчанию — из [palette.typography.md](palette.typography.md), нейтральный тон, не warn/danger:

- Фон полосы — `--surface` (тот же тёмный тил-стеклянный фон, что у toast/sheet), НЕ `--accent-warn` (это не тревога/поломка — обычное, не срочное сообщение, «яркость=важность» здесь говорит «приглушённо»).
- Текст — `--text` основной, ссылка «Подробнее» — акцентным `--accent` (зелёный) подчёркнутым.
- Кнопка «Согласен» — `Button variant="primary"` как есть, без кастомной раскраски.
- Радиус/стекло/шрифт — стандартные токены (`--card-radius-sm`, `--font-body`), отдельной палитры под юридический баннер не заводим — он часть того же приложения, не отдельный «системный» слой.

## Константа версии

`CONSENT_VERSION` — строковая константа во фронте (`apps/web/src/consent/` или рядом с эмиттером аналитики), синхронно с бэком по смыслу (не общий код, просто оба знают текущее значение). При изменении текста согласия — бампнуть константу, баннер снова покажется всем, включая ранее согласившихся (сравнение локально сохранённой/последней версии из ответа `/consent` с текущей константой).
